# 036 — Flush-left / flush-right title alignment — PLAN

## Design decisions

| Decision | Rationale |
| --- | --- |
| **In right mode, `title_pos[0]` is the block's RIGHT edge**, not its left. | That is what "flush right" means, and it is what makes the control useful: the point of right-aligning a cover title is putting it against the right of the frame. Keeping the anchor as a left edge would right-align the lines *within* the same left-hand box — typographically valid, visually pointless on a 1280×720 thumbnail. It also keeps dragging honest: you drag the edge the text is flush against. |
| **The wrap budget is measured from the anchor towards the far margin**, whichever way that is. | Right mode measures leftwards (`title_x - margin`), left mode rightwards (`W - title_x - margin`), both still capped at the original 62 %. Measuring rightwards in right mode would give a budget that has nothing to do with the space the text actually occupies. |
| **The editor mirrors the anchor (`x → 1 - x`) when you flip alignment.** | A project saved with the default `title_pos[0] = 0.035` would, on switching to right, put the right edge 3.5 % from the left — the title crushed into nothing. Mirroring lands it symmetrically on the other side, which is where someone flipping to "phải" wants it. It is reversible: flip back and you are exactly where you were. Editor-only; the renderer never second-guesses the value it's handed. |
| **`align="left"` is the default and renders byte-identically to today.** | Same reason as 035's `1.0` scale: 034's "Cập nhật ảnh bìa" pushes covers onto already-published videos, so any silent shift reaches a live channel on the next click. Asserted, not assumed. |
| **An unknown value falls back to left rather than raising.** | A hand-edited settings file must not kill a 30-part render. Same posture as `_scaled_px` flooring at 8 px. |
| **`PHẦN N` and the tagline are untouched.** | Out of scope by the user's own scoping. They centre on their anchor, which is a different control with different semantics. |

## Implementation

### 1. `src/noveltrans/tts/thumbnail.py`

```python
TITLE_ALIGNS = ("left", "right")
DEFAULT_TITLE_ALIGN = "left"
```

`compose_thumbnail(..., title_align=DEFAULT_TITLE_ALIGN)` and the same on
`render_thumbnail`. In the title block:

```python
right = str(title_align or "").lower() == "right"
max_text_w = max(
    round(W * 0.2),
    min(round(W * 0.62), (title_x - margin) if right else (W - title_x - margin)),
)
...
for line in lines:
    line_w, line_h = _line_size(title_font, line, title_stroke)
    x = title_x - line_w if right else title_x
    _draw_glow_line(bg, (x, y), line, ...)
```

`_line_size` is already what the `PHẦN N` block uses to centre itself, so right-aligning
with the same measure keeps the two blocks consistent.

### 2. `src/noveltrans/config.py`

`video_thumbnail_title_align`, validated against `TITLE_ALIGNS` on read and write (an
unknown stored value reads as `"left"`), matching the clamping the `*_scale` properties do.

### 3. `src/noveltrans/gui/thumbnail_editor.py`

A "Canh tiêu đề: (Trái) (Phải)" radio pair next to the size sliders. Toggling mirrors
`title_pos[0]` and re-renders. Saved in `_save_to_config`. "Đặt lại" restores `left`.

### 4. Threading

`tab_video.py` (`_render_thumbnail_now`, `_launch_video`) → `VideoWorker` →
`render_thumbnail`, following the `title_scale` path added in 035 exactly.

## Test plan

- `test_left_is_byte_identical_to_the_old_layout` — the no-migration guarantee.
- `test_right_alignment_changes_the_pixels`.
- `test_right_aligned_lines_end_at_the_anchor` — measure the rendered lines and assert
  their right edges coincide, which left mode's ragged right edge does not.
- `test_an_unknown_align_falls_back_to_left` — a bad settings value renders.
- `test_the_wrap_budget_flips_with_the_alignment` — a right-anchored title near the right
  edge gets a *wider* budget than the same anchor in left mode.
- Config: default, round-trip, unknown value reads as left.
- Editor: the radio seeds from config, toggling mirrors the anchor and is reversible,
  save persists, reset restores left.
- Tab: both cover-writing paths (`_render_thumbnail_now` **and** `VideoWorker`) carry it.

## Risks

1. The anchor reinterpretation is the only real risk: a saved `title_pos` means something
   different in right mode. Contained because the default is left (so nothing existing
   changes) and the editor mirrors on toggle (so the first flip looks right).
2. `_line_size` measures the stroked bbox, so a right edge is flush to within the stroke
   width — a pixel or two of raggedness at large stroke sizes. Acceptable, and the same
   approximation the centred `PHẦN N` block already lives with.
