# 036 — THUMBNAIL TITLE ALIGN — history

## [DECISIONS] — 2026-07-28

Settled with the user before planning:

- **The novel title only.** It is the one text that wraps onto several lines, so the only
  one where alignment is visible. `PHẦN N` and the tagline keep centring on their anchor.
- **Left and right only.** No centre option.

## [PLAN] 036.01-INITIAL-PLAN — 2026-07-28

Generated plan: `036.01-INITIAL-PLAN.md`. The load-bearing call: in right mode
`title_pos[0]` is re-read as the block's **right** edge, not its left.

Keeping it as a left edge would right-align the lines *within* the same left-hand box —
typographically valid, visually pointless on a thumbnail. Reading it as the right edge is
what "flush right" means, is what makes the control useful (title against the right of the
frame), and keeps dragging honest: you drag the edge the text is flush to.

## [IMPLEMENTATION] — 2026-07-28

921 tests pass (904 before, +17), ruff clean.

### `tts/thumbnail.py`

`TITLE_ALIGNS = ("left", "right")`, `DEFAULT_TITLE_ALIGN = "left"`, and a `title_align`
argument on `compose_thumbnail` / `render_thumbnail`. The title block now:

- picks its wrap budget from the anchor towards the **far** margin — leftwards when flush
  right, rightwards otherwise — still capped at the original 62 %;
- draws each line at `title_x - line_w` in right mode, using `_line_size`, the same
  measure the `PHẦN N` block already uses to centre itself;
- treats anything unrecognised as `left` (case- and whitespace-insensitive) rather than
  raising — same posture as `_scaled_px` flooring at 8 px, for the same reason: a
  hand-edited settings file must not kill a 30-part render.

### `config.py`

`video_thumbnail_title_align`, validated on **read as well as write** against
`TITLE_ALIGNS`.

### `gui/thumbnail_editor.py`

A "Canh tiêu đề: (Trái) (Phải)" radio pair below the size sliders, live-previewed.
"Đặt lại" restores `left`.

**The mirror.** Flipping alignment mirrors `title_pos[0] → 1 - title_pos[0]`. Without it,
a project at the default `0.035` would on switching to "phải" put its right edge 3.5 %
from the left — the title crushed into nothing. Mirroring lands it symmetrically on the
other side, and flipping back returns it exactly where it was (asserted). Editor-only: the
renderer never second-guesses the value it is handed.

### Threading

`tab_video.py` (`_render_thumbnail_now` **and** `_launch_video`) → `VideoWorker` →
`render_thumbnail`, following the `title_scale` path from 035. Both cover-writing paths
are covered by one test, because a full video render silently undoing an editor setting is
the failure mode that would take longest to notice.

### Verified visually, not just by assertion

Rendered a left/right pair and measured where the title's ink actually lands in the top
band: **466 / 92** (left-half / right-half) flush left, **95 / 465** flush right. A clean
mirror, which is the behaviour the pixel-inequality tests can't by themselves prove.

### Notes

- `test_right_aligned_lines_all_end_at_the_anchor` was written vacuously the first time
  (`{anchor for _ in lines}` is trivially a one-element set). Rewritten to compute both
  modes' draw positions from the real font metrics and assert the shared-edge /
  ragged-edge pair swaps over.
- `align="left"` is asserted byte-identical to the pre-036 output. Same reason as 035:
  034's "Cập nhật ảnh bìa" pushes covers onto already-published videos, so a silent shift
  would reach a live channel on the next click.

### Known limitation

`_line_size` measures the stroked bounding box, so the right edge is flush to within the
stroke width — a pixel or two of raggedness at large title sizes. The centred `PHẦN N`
block already lives with the same approximation.
