# 073.01 — Initial plan: app logo update

## Summary

Two brand assets replace two hand-drawn ones:

- `design/logo-icon.png` → `packaging/NovelTrans.png` → `.icns` (macOS bundle) + `.ico`
  (Windows exe), plus a small in-app copy so the window/dock icon exists in a dev run.
- `design/bar-icon.png` → a trimmed black-on-transparent glyph shipped as package data
  and used by `build_tray_icon()` in place of the QPainter book mark.

Consequences that ripple: `packaging/make_icon.py` stops being a *generator* and becomes a
*converter*; a new `src/noveltrans/gui/assets/` package-data directory appears; `tray.py`'s
module docstring stops being true; `make.ps1`'s "don't re-run make_icon.py on Windows"
special case loses its reason to exist; README's icon workflow changes.

## Confirmations added to the prompt's findings

- **No CI.** Nothing regenerates icons automatically; the derived artefacts
  (`packaging/NovelTrans.{png,icns,ico}`) are committed and stay committed.
- **`design/logo-icon.png` and `design/bar-icon.png` are already `git add`ed**, and the
  staged `.gitignore` edit re-anchors the old rule to `/design/fox_logo.png`. The two new
  sources are the only design files under version control — correct, since they are now
  *build inputs*, not one-off references.
- **The logo tile is not flat.** Sampling along row/column 512, the tile interior runs
  ≈188–215 with photographic texture, not a constant colour, and the checkerboard squares
  are 253/≈216. There is no clean threshold that separates tile from background — this
  rules out a colour key and drives Decision 1.
- **The bar glyph survives menu-bar sizes.** Converting luminance to alpha with
  `alpha = clip((233 − L) / 233)` over the measured bbox `(175,108)–(854,918)` gives mean
  alpha 0.427; downscaled to 18 px tall (15×18) it keeps mean 0.434 with full 0.0–1.0
  range, i.e. it still has holes and contrast rather than collapsing to a grey blob. The
  alpha ramp (not a hard threshold) is what preserves the antialiased facet edges.
- **The UI theme is blue, the new logo is warm.** `src/noveltrans/gui/style.py:24`
  `ACCENT = "#3f7bef"`; the logo's dominant saturated tones are `#685838`, `#b89878`,
  `#c8a898`, `#483818`. The tray fill colour is therefore a genuine taste call.
- **`resources.as_file` is only needed when an external process wants a real path**
  (`tts/video.py:125`, for ffmpeg/libass). Qt can take bytes, so the new loader should use
  `resources.files(...).read_bytes()` + `QPixmap.loadFromData` — no temp-dir context
  manager, works inside the frozen archive. `translators/names.py:96` is the precedent.
- **`src/noveltrans/gui/assets/` needs no `__init__.py`.** `[tool.setuptools.packages.find]`
  won't see it, but `[tool.setuptools.package-data] noveltrans = [...]` attaches relative
  paths to the `noveltrans` package — exactly how `tts/assets/*.png` already ships.

## Decisions

**1. Checkerboard removal — measure the tile once, then re-render through a rounded-rect
mask. Do not colour-key.**
The tile art is near-white, textured, and sits on a soft drop shadow that blends into the
checkerboard, so every keying strategy (colour key, border flood fill, checker-model
division) leaves either a halo or holes in the tile; cropping to a measured rect and
compositing through a generated alpha mask discards checkerboard *and* shadow by
construction, and the constants are reviewable in the diff.

**2. Corner radius — re-round to Apple's proportion, don't preserve the source's.**
Render the tile at 824×824 inside the 1024 canvas (100 px margin) with radius
≈ 0.2246 × 824 ≈ 185, so it sits at the same visual weight as every other Big Sur icon;
the source's own radius was authored for a mockup, not for the macOS grid.

**3. `make_icon.py` becomes a Pillow-only converter, not a generator.**
It reads `design/logo-icon.png` and writes `packaging/NovelTrans.png`; dropping
PySide6/QPainter/"Songti SC" also drops the `QT_QPA_PLATFORM=offscreen` dance from the
Makefile and makes the script deterministic and cross-platform.

**4. `make.ps1 icon` now runs both steps.**
The only reason it skipped `make_icon.py` was the macOS-only font (its own comment says
so); with that gone, running converter + `.ico` on Windows restores the 1:1 Makefile
mirror the script's header claims. Accepted cost: re-running on either OS may produce
byte-different PNGs across Pillow versions — noted in Risks.

**5. Tray icon — ship one master asset, recolour at runtime.**
A single trimmed black-on-transparent PNG at `src/noveltrans/gui/assets/tray-glyph.png`
serves both platforms: macOS gets it as-is with `setIsMask(True)` (mask reads the alpha
channel, so black RGB is the safe default), everything else gets the same silhouette
filled via `QPainter.CompositionMode_SourceIn`. One asset, one trim, no per-platform
export.

**6. Menu-bar sizing — scale by height to 82 % of the box, centred, aspect preserved.**
The glyph is portrait (679×810); Apple's menu-bar content is ≈18 pt inside a 22 pt box
(18/22 = 0.818), so at 22 → 18 tall × 15 wide, at 44 → 36 × 30. Trimming to the bbox
happens at asset-prep time so the runtime never re-measures.

**7. Add `app.setWindowIcon(...)` — yes, in scope.**
Once step 5 has built `gui/assets/` + the package-data entry + a loader, the marginal cost
is one 256×256 PNG and three lines in `app.py`, and it closes the "`make run` has no icon
at all" gap (plus Linux WM taskbars, which read neither the `.icns` nor the `.ico`).

**8. `src/noveltrans/tts/assets/vinyl_label.png` — out of scope.**
It is the spinning-record centre label in generated videos (`tts/video.py:64`
`VINYL_LABEL`), a content asset rather than an app icon. Flag as follow-up 074 since it is
visibly the old brand. `design/fox_logo.png` is its untracked source and stays ignored.

**9. Keep `design/logo-icon.png` / `design/bar-icon.png` committed.**
≈3.2 MB total, but they are now inputs to `make icon`; an uncommitted build input means
the icons cannot be regenerated from a fresh clone.

### Open questions for the user

   disagrees with the new warm logo — but the *app UI* is still blue, so this is

3. **Tile radius:** confirm Decision 2 (re-round to the macOS proportion) vs. preserving

## Implementation steps

### 1. Measure the logo tile (throwaway, not committed)

Run a one-off script (scratchpad, never added to the repo) against `design/logo-icon.png`
to find the tile's outer rect. Robust method given the texture: for each of rows/columns
near the tile's mid-line, the background is a strict two-level checkerboard (≈253 / ≈216,
period ≈28 px) plus JPEG noise, while the tile interior is warm-tinted
(`max(c) − min(c) > 12`) and non-periodic. Walk inward from each edge along the
mid-row/mid-column until the checker model stops predicting the pixel; that gives
left/right/top/bottom. Sanity-check against the coarse saturated-pixel bbox
`(108,112)–(916,916)` — the true tile edge should be at or slightly outside it, and the
bottom edge should sit *above* the shadow band (the vertical profile at x=512 shows the
shadow as a smooth ramp from ≈93 up to ≈220 across y≈824–1024).

Record four integers. They go into the converter as named constants with a comment saying
they were measured from this specific source file.

### 2. Rewrite `packaging/make_icon.py`

Replace the QPainter drawing entirely. New shape (Pillow only, matching `make_ico.py`):

- Module docstring: it now *converts* `design/logo-icon.png`, and states plainly that the
  source PNG has an opaque alpha channel with a checkerboard painted into RGB, which is
  why the tile rect is cropped and re-masked rather than keyed.
- Constants: `SIZE = 1024`, `TILE = 824`, `MARGIN = 100`, `RADIUS = 185`, and
  `_SRC_TILE = (left, top, right, bottom)` from step 1.
- `main(argv)`: open the source as RGB, crop `_SRC_TILE`, resize to `TILE×TILE` with
  `Image.LANCZOS`, build an `L` mask by drawing a filled rounded rectangle
  (`ImageDraw.rounded_rectangle`) at `RADIUS` — supersample the mask 4× and downscale for
  clean antialiased corners, since `rounded_rectangle` aliases badly at 1×. Paste onto a
  transparent 1024 RGBA canvas at `(MARGIN, MARGIN)` using that mask. Save.
- Keep the same CLI contract (`argv[1]` = output path, default `NovelTrans.png`) and the
  `print(f"wrote {out}")` / `return 1` on failure convention so the Makefile and
  `make.ps1` lines stay shaped the same.
- Source path: resolve `design/logo-icon.png` relative to the repo root computed from
  `__file__` (`Path(__file__).resolve().parent.parent`), **not** the cwd — `make.ps1 app`
  and `make app` both `cd`/`Push-Location` into `packaging/`.

### 3. Add `packaging/make_tray_glyph.py`

New sibling script, Pillow only:

- Reads `design/bar-icon.png`, converts to `L`.
- `alpha = clip((BG − L) / BG, 0, 1) × 255` with `BG = 233` (the measured background
  luminance). Named constant with the measurement in a comment; the ramp is deliberate — a
  hard threshold would alias the low-poly facet edges at 22 px.
- Crops to the known glyph bbox `(175, 108, 854, 918)` — assert the computed alpha bbox
  matches within a pixel or two and fail loudly if the source ever changes.
- Resizes to `HEIGHT = 512` preserving aspect (→ 429×512), builds RGBA with RGB = pure
  black and the computed alpha, saves to `src/noveltrans/gui/assets/tray-glyph.png`.
- Same CLI/print conventions as the other two scripts.

### 4. App-icon asset

Prefer a `--asset` output path on `make_icon.py` over a fourth script: same tile-rendering
code, just saved at 256×256 to `src/noveltrans/gui/assets/app-icon.png`. Keeps the tile
geometry defined in exactly one place.

### 5. Regenerate the derived artefacts

`packaging/NovelTrans.icns`, `src/noveltrans/gui/assets/{tray-glyph,app-icon}.png`. Then
`make_ico.py` for `packaging/NovelTrans.ico`.

### 7. New `src/noveltrans/gui/assets.py`

Small loader module, mirroring `translators/names.py:96`'s `resources.files(...)` form:

- `load_pixmap(name: str) -> QPixmap` — `resources.files("noveltrans.gui").joinpath(
  "assets", name).read_bytes()` → `QPixmap()` + `loadFromData`. Bytes, not `as_file`:
  nothing external needs a real path, and this works unchanged inside the frozen bundle.
- Cache the result in a module-level dict — `build_tray_icon()` loads the same master four
  times (once per size).
- Docstring should say why bytes-not-path, so the next person doesn't "fix" it into
  `as_file` by analogy with `tts/video.py`.

### 8. `src/noveltrans/gui/tray.py`

- **Module docstring:** the third bullet's closing claim ("Nothing ships as an asset either
  way … so the specs need no change") is now false about the asset and *accidentally still

- **`_ACCENT_COLOR`:** its comment points at `packaging/make_icon.py`'s gradient, which

- **`_glyph(size, color)`:** keep the signature (tests and readers depend on it). New body:

  `CompositionMode_SourceIn` fill so the silhouette takes the colour and alpha survives.
  Add a `_GLYPH_HEIGHT_RATIO = 0.82` constant with the 18-in-22 rationale.
- **`build_tray_icon()`:** unchanged in structure — same `is_macos` branch, same `sizes`

## Risks / gotchas

- **The fake transparency is the headline risk.** If step 1's tile rect is off by even a
  few pixels, the checkerboard reappears as a thin fringe along one edge. Verify by
  zooming, not by trusting the script.
- **The drop shadow blends into the checkerboard**, so a rect measured by "where does the
  checker stop" may land *outside* the tile and include shadow. Err inward by 1–2 px; the
  rounded mask hides a slightly tight crop, but not a loose one.
- **macOS icon cache.** Finder and the Dock cache `.app` icons aggressively; `killall
  Dock`, or move the `.app` and move it back, before concluding the icon didn't take.
- **Byte churn on the committed PNGs** across Pillow versions. Acceptable; mentioned so it
  isn't mistaken for a bug.
- **`collect_data_files` and editable installs.** A freshly added `gui/assets/` may not be
  visible to PyInstaller until `uv pip install -e ".[dev]"` re-runs.
- **22 px softness.** Scaling a 512-tall low-poly master down to 18 px can look muddy where
  facets meet. Fallback: emit pre-rendered exact sizes and have `_glyph` pick the nearest.
- **`test_it_is_a_filled_color_icon_off_macos` monkeypatches `sys.platform`,** so the asset
  must load under offscreen Qt with no display. Bytes-based `loadFromData` is fine there.
- **`app.setWindowIcon` placement.** The real ordering constraints in `main()`
  (`ensure_std_streams` → `augment_tool_path` → `QApplication`) are documented and must not
  be disturbed.
