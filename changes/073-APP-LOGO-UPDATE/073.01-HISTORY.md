## [IMPL] Icons converted from design/ — 2026-08-29

**Measured first.** `design/logo-icon.png`'s tile is a 900×900 rounded square inset 62 px
on every side, edged by a thin grey outline stroke (the darkest pixels on every mid-height
row sit at x=62..63 and x=960..962). There is no soft drop shadow — the checkerboard butts
straight up against the stroke — so the crop can sit 2 px inside it at (64, 64, 960, 960)
without picking up a single checker pixel. Source corner radius fits ≈181/900; the output
mask uses Apple's larger 0.2246 proportion, so it always cuts *inside* the source corner.

`design/bar-icon.png` maps luminance straight to alpha. The floor had to be 150, not the
background's own 233: at 233 every background pixel picks up an alpha of ~2, `getbbox()`
then returns the whole canvas and the glyph cannot be trimmed to its own extent. At 150
the bbox lands exactly on the measured (175, 108, 854, 918) and the grid and watermark
vanish.

**Changed**
- `packaging/make_icon.py` — rewritten from a Qt/QPainter *generator* (rounded blue tile +
  「小說」 in Songti SC) into a Pillow *converter*. New `--asset` flag also emits the 256 px
  in-app copy, so the tile geometry is defined in exactly one place.
- `packaging/make_tray_glyph.py` — new. Asserts the glyph bbox against the measured one and
  fails loudly rather than silently shipping a differently-trimmed mark.
- `src/noveltrans/gui/icons.py` — new `load_pixmap()`. Reads bytes via `resources.files`
  rather than `resources.as_file`: only ffmpeg/libass need a real path (`tts/video.py`),
  Qt takes bytes, and this works unchanged inside the frozen archive. Never raises.
- `src/noveltrans/gui/assets/{app-icon,tray-glyph}.png` — new package data.
- `src/noveltrans/gui/tray.py` — `_glyph()` now scales the shipped master by height and
  refills it via `CompositionMode_SourceIn`; `build_tray_icon()` untouched in structure, so
  the macOS-mask / non-macOS-fill contract and its tests hold as-is. `_ACCENT_COLOR` now
  comes from `style.ACCENT` (`#3f7bef`) — the old `#2f5fd0` referenced a gradient in
  `make_icon.py` that no longer exists. Module docstring corrected: it claimed nothing
  ships as an asset.
- `src/noveltrans/app.py` — `setWindowIcon`, so `make run` and Linux/Windows taskbars have
  an icon at all.
- `pyproject.toml` — `gui/assets/*.png` package data. Both PyInstaller specs need no edit;
  `collect_data_files("noveltrans")` already sweeps it up.
- `Makefile` / `make.ps1` — `icon` now builds all five artefacts from `design/`. Dropped
  `QT_QPA_PLATFORM=offscreen` (no Qt any more) and `make.ps1`'s "don't re-run make_icon.py"
  special case, whose premise was the macOS-only Songti SC font. `.icns` is still the one
  macOS-only step (`sips`/`iconutil`).
- `tests/test_tray.py` — added `TestGlyphAsset`; `tests/test_gui_assets.py` — new.
- `README.md` — icon workflow on both the macOS and Windows packaging sections.

## [IMPL] New bar-icon source — 2026-08-29

`design/bar-icon.png` was replaced with a bold line-art wolf head (the previous one was the
same low-poly mark as the app tile). Regenerated `gui/assets/tray-glyph.png` from it.

**The source's shape changed, so the measured constants did too.** The old file was flat
light grey (≈233) with a printed grid and a corner watermark. The new one carries the same
fake transparency as `design/logo-icon.png` — opaque alpha, a checkerboard painted into the
RGB pixels — but that costs nothing here: the checkerboard is 254-255 and 206-209, the
strokes are 0-1, and nothing lives in between, so luminance still maps straight to alpha.
`_FLOOR = 150` was already in the stable plateau and did not move (120, 150 and 175 all
produce the same trim). `_EXPECTED_BBOX` is now (169, 102, 855, 922) — the guard did its
job and refused to run until it was re-measured deliberately.

**This closes the 16-18 px legibility question** left open above. Line art survives the
downscale where the low-poly facets turned to speckle: at 18 px the mark still reads as a
wolf head on both a light and a dark bar. Ink coverage dropped with the art style (0.41 →
0.25 at 22 px), so the band in `test_the_menu_bar_size_has_ink_but_is_not_a_solid_block`
widened to 0.12-0.50 — how much ink the mark carries is a design choice; only "none" and
"all of it" are bugs.

The app icon is untouched: `design/logo-icon.png` did not change.

**Verified** — `make lint` clean, full suite 2844 passed, glyph 428×512, 22 px ink bbox
15×18 (portrait preserved).

## [IMPL] bar-icon source again — aspect flipped to landscape — 2026-08-29

`design/bar-icon.png` was replaced a second time: same line-art wolf head, now with swept
side elements that widen it well past square.

**This was not just a constants bump — it broke an assumption in the runtime code.** Both
earlier marks were portrait, so `tray._glyph` scaled by height alone (`scaledToHeight`) to
82 % of the icon box. The new mark trims to 976×820, aspect 1.19: scaled to 18 px tall in a
22 px box it comes out ~21.4 px wide, and anything past the box edge is silently clipped by
the pixmap — no error, just a mark with its outer edges shaved off. `_glyph` now uses
`QPixmap.scaled(..., KeepAspectRatio)` against a per-axis budget: `_GLYPH_HEIGHT_RATIO`
0.82 (the tight one — menu-bar items have vertical padding) and a new `_GLYPH_WIDTH_RATIO`
0.98 (the horizontal padding either side of a menu-bar item is the system's to decide).
Whichever axis binds now governs, so portrait and landscape marks both fit.

At the current aspect the height still binds at every size, so nothing lost any size: ink
height lands exactly on the vertical budget (13/18/26/36 px for the 16/22/32/44 boxes) and
width fits with a pixel or two to spare.

**Constants re-measured.** The ground changed style again — flat ≈230-232 with faint plus
marks, where the previous export was a checkerboard and the one before that flat grey with
a printed grid. `_FLOOR = 150` held for the third time (100, 120 and 150 all give the same
trim); `_EXPECTED_BBOX` is now (24, 102, 1000, 922). The bbox guard again refused to run
until re-measured. Given three different grounds in three exports, the script's docstring
now states the *invariant* it actually relies on — light ground, decoration within a few
levels of it, strokes 0-2, nothing in between — rather than describing whichever decoration
the current file happens to carry.

**Tests reworked to stop assuming a shape.**
- `test_the_master_loads_and_is_portrait` → `..._is_trimmed`: asserts the ink reaches all
  four edges of the master. Says nothing about orientation, which has now changed twice.
- The 44-px-only aspect check and a too-strict "never touches the edge" check (it failed at
  16 px, where the 1-px centring remainder legitimately puts ink at x=0 — flush, not
  clipped) were merged into `test_the_glyph_fits_the_box_at_every_size`: width within the
  box, height within the vertical budget, and the master's aspect preserved to within 0.06
  at 16/22/32/44. That is the check that would have caught the clipping regression.

**Verified** — `make lint` clean, full suite 2844 passed, glyph 609×512, and the mark reads
on both a light and a dark bar at 13/18/36 px. App icon untouched (`logo-icon.png` unchanged).
