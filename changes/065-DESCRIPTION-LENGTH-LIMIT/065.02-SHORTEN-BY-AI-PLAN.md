# 065.02 — Nút `Shorten by AI` trong "Chi tiết phần"

Extends `065.01-INITIAL-PLAN.md`. That plan makes the description *fit* by dropping the
tail of the chapter index; this one makes it fit by making every line *cheaper*, so far
more chapters survive. They compose: the shortened text still goes through
`fit_description`, so the 5000-char invariant holds either way.

## 0. What the button produces

Today's description for a part costs a ~130-char mandatory skeleton plus ~63 chars per
chapter line. After `Shorten by AI`:

```
Số chương: 1990

Mục lục chương:
0:00 C.1 Nhặt được chậu rách
5:51 C.2 Trương lão đại thử linh căn
```

Dropped: the `Tên truyện:` line, the `Tác giả:` line, and the trailing blank +
`Tạo bởi: {credit}` line. Kept: the `Mục lục chương:` block.

A line goes from `1:23:45 Chương 1234: <45-char Vietnamese title>` (~63 chars) to
`1:23:45 C.1234 <≤35-char title>` (~50), and the skeleton from ~130 to ~32 — roughly
**74 → ~99 chapters** at the 5000 cap, more when titles shorten well.

### Assumption to confirm

The prompt says to drop "the name and author and `Tạo bởi: Fox Novel`". **`Số chương: N`
was not named, so this plan keeps it** — it is ~15 characters (a quarter of one chapter
line), and it is the one header fact a viewer actually uses. One word from the user flips
it: dropping it means passing `before=["Mục lục chương:"]` instead of
`["Số chương: N", "", "Mục lục chương:"]` in §2.1's `build_short_description`.

## 1. Decisions

### 1.1 The chapter number is taken structurally, never from the AI

`Chương 1` → `C.1` is **not** an AI job. Handing the model a numbered list and trusting it
to preserve 200 chapter numbers is exactly the kind of task LLMs quietly get wrong, and a
renumbered index is a worse bug than a long description — it makes every timestamp link
point at the wrong chapter in the viewer's mind.

So the split is deterministic:

1. `split_chapter_number(title)` strips a leading `Chương N` / `Chương N:` prefix and
   returns `(number, rest)`.
2. Only `rest` — the descriptive half — is sent to the model.
3. The label is reassembled locally as `f"C.{number}"`.

**Which number wins:** the one parsed from the title when present, else `chapter.index + 1`
(the app's own chapter number — `plan_locked_video_windows` and `_COMMITTED_SUFFIX_RE`
already treat `index + 1` as authoritative). Preferring the parsed number keeps the index
consistent with what the source site actually published when a scrape has gaps; falling
back to `index + 1` covers scrapers that emit bare titles (`giatocvuongtai.py:107` and
`tieuthuyetmang.py:325` both synthesise `f"Chương {n}"` only as a *fallback*, so bare
descriptive titles do occur).

**When neither the title nor a chapter object yields a number** (e.g. the `MergeSegment`-only
path), no `C.N` label is emitted — the shortened title stands alone. Never invent a number.

### 1.2 A dedicated worker, not chained `CompletionWorker`s

`CompletionWorker` (`workers.py:615`) is the right *shape* — generic prompt in, raw text
out, same engine params — but a 200-chapter part must be chunked, and chaining N workers
through `finished_ok` from inside a modal dialog is fragile. New **`ShortenTitlesWorker`**
in `workers.py`, modelled on `TagsWorker`: it loops the chunks internally on its own thread,
emits `progress(done, total)` so the dialog can show `⏳ 60/200…`, and emits
`finished_ok(list[str])` once with every shortened title in input order.

**Chunk size: 60 titles per request.** Big enough that a normal batch (10) is one call,
small enough that a reply stays well inside any engine's output limit and a mis-parse costs
one chunk, not the whole part.

### 1.3 Chunk-level failure is degraded, not fatal

If a chunk's reply doesn't parse into exactly the expected number of lines, that chunk falls
back to its **original titles** (still `C.N`-prefixed) and the worker records it. The button
then reports `⚠️ Đã rút gọn 140/200 chương (một số chương giữ nguyên tên).` Failing the whole
operation because the model miscounted one chunk of 60 would throw away good work; silently
returning fewer lines than chapters would corrupt the index. Neither is acceptable.

A hard failure (engine unavailable, `supports_completion` false, every chunk unparseable)
goes to `failed` and a `QMessageBox.warning`, matching `_on_tags_failed`.

### 1.4 Where the result goes

1. Into `desc_edit` in the open dialog (the user's immediate goal is to copy it).
2. Into the part's `.txt` sidecar **only if the part has actually been rendered**
   (`_part_output_path(...).is_file()`) — that is the file `_upload_request` reads at
   `tab_video.py:2915`, so without this write the shortened text would never reach YouTube.
   For an unrendered part there is no folder to write into and no upload can happen yet, so
   the dialog copy is the whole deliverable.
3. Nowhere persistent beyond that. **A re-render overwrites the sidecar** via
   `_write_metadata` and the shortening is lost — same as a hand-edited `.tags.txt` before
   `_resync_tags_sidecars` existed. Flagged in §5, not solved here.

### 1.5 Existing copy buttons become live

`desc_copy.clicked.connect(lambda: copy(description, "mô tả"))` (`tab_video.py:1527`)
captures the string by value, so after a shorten it would still copy the *old* description.
Change it to `lambda: copy(desc_edit.toPlainText(), "mô tả")` — correct regardless, and
required for this feature.

## 2. File-by-file changes

### 2.1 `src/noveltrans/tts/description.py` (the module 065.01 creates) — additions

```python
_CHAPTER_PREFIX = re.compile(
    r"^\s*(?:chương|chuong|ch\.?)\s*0*(\d+)\s*[:.\-–—]?\s*", re.IGNORECASE
)
_CJK_CHAPTER_PREFIX = re.compile(r"^\s*第\s*(\d+)\s*[章回]\s*")

SHORT_TITLE_MAX_CHARS = 35

def split_chapter_number(title: str) -> tuple[int | None, str]:
    """`"Chương 12: Nhặt được chậu rách"` → `(12, "Nhặt được chậu rách")`.

    Returns `(None, title)` untouched when there is no recognisable prefix — a bare
    descriptive title is common (several scrapers only synthesise "Chương N" as a
    fallback), and inventing a number would renumber the index.
    """

def short_chapter_label(number: int | None) -> str:
    """`12` → `"C.12"`; `None` → `""` (no label rather than a made-up number)."""

def build_shorten_prompt(titles: list[str]) -> str:
    """Vietnamese instruction: rewrite each title shorter but same meaning.

    Numbered `1.`…`N.` in, numbered `1.`…`N.` out, one line each, nothing else — the
    same "output ONLY the list" discipline as `build_tags_prompt`. States the
    SHORT_TITLE_MAX_CHARS budget, that Vietnamese diacritics stay, that no trailing
    period is wanted, and that a title already short enough must be echoed unchanged.
    """

def parse_shortened_titles(raw: str, originals: list[str]) -> tuple[list[str], bool]:
    """Numbered reply → one title per original, plus `ok` (False = fell back).

    Strips `N.` / `N)` / bullet prefixes (reuse `tags._LEADING_BULLET`'s approach),
    drops blank lines and any preamble the model added. Returns
    `(list(originals), False)` unless the line count matches exactly — a shifted list
    would attach every title to the wrong timestamp, so a mismatch is never salvaged
    by pairing what happens to line up.
    """

def build_short_description(
    entries: list[tuple[str, str, str]],   # (timestamp, label, short_title)
    *,
    total_chapters: int,
    max_chars: int | None = None,
) -> tuple[str, int]:
    """The stripped description: `Số chương:` + `Mục lục chương:` + `TS C.N title`.

    Delegates to `fit_description(before=[...], chapter_lines=[...], after=[])` so the
    5000-char guarantee and the `… còn N chương nữa` marker still apply — a shortened
    index that is *still* too long for a huge part degrades exactly like a normal one.
    """
```

Line assembly is `" ".join(x for x in (timestamp, label, short_title) if x)`, so a missing
label collapses cleanly instead of leaving a double space.

### 2.2 `src/noveltrans/gui/workers.py` — new `ShortenTitlesWorker`

Placed next to `CompletionWorker`; same engine-param constructor as `TagsWorker`
(`engine_name`, `api_key`, `model`, `cli_command`, `base_url`) plus `titles: list[str]`.

```python
class ShortenTitlesWorker(QThread):
    """Shorten a part's chapter titles via an LLM, in chunks, order preserved.

    Chunked because a single part can hold hundreds of chapters; a chunk whose reply
    doesn't parse falls back to that chunk's original titles rather than failing the
    whole run (see 065.02 §1.3), so the returned list always has exactly one entry
    per input title.
    """
    progress = Signal(int, int)          # done, total
    finished_ok = Signal(list, int)      # shortened titles, chunks that fell back
    failed = Signal(str)

    CHUNK = 60
```

`run()` mirrors `TagsWorker.run()`: `get_translator(...)`, the `supports_completion` guard
with the same Vietnamese message, then per chunk `build_shorten_prompt` → `translator.complete`
→ `parse_shortened_titles`. An engine exception inside a chunk is caught and treated as that
chunk falling back; only a failure to construct the translator, an unsupported engine, or
*every* chunk falling back reaches `failed`.

No `NovelProject` is opened — unlike `TagsWorker` this worker persists nothing, so it takes
plain strings and stays trivially unit-testable with a fake translator.

- `desc_copy`'s lambda switches to `desc_edit.toPlainText()` (§1.5).
- `shorten.clicked.connect(lambda: self._shorten_description(window, desc_edit, shorten, status, whole_novel))`.
- The label from 065.01 §2.5.5 is kept in a local and refreshed after a shorten, so the
  `(N/5000 ký tự)` counter reflects the new text.

**New `_shorten_description(self, window, desc_edit, button, status, whole_novel)`** —
the orchestration, deliberately outside the dialog closure so it is reachable from tests:

1. Guard `self.project is None`, and `self._shorten_worker is not None and isRunning()`.
2. Build `entries` from `window.chapters`: `timestamp = _yt_timestamp(cumulative)` over
   `c.audio_seconds` (the same cumulative walk `_chapter_timestamp_lines` does — reuse it
   rather than re-deriving), `number` from `split_chapter_number(chapter_marker_title(c))`
   falling back to `c.index + 1`, and `rest` as the descriptive half.
3. Disable the button, `status.setText("✨ Đang rút gọn bằng AI…")`.
4. `self._shorten_worker = ShortenTitlesWorker(titles=rests, **self._ai_engine_params())`,
   `track_worker(...)`, `start()`.
5. `progress` → `status.setText(f"✨ Đang rút gọn… {done}/{total}")`.
6. `finished_ok` → `_on_shorten_ready(...)`: zip the shortened titles back with the
   timestamps and labels, call `build_short_description`, `desc_edit.setPlainText(text)`,
   write the sidecar when the part is rendered (§1.4), re-enable the button, and set the
   status — including the partial-fallback wording from §1.3 and the
   `(đã lưu vào .txt)` / `(chưa tạo video nên chưa lưu)` suffix.
7. `failed` → re-enable, `QMessageBox.warning(self, "Rút gọn thất bại", message)`, mirroring
   `_on_tags_failed`'s non-render branch.

`self._shorten_worker: ShortenTitlesWorker | None = None` joins `_tags_worker` in `__init__`
(line ~105), and `ShortenTitlesWorker` joins the `workers` import block (line ~63).

## 5. Risks / follow-ups

- **A re-render silently discards the shortening** (§1.4). The proper fix is a
  `_resync_description_sidecars` alongside `_resync_tags_sidecars`, or persisting the short
  form on the project. Deferred: it needs a storage decision (per-part, not per-novel, so
  `meta` is the wrong home) that is out of scope here.
- **Cost/latency on a huge part.** 200 chapters is 4 sequential LLM calls; the dialog stays
  responsive (worker thread) and shows progress, but there is no cancel button. If this
  proves annoying, add a `cancel` flag polled between chunks — the worker's chunk loop is
  already the natural place for it.
- **The model may not respect `SHORT_TITLE_MAX_CHARS`.** Nothing enforces it — a
  too-long "shortened" title just costs more budget and `fit_description` handles the
  overflow. Deliberately *not* hard-truncated locally: cutting mid-word produces worse text
  than an honest long title, and the cap already guarantees the invariant.
- **`Số chương:` retention is an assumption** (§0) — one line to flip.
- **English button label in an otherwise Vietnamese UI.** `Shorten by AI` is the name the
  user asked for and is kept verbatim; the tooltip carries the Vietnamese explanation.
