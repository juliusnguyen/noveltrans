## [IMPL] 065 — 2026-08-27
Implemented all three plans. Full suite: 2552 passed (was 2446 — 106 new tests); ruff clean.

**New — `src/noveltrans/tts/description.py`** (pure, stdlib-only; `youtube_upload.py` needs
the clamp and must not import `tts/video.py`, which drags in subprocess + PIL):
- `YOUTUBE_DESCRIPTION_CHAR_LIMIT = 5000`, applied literally with **no headroom** — unlike
  `tags.py`, YouTube documents this one and Studio counts it plainly.
- `description_length` counts **UTF-16 code units** (Studio's counter is JS `String.length`,
  so an emoji is 2). The cap is resolved at *call* time, not bound as a default, so tests can
  monkeypatch it and drive the real GUI path with the existing 5-chapter fixtures.
- `fit_description` keeps the mandatory lines, trims the index tail, `break`s at the first
  line that doesn't fit (a hole mid-index reads as a bug; YouTube also needs the first
  timestamp to be `0:00`), and reserves the `… còn N chương nữa` marker at its worst-case
  digit width before the greedy loop.
- `clamp_description`, `was_truncated`, `indexed_chapter_count` (listed + reported-dropped,
  so a *trimmed* index isn't mistaken for a part that lost chapters), `looks_generated`.
- Short form: `split_chapter_number` / `short_chapter_label` / `build_shorten_prompt` /
  `parse_shortened_titles` / `build_short_description`.

**Cap** — `tts/video.py` gains `fit_video_description` (returns `(text, dropped)`);
`build_video_description` is now its plain-string wrapper with an unchanged signature, so
every existing caller and test kept working untouched. `build_youtube_description` capped too
(same `.txt` path, and it's what an upload reads if `_write_metadata` fails after a good
render). `UploadRequest.__post_init__` clamps — the `save_tags`-style choke point, needed
because uploads read sidecars possibly written before this feature existed.

**Shorten by AI** — new `ShortenTitlesWorker` (chunks of 60; a chunk that misparses falls
back to its *original* titles rather than failing the run or returning a short list). The
chapter number is stripped by regex, only the descriptive half is sent to the model, and
`C.N` is reassembled locally — a renumbered index would be far worse than a long description.
Sidecar written only for rendered parts.

**Auto-refresh** — `_resync_description_sidecars` runs once per project open (not per
`_refresh_video_list`, which fires on every spinbox tick; once is enough because returning to
the tab forces a reopen). Detects staleness by regenerating and diffing rather than hooking
any of the six rename routes. Enumerates parts from disk via a new
`iter_rendered_part_dirs` (factored out of `discover_committed_video_windows`), plus the
whole-novel folder, which has no span suffix. An AI-shortened sidecar is **never** overwritten
— flagged on the row instead, with `Khôi phục mô tả gốc` in the detail dialog as the
deliberate way out. A part whose chapter count changed (a deletion) is likewise flagged, not
rewritten: the .mp4 still narrates the old set.

**Also fixed** — the detail dialog's "Copy mô tả" captured the description string by value,
so it would have copied stale text after a shorten; it now reads the widget.

**Assumption** — `Số chương: N` is kept in the short form; the ask named only title, author
and the `Tạo bởi:` line. Pinned by `test_keeps_the_chapter_count_line`.

Files: `tts/description.py` (new), `tts/video.py`, `gui/workers.py`, `gui/tab_video.py`,
`youtube_upload.py`, `README.md`; tests `test_description.py` (new),
`test_workers_shorten.py` (new), `test_video_metadata.py`, `test_video.py`,
`test_youtube_upload.py`, `test_tab_video.py`.

## [IMPL] 065 — header/credit trở lại sau khi rút gọn — 2026-08-27
Follow-up ask: after `Shorten by AI`, offer to put `Tên truyện:` / `Tác giả:` / `Tạo bởi:`
back when the description still has room. Suite: 2563 passed (was 2552); ruff clean.

**The rule: added only when FREE.** `build_short_description` now takes `extras_before` /
`extras_after` and returns `(text, dropped, extras_kept)`. It fits the index twice — once
bare, once with the extras — and keeps the extras only when `dropped` is identical. If the
header would push even one chapter out of the index, the header is what goes: shortening
exists to fit more chapters, so that trade is never made silently. The status line says
which way it went.

**One spelling of the header.** Extracted `description_header_lines()` in `tts/video.py`
(the `Tên truyện:` / `Tác giả:` pair, including the empty-`vn_author` case) and made
`fit_video_description` use it too, so a shortened description that has room reads
identically at the top rather than growing a second, subtly different version.

**UI** — a `Giữ tên truyện / tác giả nếu còn chỗ` checkbox next to `Shorten by AI` in the
detail dialog, checked by default, with a tooltip stating the never-at-a-chapter's-cost rule.

Files: `tts/description.py`, `tts/video.py`, `gui/tab_video.py`, `README.md`;
tests `test_description.py`, `test_tab_video.py`.
