# 090-AI-MODEL-ENGINE-LEAKS — History

## [FIX] The last two pickers that kept another engine's model — 2026-09-14

Follow-up to 089, which fixed the same leak in the QC judge and chain. The two remaining
cases were named in 089's "not done" list and the user asked for them next:

- **Rewrite dialog** — `rewrite_ai_model` is ONE string shared across whichever engine
  `engine_combo` is set to. Switching Claude CLI → Codex CLI kept `sonnet`.
- **Video tab** — `video_ai_model` likewise, for the AI row shared by tags and the image
  prompt (`_build_engine_row`).

Both fail the same way 089 documented: the backend answers `400 "The 'sonnet' model is not
supported when using Codex with a ChatGPT account"` and nothing gets done.

### Changes

- `config.py`: `AppConfig.model_for_engine(engine)` — "this engine's own model, or ""'.
  All four pickers (QC judge, QC chain, Rewrite, Video) offer the same `LLM_ENGINES`, so
  the resolution has to agree across them; a third and fourth copy of the branching was
  the wrong answer. `cli_model_for` for the three CLI engines and LM Studio,
  `claude_model` for the API engine, "" otherwise.
- `gui/qc_dialog.py`: `_remembered_model` now delegates to it (its local copy of the
  branching is gone, as is the `CLI_ENGINES` import 089 added).
- `gui/rewrite_dialog.py`: `engine_combo.currentIndexChanged` resets the Model box through
  it. Connected after the saved value is in, so opening the dialog never rewrites it.
  (`_refresh_estimate`, already on that signal, does not read the model — order is moot.)
- `gui/tab_video.py`: the engine combo's inline save lambda became `_on_ai_engine_changed`,
  which saves the engine and then resets and saves the model. It returns early while
  `_loading_video_settings` is set, because `_apply_video_settings` pushes a novel's saved
  engine and model in together and the saved model must win. `_ai_engine_params` now
  resolves an empty box through the same helper — which also gives it the LM Studio case
  it was missing — and `CLI_ENGINES` is no longer imported there.

Tests: 6 new (engine switch carries the new engine's model / clears to "" when it has
none, for both dialogs; the Video tab's empty-box fallback including LM Studio; and a
novel's saved model surviving `_apply_video_settings`). Affected modules: 298 passed.

### On the test run — a false alarm worth recording

Mid-verification `tests/test_workers_pause.py` started dying with **exit 9, no traceback,
no F/E markers**, at 91% of the suite. One A/B run said main passed and this branch died,
which looked decisive. It was not: re-running five times per side, **main dies 5/5 and
this branch dies 5/5**. The single passing run on main was the outlier. That file walks a
real QThread and never touches any code changed here; the machine had 4.3 GB of 15.8 GB
free. This is exactly the memory-pressure kill the project notes warn about, and it
imitates a regression convincingly — n=1 is not enough to attribute it.

Full suite with `test_tts.py` (numpy) and `test_workers_pause.py` excluded: **3522 passed**
— the 089 baseline of 3542 minus that file's 26, plus the 6 added here — 4 skipped, and the
same 43 pre-existing environmental failures, none outside them. Ruff: 29 findings before
and after on the touched files.
