# Implementation Plan: Multi-Chapter Concurrent Translation

## Goal

In the `Dịch` (Translate) tab, allow translating 2+ chapters concurrently, with the
concurrency limit configurable in Settings. Each chapter's status must show
`Đang dịch` ("Translating") while it is actively in flight, correctly per-chapter
even when several are in flight at once. `translate_workers == 1` must behave
identically to today (no regression).

## Key design decision: "Đang dịch" is transient/UI-only, not persisted to the DB

`models.py:245` documents the chapter lifecycle as
`pending -> downloaded -> translated (or error at any step)`. Adding a persisted
`STATUS_TRANSLATING` would mean every reader of `Chapter.status`
(`project.pending_translation()`, `pending_rewrite()`, exporters, other tabs) has to
tolerate a new mid-flight state, and a crash/kill would leave chapters stuck showing
"translating" forever with no reconciliation pass anywhere in the codebase to clear it.

Instead: add a new Qt signal `chapter_started(int)` emitted by `TranslateWorker` when a
chapter is handed off, and let the GUI's `ChapterTableModel` track an in-memory set of
"in-flight" indices, overlaid on top of the real persisted status when rendering. The
set is cleared per-index as soon as that chapter's real `chapter_done`/`chapter_error`
arrives (or defensively on run-finished/failed/cancel).

Qt signal emissions from the worker thread are queued and delivered one at a time on
the GUI thread, so concurrent chapters finishing "simultaneously" still produce
correctly ordered, non-clobbering per-row updates — `_on_chapter_updated`
(`tab_translate.py:1309`) already works fine as-is for the "done" side; only the
"started" side is new.

## 1. Settings (`src/noveltrans/config.py`)

- Add `DEFAULT_TRANSLATE_WORKERS = 1` near the other defaults (~line 28).
- Add a `translate_workers` property/setter right after `request_delay` (~line 190),
  matching the existing `tts_workers` pattern (lines 432-439) exactly:

```python
@property
def translate_workers(self) -> int:
    """Chapters translated concurrently. 1 = sequential (default, current behavior)."""
    return max(1, self._s.value("translate_workers", DEFAULT_TRANSLATE_WORKERS, type=int))

@translate_workers.setter
def translate_workers(self, value: int) -> None:
    self._s.setValue("translate_workers", max(1, int(value)))
```

## 3. Worker refactor (`src/noveltrans/gui/workers.py`)

### 3.1 Pure refactor first, no behavior change

Today `TranslateWorker.run()` (line 477) interleaves engine calls with
`project.save_*`/`project.mark_*` writes and signal emissions across three spots:
`_fix_names` (357-399), `_retranslate_title` (401-447), and the main loop
(618-707). Split each into a **pure-compute** half (engine calls + in-memory QC
checks only, safe to run on a pool thread) and a **commit** half (DB writes + Qt
signal emission, orchestrator-thread only):

- `_TranslateResult` (NamedTuple): `index, kind, status, title, translated_title,
  translated_body, engine_label, seconds, fingerprint, attempts_used, qc_code,
  qc_reason, error`.
- `_compute_name_fix`, `_compute_title_only`, `_compute_chapter` — ported from
  `_fix_names`/`_retranslate_title`/the main loop's branches, with every
  `fresh = project.chapter(chapter.index)` DB re-read replaced by
  `dataclasses.replace(chapter, translated_title=..., translated=...)` (the re-read
  was only ever used for in-memory `check_translation()`/`qc_fingerprint()` calls —
  zero DB access needed). Each wraps its body in `try/except NovelTransError / except
  Exception` so a `Future.result()` can never raise (error isolation).
- `_commit_name_fix`, `_commit_title_only`, `_commit_chapter` — verbatim moves of the
  write+signal side (`project.save_name_fix`/`save_qc_verdict`/`mark_qc_failed`/
  `chapter_error.emit(...)` etc.) taking a `_TranslateResult`.
- `_run_sequential`: calls compute-then-commit per chapter, in the same
  try/except structure as today, using the SAME already-built `translator`/
  `qc_plans`/`title_plans`/`qc_judge` objects built once up front (lines 522-616,
  untouched). This must be a **literal, line-for-line move** of today's loop body —
  this is what guarantees backward compatibility (item 5 below).
- Add `self.chapter_started.emit(chapter.index)` at the top of each chapter's body in
  `_run_sequential` (after the existing `if self._checkpoint(): break`).

**Validate this step in isolation**: run the full existing test suite
(`test_workers_qc.py`, `test_translation_qc.py`, `test_workers_identity.py`,
`test_tab_translate_*`) against the pure refactor before adding any new
concurrency/signal/setting code. Any behavior diff here is a refactor bug.

### 3.2 New signal + constructor param

- `chapter_started = Signal(int)` on `TranslateWorker`.
- `translate_workers: int = 1` constructor param, stored as
  `self.translate_workers = max(1, int(translate_workers))` (same defensive clamp as
  `AudioWorker.workers`, line 1422).

### 3.3 Per-thread engine/QC-chain context

`GoogleFreeTranslator` keeps unsynchronized shared mutable state for its
request-delay throttle (`google_free.py:25-31`), and today's code builds the
translator/QC chain exactly once and closes over it for every chapter. Under
concurrency this must become **one instance per pool thread** — same pattern as
`AudioWorker._engine_for_thread` (1606-1630):

```python
def _ctx_for_thread(self, tl, seed, source_lang) -> _TranslateCtx:
    ctx = getattr(tl, "ctx", None)
    if ctx is not None:
        return ctx
    try:
        translator = seed.get_nowait()   # reuse the eagerly-built probe on thread #1
    except queue.Empty:
        translator = get_translator(self.engine_name, api_key=self.api_key, model=self.model,
                                     request_delay=self.request_delay,
                                     cli_command=self.cli_command, base_url=self.base_url)
    qc_plans = self._build_qc_plans(source_lang) if self.qc is not None else None
    title_plans = qc_plans or (self._fallback_title_plans(translator) if self.title_only else None)
    qc_judge = build_qc_judge(self.qc.judge) if self.qc is not None else None
    ctx = _TranslateCtx(translator, qc_plans, title_plans, qc_judge)
    tl.ctx = ctx
    return ctx
```

The translator built eagerly up front (line 505-513, kept as-is so the existing
fail-fast `except NovelTransError: self.failed.emit(...); return` at 514-516 is
preserved) seeds thread #1 via a `queue.Queue`, exactly like `AudioWorker`'s
`probe`/`seed` (1699-1700, 1716-1720). `glossary`/`qc_glossary`/`name_profile` are
built once and never mutated during the run — safe to read from pool threads without
a lock.

### 3.4 `_run_parallel` — structural port of `AudioWorker._run_parallel` (1687-1775)

- `n_workers = min(self.translate_workers, total)`, `ThreadPoolExecutor(max_workers=n_workers)`.
- `submit_next()`: gated on `self._cancelled or self.is_paused()`; pulls the next
  chapter, **emits `chapter_started` on the orchestrator thread before
  `pool.submit(...)`**; dispatches to `_compute_name_fix`/`_compute_title_only`/
  `_compute_chapter` per the existing `name_fix`/`title_only`/default routing (today's
  lines 626-642), passing a `_ctx_for_thread(...)`-resolved context.
- Main loop: `self._checkpoint()` (pause holds here — nothing new starts while paused,
  in-flight chapters finish, same as `AudioWorker`'s comment at 1728-1732);
  `wait(inflight, return_when=FIRST_COMPLETED)`; for each finished future,
  `fut.result()` (never raises) → matching `_commit_*` → `chapter_done`/
  `chapter_error.emit(...)` → `progress.emit(...)` → `submit_next()` to backfill.
- `finally: pool.shutdown(wait=True)` (mirrors 1772-1773) so cancel drains cleanly.
- `status == "cancelled"`: skip commit, don't count (mirrors 1743-1744).

### 3.5 Branch in `run()`

```python
if self.translate_workers == 1:
    self._run_sequential(...)
else:
    self._run_parallel(...)
```

### 3.6 Thread-safety invariant

No `project.*` call and no `self.<signal>.emit(...)` may appear inside any
`_compute_*` method or anything running on a pool thread — same discipline
`AudioWorker._run_parallel`'s docstring already states (1688-1689). Enforce this
explicitly during self-review of the diff.

### 3.7 `_run_identity` (line 460) — leave sequential

No engine call, just a `project.save_translation(...)` DB write per chapter — nothing
to parallelize, and sqlite writes shouldn't be spread across threads for zero
throughput benefit. Only add `self.chapter_started.emit(chapter.index)` right before
the existing `self.progress.emit(...)` (460-463), for signal-contract consistency
("started always precedes done/error" on every code path). Harmless since the row's
real status overwrites it on the very next line via `chapter_done`.

## 4. UI model (`src/noveltrans/gui/widgets.py`, `ChapterTableModel`)

- Add `self._in_progress: set[int] = set()` (near line 685).
- `mark_in_progress(idx)`: add to the set, emit `dataChanged` for that row.
- `clear_in_progress()`: clear the set (defensive reset).
- `update_chapter()` (line 722): `self._in_progress.discard(chapter.index)` before
  replacing the row — a fresh DB read means it's no longer in flight.
- `set_chapters()` (line 717): reset `_in_progress` to empty.
- `data()` (757): in the status-column branch (769-770), check
  `if chapter.index in self._in_progress: return "Đang dịch"` before falling back to
  `STATUS_LABELS.get(...)`. Same check in the color-role branch, using a new
  `STATUS_COLOR_TRANSLATING = QColor("#ef6c00")` constant near `STATUS_COLORS` (195) —
  kept separate from that dict since it's not a real persisted `STATUS_*` value.

## 5. Tab wiring (`src/noveltrans/gui/tab_translate.py`)

## 6. Backward compatibility (item 5 of the request)

Guaranteed by construction: `translate_workers == 1` routes to `_run_sequential`,
which is a verbatim, unmodified move of today's loop — same objects, same call order,
same exception points, same signal emissions, no new thread, no per-thread
`get_translator`/`_build_qc_plans` call. Validate with the existing test suite
unmodified against the refactor, *before* adding `_run_parallel`/setting/signal
wiring — any diff is a refactor bug, not an intended change.

## 7. Tests

- No dedicated `test_workers_translate.py` exists; `tests/test_workers_qc.py` is the
  primary `TranslateWorker` test file today (monkeypatches
  `noveltrans.translators.get_translator` to return one shared fake engine, calls
  `worker.run()` directly, asserts on `project.chapter(i).status`/`.qc_status`).
  Extend it with:
  - A `translate_workers=1` case confirming identical behavior to today (should pass
    unmodified, since it's the same code path).
  - New `translate_workers=2+` cases with a `_FakeEngine` subclass that records
    `threading.get_ident()` per call, to assert chapters actually overlap and that
    `get_translator` is called more than once when `translate_workers > 1` vs. exactly
    once when `== 1`.
- `tests/test_workers_identity.py` — only touch if asserting the new
  `chapter_started` emission there.
- `tests/test_translation_qc.py` — unaffected as long as `_compute_*` call the same
  underlying `check_translation`/`translate_with_qc` functions with the same args.
- `tests/test_tab_translate_multiselect.py`, `tests/test_tab_translate_qc.py` — grep
  for hard-coded `TranslateWorker(...)` constructor kwargs/positional args that might
  break; default `translate_workers=1` keeps them passing either way but worth a
  spot-check.
- `tests/test_settings_dialog.py` (line 205-214, `tts_workers` clamp/enable tests) is
  the template for a new case covering `translate_workers_spin` (range, default,
  save-on-accept).
- No existing test exercises `AudioWorker._run_parallel` with `workers>=2` directly —
  flag that the new `TranslateWorker` parallel tests may be the first of their kind in
  this repo; keep `_FakeEngine.translate()` fast/synchronous (no real sleeps) so they
  stay deterministic and fast.
