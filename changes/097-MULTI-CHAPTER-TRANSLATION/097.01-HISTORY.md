## [IMPLEMENT] 2026-09-26

Implemented per `097.01-INITIAL-PLAN.md`.

- `src/noveltrans/config.py` — `DEFAULT_TRANSLATE_WORKERS = 1` and a `translate_workers`
  property/setter (clamped to >= 1), same pattern as `tts_workers`.
- `src/noveltrans/gui/settings_dialog.py` — new "Số chương dịch song song" `QSpinBox`
  (range 1-6, default 1), placed right after the request-delay row; saved on accept.
- `src/noveltrans/gui/workers.py` — `TranslateWorker` refactored:
  - New `_TranslateResult` (NamedTuple) / `_TranslateCtx` (dataclass) types.
  - Each per-chapter branch (`name_fix`, `title_only`, plain/QC translate) split into a
    pure `_compute_*` method (engine + QC calls only, safe on a pool thread) and a
    `_commit_*` method (DB writes + signal emission, orchestrator-thread only) —
    `dataclasses.replace` substitutes for the old `project.chapter(...)` re-reads used
    only to compute a QC fingerprint, so no extra DB access was introduced.
  - `_run_sequential` is a literal compute-then-commit port of the original loop —
    used whenever `translate_workers == 1`, verified against the full existing test
    suite before adding anything else (zero behavior drift).
  - `_run_parallel` (new) mirrors `AudioWorker._run_parallel`: a bounded
    `ThreadPoolExecutor`, one engine + QC chain per pool thread via `_ctx_for_thread`
    (guards against `GoogleFreeTranslator`'s unsynchronized request-delay throttle),
    per-chapter error isolation (`_compute_*` never lets an exception escape a
    `Future`), and pause/cancel gating identical to the audio worker's.
  - New `chapter_started` signal, emitted right before a chapter is handed to a
    translate slot (sequential, parallel, and the identity passthrough path all emit
    it), so the UI can show "Đang dịch" per chapter while others are also in flight.
- `src/noveltrans/gui/widgets.py` — `ChapterTableModel` gained an in-memory
  `_in_progress` set (`mark_in_progress`/`clear_in_progress`), overlaid in `data()` on
  top of the persisted status ("Đang dịch" / `STATUS_COLOR_TRANSLATING`), cleared per
  chapter by `update_chapter` and wholesale by `set_chapters`/`clear_in_progress`. The
  "Đang dịch" state is deliberately never persisted to the DB (see plan) — a crash
  mid-run cannot leave a chapter stuck showing "translating" forever.
- `src/noveltrans/gui/tab_translate.py` — passes `translate_workers=self.config.translate_workers`
  into the worker, connects `chapter_started` to `model.mark_in_progress`, and clears
  the in-flight set in `_reset_buttons()` as a safety net for a cancelled/failed run.

Tests added:

  still resolves correctly through the per-thread fallback title chain under

- `tests/test_widgets.py` — `TestChapterTableModelInProgress`: marking, clearing (per
  chapter and wholesale), and that a fresh `update_chapter`/`set_chapters` drops the mark.
- `tests/test_settings_dialog.py` — `translate_workers_spin` default and round-trip.
