# 033 — Video tab: automated YouTube upload via browser, not the API

## The ask

> In the video tab, can we auto the workflow upload the video — not using the API,
> but using automation like when we auto the Discord?

## What exists today

The video tab (`gui/tab_video.py`, feature 025/026) already produces, per part, the
complete set of files an upload needs:

| file | content |
| --- | --- |
| `<name>.mp4` | the rendered video |
| `<name>.title.txt` | `"{tên truyện} - Phần {N}"` |
| `<name>.txt` | the YouTube description (titles, chapter count, timestamp table) |
| `<name>.tags.txt` | LLM-generated YouTube tags (`tts/tags.py`, 500-char budget) |
| `<name>.jpg` | the thumbnail (`tts/thumbnail.py`, 1280×720, ≤ 2 MB) |

Everything is there — the only manual step left is a human dragging each file into
YouTube Studio. That's the step to automate.

The project already has the browser-automation machinery this would build on:

- `browser.py` — shared Playwright launch (real Chrome preferred, bundled Chromium
  fallback, automation markers suppressed), raises `BrowserUnavailableError`.
- `discord_unlock.py` — the pattern to copy: a persistent profile dir
  (`profile_dir()`), an `open_login()` that opens a visible window so the user signs
  in *once* by hand, then headless-ish runs reusing that profile
  (`_launch_context(headless=…)`), with its own user-facing Vietnamese errors.
- `cf_browser.py` — the other consumer, for reference.
- Playwright is an optional extra (`noveltrans[browser]`), imported lazily.

## Goal

An "Upload lên YouTube" action in the video tab that drives YouTube Studio in a real
browser and fills the upload flow from the files above: video, title, description,
tags, thumbnail, plus the fixed choices (visibility, "not made for kids", playlist,
schedule?). No Google API / OAuth / quota.

## Open questions to settle in `/plan`

- **Login**: mirror Discord — a "Đăng nhập YouTube" button opening a visible Chrome on
  a dedicated profile dir, session persisted, re-prompt when it expires. Google is
  more hostile to automated logins than Discord, so the user *must* do it by hand in a
  real Chrome window; confirm that holds.
- **Scope of a run**: one part at a time, or queue every part of the project?
- **Visibility / schedule**: publish immediately, unlisted, private, or scheduled
  (a series of parts released daily is the obvious use case)?
- **Failure handling**: YouTube Studio's DOM is unstable and A/B-tested. Decide how far
  to go before handing back to the user (leave the tab open at the failed step?) and
  what happens on a partial upload — never silently double-publish on retry.
- **Detection/ToS**: automating Studio is against YouTube's ToS on paper and can trip
  bot checks. Confirm the user accepts that risk; keep it opt-in, human-paced, and
  never headless-invisible during login.

## Out of scope

- The rendering pipeline (`tts/video.py`), thumbnail editor, and tag generation are
  unchanged — this feature only *consumes* their output.
- No Google Data API integration.
