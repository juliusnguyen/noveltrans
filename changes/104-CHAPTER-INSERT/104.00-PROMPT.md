# Feature: insert a chapter manually — right-click → add above / add below

## Request (original)

> support add the new chapter manually, right-click then add above or add below. plan and implement

## Context

Local (hand-written) novels can already add chapters, but only appended at the end via the
"＋ Thêm chương" button (`tab_scrape._add_chapters` → `NovelProject.add_chapters`), and
delete one via right-click (`_delete_chapter`). There is no way to put a new chapter
*between* existing ones.

## Goal

Right-click a chapter row → "Thêm chương phía trên" / "Thêm chương phía dưới" inserts a new
chapter at that position. Open questions for the plan: which novels (local only, or scraped
too — a rescan's `replace_toc` may undo it), and what a positional insert does to
everything keyed by chapter index (stored audio, video parts/windows, upload state,
disabled flags, chapter numbering in titles).

## Scope decision (user, 2026-10-10)

> support both local and scraped novels

So a manually inserted chapter in a scraped novel must survive a rescan (`replace_toc`) at
its position — not clobbered, not shifted onto a scraped chapter's data, not duplicated —
and download must skip it (no URL; its content is pasted, like a local chapter).

## Revision (user, 2026-10-10)

> tôi muốn chèn ở bất kỳ đâu, không kể phần có video/audio. chỉ cần thông báo ở video là
> phần này có chương mới chèn vào, có muốn render lại không

Translation: allow inserting anywhere, even inside sections that already have video/audio.
Instead of refusing, the video tab should tell the user that a part has a newly inserted
chapter and ask whether to re-render it.

Consequence: the insert must renumber every number-keyed artifact consistently (audio file
names, merged audio, part folders + sidecars, manual windows, part offsets) so that only the
part that now contains the new chapter changes; every other part keeps exactly its chapters.
