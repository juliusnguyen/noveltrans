# Feature: Editable part number in the Video tab (renumber, later parts follow)

## Request (original, Vietnamese)

Trong phần `Video`, cho phép chỉnh sửa phần. Ví dụ `https://www.novel543.com/0122647940/`
Phần hiện tại có thể tạo là `Phần 75` và `Phần 76`; Tôi muốn có thể tuỳ chỉnh từ phần 75
thành phần 74, sau đó phần 76 sẽ tự động điều chỉnh thành phần 75.

## Translation / summary

In the `Video` tab, let the user edit a part's number. Example novel:
`https://www.novel543.com/0122647940/` — the parts currently plannable are `Phần 75` and
`Phần 76`. The user wants to change `Phần 75` to `Phần 74`; `Phần 76` should then
automatically become `Phần 75`.

So: editing one part's number is a **renumbering of the whole plan from that part onward**
(an offset), not a one-off relabel of a single row. Every later part shifts by the same
delta.

## Why

The part number today is pure arithmetic off the chapter range
(`noveltrans.tts.merge.part_number(first_num, batch_size)`, see
`src/noveltrans/gui/tab_video.py:800` `_part_number`). When the real, already-published
series on YouTube is off by one from what that arithmetic produces — e.g. an earlier part
was published as two, or the novel's first part was numbered differently — every new part
this app plans carries the wrong number, and the wrong number goes into the upload title
(`tts/video.py:797` `build_upload_title` → `{tên} - Phần {N}` / `Phần {N} - {tên}`) and
into the rename/resync logic (`src/noveltrans/rename.py`).

## Requirements

- From the Video tab's parts table, allow editing a part's displayed number (e.g. a
  context-menu action or an inline edit on the "Phần" column).
- Changing part N to M applies the delta `M - N` to that part **and every part after it**;
  parts before it are untouched. In the example: 75 → 74 makes 76 → 75.
- The adjustment must persist per novel (like `video_manual_windows.json` does for manual
  split/merge boundaries — see `src/noveltrans/video_windows.py`), so every later
  "Tạo video" run keeps the corrected numbering.
- The corrected number must be the one used by:
  - the parts table display,
  - the upload title (`build_upload_title`),
  - anything reading the part number back out of a title (`rename.py` resync),
  - file naming / thumbnails / covers if those embed the part number.
- Interaction with existing locked windows (`plan_locked_video_windows`) and manual
  split/merge must stay coherent — a renumber shifts numbers, it must not reshape chapter
  spans.
- Needs a way to undo / reset back to the plain arithmetic numbering.
- Decide (and document) the behaviour for the source-edition ("nguồn") plan, which
  deliberately opts out of `video_manual_windows.json` because that file has no room for a
  second number space.
