## [IMPLEMENT] Codex CLI as the `codex_cli` engine — 2026-09-14
Implemented `088.01-CODEX-CLI-SUPPORT-PLAN.md`, after first checking its **(verify)** items
against the real `codex-cli 0.154.0` on this machine (installed via npm, Homebrew node):

- **Verified:** `exec` (alias `e`), `-m/--model` (exec and root level), `-s/--sandbox`,
  `--skip-git-repo-check`, `--ephemeral`, `-o/--output-last-message`, `-` = prompt from stdin.
  Without `--skip-git-repo-check`, running in the temp dir fails with "Not inside a trusted
  directory…". stderr carries a banner plus the **full echoed prompt**; the answer is in the
  `-o` file (and repeated on stdout). An API failure ends with
  `ERROR: {"type":"error","status":400,"error":{"message":"The 'x' model is not supported
  when using Codex with a ChatGPT account."}}`; clap arg errors are `error: …`, exit 2.
- **Found in verification, not in the plan:** in `codex exec`, `-p` is `--profile` — a
  user typing `codex -p` by analogy with `claude -p` would get an argument error, so a
  trailing bare `-p` is dropped.

Changes:
- `translators/__init__.py`: `CLI_ENGINES = ("cli", "claude_cli", "codex_cli")`, factory uses it.
- `translators/cli_agent.py`: `binary_name()` (strips dir + .exe/.cmd/.bat);
  `_codex_args()` normalises the command (adds `exec`, `--skip-git-repo-check`,
  `--sandbox read-only` unless a sandbox was chosen; GUI model as `-m` right after `exec`,
  replacing any in the command). `complete()` for codex: prompt on stdin with `-`, answer
  read from a mkstemp `--output-last-message` file (deleted in `finally`). Errors come from
  `_codex_error()` — the last `ERROR`/`error:` line only, JSON message unwrapped — mapped by
  a separate `_friendly_codex_error()` (unsupported model / usage limit / not logged in), kept
  apart from `_friendly_error` so claude/agy failures never get Codex advice. On real Windows,
  `_resolve_executable()` runs `shutil.which` so npm `.cmd` shims are found; gated on
  `os.name` (module constant `_ON_WINDOWS`) because `shutil.which` crashes when tests fake
  `sys.platform = "win32"` (measured: AttributeError on `_winapi`). Other engines' spawn
  kwargs are unchanged (no `input=`).
- `config.py`: `DEFAULT_CODEX_CLI_COMMAND = "codex exec --skip-git-repo-check --sandbox
  read-only --ephemeral"` (`--ephemeral` confirmed to exist, so it went into the default),
  `TRANSLATORS["codex_cli"]`, `LLM_ENGINES`, `translator_labels`, `codex_cli_command`
  property, `cli_command_for`, `CLI_MODEL_SUGGESTIONS` keyed by binary (codex list taken
  from `~/.codex/models_cache.json`: gpt-5.6-luna/terra/sol, gpt-6-astra, gpt-5.5),
  re-exports `CLI_ENGINES`.
- `gui/settings_dialog.py`: "Lệnh Codex CLI:" row + save. `gui/tab_translate.py`: uses
  `CLI_ENGINES`; suggestions seeded from `CLI_MODEL_SUGGESTIONS` by `binary_name`, which
  also stops `CliModelsWorker` running `codex models`. `gui/tab_video.py`: `CLI_ENGINES`.
  QC and Rewrite dialogs pick the engine up from `LLM_ENGINES` untouched.
- `runtime_env.py`: `%APPDATA%\npm` added to the Windows tool dirs.
- Docstrings in `rewrite.py` / `qc.py`: prompt goes in argv, or stdin for Codex.
- README: Codex CLI engine notes; Rewrite engine list.

Tests: `TestCodexCli` (20) in `test_translators.py` + registry/label cases;
`test_config_codex_cli.py`; `test_tab_translate_codex.py`; settings dialog and runtime_env
cases. Full suite (`python -m pytest`, as the Makefile runs it): **3612 passed**; `ruff` clean.
(Bare `pytest` fails collecting 6 scraper test modules with `No module named 'tests'` —
pre-existing, same on a clean tree.)

Real end-to-end through `get_translator("codex_cli", …)` with the default command:
`第12章 傅清辭 / 傅清辭看了江妤一眼，轉身離開了。` →
`Chương 12 Phó Thanh Từ / Phó Thanh Từ liếc Giang Dư một cái, xoay người rời đi.`; with
`model="gpt-nope"` the error shown is the Vietnamese "đổi model trong ô Model" advice.

Not done / noted:
- Timeout only kills the direct child (`cmd.exe`/node shim), so codex itself may keep
  running — left for a separate feature, as planned.
- Pre-existing: commands are split with POSIX `shlex`, which eats unquoted Windows
  backslashes (`C:\npm\codex.cmd` → `C:npmcodex.cmd`) for every CLI engine. Not changed.
- `uv.lock` was rewritten by `uv run` (adds cuda-bindings etc. — a lock/pyproject drift
  unrelated to this feature); not part of this change.
- Usage-limit and not-logged-in message strings are unverified (couldn't trigger them
  without exhausting quota or logging out); markers are deliberately broad and only ever
  matched against the final ERROR line.
