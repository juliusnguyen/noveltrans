# Plan: 088-CODEX-CLI-SUPPORT (Codex CLI as a built-in `codex_cli` engine)

## Environment check
**Codex CLI is not installed on this machine.** `which codex`, `/opt/homebrew/bin`, `/usr/local/bin`, `~/.local/bin`, `~/.npm-global/bin` and `npm ls -g` all come up empty, and there is no `~/.codex`. `claude` and `agy` are both in `~/.local/bin`. So the Codex facts below come from what is known about the CLI, not from `codex exec --help`. Anything marked **(verify)** needs checking against a real install before merging.

## Goal
Add OpenAI's Codex CLI as an engine next to `claude_cli`. It should be:
- selectable in Settings, the Translate tab, the Video tab's AI helpers, the Rewrite dialog, the QC chain and the QC judge;
- configured with its own command and remembered model;
- run by the existing `CliAgentTranslator`.

Output must be clean (the final answer only), and it must work in a Finder-launched macOS app and in the console-less Windows build.

## Key design decisions

**1. Reuse the class and detect Codex by binary name.**
- Add `codex_cli` to the factory's CLI tuple and keep using `CliAgentTranslator`.
- Branch on the binary name, like the agy branch does, so `cli` with `codex exec …` also works.
- Normalise the name on Windows (`codex.exe` / `codex.cmd` → `codex`) with a helper: `os.path.splitext(os.path.basename(a))[0].lower()`.
- Put the Codex-specific argv work in pure module-level functions so it is easy to test.

**2. Default command: `codex exec --skip-git-repo-check --sandbox read-only`.**
- `exec` is headless mode.
- `--skip-git-repo-check` is required because the app always runs in the temp dir, which is not a git repo.
- `--sandbox read-only` because this is a text-only task, and it overrides any `sandbox_mode` in the user's `~/.codex/config.toml`.
- Leave `--ephemeral` out of the default for now **(verify)**. On a version without it, clap rejects the whole command with exit code 2. Suggest it in the tooltip instead.

**3. Normalise the command once, in `__init__`, so `engine.args` can be checked in tests.**
- If there is no `exec` or `e` subcommand, insert `exec` at index 1.
- Add `--skip-git-repo-check` if it is missing. Without it every call fails.
- Add `--sandbox read-only` only if neither `--sandbox` nor `-s` is present, so an explicit user choice wins.
- **Model:** remove both `--model` and `-m` from the command (reuse `_remove_flag_with_value` twice), then insert `-m <model>` right **after `exec`**. Do not put it right after the binary as agy requires: a root-level `codex --model X exec` is the TUI's flag and exec ignores it **(verify)**.

  Example: `get_translator("codex_cli", cli_command="codex exec --skip-git-repo-check --sandbox read-only", model="gpt-5.4")` gives `["codex", "exec", "-m", "gpt-5.4", "--skip-git-repo-check", "--sandbox", "read-only"]`.

**4. Send the prompt through stdin (`-`), not argv.** This is Codex-only; other engines stay exactly as they are.
- On Windows, an npm install of Codex is a `codex.cmd` shim, and batch files mangle multi-line arguments (newlines cut them off, and cmd.exe has an ~8191-char limit). An 8000-character chapter plus the prompt is not safe there.
- Recent `codex exec` versions also read piped stdin when a prompt is given. Passing `input=` explicitly avoids a stdin that is inherited and never closed.
- Final command: `[*args, "--output-last-message", tmp, "-"]`, run with `input=prompt`. `text=True, encoding="utf-8"` already writes UTF-8 bytes, so there is no Windows code-page problem.
- For non-Codex engines, do **not** pass `input=`, so the current `subprocess.run` kwargs and existing mock assertions stay the same.

**5. Read the answer from the `--output-last-message` file, never from stdout.**
- Older versions print a banner (version, workdir, model) to stdout, newer ones don't, and stderr carries the progress transcript. The file holds only the final agent message in every version.
- Create it with `tempfile.mkstemp(prefix="noveltrans-codex-", suffix=".txt")` and close the handle so Windows lets Codex overwrite it. Read it as UTF-8, strip it, and delete it in the same `finally` as the agy log.
- No stdout fallback. If the flag weren't supported, clap would already exit non-zero. An empty file with exit code 0 raises "Lệnh CLI không trả về nội dung dịch — <last ERROR line from stderr>".
- Keep the `_POLICY_MESSAGE` check on the returned text.

**6. Clean up the error detail.**
- Codex's stderr echoes the user prompt, which is the chapter text. So `raw[-300:]`, and especially marker matching, must not scan the whole stderr.
- For Codex, pull out the last line that starts with `ERROR` or `error:`, and fall back to the tail.
- Add Codex cases to `_friendly_error` using distinctive phrases **(verify exact strings)**. Never use a bare "429", which matches `第429章` in echoed text.
  - Usage limit ("You've hit your usage limit", `usage_limit_reached`) → a Codex quota message, instead of the agy text that hard-codes "agy".
  - Not logged in / 401 → "chạy `codex login` trong Terminal".
  - "model is not supported when using Codex with a ChatGPT account" → "đổi model trong ô Model".
  - "Not inside a trusted directory" → mention `--skip-git-repo-check`. This should never fire now that the flag is injected.

**7. Model suggestions.**
- Replace the `claude_cli`-only `setdefault` with a table keyed by **binary**, e.g. `CLI_MODEL_SUGGESTIONS = {"claude": ["haiku", "sonnet", "opus"], "codex": [...]}` in config.py.
- Any engine whose binary is in the table skips `CliModelsWorker`, so `codex models` is never run (this also covers `cli` = `codex exec`).
- Codex model IDs change often. Fill the list at implementation time from the model picker of the installed CLI **(verify)**. The combo box stays editable.

**8. A shared constant.** Add `CLI_ENGINES = ("cli", "claude_cli", "codex_cli")`.
- Define it in `translators/__init__.py`, which has no Qt import, and re-export it from `config.py`. The GUI imports it from config.
- Replace the hard-coded tuples in tab_translate (269, 322, 497: `in CLI_ENGINES or engine == "lmstudio"`), tab_video (2827) and the factory.
- The next CLI engine then touches one tuple, not five.

## Windows
- **Finding `codex.cmd`:** `subprocess.run(["codex", …])` without a shell only looks for `.exe`, so an npm install would fail with "Không tìm thấy lệnh". Fix it in `complete()`: when `sys.platform == "win32"`, swap `cmd[0]` for `shutil.which(cmd[0]) or cmd[0]`. `which` respects PATHEXT, and CreateProcess can run a full `.cmd` path.
  - This also helps claude and agy. macOS tests are unaffected because the swap only happens on win32.
  - The `.cmd` argv is safe because Codex's arguments are just flags, a temp path (quoted by `list2cmdline`) and a model name. The chapter goes through stdin.
- **Console window:** keep `**no_console_kwargs()`. The hidden console is inherited by `cmd.exe` → `node` → the native codex, so no window flashes.
- **Output file:** mkstemp then `os.close` before spawning (the same pattern as agy), otherwise Windows file locking blocks Codex from writing.
- **Timeout orphans** (a risk on both platforms): `subprocess.run(timeout=…)` kills only the direct child. That is `cmd.exe`, or the node shim on macOS, so the native `codex` can keep running and using quota. Accept this for now and record it. The real fix (Job Object on Windows, `start_new_session` + `killpg` on POSIX) belongs in its own feature.

## Risks and open questions
1. **Codex flags and messages are unverified here:** `-m` placement after `exec`, `--ephemeral`, the exact error strings, the `e` alias. Check them against the installed version first; decisions 3 and 6 depend on them.
2. **Global `~/.codex/AGENTS.md` and `config.toml` still apply**; the neutral cwd only hides project files. The task-framed prompt helps. `--sandbox read-only` stops file writes, but Codex may still spend time running `ls` in the temp dir. An option is a dedicated empty `mkdtemp()` cwd for Codex, but existing tests assert `cwd == gettempdir()`, so it is left as an option.
3. **Session buildup:** without `--ephemeral`, every chapter saves a rollout under `~/.codex/sessions` (thousands for one novel). Add the flag to the default if the supported versions have it.
4. **Speed and cost:** reasoning models at default effort may approach the 360s timeout on long chapters. Consider a Codex-specific timeout or recommending low effort.
5. **PATH on macOS:** an nvm-installed Codex (and its `node`) is not on the Finder-launched PATH, and neither are brew or `~/.local/bin`. The error message already asks the user to check Settings; an absolute path in the command works as a workaround.
6. **Preambles:** Codex may start with "Here is the translation:". The existing QC and `looks_like_refusal` catch some of these but not all. Watch during the manual check.
7. **Downgrades:** an older build meeting `translator = "codex_cli"` falls back to combo index 0, and `qc_engine_chain` drops the entry. Acceptable.
