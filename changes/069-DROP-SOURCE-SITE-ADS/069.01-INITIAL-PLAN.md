# 069.01 — Initial plan: drop source-site advertising lines from translations

> The predicate in §1 was prototyped against 11 positive and 8 negative cases in this
> repo's venv before this plan was written. The numbers below are from that run.

## Summary

Add one pure module, `src/noveltrans/translators/ads.py`, exporting a `str -> str` filter
`drop_site_ads()` and a prompt constant `PROMPT_RULE`. Hook the filter into
`Translator.translate_chapter` (`base.py:94`) — the single production chokepoint for every
engine's chapter translation, and the one that sits *outside* `complete()` (tags / image
prompts / shortening) and *outside* the CJK retry scoring. Import `PROMPT_RULE` into the
three engine prompts so the wording exists once and cannot drift.

The filter's predicate is conjunctive and domain-anchored: **a line is only ever dropped if
a domain-like token survives de-obfuscation on that line.** No domain, no deletion — that
one conjunct is what makes "the filter ate my story" structurally impossible for the
overwhelming majority of prose.

## Corrections to the framing

1. **`translate_chapter` beats `_translate_with_retry` as the seam.** `_translate_with_retry`
   (`base.py:65`) is translation-only, correct — but its *only* caller anywhere in `src/` is
   `translate_chapter` (`base.py:98` and `:100`), whose only production callers are
   `gui/workers.py:267`, `:275`, `:294`. So `translate_chapter` is equally total, runs once
   per chapter instead of once per chunk, operates on the already-joined body (so a
   paragraph break at a chunk seam normalises correctly), and — the deciding point — it is
   *after* the `leftover = cjk_count(result)` scoring at `base.py:75`, so it cannot perturb
   the retry heuristic. Filtering inside the retry loop would silently change which attempt
   counts as "best".

2. **The three `save_translation` sites are three different features, not three call sites
   of one.** Only `workers.py:300` is downstream of a translator.
   - `workers.py:203` is `TranslateWorker._run_identity` — the passthrough when
     `source_lang == target_lang` (medoctruyen / tieuthuyetmang Vietnamese sources). Copies
     `chapter.content` verbatim, labelled `"(nguyên bản)"`. No translator runs.
   - `workers.py:2263` is `DownloadWorker`, for adapters with `content_is_translated`
     (webtruyendich) — the *site's own* finished translation. No translator runs.

3. **The ad line arrives as its own paragraph, and that is structural, not luck.**
   `scrapers/sto9.py:226` splits the `<br>`-separated body into one line per `<br>` and
   `:235` joins them with `"\n\n"`. Since all three prompts say "Keep the paragraph breaks
   exactly as in the source", the translated ad will be its own paragraph too. This supports
   the whole-line unit and makes the "ad joined onto a real sentence" case rare.

4. **A trap: the rule must NOT go in the rewrite prompt.** `check_rewrite` (`rewrite.py:264`)
   rejects any rewrite whose paragraph count differs from its input (`rewrite.py:280`), and
   `rewrite_chapter` re-asserts it over the whole chapter (`:383`). Telling the rewrite model
   to drop a line would make it fail validation and burn all three attempts —
   `rewrite_chunk` raises rather than returning a best effort (`:344`).

5. **The filter also runs on the novel title / description / author**, because
   `workers.py:267` and `:275` route those through `translate_chapter` too. A bonus (scraped
   descriptions carry site ads), but it makes a non-empty guard mandatory: a description
   that is *entirely* an ad must not become `""`.

Everything else checked out. `ClaudeTranslator.translate` (`claude.py:49-57`) and
`LmStudioTranslator.translate` (`lmstudio.py:80-85`) do call `self.complete(...)`, which is
also called from `workers.py:596` (tags), `:667` (image prompt) and `:755`
(`build_shorten_prompt`). `CliAgentTranslator.translate` (`cli_agent.py:127`) does the same.
`google_free.py` implements `translate` directly. No engine overrides `translate_chapter`.

## Design decisions

### 1. The predicate

Drop a line iff **all** of:

- `len(line.strip()) <= 200` — an ad line is short by nature; a real paragraph is not; **and**
- a **domain-like token** is found in the line's *detection view*; **and**
- at least one of three corroborating signals fires: **promo cue**, **obfuscation**, or
  **bare domain**.

Plus one global valve: if filtering would empty a non-empty text, return the input unchanged.

#### 1a. The detection view (the de-obfuscation)

A throwaway string used *only* for matching; the output is never derived from it.

- NFKC + casefold (fullwidth `ｓｔｏ９．ｃｏｍ` -> `sto9.com`)
- dot-lookalikes (`。．・･•∙‧⋅·﹒｡`) -> `.`
- `đ` -> `d`, then NFD and drop combining marks (fold Vietnamese tone marks)
- **DELETE** (not space-replace) anything not ASCII alnum / `.` / `-`

That last step is the whole trick: emoji, CJK, zero-width and decorative glyphs vanish, so
`sto9🍀.com` closes up into `sto9.com`. Deleting rather than space-substituting is the exact
inverse of `tts/clean.py`'s choice (which maps a dropped symbol to a space so `A★B` doesn't
become `AB`) — here we *want* the join, and it is safe precisely because this string is
never emitted.

Then a second detection-only pass: collapse runs of 4+ isolated single characters
(`s t o 9 . c o m`), and `" . "` -> `"."`.

#### 1b. The domain regex

3+ char TLDs match generically (`com|net|org|xyz|info|vip|top|club|site|online|shop|live|
icu|fun|biz|pro|space|store|website|blog|link|host|press|world|life|today|news`). 2-char
TLDs are an explicit short allowlist (`cc|tw|hk|kr|jp|cn|ru|vn|tv|io|pw|su`).

`co`, `me`, `la`, `no`, `ta` are deliberately **absent** — they are folded Vietnamese words
and would collide across a missing space (`"Rồi.Mẹ"` -> `roi.me`, `"sổ. Có"` -> `so.co`).
Even if one slipped in, the conjunction saves us: that sentence has no promo cue, no
obfuscation, and is not bare. Defence in depth.

#### 1c. The three corroborating signals

**Promo cue — two tiers**, matched on an accent-folded, casefolded copy of the *raw* line
(so `truy cập` also matches `truy cap`).

*Strong* (fire anywhere): `truy cap`, `ghe tham`, `doc tiep tai`, `doc them tai`,
`xem tiep tai`, `xem them tai`, `chuong moi nhat`, `cap nhat nhanh nhat`,
`cap nhat som nhat`, `doc mien phi`, `dia chi moi`, `ghi nho`, `goi nho`, `dich boi`,
`dang tai tai`; `visit`, `read more at`, `latest chapter`, `full text at`, `translated at`,
`bookmark`; `请访问`, `請訪問`, `更多精彩`, `最新章节`, `最新章節`, `请记住`, `請記住`,
`无弹窗`, `無彈窗`, `免费阅读`, `免費閱讀`, `全文阅读`, `全文閱讀`, `首发`, `首發`, `转载`,
`轉載`, `域名`, `收藏`, `手机版`, `手機版`, `更新最快`.

*Weak* (only within ~30 chars of the matched domain): `trang web`, `website`, `nguon`,
`ban quyen`, `source`. The tiers exist so `"Trang web của công ty bị hack…"` survives while
`"Đọc tiếp tại trang web sto9.com nhé"` does not.

**Obfuscation.** True when the domain found in the detection view is *not* present verbatim
in the NFKC-casefolded line. `sto9🍀.com` qualifies. This is the strongest single signal:
**legitimate prose never writes a domain with a decorative glyph inside it.** It is exactly
the property the site operator introduced to defeat naive filters, turned against them.

**Bare domain.** After removing the matched span from the detection view, fewer than 4
alphanumerics remain. Catches `sto9.com`, `www.sto9.com`, `【sto9.com】`, `— sto9🍀.com —`,
`https://sto9.com/book/13908/index.html`.

#### What it deliberately does NOT match

- **Any line with no domain-like token** — the load-bearing guarantee.
  `"Truy cập vào hệ thống, hắn thấy một dòng chữ đỏ."` (strong cue, no domain) is kept.
- **Any line over 200 characters**, even with a domain and a cue.
- **Prose containing a domain with no cue and no obfuscation**:
  `"Hắn mở trình duyệt, gõ vào địa chỉ example.com rồi nhấn Enter…"` is kept.
- **Websites named without a TLD** ("trang Weibo", "diễn đàn Tấn Giang").
- **Sub-line spans** — whole lines only, never a clause. See §2.
- **The stored original `content`**, **already-translated chapters**, and **`complete()`
  output** (tags, image prompts, shortened descriptions).

#### False-positive risk, stated plainly

1. **A line that is nothing but a bare URL** is dropped by the bare-domain branch. In a
   Chinese web novel this is essentially always the site watermark, but a chapter where a
   character sends a link as a standalone line would lose it. Accepted consciously —
   requiring obfuscation for the bare branch would miss `sto9.com` written plainly, which is
   a shape the operator will trivially switch to.
2. **A short line where a character reads a URL aloud alongside a directing verb.** A novel
   genuinely about the internet, or a system/game-panel novel, could hit this.
3. **A translator's note naming the source site** — dropped, correctly. That is the feature.

The risk is **asymmetric and that is intentional**: a miss costs one visible junk line the
user can find-and-replace; an over-deletion is silent data loss noticed chapters later.
Every tuning choice biases to under-delete, mirroring `shuba69.py:149-151`'s explicit "bias
hard to under-strip" reasoning.

**Alternative considered — key off the project's own source host** (`project.meta.url`).
Rejected: it needs the host plumbed into `Translator`, which knows nothing about the
project; mirror farms advertise *sister* sites so the host often won't match; and the
predicate must work host-blind anyway. Worth revisiting only if a real miss is reported.

**Alternative considered — a literal blocklist.** Rejected outright: the domain is
obfuscated specifically to defeat this, and the Vietnamese wording varies run to run because
it is model output.

### 2. Line-level mechanics

Process paragraph-by-paragraph, remove the line, drop the paragraph if it empties, and
never return empty for non-empty input.

Deliberately **not** `tts/clean.py`'s blank-the-line-then-collapse-`\n{3,}` trick. That is
right there because a dropped beat *should* become a paragraph gap = real silence. Here the
ad should leave no trace — and blanking a line inside a multi-line paragraph would create a
blank line and thereby **split one paragraph into two**, corrupting the very structure the
prompts protect.

| case | in | out |
|---|---|---|
| ad alone in its own paragraph | `A\n\nAD\n\nB` | `A\n\nB` — exactly one `\n\n` |
| ad is one line inside a paragraph | `L1\nAD\nL2` | `L1\nL2` — still one paragraph |
| ad is first / last paragraph | `AD\n\nA` | `A` — no leading blank |
| ad joined onto a real sentence | `…hắn nói. Muốn xem thêm… sto9🍀.com` | **unchanged** |

The last row is the deliberate limitation. Sub-line surgery is where over-deletion lives,
and correction 3 shows the source CMS puts the ad on its own `<br>` line. The prompt clause
is the mitigation. If it proves common, the bounded follow-up is "cut only a *trailing*
sentence that satisfies the same predicate".

`drop_site_ads` must be **idempotent** and must return non-ad text **byte-identical**.

### 3. The seam

`Translator.translate_chapter`, `base.py:94-101` — wrap both return values.

Verified: every engine inherits it (one definition, `base.py:94`, no override), every
production translation goes through it (`workers.py:267`, `:275`, `:294`), nothing else
calls it. `complete()` is untouched, so `workers.py:596` / `:667` / `:755` and
`translators/rewrite.py` are structurally unreachable from the filter.

**Why not `_translate_with_retry`:** it returns from four places inside the loop, runs per
chunk, and sits *before* `leftover = cjk_count(result)` at `base.py:75`. Filtering there
would change which attempt the retry loop scores as "best" — a behaviour change to an
unrelated heuristic, smuggled in on an ad-filtering ticket.

> Honest note the other way: filtering *before* `cjk_count` would have a real benefit — if a
> model leaves the Chinese ad line untranslated, `leftover != 0` forces all 3 attempts on
> **every** chapter of that novel, tripling API cost. If that shows up in practice, moving
> the call to just after `base.py:71` is the fix. Not done now because it is a separate,
> riskier decision than the one asked for.

**Paths that bypass this seam — named deliberately:**

| path | why it's not covered |
|---|---|
| `workers.py:203` `_run_identity` | verbatim copy of `content`; originals are out of scope |
| `workers.py:2263` `DownloadWorker` (`content_is_translated`) | the site's own translation, no engine involved |
| `RewriteWorker` → `save_rewrite` (`workers.py:464`) | operates on stored translations; see correction 4 |
| `project.edit_translation` (manual edit) | the user's own text |

All four fall under "new translations only", so none contradicts the decision taken.

### 4. The three prompts

The clause names the *purpose* ("promote the website the text was copied from") — a test the
model can apply, where "remove advertising" is not — plus the *shape* (domain + call to
action, often with a disguising character), and then clamps against over-deletion by stating
it is the ONLY permitted omission and that every other paragraph break stays. It contains no
role-play, so it is safe to append to `cli_agent.py`'s task-framed `_PROMPT`.

**Placement:** immediately after `"Translate every word — leave NO Chinese characters in the
output. "`, before `"Output ONLY the translation…"` — that sentence is what the clause is an
exception to, so they must be adjacent. `claude.py:21`->`:22`, `lmstudio.py:38`->`:39`,
`cli_agent.py:41`->`:42` (before the trailing `"\n\n{text}"`).

**Position on factoring the three prompts: factor the new clause only — one shared constant
— and leave the three prompts otherwise untouched.**

Full merge is tempting and recommended against *in this change*: `cli_agent.py:31` opens with
a task frame where the others open with a role frame, carries a clause the others don't
(`:40`), and ends with `"\n\n{text}"`. The comment at `:29-30` documents that this difference
is load-bearing — agent CLIs refuse role-redefinition. A shared blob invites a future edit
that quietly re-role-frames the CLI prompt and breaks it in a way no unit test would catch.
The `_NAME_RULES` dicts are also triplicated (`claude.py:25`, `lmstudio.py:21`,
`cli_agent.py:21`) and differ by one character (傅清**詞** vs 傅清**辭**) — evidence that
these copies do drift, but also that untangling them is its own change. Extracting only the
new clause captures the whole benefit that matters here at zero risk to the framing.

**Where the constant lives:** in `translators/ads.py`, next to the filter, so the module
docstring can state the fact that matters most — *the prompt is advisory, the filter is the
enforcement, and they target the same definition*. `ads.py` imports nothing from
`noveltrans`, so no cycle.

### 5. User-configurable extras

**No.** No `AppConfig` property, no settings field, no `extra_*` parameter.

`clean_for_tts(text, extra_remove="")` exists because it is a **preference** knob — whether
`()` should be voiced is genuinely taste. "Is this line a site advertisement?" **has** a
correct answer. A settings box would be a way of not deciding the predicate, and it would put
the burden of defeating an adversarial obfuscation scheme on the user — who cannot type
`sto9🍀.com` reliably in the first place.

There is already a shipped escape hatch for misses: the Dịch tab's **Tìm & thay thế**
(`find_replace.py`, `FIELD_TRANSLATED`). It is also the only tool that works on
already-translated chapters, which are out of scope — so it needs mentioning regardless.
Cost of adding extras later is ~15 lines, exactly as `tts_clean_extra_remove` was added.

## Step-by-step changes

1. **New `src/noveltrans/translators/ads.py`.** Docstring in the house style of
   `tts/clean.py`: pure `str -> str`, no Qt, no I/O; the ad arrives *translated* so the
   predicate keys on shape not literals; the domain conjunct is the safety property; what it
   must not break (never touches `content`, never runs on `complete()` output, never splits
   or merges a paragraph, never returns empty for non-empty input); and that `PROMPT_RULE` is
   the advisory half of the same rule. Then `PROMPT_RULE`, the constants,
   `_fold` / `_detect_view` / `_cue_view`, `_is_ad_line` (three signals as named locals so
   the logic reads as prose), and `drop_site_ads`. Ruff `line-length = 100`.
2. **`base.py`** — import `drop_site_ads`, wrap both return values of `translate_chapter`
   (`:98-101`). Add a comment explaining why it is here and not in `_translate_with_retry`
   (the `cjk_count` scoring at `:75`) — that comment is what stops a future reader
   "simplifying" it into the retry loop.
3. **`claude.py`** — import `PROMPT_RULE`; insert between `:21` and `:22`.
4. **`lmstudio.py`** — same, between `:38` and `:39`.
5. **`cli_agent.py`** — same, between `:41` and `:42`. Leave the comment at `:29-30` and the
   clause at `:40` exactly as they are.
6. **Explicitly do not touch `translators/rewrite.py`** — correction 4. Worth a line in
   `ads.py`'s docstring, since it is the obvious next place someone would paste the rule.
7. **`README.md`** — extend the "2. Dịch" row with one sentence: new translations drop
   source-site ad lines; already-translated chapters are unaffected — use **Tìm & thay thế**.

## Tests

**New `tests/test_ads.py`** (pure — no engine, no model), mirroring `test_tts_clean.py`:

- `TestTheReportedLine` — the exact reported line; emoji removed; emoji swapped
  (parametrised `🍀 🌸 ★ ⭐ ✿ ·`); fullwidth; spaced-out letters; the untranslated Chinese
  original; and 4 plausible re-wordings (the wording is model output and varies run to run).
- `TestBareDomainLines` — `sto9.com`, `www.sto9.com`, a full URL, `【sto9.com】`,
  `— sto9🍀.com —`.
- `TestLegitimateContentSurvives` — **the anti-regression.** Prose mentioning a domain; a
  character reading a URL mid-sentence; promo phrasing with no domain; a >200-char paragraph
  with both; a missing space after a full stop (`"Rồi.Mẹ nói…"`, pins the TLD-list
  reasoning); ordinary prose returned byte-identical; idempotence.
- `TestParagraphStructure` — one break not three; an ad line inside a paragraph does not
  split it; no blank start/end; and the joined-onto-a-sentence case pinned as a documented
  limitation rather than a bug.
- `TestSafetyValves` — a text that is only an ad is returned unchanged; empty/whitespace.

**`tests/test_translators.py`** — `TestSiteAdsFilter`: the seam test; per-engine
parametrised coverage via `get_translator` with each transport mocked as the existing
`TestGoogleFree` / `TestClaude` / `TestCliAgent` / `TestLmStudio` classes already do;
**`test_complete_output_is_not_filtered`** (the important negative — a tag list containing a
domain must come back untouched); and a title that is only an ad not being blanked.

`TestPromptCarriesTheAdRule` — parametrised `assert PROMPT_RULE in prompt` over all three
engines, plus `test_the_cli_prompt_is_still_task_framed` (does not start with "You are", and
still carries the data-not-instructions clause).

**`tests/test_rewrite.py`** — `test_the_rewrite_prompt_does_not_carry_the_ad_rule`, with a
docstring explaining that dropping a line would fail `check_rewrite`'s paragraph-count
equality (`rewrite.py:280`) and burn all three attempts. This is the test that stops someone
"finishing the job" later.

## Risks / out of scope

**Risks**

- **Over-deletion is the only serious one.** Mitigated by the domain conjunct, the 200-char
  cap, the two-tier cue list, the conservative TLD list and the non-empty guard; pinned by an
  anti-regression test class. The residual accepted case is a standalone bare-URL line.
- **The predicate will be outmatched eventually** — `sto9 dot com`, `s-t-o-9.com`, the domain
  spelled in words. The design degrades gracefully (the prompt clause still applies) and the
  extension points are named: `(dot)`/`chấm` substitution, host-awareness, trailing-sentence
  cutting.
- **Prompt drift across the three engines** — reduced to one constant plus a per-engine test,
  but the `_NAME_RULES` triplication (and its 詞/辭 discrepancy) remains and will bite later.
- **A false negative costs API calls, not just cosmetics**: if the model leaves the ad in
  Chinese, `base.py:75`'s `cjk_count` forces all 3 retries on every chapter. Named in §3 with
  the one-line fix if it materialises.

**Out of scope (per the decisions taken)**

- Retro-cleaning already-translated chapters. The tool is **Tìm & thay thế**, with the caveat
  that it is a *literal* replace (`find_replace.py:51`), so the obfuscated domain must be
  pasted exactly.
- Stripping the line from the stored original `content`; any scraper change.
- The two non-translator paths that write the `translated` column (`workers.py:203`,
  `workers.py:2263`).
- The rewrite pass — deliberately excluded, see correction 4.
- Consolidating the three engine prompts / `_NAME_RULES` — recommended as a separate ticket.
- Any settings-dialog or `AppConfig` change.
