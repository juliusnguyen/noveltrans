# 069 — Drop source-site advertising lines from translations

## Ask (user)

> In Dịch, sometime there is the line like
> `Muốn xem thêm nhiều chương đặc sắc, xin truy cập sto9🍀.com`
> it use to advertise the website that use to crawl this novel; we don't want that kind of
> line in the translation. Can we update the prompt to auto drop that kind of line

## Decisions taken with the user

| question | answer |
|---|---|
| Prompt alone can't guarantee removal — how should this work? | **Both**: instruct the model *and* run a deterministic filter over the result, so anything that slips past the model is still removed. |
| What gets cleaned? | **New translations only.** Already-translated chapters keep their ad lines unless re-translated; the stored original (`content`) is left alone. |

The "both" choice is the important one. A prompt instruction is advisory — the model will
sometimes keep the line, and a vaguely worded "drop adverts" instruction risks it cutting
real story content instead. The filter is what makes the outcome actually true; the prompt
just means the filter usually has nothing left to do.

## What the line actually looks like

The user's example — `Muốn xem thêm nhiều chương đặc sắc, xin truy cập sto9🍀.com` — is
already **in Vietnamese**, so the ad exists in the Chinese source and the translator
faithfully translated it. That has two consequences worth designing around:

- The filter has to match **translated** text, not a fixed source string. The Vietnamese
  wording will vary run to run, because it is whatever the model produced that time.
- The domain is **deliberately obfuscated** (`sto9🍀.com` — an emoji standing in for a
  character) precisely so naive filters miss it. Any exact-string match will fail on the
  next variant. The obfuscation is itself a strong signal.

So the pattern needs to key off the *shape* of these lines — a domain-like token plus
call-to-action phrasing ("truy cập", "xem thêm", "đọc tiếp", "website", …) — rather than a
literal. The plan should decide the exact predicate and, importantly, **how it avoids
eating legitimate lines** (a chapter that genuinely mentions a website, a character reading
a URL aloud).

## Scope

### 1. The prompt, in three places

The instruction has to go in all three engines or it will apply inconsistently:

- `src/noveltrans/translators/claude.py:12` `_SYSTEM_PROMPT`
- `src/noveltrans/translators/lmstudio.py:29` `_SYSTEM_PROMPT`
- `src/noveltrans/translators/cli_agent.py:31` `_PROMPT` (note: task framing, not
  role-play — the comment above it explains why, and a new clause must not break that)

These three are near-identical copies. Worth deciding whether this feature should also
factor the shared text into one constant, or whether that is scope creep — say which and
why rather than doing it silently.

The wording must be narrow. "Remove advertising" is too loose; something closer to
"a line whose purpose is to promote the website the text was copied from" gives the model
a test it can apply, and makes over-deletion less likely.

### 2. The deterministic filter

New pure module, following the shape of `src/noveltrans/tts/clean.py` — which is the
established precedent here: pure `str -> str`, no Qt, no I/O, heavily unit-tested, with a
docstring that states what it must not break. Note `clean_for_tts(text, extra_remove="")`
also takes a user-supplied extra list; whether this feature needs an equivalent
(user-added ad phrases in settings) is a judgement call for the plan.

Where it hooks in is the other real decision. Candidates:

- inside `Translator._translate_with_retry` / `translate` (`translators/base.py:55`), so
  every engine and every caller gets it; or
- at the three `project.save_translation(...)` sites in `gui/workers.py` (lines ~203, ~300,
  ~2263), so only stored translations are filtered.

Pick one and justify it — note that `base.py` also serves `complete()` for tags and image
prompts, which must **not** be filtered.

### 3. Line-level, not character-level

The unit is a whole line. Removing the line must not leave a blank gap or collapse the
paragraph breaks that downstream code depends on — `tts/clean.py`'s docstring is explicit
that `\n\n` matters for sentence chunking, and the translation prompts all say "keep the
paragraph breaks exactly as in the source".

## Out of scope

Cleaning already-translated chapters (the user chose new translations only), stripping the
line from the stored original `content`, and any change to the scrapers.

## Test plan sketch

The filter is pure, so it should be covered directly and hard: the user's exact example;
the same line with the emoji swapped or removed; a bare domain line; a line in the middle
of a paragraph vs on its own; **and the negative cases that matter most** — a chapter line
that legitimately mentions a website or a URL must survive. Add a prompt-content assertion
per engine so a future edit cannot silently drop the instruction from one of the three.
