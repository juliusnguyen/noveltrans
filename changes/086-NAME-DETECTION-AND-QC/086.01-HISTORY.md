## [BUG] Four defects, all measured on the real library — 2026-09-08

**1. The detector discarded names for being famous.** `_is_common_word(candidate, 50)` asks
jieba's frequency dictionary, and a real historical person IS a dictionary entry: 尹志平
scores **367** and was rejected as ordinary vocabulary, while the purely fictional 郭靖
(score 0) passed. Library-wide the gate was discarding **54 real names** (李莫愁 ×3931,
張無忌 ×1790, 朱元璋 ×1149, 歐陽鋒 ×704…).

*The obvious fix was measured and rejected:* jieba tags 尹志平 `nr`, but it also tags 武功,
熊貓, 王八 and 謝謝 as person names — trusting the tag would substitute invented names over
ordinary words throughout a novel.

*Shipped rule:* the dictionary gate applies only to **two-character** candidates. Anything
longer has already survived the 80%-extension, varied-preceder and varied-follower tests.
Measured: recovers 54 real names, admits 4 non-names (金字塔, 夏令營, 白熱化, 連衣裙 — none
over 11 occurrences, and the review dialog exists to untick them). Library totals 927 → 981
names; nine of twelve novels unchanged.

**2. Surname readings.** Even once detected, the reading was wrong. Added to
`_SURNAME_READING_OVERRIDES`: 尹 → doãn (19078 surname occurrences library-wide; the novel's
own translations said "Doãn" 14364 times against 350 for "Duẫn"), 任 → nhậm, and — found
while measuring — **李 → lý**: the table read "lí" while the engines' own output used
"Lý Mạc Sầu" 3881 times against 19 for "Lí", so the glossary was substituting a spelling the
engine then corrected back. Also 區/区 → âu and 繆/缪 → mậu, correct but not exercised here.

**3. QC had no concept of proper nouns**, which is why chapter 119 passed with "Yin Chí
Bình". New `QC_NAME_DRIFT`: a glossary name present in the source must appear in the
translation. Comparison folds i/y (Lý/Lí, Kỳ/Kì) because both spellings are correct
Vietnamese and treating them as different flagged 95% of chapters. Matches the name under
either spelling in the source, because a scan sees raw Chinese while a live translation sees
text the glossary has already substituted into.

**4. The check could not be trusted against auto-detected names.** Measured flag rates per
novel with the full glossary: 38%, 69%, 11%, 61%, 64%, 7%, 94%, 86%. A frequency floor helped
(≥500 occurrences → 0–77%) but did not fix it: the auto glossary contains non-names (武者
"martial artist", 尹府 "the Yin residence") that can never appear in a translation, and
chapters translated under an older glossary legitimately disagree with the current one.

*Shipped:* `confirmed_glossary` — QC checks only names the user **edited or added by hand**.
Zero false positives by construction (measured: 0/4901 chapters today), at the cost of
checking nothing until the name list is reviewed. The substitution still uses every enabled
entry; only the check, which can trigger a re-translation, is held to the higher standard.

## [FIX] The confirmed-names compromise did not work — 2026-09-08
User re-scanned names (glossary went 300 → 348 with 尹志平 → "Doãn Chí Bình" ×14692, so the
detector fix was live) and QC still passed chapter 119. Correct per the design and useless
in practice: a re-scan produces `auto` entries, `confirmed_glossary` requires an edited or
hand-added one, so the check had nothing to check. The compromise was wrong.

Built the check that had been deferred: **internal consistency**. The novel's own
translations say how it spells each character, and the odd chapter out is the error —
"Yin Chí Bình" is catchable exactly because 14838 other occurrences say "Doãn Chí Bình".

This reframing is what makes it usable at all. A mis-detected "name" (武者, 尹府) has no
competing spellings, so it can never produce a minority variant — the false-positive class
that sank the glossary comparison simply cannot arise.

Four rules, each added because the measurement demanded it:

| rule | flag rate on the reporting novel |
| --- | --- |
| naive: compare against the glossary | 64% |
| consistency, but folding case before matching | 36% |
| …requiring a capital (a name's first syllable is capitalised) | 5.1% |
| …ignoring sentence-initial capitals ("Còn Kiếm Tiên…" is not a person) | 2.4% |
| …ignoring honorifics ("Tiểu Vô Kỵ" is "little Wuji") | **2.0%** |

Library-wide: **35 of 4874 chapters (0.7%)**, and chapter 119 is among them. Only names of
3+ syllables are profiled (a one-syllable stem like "Tĩnh" collides with every other name
ending in it) and only those used at least 20 times, so one early chapter cannot define the
canon. A variant used more than 2% as often as the dominant spelling is treated as an
established convention, not a slip — which keeps 350 legacy uses of an older reading out of
the results while still catching variants used 30, 21, 13, 12 and 9 times.

`QcScanWorker` builds the profile once per scan; the live-translation path keeps the
confirmed-glossary check, because a fresh translation has no corpus to learn from.

### Repairing an already-translated novel
Fixing detection does not repair chapters already translated. The reported novel holds ten
spellings of one name (Doãn 14364, Duẫn 350, Bạc 30, Yêu 21, Dọc 13, Doan 12, Yin 9, and
three singletons) — roughly 483 wrong occurrences. **Tìm & thay thế** repairs that in seconds;
re-translating would cost hours.

### Tests: 28 new (3575 passing)
A famous 3-char name is kept while 安全/高興/任何 are still rejected; jieba's `nr` tag is
explicitly not trusted (武功, 熊貓, 謝謝); surname readings win only in first position;
the QC name check catches the reported "Yin Chí Bình" case, folds i/y, works on both an
already-substituted and a raw source, needs only one mention, and does nothing without a
glossary; `confirmed_glossary` excludes auto entries while `applied_glossary` keeps them. For the
consistency check: the odd chapter out is found; the usual spelling passes; a lowercase word,
a sentence-initial capital and an honorific are each not treated as a spelling; an
established alternative is left alone; a barely-used or two-syllable name is not profiled.


## [BUG] Crash on "dịch lại chương đã chọn" — 2026-09-08
Reported from the running app:

    AttributeError: 'TranslateTab' object has no attribute '_reload_table'
    tab_translate.py:781 in _retranslate_indices

`_reload_table` has **never existed on `TranslateTab`**. `git log -S` puts the call in
feature 072, copied from `tab_scrape` and `name_glossary_dialog`, which do have one. It has
been a latent crash on the Name Glossary dialog's re-translate button ever since; 084's QC
result view added a second route to the same line, which is how a user finally reached it.

Fixed by delegating to `_on_replacements_applied`, which already refreshes the table AND
reloads the preview panes when the open chapter is one of the affected ones — the two things
clearing a translation actually changes.

**Why no test caught it:** nothing exercised the handler. 084 tested that the result view
*emits* the right indices and that the tab *connects* the signal, but never called the slot,
so the crash sat one call away from a green suite. Three tests added that call it: the
translations are dropped and exactly those chapters queued, the model the user is looking at
is refreshed, and an empty selection does nothing.

An AST sweep of `TranslateTab` for other `self._x()` calls with no definition found none.
