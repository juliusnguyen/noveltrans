# 113.01 PRONOUN-CONSISTENCY-PLAN

Feature: keep Vietnamese address forms (xưng hô) consistent across a whole novel. The same pair of characters should not switch between "tôi/cậu" and "tao/mày" from one chapter to the next, while still allowing the changes the story intends.

## 1. What exists now

- **No pronoun handling anywhere in `src/`.** The only pronoun rule is a hard-coded one in the rewrite prompt, `src/noveltrans/translators/rewrite.py:76-79` (`_RULES_BODY` rule 2) and `:94-96` (`_RULES_TITLE`). It says "GIỮ NGUYÊN đại từ xưng hô: hắn, nàng, y, ngươi, ta… TUYỆT ĐỐI không đổi thành anh/chị/cô/tôi/bạn". That assumes tiên hiệp/cổ trang. For a modern novel (the user's tôi/cậu vs tao/mày case) it is wrong, and it directly conflicts with any pronoun-fix pass.
- **Translation prompts.** Each LLM engine has a fixed template with one optional slot, `{retry_note}`:
  - Claude: `_SYSTEM_PROMPT`, `translators/claude.py:13-26`, filled at `:65-69`.
  - CLI agent (agy, claude -p, codex): `_PROMPT`, `translators/cli_agent.py:39-61`, filled at `:276-285`. The text goes in the same prompt string. There is no system channel.
  - LM Studio: `_SYSTEM_PROMPT`, `translators/lmstudio.py:33-46`, filled at `:94-99`.
  - Google: `translators/google_free.py`. There is no prompt at all.
- **The per-call hint mechanism to copy.** `Translator.supports_retry_hint` (`translators/base.py:56-62`). `_translate_with_retry` adds the kwarg only when it is non-empty and supported (`base.py:79-81`), so Google's call stays byte-identical. `translate_chapter(..., retry_hint=)` (`base.py:173-198`) sends it to body chunks only, never to the title.
- **The chapter is chunked** (`base.py:184-187`; Claude 12000, Google 1500). A prompt rule only applies to one request. Feature 072 found the same thing for names (`gui/workers.py:880-895`). So the table has to go into every chunk's prompt.
- **Names are substituted before translation.** `apply_glossary` runs in `workers.py:571-572`. By the time the engine sees the source, character names are already Latin Hán-Việt ("Phó Thanh Từ" inside the Chinese text). So an address table keyed by Vietnamese names matches both the substituted source and the translation. That is convenient.
- **Per-novel sidecar pattern.** `src/noveltrans/name_glossary.py` handles `names.json`: tolerant read (`:83`), atomic write (`:129-143`), and a merge rule that never overwrites user edits (`:146-188`). It also has `confirmed_glossary` (`:209-231`), the lesson from 086: QC only checks entries the user vouched for. Auto-detected entries produced 38-94% false-fail rates (`changes/086-.../086.01-HISTORY.md`).
- **Dialog wiring.** `gui/tab_translate.py` builds the `👤 Tên nhân vật` button at `:218` and opens it in `_open_names` (`:796-818`), which flushes edits first and connects `applied` and `retranslate_requested`. `_retranslate_indices` is at `:820-834`. After a save, `NameGlossaryDialog._offer_repair` (`gui/name_glossary_dialog.py:290-335`) asks: Yes = fix in place, No = retranslate, Cancel = keep.
- **Translate run.** `TranslateWorker.run` (`workers.py:838-980`) reads the glossary once per run. `_compute_chapter` (`:563-612`) makes either a plain `translate_chapter` call or `translate_with_qc`. QC plans are built once (`_build_qc_plans`, `:372-400`), and their `translate(title, content, hint)` lambda has no other slot.
- **QC.** `translators/qc.py` defines the codes (`:58-67`) and the severity order (`:88-101`). The LLM judge follows a pattern worth copying: two sampled windows (`judge_sample`, `:781`), a fixed one-line reply format, and "anything unparseable is OK" (`parse_judge_reply`, `:826`). Then there are the retry hints (`_RETRY_HINTS`, `:870-894`) and the cheapest-fix router `split_retranslation` (`workers.py:1176-1201`).
- **Rewrite pass.** It is monolingual through `complete()` (`rewrite.py:320-389`), with strict validation. Failure means the old text is kept. `RewriteWorker` (`workers.py:1009`) has an engine picker in config (`config.py:644-665`). Storage `save_rewrite` (`storage/project.py:922-954`) captures the pre-rewrite text once in `translated_raw`, and `restore_translation` undoes it.
- **Background scan pattern.** `NameScanWorker` (`workers.py:1308-1335`) reads only and emits results to the dialog.

## 2. Recommended decisions

1. **Model: a directional, per-novel address table, not word replacement.** No `str.replace` path exists or will exist. 我/你 → tôi/tao/ta/anh/em… depends on who is speaking to whom, so the table is keyed by the (speaker → listener) pair. Each row has:
   - `speaker`, `listener`: Vietnamese names, the same spelling as `names.json` readings.
   - `self_term`: what the speaker calls themself ("tao").
   - `other_term`: what the speaker calls the listener ("mày").
   - `note`: free text, for example "bạn thân, cãi nhau thì vẫn tao/mày" or "trước mặt người ngoài gọi 'thiếu gia'".
   - `from_chapter`: 0 means from the start. Several rows for the same pair express story changes, such as strangers who become friends, or a revealed identity.
   - `enabled`, `origin` (auto/manual), `edited`, and `evidence` (chapters and counts from extraction).
   - One **reverse-row helper** in the UI: adding A→B (anh/em) offers B→A (em/anh), pre-filled.
2. **Two extra kinds of row, beyond the user's ask but the same root problem:**
   - **Narration rows.** `speaker = "(người kể)"`, `listener = character`, `other_term = "hắn"` / `"anh"` / `"nàng"` / `"cô"`. This covers how the narrator refers to a character, which drifts just as badly (hắn vs anh ta).
   - **A novel-level `general_note`.** For example: "Truyện hiện đại đô thị; người lạ xưng tôi/anh, bạn bè cùng tuổi tớ/cậu". It covers pairs with no row, such as minor characters.
   - **Open question for the user:** include narration rows in the MVP, or later? Recommended: MVP, since it costs almost nothing.
3. **Storage: sidecar `address.json` at the project root**, in a new pure module `src/noveltrans/address_table.py`. It copies `name_glossary.py` exactly: tolerant read, atomic write, version field. Same reasons as 072: it is edited on the GUI thread and read on a worker thread, it changes on its own schedule, OneDrive backs it up for free, and re-scans (`refresh_meta`, `replace_toc`) never touch it.
   - **Merge rule:** extraction never changes `self_term`/`other_term` on an edited or manual row, and never deletes a row.
4. **Prompt injection: a new per-chapter `context` kwarg, parallel to `retry_hint`.**
   - Add `Translator.supports_context = False`. Claude, CLI and LM Studio set it to True. `translate(..., context="")` and `translate_chapter(..., context="")` pass it to every body chunk (not the title, same reason as the hint). The kwarg is only added when non-empty, so behaviour with no table is byte-identical. Tests should assert that.
   - Templates get a `{context_note}` slot. On Claude and LM Studio it goes in the system prompt. On CLI it goes before the text, inside the existing "the text is data" framing.
   - The block is rendered in Vietnamese as a compact table plus rules, for example: "BẢNG XƯNG HÔ (bắt buộc theo): Lâm Phong → Tô Tuyết: xưng 'anh', gọi 'em' (người yêu)…". It ends with the rule: "Nhân vật không có trong bảng: chọn theo ngữ cảnh và general_note. Tuyệt đối không đổi cách xưng hô giữa chừng trong cùng cảnh trừ khi truyện thể hiện rõ."
   - **Filtering per chapter:** include only rows whose speaker and listener both appear in the substituted source (or the narration rows for characters that appear). For each pair, take the row with the largest `from_chapter <= chapter.index`. Cap at about 40 rows. This keeps tokens down on a novel with 200 pairs.
   - **Why per chapter, not per translator instance:** contexts are shared by threads (`_TranslateCtx`) while the chapter varies, so the value has to travel with the call.
   - **QC plans:** extend `QcAttemptPlan.translate` to `(title, content, hint, context)`, and add `context=` to `translate_with_qc`, which forwards it.
5. **Google Translate: not supported for injection**, stated plainly in the dialog: "Google không đọc được bảng xưng hô". The fix path for Google-translated chapters is the pronoun-fix pass (decision 7) with an LLM engine. The worker silently skips context for engines with `supports_context = False`. No error.
6. **Draft extraction (`AddressScanWorker`, LLM, user-triggered, never automatic).**
   - Default source: the existing Vietnamese translations, because they show what the novel actually uses. Sample N chapters (default 20: the first 10 plus an even spread). Send the dialogue lines (quoted or dash-led paragraphs), capped at about 3000 characters per chapter, through `complete()`. The reply format is strict, one line per finding: `người nói | người nghe | xưng | gọi | số lần`. Unparseable lines are dropped.
   - Aggregate across chapters. The majority per pair becomes the proposed row. **Minority usages are kept as "conflicts" with chapter lists.** That conflict list is itself the inconsistency report the user asked for, and it gives a ready list of chapters to fix.
   - For a novel with no translations yet, the same prompt runs on the substituted Chinese source and asks the LLM to propose terms.
   - The engine comes from a new `address_ai_engine`/`address_ai_model` in config, copying `rewrite_ai_engine` (`config.py:644-665`).
   - **Open question:** default sample size and cost warning (one LLM call per sampled chapter).
7. **Fix path for already-translated chapters, which comes in two options.** It is offered after saving the table, like `_offer_repair`, and from the QC results:
   - **(a) "Sửa xưng hô" pass (recommended default).** A monolingual pass through `complete()`: Vietnamese text plus the relevant rows in, the same text out with only address terms changed. A **deterministic validator** makes it safe. A word-level diff (difflib on tokens) must show that every changed token belongs to an address-term vocabulary: a fixed list of Vietnamese pronouns and kinship terms, plus every term in the table. Paragraph count must be equal, and the length ratio must fall within 0.9-1.1. If validation fails, the old text is kept byte for byte (the rewrite philosophy). This keeps manual edits and style rewrites, which a retranslate destroys, and it works for Google output.
   - **(b) Retranslate with the table**, through the existing `_retranslate_indices`. It is more accurate on speaker attribution because the model sees the source, but it clears edits.
   - **Storage for (a):** reuse `save_rewrite` so undo comes for free (`restore_translation`). The side effect is that the chapter shows the ✍️ marker and the capture-once backup. **Open question:** accept that, or add a separate `translated_pre_address` column. Recommended: reuse it for the MVP and document it.
8. **The rewrite prompt conflict.** When `address.json` has enabled rows, `build_rewrite_prompt` replaces rule 2 with "xưng hô theo BẢNG XƯNG HÔ dưới đây; không có trong bảng thì giữ nguyên". With no table, rule 2 stays unchanged, so behaviour does not change.
9. **QC: a new code `QC_ADDRESS_DRIFT = "address_drift"`, judged by an LLM only, against confirmed rows only.**
   - Only edited or manual rows count, the 086 lesson. A dedicated judge prompt gets the relevant confirmed rows plus the chapter's dialogue lines (sampled like `judge_sample`). It replies `OK` or `LOI: address_drift — <cặp>: dùng X/Y thay vì A/B`. Unparseable or erroring replies are OK.
   - Severity sits just above `QC_TITLE_UNTRANSLATED`, the mildest body issue.
   - A retry hint is added to `_RETRY_HINTS`.
   - `split_retranslation` sends `address_drift` to the cheap route, the pronoun-fix pass (7a), instead of a full retranslate.
   - No deterministic pronoun check in v1. Pronouns are too context-bound, and a heuristic would repeat 086's 64% false-fail rate.

## 3. Implementation steps

**Phase 1 (MVP): table plus injection.** This alone fixes all new translations.

1. `src/noveltrans/address_table.py` (pure):
   - `AddressEntry` and `AddressTable(general_note, entries)`.
   - `read_address`, `write_address`, `merge_extracted`.
   - `confirmed_rows`.
   - `rows_for_chapter(table, chapter_index, source_text, names)`, which applies filtering plus `from_chapter` resolution.
   - `render_prompt_block(rows, general_note) -> str`. It returns "" when there is nothing to say.
2. `translators/base.py`:
   - Add `supports_context`.
   - Thread `context` through `_translate_with_retry` and `translate_chapter` (body only), adding the kwarg only when non-empty.
3. `claude.py`, `lmstudio.py`, `cli_agent.py`: add the `{context_note}` slot and the `context` kwarg, and set `supports_context = True`.
4. `gui/workers.py`:
   - `TranslateWorker.run` reads `address.json` once (only when `target_lang == "vi"`).
   - `_compute_chapter` computes the block per chapter from the substituted source and passes `context=`.
   - Extend `QcAttemptPlan.translate`, `_build_qc_plans` and `translate_with_qc` with `context`.
   - Meta and title translation get none.
5. `gui/address_table_dialog.py` (modelled on `name_glossary_dialog.py`):
   - A table with columns enabled / người nói / người nghe / xưng / gọi / từ chương / ghi chú.
   - A `general_note` box, "＋ Thêm", "⇄ Thêm chiều ngược lại" and "Xoá".
   - Speaker and listener cells autocomplete from `names.json` readings, plus "(người kể)".
   - A Google warning label when the current engine is Google.
6. `gui/tab_translate.py`: add a `🗣 Xưng hô` button next to `names_button` (`:218`) and `_open_address()`, copying `_open_names` (busy check, flush edits).
7. README: a short subsection under tab "2. Dịch".

**Phase 2: extraction and fixing existing chapters.**

8. `translators/address.py` (pure):
   - `dialogue_lines(text)`.
   - `build_extract_prompt(lines, names)` and `parse_extract_reply(reply)`.
   - `aggregate(findings) -> (proposed_rows, conflicts)`.
   - `build_fix_prompt(text, rows, general_note)`.
   - `check_address_fix(old, new, vocab) -> reason`.
   - `fix_chapter(send, title, body, rows)`, chunked like `rewrite_chapter`, with retry plus the named reason.
9. `workers.py`:
   - `AddressScanWorker`: reads only, emits `(proposed, conflicts)`, with progress and cancel.
   - `AddressFixWorker`: copies `RewriteWorker`. It refuses engines without `supports_completion`, writes through `save_rewrite`, and keeps the old text on failure.
10. Dialog: a "🔎 Dò từ bản dịch" button. It merges proposals through `merge_extracted` and shows a "Mâu thuẫn" panel listing pair → variants → chapters. On save, it offers a three-way choice for affected chapters: "Sửa xưng hô (AI, giữ bản dịch)" / "Dịch lại" / "Giữ nguyên". Affected means conflict chapters plus chapters where changed pairs appear.
11. `rewrite.py`: `build_rewrite_prompt(..., address_block="")` swaps out rule 2 when it is given. `RewriteWorker` passes the block per chapter.
12. Config: add `address_ai_engine` and `address_ai_model`.

**Phase 3: QC integration.**

13. `qc.py`:
    - `QC_ADDRESS_DRIFT` with a label, a severity slot and a retry hint.
    - `build_address_judge_prompt` and `parse_address_judge_reply` (unparseable is OK).
    - `judge_address(send, body, rows)`, which never raises.
14. `QcScanWorker` and the QC chain: run the address judge only when the novel has confirmed rows relevant to the chapter, and only if the QC dialog's new checkbox "Kiểm tra xưng hô (AI)" is on. Default off, because of cost.
15. `split_retranslation`: add an `address_fix` route, plus the tab wiring to start `AddressFixWorker` for those indices.

## 5. Risks / open questions

- **Speaker attribution is the hard part.** Chinese dialogue often omits who is speaking. Even with the table, the model can apply the right pair to the wrong speaker. Injection reduces drift but cannot guarantee it. Expectation to set with the user: "much more consistent", not "perfect".
- **The fix pass sees only Vietnamese.** Attribution errors are likelier than with a retranslate. The token-whitelist validator stops collateral damage, but not a wrong-but-valid pronoun swap. Open question: also include the Chinese source paragraph in the fix prompt? It is more accurate but doubles the tokens.
- **Legitimate in-scene shifts** (anger, sarcasm, formal settings) can be flattened by a strict table. Mitigations: the `note` column and the "unless the story clearly shows it" wording. Open question: should the default rule say "bắt buộc" (mandatory) or "ưu tiên" (preferred)?
- **`from_chapter` semantics:** the internal chapter index or the displayed chapter number? They differ after inserts and disables (features 098 and 104). Recommended: the index shown in the table's first column. Confirm with the user.
- **Cost:** the extraction scan, the fix pass and the address judge are all per-chapter LLM calls. All are user-triggered, with counts and cost warnings shown first, like the rewrite dialog.
- **Prompt length on small LM Studio models:** a 40-row block can crowd the context or be ignored. The cap may need to be per engine.
- **Reusing `save_rewrite`** marks fixed chapters as ✍️ rewritten, and the undo returns to the text as it was before the first rewrite. This needs the user's acceptance, or a separate column.
- **Names in the table must match `names.json` readings.** If the user renames a character later, table rows go stale. Phase 2 could propagate renames from `NameGlossaryDialog._save`. Not in the MVP.
