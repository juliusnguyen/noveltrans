# 111.01 AUTO-COMMENT-PIN-PLAN

Feature: after a video is published, post a comment with a configured text and pin it.

## 1. What exists now

- No comment or pin code in `src/`.
- `upload_one` (`src/noveltrans/youtube_upload.py:3165`): `STATE_COMMITTED` is written at ~3241, `_finish` runs at ~3251, `STATE_PUBLISHED` is written at ~3254, and `UploadResult` is returned at ~3264.
- State: `write_upload_state` merges fields (~766). `is_published` (~787) is the double-publish guard. `needs_attention` (~792) ignores published records, so comment state needs its own check.
- Helpers to reuse: `_first_present` (~935), `_click_any` (~994), `_fill_box` (~1006), `_click_text_anywhere` (~2612). There is no comment-box or watch-page helper yet.
- Studio URL templates: `_EDIT_URL` (~213) and `_SUBTITLE_URLS` (~225).
- No config field for comment text. Pattern to copy: `tts_clean_extra_remove` in `src/noveltrans/config.py` (~431-439), with a `QLineEdit` in `src/noveltrans/gui/settings_dialog.py` (~494, save at ~961).

## 2. Recommended decisions

1. **Where the setting lives (updated by user):** in the `5. Video` tab (`workspace.py:48`, `gui/tab_video.py`), as a per-novel setting stored in `meta.json`, the same way as `save_upload_playlist` / `save_upload_visibility` (`storage/project.py` ~1370-1390). It has:
   - An enable checkbox. Off by default for novels that have no setting yet.
   - A text box. Default value (user-supplied, use exactly):
     ```
     Các bác bơm tí lúa mình có động lực làm video sớm nhé!
     19038324284018
     Techcombank
     ```
   - Passed to the upload as `UploadRequest.comment: str = ""` (empty when disabled), set in `tab_video._upload_request` (~4218). `youtube_upload.py` stays free of Qt.
   - **Security note:** the default contains a bank account number. Putting it in the default in `src/` would commit it to the public repository's history. Recommended: keep the default in `meta.json` only, and not in source code. Needs the user's confirmation before commit.
2. **Failure policy:** warn only. The comment step catches all exceptions and never raises, so `STATE_PUBLISHED` and the return value stay the same. Add `UploadResult.comment_note: str = ""`, report progress through `_report`, and list warnings in the finished summary in `gui/workers.py`.
3. **Idempotency:** store `comment_status` in the `.upload.json` file: `posting` before the Post click, then `posted`, then `pinned: true`. On a re-run, skip Post if `posted` is set and skip Pin if `pinned` is set. `posting` without `posted` after a crash means unknown: do not re-post, and show a warning.
4. **Placement:** in `upload_one`, right after the `STATE_PUBLISHED` write, on the same page, with no cancel checks, since the publish fence has been passed. Already-published parts get nothing in v1. Backfilling existing videos is a separate action.
4a. **Which visibilities get a comment (user: "every visibility that able to add comment"):** a constant set, not a guess per part. Proposed: `public`, `unlisted`, `schedule`, `members_then_public`. `private` is skipped, since viewers can't see or comment on it. Confirm in the live probe.
4b. **Scheduled and members-then-public videos are not public at upload time.** Commenting may be impossible until the video goes public (`publish_at` / `public_at`). Two options: (a) comment at upload if Studio allows it, otherwise skip with a warning; (b) a later step, run after the public switch, which needs state for "waiting to comment". Recommend (a) for v1, with the probe deciding. Option (b) is a separate follow-up.
5. **Reuse:** follow the `_open_subtitles_page` pattern (~2572): `goto` in the same context, check `_LOGGED_OUT_URL_RE` and the Studio error page, and handle the browser closing. Do not reuse `_finish`'s dialog wait.

## 3. Implementation steps

0. **Live probe first** (section 5). Do not write selectors before it.
1. `storage/project.py`: add `save_upload_comment(enabled, text)` and a reader, storing both in `meta.json` (same pattern as `save_upload_playlist`). `gui/tab_video.py`: add the enable checkbox and text box to the `5. Video` tab, load and save them per novel, and seed the default text when the novel has none yet.
2. `youtube_upload.py`: add `UploadRequest.comment` and `UploadResult.comment_note`. Add constants for the watch or comments URL, the labels, and the distractor labels.
3. Add `_post_and_pin_comment(page, video, video_id, text, on_progress) -> str`. It writes state, catches `Exception`, returns a note, and never raises.
4. Call it from `upload_one` after the `STATE_PUBLISHED` write, only when `request.comment.strip()` is non-empty and `comment_status` is not `posted`.
5. `tab_video._upload_request`: pass `comment=` (empty when disabled) and only for visibilities in the set from 4a.
6. `gui/workers.py`: show `comment_note` warnings in the finished summary.

## 4. Test plan (`tests/test_youtube_upload.py`)

- Add `_FakeCommentPage` in the style of `_FakeStudioPage`. It has labelled Post ("Bình luận" / "Comment") and Pin ("Ghim" / "Pin") buttons, and distractors "Bỏ ghim" / "Unpin" that a substring match on "Ghim" would catch. It records each click label.
- Cases, asserting exact click lists:
  - Empty text: no navigation, no clicks, no comment keys in state.
  - Success: clicks are exactly [Post, Pin]. State has `posted` and `pinned`.
  - Post fails: `STATE_PUBLISHED` is kept, `comment_note` is set, no exception.
  - Pin fails: `posted` is set, and a re-run does not click Post again.
  - Re-run with `pinned` set: no clicks.
  - `posting` without `posted` (simulated crash): no re-post, warning shown.
  - `_finish` raises: no comment attempted.
  - Browser closed mid-step: caught, note set.

## 5. Live probe (user runs it; throwaway video on their own channel)

- Pass 1, read-only: open the watch page and the Studio comments page. Log `count()`, text, tag and bounding box for the comment box, the submit button, the per-comment menu, and any Pin or Unpin items. Click nothing.
- Pass 2: post and pin one comment by hand, then log the same candidates. Also record whether comments are disabled on the video (this happens for made-for-kids settings).
- Use the results to set the final selectors and labels.
