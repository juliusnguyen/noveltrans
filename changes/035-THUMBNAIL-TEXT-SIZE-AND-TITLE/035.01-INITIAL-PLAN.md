# 035 — Adjustable thumbnail text sizes + an editable display title — PLAN

## Design decisions

| Decision | Rationale |
| --- | --- |
| **Sizes are multipliers on today's fractions, not absolute sizes.** `1.0` reproduces the current look pixel-for-pixel. | Every existing project keeps rendering exactly as it does now, with no migration and no surprise re-render. That matters more than usual right now: 034 just shipped a button that pushes covers onto already-published videos, so a silent layout change would propagate to a live channel on the next click. |
| **Three independent multipliers** (title / `PHẦN N` / tagline), clamped 0.5–2.0. | What the user asked for. The clamp is what keeps the result a thumbnail: below ~0.5 the text is unreadable at YouTube's grid size, above ~2.0 the title wraps past the frame. |
| **Stroke widths and glow radii are left deriving from the pixel size.** | They already are (`round(title_px * 0.06)` etc.), so scaling the size scales the outline for free. Hard-coding them would make a 2.0 title look like a thin sticker. |
| **The tagline keeps its shrink-to-fit loop**, starting from the user's chosen size. | The loop exists so a long tagline never runs off the frame. Setting a size explicitly is a *request*, and "the text I typed is cut off" is worse than "it came out a bit smaller than the slider says". |
| **`display_title` is a new `NovelMeta` field**, not an app-config setting. | It's a property of one novel. In app config it would apply `CHÀO MỪNG…` to every other project in the library. `NovelMeta.from_dict` already filters unknown keys, so old `meta.json` files load unchanged and default to `""`. |
| **One resolver, `NovelMeta.display_name()`**, replacing `meta.translated_title or meta.title` at every *video* call site. | There are ~13 of these. A helper is the only way the override can't be half-applied — the failure mode otherwise is a thumbnail that says one thing and a YouTube title that says another. |
| **The filename slug does NOT use `display_title`.** | `slugify(meta.translated_title or meta.title)` decides `video_dir/<stem>/<stem>.mp4` and every sidecar beside it, including `<stem>.upload.json`. Changing the display title would move all of them: rendered parts would read as "chưa tạo", and 034's upload records would orphan — the app would offer to re-upload videos already on the channel. The slug stays keyed to the translated/original title, with a comment at each site saying why. |
| **Exporters (EPUB/DOCX/Markdown) are unchanged.** | The ask is the video pipeline. An ebook's title page wanting the `[ĐM/EDIT]` tag stripped is a separate question with a separate answer. |

## Implementation

### 1. `src/noveltrans/models.py`

```python
display_title: str = ""   # overrides the title on video/thumbnail output only

def display_name(self) -> str:
    """The novel title as it should appear on a video, thumbnail and description.

    `display_title` is the user's override — the point is stripping a source tag like
    `[ĐM/EDIT]` without touching the scraped metadata. Falls back to the translated
    title, then the original.

    NOT for filenames: the slug is keyed to the translated/original title so that
    editing this never moves a rendered part or orphans its `.upload.json`.
    """
    return (self.display_title or self.translated_title or self.title or "").strip()
```

### 2. `src/noveltrans/storage/project.py`

`save_display_title(title)` — the same three-line meta.json merge as `save_tags`.

### 3. `src/noveltrans/tts/thumbnail.py`

- `DEFAULT_TITLE_SCALE = DEFAULT_PART_SCALE = DEFAULT_TAGLINE_SCALE = 1.0`;
  `MIN_TEXT_SCALE = 0.5`, `MAX_TEXT_SCALE = 2.0`.
- `_scaled_px(base_px, scale)` — clamps and floors at 8 px so a bad value can't produce a
  zero-size font (Pillow raises) or an invisible one.
- `compose_thumbnail(..., title_scale=1.0, part_scale=1.0, tagline_scale=1.0)` and the
  same three on `render_thumbnail`.

### 4. `src/noveltrans/config.py`

`video_thumbnail_title_scale` / `_part_scale` / `_tagline_scale`, clamped on both read and
write like the existing `_pos` properties.

### 5. `src/noveltrans/gui/thumbnail_editor.py`

Three live sliders (50–200 %) under the existing position sliders, each with a `%` readout.
The existing "Đặt lại vị trí" becomes "Đặt lại" and resets sizes too. Saved in
`_save_to_config`.

### 6. Threading through

`gui/tab_video.py` (`_render_thumbnail_now`, `_launch_video`, the preview path) →
`gui/workers.py` (`VideoWorker`, `ThumbnailWorker` if present) → `tts/video.py` →
`render_thumbnail`, exactly as `thumb_title_pos` / `thumb_part_pos` already do.

### 7. The display-title field

A "Tên hiển thị" `QLineEdit` in the Video tab's metadata area, seeded from
`meta.display_name()`, saved on edit via `save_display_title`. Placeholder shows the
current fallback so an empty box reads as "dùng tên gốc", not "no title".

A hint line stating what a change does *not* do: covers already on YouTube need
"🖼️ Cập nhật ảnh bìa" (034), and the title of a published video can't be changed from
this app at all.

## Test plan

**`tests/test_thumbnail.py`** — `title_scale=1.0` is byte-identical to no argument (the
no-migration guarantee); a larger scale produces more/taller wrapped lines; scales clamp at
0.5/2.0; a 0 or negative scale still renders; the tagline still shrinks to fit when its
scaled size would overflow.

**`tests/test_models.py`** — `display_name()` precedence (override → translated → original);
an old `meta.json` without the key loads and returns the translated title; whitespace-only
override falls through.

**`tests/test_tab_video.py`** — the slug is unchanged when `display_title` is set (the
regression that would orphan every upload record); the video title, description and
thumbnail all use the override; the editor's sliders round-trip through config.

## Risks

1. **The slug/display-title split is the whole risk of this feature.** One call site
   switched to `display_name()` by mistake and a project's rendered parts vanish from the
   table while its upload records point at files that no longer exist. Pinned by a test.
2. A large title scale can wrap past the bottom of the frame. The editor previews live, so
   it's visible before saving; not clamped further, because a two-line title at 1.6 is a
   legitimate look.
3. Existing thumbnails don't re-render on their own. Deliberate — but it means a size
   change looks like nothing happened until "Tạo lại tất cả ảnh bìa", which the status
   line should keep saying.
