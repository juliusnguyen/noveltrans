# 035 — Adjustable thumbnail text sizes + an editable display title

## The ask

> - support adjust the size of text in thumbnail
> - support adjust the title of the novel
>   (e.g. from `[ĐM/EDIT] CHÀO MỪNG ĐẾN VỚI PHÒNG LIVESTREAM ÁC MỘNG`
>    to `CHÀO MỪNG ĐẾN VỚI PHÒNG LIVESTREAM ÁC MỘNG`)

## Settled scope

- **Text sizes**: all three thumbnail texts get their **own** size control — the novel
  title, `PHẦN N`, and the tagline. Adjustable live in the cover editor
  (`gui/thumbnail_editor.py`), persisted like the existing position settings.
- **Display title**: one editable "tên hiển thị" per project, used **everywhere the
  novel title is used** — the thumbnail, the YouTube video title (`"{tên} - Phần {N}"`),
  and the description. One place to fix it; the source `[ĐM/EDIT]` tag stays untouched
  in the scraped metadata.

## What exists today

`tts/thumbnail.py` hard-codes every text size as a fraction of the frame height:

| text | size | where |
| --- | --- | --- |
| novel title | `round(H * 0.11)` | `compose_thumbnail`, wrapped by `_wrap_title` |
| `PHẦN N` | `round(H * 0.15)` | `compose_thumbnail` |
| tagline | `round(H * 0.055)` | shrinks in a loop until it fits one line |

Stroke widths and glow radii are derived from those sizes, so a size control has to carry
them along or the outline stops scaling with the text.

Positions are already adjustable and show the pattern to copy end-to-end:
`DEFAULT_TITLE_POS` / `DEFAULT_PART_POS` in `tts/thumbnail.py` → `video_thumbnail_title_pos`
/ `video_thumbnail_part_pos` in `config.py` (clamped, with defaults) → sliders and a
draggable preview in `gui/thumbnail_editor.py` → threaded through `gui/tab_video.py` and
`VideoWorker` into `render_thumbnail`.

The title currently comes from `project.meta.translated_title or project.meta.title` at
every call site (`tab_video.py`, `tts/video.py`, `build_upload_title`), which is why an
override needs one storage location rather than a fix at each site.

## Open questions for `/plan`

- Where the display title is stored: `NovelMeta` (travels with the project, like
  `translated_title`) vs. app config (would wrongly apply to every novel). Whether it
  needs a "gợi ý: bỏ `[ĐM/EDIT]`" affordance or just a text box seeded with the current
  title.
- Whether the size control is a multiplier on the existing fraction (`1.0` = today's
  look) or an absolute fraction of `H`. The multiplier keeps existing projects
  pixel-identical by default, which matters — 034 just shipped a button that pushes
  covers to already-published videos.
- Whether the tagline's existing shrink-to-fit loop still applies once the user sets a
  size explicitly, and what the title does when a larger size makes it wrap past the
  bottom of the frame.
- Re-rendering: covers already on YouTube don't change until "🖼️ Cập nhật ảnh bìa" (034)
  is pressed, and the video title of a published video isn't editable from this app at
  all — say so where it matters rather than implying a title edit propagates.

## Out of scope

- The video render itself (`tts/video.py` frame composition) beyond passing the new
  values through.
- Retitling videos already on YouTube.
