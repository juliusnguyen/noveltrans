# 035 — THUMBNAIL TEXT SIZE AND TITLE — history

## [DECISIONS] — 2026-07-28

Settled with the user before planning:

- **Text sizes**: all three thumbnail texts get their own control — the novel title,
  `PHẦN N`, and the tagline.
- **Display title**: applies **everywhere the novel title is used** in the video
  pipeline — thumbnail, video title, description — not just the cover.

## [PLAN] 035.01-INITIAL-PLAN — 2026-07-28

Generated plan: `035.01-INITIAL-PLAN.md`. Key calls:

- Sizes are **multipliers** on the existing fractions, not absolute sizes, so `1.0`
  reproduces the current layout pixel-for-pixel and nothing re-renders differently.
  That matters more than usual: 034 just shipped a button that pushes covers onto
  already-published videos, so a silent layout change would reach a live channel.
- `display_title` is a `NovelMeta` field (per novel), not app config (would apply to
  every novel in the library), resolved by one helper `NovelMeta.display_name()`.
- **The filename slug does NOT use it** — see the KNOWN RISK section below.

## [IMPLEMENTATION] — 2026-07-28

903 tests pass (874 before, +29), ruff clean.

### Text sizes

- `tts/thumbnail.py` — `DEFAULT_TEXT_SCALE` / `MIN_TEXT_SCALE` / `MAX_TEXT_SCALE`
  (1.0 / 0.5 / 2.0), the `_TITLE_/_PART_/_TAGLINE_FRACTION` constants that were inline
  magic numbers, and `_scaled_px()` which clamps and floors at 8 px. `compose_thumbnail`
  and `render_thumbnail` take `title_scale` / `part_scale` / `tagline_scale`.
  Stroke widths and glow radii already derive from the pixel size, so outlines scale for
  free. The tagline keeps its shrink-to-fit loop, now starting from the chosen size.
- `config.py` — three clamped properties, clamped on **read** as well as write.
- `gui/thumbnail_editor.py` — three live sliders with `%` readouts, whose range is the
  renderer's own clamp (so the slider cannot ask for a size the renderer would refuse).
  "Đặt lại vị trí" became "Đặt lại" and now resets sizes too.
- Threaded through `tab_video.py` → `VideoWorker` → `render_thumbnail`, following the
  existing `thumb_title_pos` / `thumb_part_pos` path exactly.

### Display title

- `models.py` — `display_title: str = ""` plus `NovelMeta.display_name()`.
- `storage/project.py` — `save_display_title()`, the same meta.json merge as `save_tags`.
- `gui/tab_video.py` — a "Tên hiển thị" box at the top of the thumbnail/metadata group,
  seeded from meta with the current fallback as its **placeholder**, so an empty box
  reads as "dùng tên đã dịch" rather than "there is no title".
- All 8 video-pipeline title sites switched to `display_name()`; the 3 slug sites left
  alone with a comment saying why.

### Found while building

**A whitespace-only override blanked the title everywhere.** `display_title or
translated_title` — `"   "` is truthy, so it won the fallback chain and then stripped to
`""`, giving every video, cover and description an empty title. Now each candidate is
stripped *before* the fallback. Caught by
`test_a_blank_override_falls_through_rather_than_blanking_the_title`.

### KNOWN RISK — the slug/display-title split

`slugify(meta.translated_title or meta.title)` decides `video_dir/<stem>/<stem>.mp4` and
every sidecar beside it, **including the `<stem>.upload.json` feature 034 uses to know
what is already on YouTube**. Deriving it from `display_name()` would move all of them
the moment someone edits the display title: rendered parts would read as "chưa tạo", and
the app would offer to re-upload videos already live on the channel.

Three call sites carry an explicit comment (`tab_video.py:474`, `workers.py:843`, `:1000`).
Pinned by two tests — one at the storage layer, one end-to-end through the Video tab
(`test_the_slug_and_therefore_every_rendered_part_stays_put`) which renders a part,
records an upload, edits the title, and asserts the path, the upload record and the
"✅ Đã tạo" status all survive.

### Not done, deliberately

- Exporters (EPUB/DOCX/Markdown) still use `translated_title`. The ask was the video
  pipeline; an ebook title page is a separate question.
- Covers already on disk don't redraw on their own, and a published video's YouTube title
  can't be changed from this app at all. Both are stated in the field's tooltip, and the
  status line after an edit points at "Tạo lại tất cả ảnh bìa".
