# 070.01 — Initial plan: timotxt.com scraper adapter

## Summary

One new module `src/noveltrans/scrapers/timotxt.py`, one line in `_import_adapters()`, one
test module, one fixture directory, one README row. No change to `SiteAdapter`, no model
change, no new dependency, no browser, no cookies.

`sto9.py` is the right structural template (pinned `ORIGIN`, `book_id`/`read_url` helpers, a
`parse_*` line below which everything is pure, policy in `fetch_chapter_list`, `_status` for
anything non-fatal). It is the **wrong** template for two things: its `<br>`-splitting
`parse_chapter` (`sto9.py:213-236`) and its `meta[property='og:…']` reader
(`sto9.py:124-126`).

## ⚠️ What the survey missed entirely — the hardest part of this feature

**Chapter bodies are character-obfuscated. Roughly 2–5 % of characters are replaced with
visually-similar Hangul syllables (U+AC00–U+D7A3), server-side, with a different random
subset substituted on every request.**

Independently verified on `https://www.timotxt.com/2608569069/1.html`:

- Two fetches minutes apart: 117 paragraphs each, **identical paragraph lengths**, different
  text. 65 vs 64 Hangul characters — different subsets.
- **26 mappings recovered from one pair with zero conflicts.** Across 6 chapters × 2 fetches
  the plan agent recovered 88 distinct mappings, also with zero conflicts: **the table is
  fixed, only its application is random.**
- **Not a webfont** — no `@font-face`, no `.woff`/`.ttf` on the page. The corruption is in the
  delivered text; no browser renders it correctly either.
- Not avoidable: `www.` vs bare host, desktop vs iPhone UA all obfuscate. `m.timotxt.com`
  does not resolve.
- **Chapter titles and the description are NOT obfuscated** (`/dir` titles byte-identical
  across fetches, 0 Hangul; `div.intro` 0 Hangul). Bodies only.

Shipping raw would put 60–120 corrupt characters into every chapter — which the translator
renders as garbage and TTS reads aloud as Korean. §5 is the design. **This is the feature's
real risk surface, not the TOC.**

## Design decisions

### 2. The truncation guard

**Always fetch `/dir`; never parse the landing page for chapters — not even as a fallback;
validate `/dir` against a self-contained contiguity invariant.**

sto9 raises rather than falling back (`sto9.py:303-308`) because `ChapterRef.index` is dense
and positional and `replace_toc` upserts by `idx` preserving content. All of that applies
here **more sharply**: sto9's truncated page at least starts at chapter 1, whereas timotxt's
landing block is 12 chapters **newest-first** plus a `開始閱讀` link. Accepting it would put
chapter 376 at `index=1` and chapter 1 at `index=0` — the worst possible corruption of a
positional key.

sto9 keeps one legitimate page-fallback branch (`sto9.py:310-314`) for short novels with no
`LoadMore` button. **timotxt has no equivalent safe case and therefore no fallback branch at
all**: `/dir` is a static path that exists for every novel, and the landing block is always
the 12-newest excerpt regardless of length. If `/dir` is unreachable, `HttpClient._request`
already raises `ScrapeError` (`base.py:67`) — let it propagate.

**Three cross-check signals, all verified:**

1. **`/dir` internal contiguity — self-contained and load-bearing.** Chapter URLs embed `n`.
   Measured on `ul.all`: 376 links, min=1, max=376, ascending, and
   `numbers == list(range(1, 377))` is `True`. Any realistic degradation breaks it: losing
   `ul.all` leaves `[365…376]` ≠ `[1…12]` → refused; a dropped middle → gap → refused.
   **Stronger than sto9's guard**, whose `data-num` is display metadata where here the
   ordering key is in the URL itself.
2. **`og:novel:latest_chapter_url`** → `…/376.html` → 376.
3. **`og:novel:latest_chapter_name`** → `第(\d+)章` → 376.

Signals 2–3 live on the landing page, not `/dir`. The landing page is already cached for
`fetch_metadata`, so in the normal `ScanWorker` order (`workers.py:108-109`) it is free.

```
dir_markup = client.get_html(dir_url(url))           # always; landing never consulted
refs = parse_chapter_list(dir_markup, dir_url(url))  # raises if no anchors
if chapter_numbers(refs) != list(range(1, len(refs) + 1)):
    raise ScrapeError(...)                            # gappy / recent-only → refuse
total = stated_total(self._landing_page(url))         # cached; may be None
if total is not None and len(refs) < total:
    self._status(f"⚠️ timotxt chỉ trả về {len(refs)}/{total} chương. Quét lại sau.")
return refs
```

**Warn rather than raise on the short-but-contiguous case** — same reasoning as
`sto9.py:294-300`: a contiguous run `1…N` is a *prefix*, so `replace_toc` merely extends it.
Nothing can be misfiled.

**If the cross-check is unavailable** (landing 404s, og tags dropped): **proceed on
contiguity alone, do not raise.** The invariant is a proof that the list is a dense prefix
from chapter 1 — precisely the property `ChapterRef.index` needs. `stated_total` upgrades
"prefix" to "complete"; it is not a safety requirement. Wrap the landing fetch in
`try/except ScrapeError`.

### 3. The duplicate block

**Select `div.chaplist ul.all`, with de-duplication-by-number as the fallback — the
contiguity check is what makes the fallback safe.**

Measured on `/dir`:

```
div.chaplist > ul.flex.one.two-700.three-900        →  12 links, DESCENDING 376→365   ← FIRST
div.chaplist > ul.flex.one.two-700.three-900.all    → 376 links, ascending 1→376
```

The recent block is **first in document order**. A flat scrape gives a list whose first 12
entries are the *last* 12 chapters reversed — every `index` after that off by 12 and the
first dozen catastrophically wrong. Fixing the count without fixing the order would not save
it.

`flex one two-700 three-900` is a CSS-grid breakpoint vocabulary — incidental, exactly what a
theme refresh rewrites. `all` and `chaplist` are the only semantic tokens. So select
`div.chaplist ul.all a[href]`, not the full class chain; fall back to every anchor matching
`/<id>/<n>.html`, **de-duplicated by `n`** (the `bookqq.py:344-347` shape) and **sorted by
`n`, never document order**. Both paths then face the contiguity check:

- normal page → 376 ascending;
- `all` renamed by a CSS refresh → fallback dedupes 388 → 376 ascending → accepted;
- the `all` block genuinely gone → 12 refs numbered 365–376 → **refused**.

That last line is why the fallback is not a hole in §2.

### 4. Chapter body extraction

**`SEL_CONTENT = "#chapterWarp div.content"`; decompose named ad chrome; take *direct-child*
`<p>` only.**

Scoping to `div.content` drops the breadcrumb and `h1` structurally rather than by naming
them. `div.content` alone is far too generic, hence anchoring under `#chapterWarp`.

```python
SEL_CHROME = "div.gadBlock, div.adUnit, ins, script, style, iframe"
for el in container.select(SEL_CHROME):
    el.decompose()
lines = [p.get_text(strip=True) for p in container.find_all("p", recursive=False)]
lines = [line for line in lines if line]
if not lines:                                   # markup changed and nested the prose
    lines = [line for line in (p.get_text(strip=True) for p in container.select("p")) if line]
```

`recursive=False` is the interesting choice: it handles the **unclassed notice `<div>`**,
which no class-based rule can name. On this markup "a direct-child `<p>` of `div.content`"
*is* the definition of a prose paragraph — 117/117 measured — so a CSS refresh cannot defeat
it. Its one failure mode is the CMS wrapping real prose in a `<div>` (what `sto9.py:70-73`
warns blanket rules about), and the recursive fallback covers exactly that: one junk 溫馨提示
line beats an empty chapter. Same asymmetry `translators/ads.py` argues.

Then drop **at most one** leading line equal to the chapter title (`sto9.py:231-233`,
`bookqq.py:418-420`). Join with `"\n\n"`. Distinct errors for a missing container
("Chapter content not found") vs an empty result ("Chapter content is empty") — they need
different fixes, and `test_scrapers_sto9.py:215-225` pins why neither may return `""`.

**Indents:** nothing to do — 0 `&emsp;`, 0 U+2003. Do not copy sto9's commentary; a comment
about a thing this site does not do is a trap for the next reader.

**On `translators/ads.py` (069): separate, and neither substitutes for the other.** `ads.py`
runs on fresh *translator output*, targeting a promotional line whose wording is model
output; this adapter strips *structurally at scrape time* on DOM nodes. If timotxt ever
watermarks chapters with a promo line inside `div.content` as a real `<p>`, this adapter
would correctly keep it as prose and `ads.py` would catch it after translation. Say so in the
docstring so nobody merges the jobs.

### 5. Character de-obfuscation

**Ship a fixed Hangul→Han table in `timotxt.py`, applied to chapter bodies only. Never raise
on residue; warn.**

| Option | Verdict |
|---|---|
| Ship raw | ✗ 60–120 corrupt chars per chapter into `content`, the translator, TTS, EPUB, video. `save_content` marks the row downloaded, so it is permanent and silent — the exact failure class these scrapers exist to prevent. |
| Always raise `ObfuscatedContentError` | ✗ Refuses the ask for a page 95–98 % clean. `errors.py:16` reserves it for content that *cannot* be decoded; this can. |
| Two-fetch positional merge at runtime | ✗ Doubles requests (376 → 752) **and** still leaves residue: with two independent draws a char stays garbled with probability p² — measured ~40 chars garbled in both. Half the problem at double the cost. Useful as the offline table-builder, not the runtime path. |
| **Static table** ✅ | Zero extra requests, deterministic, fixture-testable, and **degrades to "ship raw" for unmapped glyphs — its worst case equals the do-nothing baseline.** |

**Building the table:** `scripts/build_timotxt_table.py` (same family as
`scripts/capture_69shuba.py`), fetching sampled chapters twice, aligning `div.content`
paragraphs positionally, unioning pairs, asserting no conflicts. Sample ~30–40 chapters plus
a second novel to confirm the table is site-wide, not per-novel. Output pasted into the
module with a provenance comment naming the date, novels and method.

Properties to document and pin:

- **Only Hangul syllables are keys** — nothing Chinese, Latin or punctuation can be touched.
  An incomplete table under-corrects; it can never damage clean prose.
- **1:1, so length and paragraph structure are preserved** — TTS chunking and the exporters
  depend on it.
- **Idempotent**; **never raises**; unmapped Hangul survives verbatim.
- Applied **only to chapter bodies** — titles and description are clean (measured).

**Residue thresholds, deliberately asymmetric:** below `_OBFUSCATION_ALARM_RATIO` (0.20) →
`_status` warning, chapter still saved. At or above → `ObfuscatedContentError`, which can only
mean the scheme changed wholesale (`errors.py:16`, `base.py:139-142`). Observed ratios are
1.8–4.8 %, so 0.20 is ~4× the worst measurement — and unlike the reverted length heuristic
(`twkan.py:53-62`) it measures the thing itself rather than a proxy.

Keep it in `timotxt.py`. One site does this; promoting it later is mechanical, guessing now is
speculative generality.

### 6. Metadata

**Read the `<meta name="og:…">` tags; do not regex `<title>`.** Write the accessor to take
either attribute so the day the site fixes its markup nothing breaks:

```python
def og(prop: str) -> str:
    el = soup.select_one(f"meta[name='{prop}']") or soup.select_one(f"meta[property='{prop}']")
    return (el.get("content") or "").strip() if el else ""
```

| Field | Source | Fallback |
|---|---|---|
| `title` | `og:novel:book_name` | `h1.title.is-2`, then `<title>` via `《(.+?)》` |
| `author` | `og:novel:author` | `h2.title.is-4` split on `/`, then in-body `作者：`, then `<title>` via `》\((.+?)\)` |
| `description` | `div.intro` (full, 476 chars) | `meta[name=description]` (SEO-truncated with `…` — strictly worse) |
| `cover_url` | `og:image` | `div.bookimg img[src]` |
| `url` | `read_url(url)` — pinned, never the pasted string | — |

Prefer `div.intro` over the meta description: the meta version is truncated at ~100 chars.
This is the one place visible markup beats the meta tag, and the reason belongs in a comment.

Title is the only mandatory field → `ScrapeError("Novel title not found — page layout may
have changed", url)`, the family wording at `sto9.py:133` / `twkan.py:227`. Missing
author/description/cover return `""` and never raise.

No placeholder-cover check — none observed, and `twkan.py:72-76` already argues that
inventing a filename to blank is either dead code or a rule that eats a real cover.

### 7. `matches()` and registration

```python
url_patterns = [r"timotxt\.com/\d+(?:/|$)"]
```

One pattern covers all three forms since `matches()` uses `re.search` (`base.py:118`);
`www.` optional falls out for free. The `(?:/|$)` guard keeps `i1.timotxt.com/thumb/…jpg`
out.

**Order does not matter** — every registered pattern is host-anchored, so none can claim a
timotxt URL and this one cannot claim theirs. That is a genuine hazard here (`sto9.py:247-250`
and `twkan.py:345-349` both document `/txt/\d+/\d+` collisions), so add the rationale as a
comment and a test, but no reordering. Add `timotxt` to the sorted import tuple
(`scrapers/__init__.py:25-36`). **Omitting that line ships silently** — every timotxt URL
would report `Chưa hỗ trợ trang web này` (`workers.py:101-103`).

## Risks / out of scope

**Risks**

1. **The table is empirical and incomplete by construction.** Mitigated by the
   under-correct-only design (worst case = shipping raw), the residue warning, and the live
   drift test. Accepted.
2. **The table could change.** A wholesale rotation is the one failure mode that *corrupts*
   rather than leaves corrupt. Mitigated by `_OBFUSCATION_ALARM_RATIO` (a rotation drives
   unmapped Hangul up) plus the live test. Worth an explicit docstring warning.
3. **The two-fetch merge was rejected** in favour of the table; it remains the documented
   escalation and composes with the table rather than replacing it.
4. **`div.content` is generic.** Anchored under `#chapterWarp` it is unambiguous today; a
   theme change renaming `#chapterWarp` breaks extraction **loudly**, which is the right
   direction.
5. **`_CHAPTER_HREF_RE` assumes `n` is the reading position.** Verified contiguous on the
   reference novel; a novel with volume/extra chapters could number differently, in which case
   contiguity refuses a legitimate list — the accepted false-positive direction (refuse rather
   than misfile). Spot-check a second novel during implementation.
6. **`/dir` was not observed paginated** (376 links, 34 KB). A 5000-chapter novel might
   paginate; contiguity catches it as a gap or a prefix, and the prefix case warns.

**Out of scope** — no change to `SiteAdapter`, `HttpClient`, `models.py`, `errors.py`, storage
or any worker (`ScanWorker` already looks projects up by both pasted and canonical URL,
`workers.py:113-122`); no change to `translators/ads.py`; no browser/cookie support; no
encoding work (correct charset header, so `base.py:85-87`'s fixup never fires); no
search/browse; `scripts/build_timotxt_table.py` is a build tool, not a shipped path.
