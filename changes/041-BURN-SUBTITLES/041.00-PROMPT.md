# 041 — An option to burn the narration subtitles into the video

## The ask

> can you have an option to burned in when generate the video?

Feature 040 writes a `.srt` sidecar timed from the TTS run, but the video itself still
burns only the novel/chapter titles. This adds a checkbox to burn the narration in too.

## Why it's cheap here

Measured last turn: **+1.4 % encode time, +25 % file size**. The video already runs a
`subtitles=` filter (for the title block) and already encodes full motion (`showfreqs`
spectrum + sliding playhead), so neither the libass pass nor the loss of still-image
compression is a new cost.

## Where it can go without wrecking the layout

`PlayerLayout` (1080p fractions of the frame):

| element | vertical extent |
| --- | --- |
| photo (left) | 6.5 % → 65.8 % |
| visualizer bars (right) | 55.5 % → 66.6 % |
| progress track + playhead | 72 % |
| "now playing" titles | 43.5 % / 48.6 % |

Everything below ~75 % is empty gradient across the full width — the natural home for
bottom-centre subtitles, and it clears both the photo and the track.

## Open questions for `/plan`

- Style and placement: ASS alignment, margins, font size, and how many lines a cue may
  occupy before it starts climbing into the progress track.
- Whether it reuses feature 040's cues (it must — re-deriving timings would be a second
  source of truth that can disagree with the `.srt`).
- What happens when the option is on but the part's audio predates 040 and has no cues.
- Whether the setting is per-render or persisted, and where the checkbox lives.

## Out of scope

- Changing the `.srt` sidecar or the title block.
- Styling controls for the burned subtitles (font/colour/size pickers).
