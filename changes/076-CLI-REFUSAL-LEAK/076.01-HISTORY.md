# 076 — CLI translator: a refusal is saved as the chapter TITLE — History

## [INVESTIGATION] Root cause found — 2026-09-03

No source files changed yet. This entry records the diagnosis so the fix is not
built on the reported symptom, which pointed at the wrong half of the pipeline.

**The report said the refusal was in the chapter body. It is in the title.**

Read directly from the reporting novel's DB (`novel-9d42408b`, `idx` 127, the row
the UI shows as chapter 128):

- `title` = `第127章` — a bare chapter number, no title text at all
- `translated_title` = the 177-character refusal
- `content` = 5206 chars, `translated` = 18189 chars — the body translated fine

The refusal appears first on screen only because the title renders above the body.

`Translator.translate_chapter` (`base.py`) sends the title through
`_translate_with_retry` using the **same prompt written for a chapter body**.
Handed `第127章` — six characters, no prose — the model reads it as the heading of
a chapter whose content was omitted and asks for the content. That reply is
returned as the "translation" and stored.

The obvious hypothesis was an empty chunk in a long chapter. It is wrong:
`max_chunk_chars = 8000` and the content is 5206, so this chapter is a single chunk.

**Scope, measured across every project in the library** (not estimated):

- 10 bad titles across 3 novels; **0 bad bodies anywhere**. Title-only.
- 8 of them in `novel-9d42408b` at `idx` 90, 91, 96, 102, 104, 106, 107, 127 —
  every one with a bare `第N章` source title, every one `CLI (claude, sonnet)`.
- The other 2 grep hits are **false positives**: correct translations that contain
  "Xin lỗi" because the source title contains `對不起`. Any detector must not flag
  these, so a bare "does the output contain an apology" test is disqualified.

**Why the three existing defences all missed it:**

1. `_PROMPT` in `cli_agent.py` already carries "NEVER ask for more text and NEVER
   remark that content seems missing". A prompt-only fix has already been tried
   and is demonstrably not enough.
2. `_translate_with_retry` retries only when `cjk_count(result) > 0`. The refusal
   is pure Vietnamese, so it scores 0 and is accepted on the first attempt.
3. `CliAgentTranslator.complete` does block one refusal — Google's policy message —
   but that check is a fixed marker list and does not generalise.

**Adjacent, distinct, not this feature:** `novel-b1033b5d` `idx` 5 and 196 have a
`translated_title` holding a title, a newline, then body prose — the model returned
title *and* content in the title slot. A different leak from the same root design
(one prompt for two very different inputs). Noted here so it is not mistaken for a
regression later.

## [INVESTIGATION] Threshold measured against the whole library — 2026-09-03

The user chose all three prevention layers plus auto-repair. Before writing the plan I
measured the detector against every translated title in the library rather than guessing a
threshold.

**Title shapes (survey of all 14 projects):**

- 139 bare `第N章` titles — a chapter number with no title text — and **all 139 are in
  `novel-9d42408b`**, the reporting novel. No other novel has any.
- **0 bare Chinese-numeral titles** anywhere, so converting `第四十二章` → 42 is not needed:
  `novel-b1033b5d` uses Chinese numerals but always *with* title text (`第一章 ：獨孤九劍`),
  which goes to the model normally.
- Shapes the numeric matcher must not break: `第001章 撿個破盆` (zero-padded),
  `第1 章 穿書畜生` (space before 章), `第1章 第 1 章 師尊…` (doubled numbering),
  and `作品相關` (front matter, not a chapter).

Only 8 of those 139 bare titles produced a refusal — about 6%, non-deterministic. That is
precisely why the fix has to be structural and not another sentence in the prompt.

**Expansion ratio, over 4323 known-good translated titles:**

| percentile | `len(out) / len(src)` |
|---|---|
| p50 | 1.68 |
| p90 | 3.52 |
| p99 | 4.38 |
| p99.9 | 5.91 |

Excluding the leaks, nothing legitimate exceeds 5.91. A threshold of 6 therefore sits
outside 4319 real examples.

**Rule tested — `"\n" in out` OR (`len(out) > 60` AND `len(out) > 6 * len(src)`):**

Run over all 4331 translated titles in the library it flags **14, with zero false
positives**:

- **10 refusals**, every one in `novel-9d42408b`: `idx` 90, 91, 96, 102, 104, 106, 107,
  **111**, **121**, 127.
- **4 title+body leaks** where the model returned the title, a newline, then prose:
  `novel-b1033b5d` `idx` 5, 195, 196 and `novel-de19ca5c` `idx` 53.

Two findings that change the design:

1. The earlier phrase-grep found only 8 refusals. The structural rule finds **10** — `idx`
   111 ("Bạn vui lòng gửi nội dung chương 111 …") and `idx` 121 ("Không có nội dung văn bản
   nào được cung cấp ngoài tiêu đề …") are phrased in ways no marker list anticipated. So
   the sanity check is the **primary** defence and phrase-matching is the secondary net,
   not the other way round.
2. The two earlier phrase-grep hits in `novel-6804a918` and `novel-b1033b5d` were false
   positives — correct translations of `對不起`. The structural rule does not flag them,
   which is the behaviour to lock in with a test.

Corrected scope: **14 damaged titles, 0 damaged bodies.**

## [IMPL] Three guards plus a one-time repair — 2026-09-03

Implemented the plan as written. The fix is at the ABC, not in `cli_agent.py` where the
symptom was reported: `translate_chapter` is the defect, so every engine inherits the fix.

### `src/noveltrans/chapter_titles.py` (new)

Pure predicates — no Qt, no sqlite, no subprocess. Top level rather than under
`translators/` because `storage.project` needs two of them for the repair and must not
depend on the translator package; the same reasoning already places `rename.py`,
`find_replace.py` and `name_glossary.py` here.

- `numeric_title(source, target)` — `"Chương N"` when the source is only a chapter number.
  The regex requires nothing but whitespace/punctuation around `第 N 章`, so every library
  shape carrying real text (`第001章 撿個破盆`, `第1 章 穿書畜生`, `第1章 第 1 章 師尊…`,
  `第一章 ：獨孤九劍`, `作品相關`) still reaches the model.
- `is_implausible_title(source, output)` — the primary detector. Both thresholds carry the
  percentile they came from as a comment so a later reader re-derives rather than nudges.
- `looks_like_refusal(text)` — secondary, for bodies. Requires a verb of giving **and** a
  word for the thing asked for, and scans only the opening 400 chars: a long body
  eventually contains ordinary narration about handing something over.
- `repaired_title(source, stored, target)` — shared by the translator and the migration, so
  translate-time and repair-time cannot disagree about what a damaged title becomes.

No Chinese-numeral converter. Measured: zero bare Chinese-numeral titles exist in the
library, so it would have been code with no caller.

### `src/noveltrans/translators/base.py`

- New `Translator._safe_title`. Numeric shortcut first (prevents every observed case and
  saves one engine call per chapter on novels numbered that way), then translate + check +
  one retry, then fall back.
- **It swallows `TranslateError` deliberately.** `translate_chapter` does the title first
  and the body immediately after, so a genuinely dead engine is still reported — by the
  body call, with its real message. Swallowing here hides nothing and stops a title problem
  from masquerading as a chapter failure. A title is not worth losing a body over.
- `_translate_with_retry` now treats a refusal like leftover CJK: another attempt, and
  never recorded as `best`. Scored **before** the CJK check, because a refusal is pure
  Vietnamese — `cjk_count` returns 0 and would have accepted it outright, which is exactly
  how the ten damaged titles were written.

### `src/noveltrans/storage/project.py`

`_repair_translated_titles`, called from `_migrate`, gated on `PRAGMA user_version`
(previously unused — 0 in every project in the library, so free to claim). One-time per
novel; afterwards it costs a single PRAGMA read. `translated` is never touched and no
engine, key or network is needed. A row it cannot repair confidently is left visible rather
than guessed at.

### `src/noveltrans/translators/cli_agent.py`

One sentence naming the bare-heading case, marked in a comment as a nicety rather than the
fix — the two sentences above it already said "NEVER ask for more text" and were ignored 8
times in 139 chapters.

### Tests — 69 new

- `tests/test_chapter_titles.py` (46) — every fixture is a real string from the library.
  Both `對不起` false positives are asserted as must-not-flag in two separate layers.
- `tests/test_translate_title_guard.py` (12) — stub engines against the ABC: the numeric
  shortcut never calls the engine, an implausible reply retries then falls back, a hopeless
  title never costs the body, and a body that only ever refuses fails loudly.
- `tests/test_project_migrate_titles.py` (11) — each damaged shape, the apology false
  positive, body integrity, target-language handling, and the once-only guard (damage
  introduced *after* the pass stays put — this is a historical repair, not a permanent
  sanitiser that would keep rewriting hand-edited rows).
