# 076 — CLI translator: a refusal is saved as the chapter TITLE — Implementation Plan

Diagnosis and measurements are in `076.01-HISTORY.md`; this plan does not repeat them.
Confirmed scope: **14 damaged titles, 0 damaged bodies**, across 3 novels.

## 1. Where the defect is

`Translator.translate_chapter` (`base.py:104`) sends the chapter title through
`_translate_with_retry` using the prompt written for a chapter *body*:

```python
translated_title = self._translate_with_retry(title, source, target) if title else ""
```

For a bare `第127章` that prompt asks the model to translate a web-novel passage that
isn't there, and the model answers by asking for it. Nothing downstream can tell that
reply apart from a translation, so it is saved.

This is engine-agnostic — it is the ABC, so every fix placed here covers CLI, Claude API,
LM Studio and Google at once. `cli_agent.py` is where the symptom was seen, but it is the
wrong place to fix it.

## 2. New module — `src/noveltrans/chapter_titles.py`

Pure text predicates: no Qt, no sqlite, no subprocess. Top-level rather than under
`translators/` because `storage/project.py` needs it for the repair and must not depend on
the translator package — the same reasoning that already puts `rename.py`,
`find_replace.py` and `name_glossary.py` at the top level.

### `numeric_title(source, target="vi") -> str`

`"Chương N"` / `"Chapter N"` when the source carries a chapter number **and nothing else**;
`""` otherwise, meaning "ask the model".

- Matches `第 N 章` with optional spaces and leading zeros, plus surrounding whitespace and
  punctuation, and nothing further.
- Must return `""` for every shape in the library that has real title text:
  `第001章 撿個破盆`, `第1 章 穿書畜生`, `第1章 第 1 章 師尊…`, `第一章 ：獨孤九劍`, `作品相關`.
- No Chinese-numeral conversion. Measured: **0 bare Chinese-numeral titles** exist in the
  library — they always carry title text, so they go to the model as they do today. Adding
  a 四十二 → 42 converter would be code with no caller.
- `"Chương N"` is exactly the form the model already produced for the 131 bare titles that
  *did* work, so a repaired title matches its neighbours instead of standing out.

### `is_implausible_title(source, output) -> bool`

The measured rule:

```python
"\n" in output.strip() or (len(output) > 60 and len(output) > 6 * len(source))
```

Validated against all 4331 translated titles in the library: **14 flagged, 0 false
positives.** The 6× multiplier sits outside 4319 real examples (p99.9 = 5.91); the 60-char
floor keeps a short source with a legitimately chatty translation from tripping it, since
no refusal observed is under 97 characters. The newline branch is what catches the
title+body leak (`novel-b1033b5d` 5/195/196, `novel-de19ca5c` 53) — a title is one line.

Both constants get a comment naming the percentile they came from, so a later reader can
re-derive them rather than nudge them blind.

### `looks_like_refusal(text) -> bool`

The secondary net, for **bodies**, where the ratio test has no equivalent. Matches a
*request for content* — a verb of giving (`cung cấp`, `gửi`, `dán`) near
`nội dung` / `văn bản` — not an apology.

Locking in the near-miss cases as tests:

- **Must flag**, and phrase lists that "look right" miss these two:
  `"Bạn vui lòng gửi nội dung chương 111 …"`, `"Không có nội dung văn bản nào được cung
  cấp ngoài tiêu đề …"`
- **Must not flag**: `"Chương 268: Xin lỗi nhé máy liên lạc tiên sinh"` and
  `"Chương 42: Xin lỗi, biểu tỷ"` — correct translations of `對不起`. A bare "contains an
  apology" test is disqualified by these, and they are the reason this layer is secondary.

## 3. Wiring it into translation

### `base.py` — `translate_chapter`

```python
if title:
    local = numeric_title(title, target)
    translated_title = local or self._safe_title(title, source, target)
```

`_safe_title` runs `_translate_with_retry`, then applies `is_implausible_title`. On a bad
result it retries once, and if that also fails it falls back to `numeric_title(...)` or,
when there is none, to the source title unchanged. **Never raise here**: losing a whole
chapter's body because its title came back odd would be a worse failure than the one being
fixed, and the body is already translated by then.

### `base.py` — `_translate_with_retry`

A body result where `looks_like_refusal(...)` is true is treated exactly like leftover CJK:
retry, keep the best attempt, and only if every attempt refuses raise `TranslateError` so
`TranslateWorker` marks the chapter and moves on. Reuses the existing loop rather than
adding a second one — that loop is already the "the model gave us something wrong" path.

### `cli_agent.py` — `_PROMPT`

Add a line telling the model a bare chapter heading is translated as a heading. Kept
**last** and treated as a nicety, not the fix: the prompt already says "NEVER ask for more
text" and was ignored 8 times in 139 chapters.

## 4. Repair of the 14 damaged titles

In `NovelProject._migrate()`, which every `open()` and `create()` already runs, alongside
`_migrate_downloaded_audio`. Guarded by `PRAGMA user_version` so it is a one-time pass, not
a scan on every open.

For each row with a non-empty `translated_title` where `is_implausible_title(title,
translated_title)`:

- rewrite it to `numeric_title(title, target_lang)` when the source is a bare number
  (the 10 refusals — all of `novel-9d42408b`);
- otherwise take the text **before the first newline** (the 4 title+body leaks: the title
  itself is correct, only the appended prose is not);
- if neither applies, restore the source `title` untouched.

`translated` is never touched — measured: no body in the library is damaged. No
re-translation, so the repair needs no engine configured and no network.

## 5. Tests

- `tests/test_chapter_titles.py` — the three predicates, driven by the real shapes above:
  every bare-title variant, every must-not-break title shape, both `對不起` false
  positives, both phrasing near-misses, and the ratio boundary either side of 6.
- `tests/test_translate_title_guard.py` — `translate_chapter` with a stub engine: a bare
  numeric title never reaches the engine; an implausible reply retries then falls back; a
  normal title is untouched; the body still translates when the title path fails.
- `tests/test_project_migrate_titles.py` — a DB seeded with one row of each damaged shape
  plus a clean row, asserting the repair fixes exactly the damaged ones, leaves
  `translated` alone, and does not run twice.
