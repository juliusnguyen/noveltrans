### The load-bearing piece is the merge rule

**A detection never changes a reading the user edited, and never removes an entry.** Without
it, re-scanning a novel would silently undo the user's own corrections — destroying the one
thing an editable list exists to provide. It has its own test class, and the case where an
unedited entry *does* still follow the table is tested alongside it, because the rule is only
correct if it distinguishes the two.

### A finding worth keeping

`宁` (simplified `寧`) reads **`trữ`** in the app's table — the reading of the unrelated
character simplification merged it with. So the *existing* Google path already produced
`Hạ Trữ Thất` from `夏宁七`. Together with `寧 → ninh`, `檸 → nịnh`, and the model's option of
translating `檸` as *chanh* (lemon), that is **four** reachable spellings for one name, and
only one of them is the user's. This is why direction A alone would not have fixed the report:
it buys consistency, not correctness. Pinned as a test.

Also confirmed: `婳` has no table entry, so `江婳` converts to nothing at all — `to_hanviet`
drops the whole name rather than the one character. That is what `＋ Thêm tên` is for.

### Judgement calls made during implementation

- **First run auto-builds and saves the list.** The dialog is the *correction* path, not the
  *activation* path — requiring a visit would have regressed every existing Google user and
  failed this same user again, just more quietly.
- **A one-syllable rename is never offered as a bulk replace.** Too short to replace blind
  across a novel; it would hit ordinary Vietnamese words. Those fall through to Tìm & thay
  thế, where every match is previewed. Tested.
- **`＋ Thêm tên` shows a live occurrence count.** A hand-typed name is exactly where a typo,
  or the traditional form pasted into a simplified novel, goes unnoticed — and either saves an
  entry that silently never matches. The count says so before the list is saved.
- **The prompt clause was needed.** The engines are told to render names in Hán-Việt and
  "translate every word", so a model meeting an already-correct Latin name may "improve" it.
  One constant-size clause tells it to copy such names exactly. This is not direction C — it
  does not list the glossary per request.
