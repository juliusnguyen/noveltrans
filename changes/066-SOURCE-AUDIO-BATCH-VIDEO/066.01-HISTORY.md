## [PLAN] 066.01-INITIAL-PLAN — 2026-08-27
Generated plan: `066.01-INITIAL-PLAN.md`

Investigated the report ("Chưa tải mục audio nào từ trang nguồn trong phạm vi đã chọn."
when using **Tạo video** with `Audio từ nguồn`). Root cause confirmed in
`VideoWorker.run()` (`gui/workers.py:1635-1667`): the planner chain tests
`mode == "batch"` before `source_audio`, so the default batch mode plans over chapters
filtered by voice `__source_audio__` and finds nothing. Three further findings recorded in
the plan: `_redo_all_videos` plans over chapters directly; the video tab never clears its
`_locked_*` caches on the source-audio path; and `tab_audio._start_merge()` has the same
"preview plans over chapters" bug for "Ghép audio".

## [IMPL] 066.01-INITIAL-PLAN — 2026-08-27

Implemented the whole plan (steps 1-7). All 2579 tests pass; ruff clean.

### Source changes

- **`gui/workers.py`** — `VideoWorker.run()`: hoisted the `source_audio` branch above
  `mode == "batch"`, so the site's audio edition is planned with `plan_source_windows` in
  *every* mode. The old branch (unreachable behind batch) was removed. Comment records why
  the chapter-keyed locks don't apply: a source window is keyed by release ordinal.
  **This is the reported bug.**
- **`gui/tab_video.py`**
  - New `_voice_label()` / `_unit_label()` / `_nothing_selected_message()` helpers so no
    dialog prints `giọng __source_audio__`, counts releases as "chương", or tells a
    source-audio user to go voice some chapters. Applied to the three confirm dialogs
    (`_start_video`, `_redo_all_videos`, `_render_selected_parts`).
  - `_windows_for_current_selection(honor_committed=True)`; its `SOURCE_AUDIO_KEY` branch
    now clears `_locked_part_numbers` / `_locked_committed` / `_locked_manual` (they were
    only ever *written* by `_locked_batch_windows`, so a previous chapter-voice plan leaked
    into the source view — see below).
  - `_locked_batch_windows(..., honor_committed=True)` skips commit discovery when False
    and only writes the caches when True.
  - `_redo_all_videos` now plans via `_windows_for_current_selection(honor_committed=False)`
    instead of a bare `plan_merge_windows`, keeping its explicit "Phạm vi sai" check.
  - Split/merge context-menu entries are hidden for the source edition.
- **`gui/tab_audio.py`** — `_start_merge()` branches on `SOURCE_AUDIO_KEY` the way
  `MergeWorker` already does, with matching message/unit wording.

### Verified by reverting, not by assertion

Each fix was confirmed to be load-bearing by stashing it and re-running:

- Without the `workers.py` reorder: **6 of 8** new `TestSourceAudioBatchVideo` tests fail.
  The two that pass are the ones that should — `mode="all"` already worked, and the cache
  test belongs to the tab fix.
- Without the `tab_video.py` fix: all 3 tab-side tests fail; the cache leak shows up
  concretely as `{1: 1, 3: 2, 5: 3}` (a TTS plan's part numbers) surviving into the
  source-audio view.
- Without the `tab_audio.py` fix: all 3 merge tests fail, the empty case printing
  `giọng __source_audio__`.
- With the **naive** redo-all switch (`honor_committed` defaulted to True):
  `test_redo_all_still_ignores_committed_windows_in_its_count` fails — the dialog says
  "3 phần" where the worker renders 2. The flag is what keeps them in agreement.

### Two findings beyond the reported bug

1. **`_redo_all_videos` under-counted manual splits before this change.** On HEAD the
   dialog says "toàn bộ 1 phần" while `VideoWorker` renders 2 (pinned on the worker side by
   `test_video.py::test_redo_all_still_honors_a_manual_split_boundary`). The switch to the
   shared planner fixes that mismatch; `test_redo_all_count_honors_a_manual_split` is the
   test that fails on HEAD and passes now. **User-visible behaviour change** — the confirm
   dialog will report more parts than before when a manual split exists. It was the dialog
   that was wrong, not the render.
2. **A test that hung instead of failing.** `test_redo_all_counts_the_same_parts_as_the_table`
   originally patched only `QMessageBox.question`; against the unfixed code it took the
   "Chưa có audio" path and blocked on a real modal forever. It now patches `information`
   too, so a future regression fails in a second rather than wedging the run.

### Not addressed (recorded in the plan's Risks section)

both ways has part folders that collide. That needs a distinct slug/subfolder plus a
migration — a separate feature, and the strongest argument for keeping chapter-keyed locks
away from the source plan.
