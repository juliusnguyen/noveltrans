# 047 — Rename a chapter in `Tải truyện` — history

## [IMPLEMENTATION] — 2026-07-31

1206 tests pass (1186 before, +20), ruff clean.

Double-click "Tên chương" in the Tải truyện table, or right-click → **Sửa tên chương**.
The pattern already existed one column over — "Tên dịch" has been editable in the Dịch tab
since it was built — so this reuses `ChapterTableModel`'s editing path rather than adding a
second one.

### The hard part is not the editing, it is surviving a re-scan

`replace_toc` overwrites every title from the site on each scan, and **a re-scan is the
normal way to pick up newly published chapters**. A rename that a scan silently undoes
would rarely survive a day, and would fail in the worst way: quietly, long after the edit,
with the export and the TTS narration going back to the site's title.

So a renamed row is marked `title_custom = 1`, and the upsert leaves those titles alone:

```sql
title = CASE WHEN chapters.title_custom = 1 THEN chapters.title ELSE excluded.title END
```

New chapters still get added and untouched titles still refresh — both pinned by tests.

### `title_source`, because "undo" has to mean something

The first version's menu item said "lấy lại tên gốc từ trang web" while the code only
cleared the flag — the site's title had already been overwritten and was gone. A promise
the code could not keep.

The site's own title is now kept in `title_source`. Two details that are easy to get wrong:

* **Only the first rename captures it.** Otherwise a second edit would record the first
  edit as "the original" and the way back would be gone.
* **Every scan refreshes it**, even under a rename, so "undo" restores the site's *latest*
  title rather than one from months ago.

### Editing is opt-in per tab

`ChapterTableModel.set_title_editable(False)` is the default and `setData` refuses the
write, not just the view. The Dịch tab shows the same model and has no listener for
`title_edited`; an editable cell there would look like it worked and drop the text on the
next refresh. A test asserts that tab does *not* opt in.

Blank titles are refused for the same reason they matter at all — the title is read aloud
by TTS and printed in the video.

### Existing libraries

Both columns arrive through the existing `_migrate` path (`ALTER TABLE ... ADD COLUMN`),
defaulting to "not renamed". Verified by opening a hand-built pre-047 `chapters.db`:
it migrates, renames, and undoes correctly.

## [LIVE RUN 1] — 2026-07-31 — the editor was clipping the title

> after double click, I cant see all the text

Screenshot: the inline editor opens, and the chapter name is cut off mid-glyph — the top
half of the text visible, the rest sliced away.

### Cause: the app's own stylesheet

`style.py` gives every `QLineEdit` `padding: 6px 9px` plus a 1px border. That is right for
a form field and roughly 14px too tall for a table row. Qt sizes an in-cell editor to the
**cell rectangle**, so the padding eats the height from the inside and the editor's content
area ends up shorter than the text it holds.

Nothing was lost — the text was all there — but it looked like the field had eaten it,
which is the worst kind of wrong for an edit box.

`CellEditorDelegate` fixes it from both ends:

* strip the form-field padding from the editor, so it matches the row's own metrics;
* if the row is still shorter than the editor's `sizeHint`, grow the editor past the row
  rather than clipping — Qt allows an editor to overflow its cell, and that is exactly what
  a compact table is for.

### The same bug was already there in the Dịch tab

"Tên dịch" has been editable since that tab was built, with the same styled editor and the
same short rows. The delegate goes on both tables; a test asserts it stays on both.

### A crash the test found before a user did

`createEditor` assumed it always gets a widget. Qt returns **None** for a column it has no
editor for, so the first version would have raised `AttributeError` on any read-only column.
Both delegate methods now handle None, with a test for it.

(Also caught while writing that test: a `CellEditorDelegate(QWidget())` whose parent is a
temporary gets collected mid-test — "Internal C++ object already deleted". The parent has
to be held. Worth remembering for any future delegate test.)
