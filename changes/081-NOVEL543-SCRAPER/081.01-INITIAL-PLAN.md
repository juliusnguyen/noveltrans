## 1. What reconnaissance established (measured 2026-09-06; do not re-probe)

### 1.1 novel543 is timotxt's CMS behind Cloudflare

This is the single most useful fact for the implementation and it should be stated in the first paragraph of the module docstring. Compare, side by side:

| | timotxt | novel543 |
|---|---|---|
| landing | `/<10-digit id>/` | `/<10-digit id>/` (`og:url` has the trailing slash) |
| TOC | `/<id>/dir` | `/<id>/dir` |
| TOC container | `div.chaplist ul.all` after a duplicate newest-first `ul` | identical |
| chapter body | `#chapterWarp div.content`, prose in direct-child `<p>` | identical |
| junk in body | `div.gadBlock` + one unclassed trailing 溫馨提示 `<div>` | identical (+ `div.adBlock`) |
| blurb | `div.intro.is-hidden-mobile`; `meta[name=description]` is truncated SEO copy | identical |
| cover | `i1.timotxt.com/thumb/120x160/…` | `i2.novel543.com/thumb/120x160/…` |
| OG tags | `og:novel:*` declared with `name=` | full `og:novel:*` block present |

Three things differ, and each is a whole section of this plan:

1. **Cloudflare** (timotxt is plain HTTP; novel543 is browser-only).
2. **Chapter URLs carry a per-book internal id**: `/<bid>/8096_<n>.html`, where `8096` appears *only* in TOC/chapter hrefs and is not derivable from `<bid>`. timotxt's `/<bid>/<n>.html` is directly constructible; novel543's is not, so chapter URLs must come from the TOC and `chapter_url(bid, n)` cannot exist as a public helper.
3. **Chapters are paginated** — and only some of them.

`<n>` is positional, not the 章 number (`8096_400` is 第399章, `8096_439` is 第438章; the offset drifts) — exactly the bqg5 lesson about not deriving `index` from a title number, but here the URL's own `<n>` *is* a trustworthy positional key, which §5.3 turns into the load-bearing guard.

### 1.2 The three traps

**Trap 1 — `og:novel:latest_chapter_url` is a 404.** The detail page advertises `…/0802691255/439.html`; fetching it returns the site 404 page (`<title>/(ㄒoㄒ)/~~</title>`, ~1800 chars). The real URL is `…/0802691255/8096_439.html`. `timotxt.stated_total` reads exactly this tag, and `bqg5.fetch_chapter_list` uses `latest_chapter_url` as its list-orientation cross-check. **Both patterns are poison here** and must be explicitly refused in a comment, or the next reader will "harmonise" the sibling modules and break every scan on the site.

**Trap 2 — the TOC duplicate block.** `/dir` holds 451 chapter-shaped anchors for 439 chapters: a first `ul.flex.one.two-700.three-900` of 12 **newest-first** duplicates, then the real `ul.…​.all` of 439 ascending. A flat `a[href]` scrape over-counts by 12 *and* puts the newest chapters at index 0. bqg5's equivalent block was 9 on one probe and 5 on another, so "drop the first N" is wrong by construction. The blocks are distinguished only by the `all` class.

**Trap 3 — chapters are paginated, and only some of them.** The chapter `<h1>` (and `<title>`) carries a `(N/M)` suffix when and only when the chapter is split. Measured page-1 suffixes: ch 1 `(1/2)`, 3 `(1/2)`, 5 `(1/2)`, 50 `(1/2)`, 120 none, 301 none, 399 `(1/2)`, 438 `(1/2)`. Chaining 下一章 is the bqg5-mobile trap: on the last sub-page it points at the next *chapter*, and on an unpaginated chapter it can point at the page itself (measured on `8096_301.html`). The `(N/M)` count is authoritative; sub-page URLs are then `<stem>_2.html` … `<stem>_M.html`.

### 1.3 Raw measurements

Transport, same minute, all forms:

    curl -A <base.USER_AGENT desktop Chrome>  https://www.novel543.com/0802691255 -> HTTP 403
    curl -A <iPhone Safari UA>                same URL                            -> HTTP 403
    curl -A <Googlebot UA>                    same URL                            -> HTTP 403
    curl                                      https://novel543.com/0802691255     -> HTTP 403
    curl                                      https://m.novel543.com/...          -> DNS failure (no such host)

403 bodies carry `cf-mitigated: challenge`, `server: cloudflare` and the "Just a moment…" interstitial. `cf_browser.BrowserSession` cleared it on the first navigation with no visible interstitial and served 9 distinct URLs across 3 sessions with zero `_settle_challenge` waits at `delay_seconds` 1.5–2.0.

URL forms:

| what | URL |
|---|---|
| landing / detail | `https://www.novel543.com/0802691255` (canonical per `og:url`: `.../0802691255/`) |
| TOC | `https://www.novel543.com/0802691255/dir` (the 查看目錄 button) |
| chapter page 1 | `https://www.novel543.com/0802691255/8096_<n>.html` |
| chapter sub-page k | `https://www.novel543.com/0802691255/8096_<n>_<k>.html` (k = 2..M) |

Chapter body facts, measured on five chapter pages: prose lives in `div.content > p` only; zero `<br>`, zero `　`, zero `\xa0`, zero `&emsp;` — no indent characters at all. Non-`p` children are `div.adBlock`, `div.gadBlock` (empty ad slots) and one trailing unclassed `<div>` carrying a rotating 溫馨提示 notice whose wording varies per request. 1–2 empty `<p>` per page; ~1000–1900 chars over 30–118 paragraphs per sub-page.

`section.info` on `/dir` renders `章節： 439`, matching the `ul.all` anchor count exactly. Content is Traditional Chinese (稷下書院 is a TW site) → `source_lang = "zh"`. `page.content()` returns a decoded `str`, so encoding needs no handling.

## 3. Module skeleton — `src/noveltrans/scrapers/novel543.py`

### 3.1 Constants

```python
# Pinned, never taken from the pasted URL. The site answers on the bare host and on
# www., and `og:url` uses www. — echoing whichever the user pasted would make one novel
# two projects. Same reasoning as timotxt.py:97 and twkan.py:102.
ORIGIN = "https://www.novel543.com"

_ID_RE = re.compile(r"novel543\.com/(\d+)")

# A chapter href: /<bid>/<inner>_<position>[_<subpage>].html
#   group 1 bid       — filters out anchors pointing at ANOTHER book
#   group 2 inner     — the per-book internal id (8096); NOT derivable from bid
#   group 3 position  — 1..N, the reading position (NOT the 章 number)
#   group 4 subpage   — present only on a sub-page URL, which is never a TOC entry
_CHAPTER_HREF_RE = re.compile(r"/(\d+)/(\d+)_(\d+)(?:_(\d+))?\.html")

# "章節： 439" in section.info. The ONE stated total on this site that can be trusted —
# see the docstring for why og:novel:latest_chapter_* cannot.
_STATED_TOTAL_RE = re.compile(r"章節\s*[：:]\s*(\d+)")

# The "(1/2)" suffix on a paginated chapter's <h1>. Anchored at the end so a "(3/4)"
# inside a chapter title cannot be mistaken for it. Full-width parens accepted because
# this is a Traditional-Chinese site and the CMS is inconsistent about them elsewhere.
_PAGE_SUFFIX_RE = re.compile(r"[(（]\s*(\d+)\s*/\s*(\d+)\s*[)）]\s*$")

# A refusal ceiling, not a guess at the real maximum. M is 2 on every paginated chapter
# measured; if a parse ever yields something absurd, fetching 9 999 sub-pages through a
# Cloudflare-protected host is the worst possible failure. Raise instead.
_MAX_SUB_PAGES = 20

_COLONS = ":："
_WS_RE = re.compile(r"[ \t　 ]+")

# The real index. NOT the full `.flex.one.two-700.three-900.all` chain — that is a CSS
# grid framework's breakpoint vocabulary and exactly what a theme refresh rewrites.
# `chaplist` and `all` are the only semantic tokens. Identical to timotxt.py:112.
SEL_ALL_CHAPTERS = "div.chaplist ul.all a[href]"
SEL_DETAIL = "section#detail"
SEL_INFO = "section.info"
SEL_INTRO = "div.intro"
SEL_COVER = "div.cover img[src]"
# Anchored under #chapterWarp: `div.content` alone is far too generic to trust.
SEL_CONTENT = "#chapterWarp div.content"
SEL_HEADING = "#chapterWarp h1"
# Structural insurance only — the `> p` rule in parse_chapter already excludes all of
# this. Named per element, never a blanket <div> decompose (twkan.py:135 records why
# that eats prose).
SEL_CHROME = "div.adBlock, div.gadBlock, ins, script, style, iframe"
```

### 3.2 The pure/impure seam

Everything above the `adapter` line is pure: markup in, values out, no network. `_get_html` is the only method that touches a browser. That is what makes the whole parsing surface — all three traps included — testable against hand-built fixtures with no Chrome anywhere in CI, which matters more here than on any previous site because the pagination logic is the part most likely to be got wrong and it is *only* reachable through the fetch path.

To keep pagination testable, the page-count decision is a **pure function of markup** (`page_count`), and `fetch_chapter` does nothing but loop over URLs it computes from it.

## 4. URLs

```python
def book_id(url: str) -> str:
    """The numeric novel id, from any paste form. Raises ScrapeError on a non-novel URL."""

def read_url(url: str) -> str:
    """The canonical URL for a novel — the site's own og:url shape."""
    return f"{ORIGIN}/{book_id(url)}/"

def dir_url(url: str) -> str:
    """The complete chapter index — the only page this adapter reads chapters from."""
    return f"{ORIGIN}/{book_id(url)}/dir"

def sub_page_url(page_one_url: str, page: int) -> str:
    """Page `page` of a chapter whose first page is `page_one_url`.

    Deterministic, from the stem the TOC gave us — never from a 下一章 link. On the LAST
    sub-page that link points at the NEXT CHAPTER, and on an unpaginated chapter it can
    point at the page itself (measured on 8096_301.html). A chain that silently runs off
    the end of a chapter is exactly the misfiling `replace_toc` makes permanent.
    """
```

`sub_page_url` must be written against the *matched stem*, not by string surgery on `.html`:

```python
match = _CHAPTER_HREF_RE.search(page_one_url)
if match is None or match.group(4):
    raise ScrapeError("Not a chapter page-1 URL", page_one_url)
bid, inner, position = match.group(1), match.group(2), match.group(3)
return f"{ORIGIN}/{bid}/{inner}_{position}_{page}.html"
```

Rejecting a URL that already carries a sub-page component (`match.group(4)`) is load-bearing: it makes "build page 3 of page 2" impossible rather than producing `8096_1_2_3.html`.

### Why every paste form folds to one string

`Library.find_by_url` is exact string equality, and `ScanWorker` looks a project up by **both** the pasted URL and `meta.url`. If `NovelMeta.url` echoed the paste, then

```
https://www.novel543.com/0802691255
https://www.novel543.com/0802691255/
https://novel543.com/0802691255/
https://www.novel543.com/0802691255/dir
https://www.novel543.com/0802691255/8096_120.html
```

would become **five projects for one novel**, each with its own translation progress, tags, thumbnail prompt and video settings — and re-scanning from a chapter address (the normal case; the user reads, then re-scans from where they are) would fall through to `create_project`, which overwrites `meta.json` wholesale. `read_url` folds all five to `https://www.novel543.com/0802691255/`. `NovelMeta.source_host` strips only `www.`, so this also renders as "novel543.com" in the tab bar and picker.

A single `read_url` serves as both identity and fetch target here, unlike twkan (where the detail page and the TOC are different documents and `detail_url` exists separately). **Verify** the trailing-slash form actually serves the detail page (`og:url` says it is canonical, but the probe used the bare form); if it 302s, split `detail_url()` off from `read_url()` rather than dropping the slash from the identity — the identity string is the thing that must not churn.

## 5. Parsing

### 5.1 `parse_metadata(markup, url, site) -> NovelMeta`

| field | source | fallback |
|---|---|---|
| `title` | `og:novel:book_name` / `og:title` | `section#detail h1.title` |
| `author` | `og:novel:author` | `section#detail p.meta span.author`, then a colon-split over `p.meta` rows starting 作者 |
| `description` | **`div.intro` (the DOM)** | `og:description` |
| `cover_url` | `og:image` | `urljoin(ORIGIN, SEL_COVER src)` |
| `url` | `read_url(url)` | — |
| `source_lang` | `"zh"`, written explicitly | — |

The `og()` helper accepts **both** `property=` and `name=`, as `bqg5.py:206` and `timotxt.py:267` already do. timotxt — the same CMS — declares its OG block with the non-standard `name=`; accepting both costs one `or` and removes an entire class of "the CMS was fixed and our adapter broke" failure.

**`meta[name="description"]` must not be used, and the reason belongs in a comment.** It is SEO copy: `"…無彈窗最新章節由<author>所著，《<title>》最新清爽乾淨的文字章節在線閱讀: "` followed by the intro **cut off with an ellipsis**. It is not the blurb with padding — it is a *truncated* blurb with padding, so no amount of prefix-stripping recovers the tail. `div.intro` carries the full text, clean, with no escapes (unlike bqg5's literal `\n`, and unlike twkan's literal `<br />` — do **not** copy either module's `_clean_description`; a helper for something this site does not do is a trap for the next reader, per `timotxt.py:80`). A `_norm`-style whitespace collapse is all that is wanted.

Missing title anywhere → `ScrapeError("Novel title not found — page layout may have changed", url)`.

**No placeholder-cover blanking**, deliberately, with twkan's argument recorded in the docstring: no `nocover`/`noimage` string appears in any captured page, and inventing a filename to blank would be either dead code or a rule that eats a real cover. If a coverless novel turns up, the fix is one suffix constant — `sto9.py`'s shape.

### 5.2 `stated_total(markup) -> int | None`

```python
def stated_total(markup: str) -> int | None:
    """How many chapters the /dir page says the novel has. None when it does not say.

    ONE signal, `章節： N` in section.info, and it is deliberately not backed up by the
    OpenGraph block the way twkan and timotxt back theirs up:

      * `og:novel:latest_chapter_url` is a **404 URL** on this site — it advertises
        /<bid>/439.html while the real address is /<bid>/8096_439.html. timotxt's
        stated_total reads exactly that tag; transplanted here it would still yield the
        right number by luck today, and would be a landmine the day the site's positional
        numbering changes. Do not read it, and do not fetch it as a cross-check the way
        bqg5 does.
      * `og:novel:latest_chapter_name` is a chapter TITLE (第438章) against 439 real
        entries, because <n> is positional and the 章 numbering drifts. That is the bqg5
        mismatch, and any equality guard built on it refuses every scan on the site.

    Measured: 章節： 439 against exactly 439 anchors in ul.all.
    """
```

### 5.3 `parse_chapter_list` and the guard that carries the module

```python
def parse_chapter_list(markup: str, bid: str, url: str) -> list[ChapterRef]: ...
def chapter_positions(refs: list[ChapterRef]) -> list[int]: ...
```

**Locating the list.** Prefer `SEL_ALL_CHAPTERS` (`div.chaplist ul.all a[href]`). If that selects nothing, fall back to a flat `a[href]` scrape **keyed and sorted by the URL's positional `<n>`**, exactly as `timotxt.parse_chapter_list` does — never by document order. Both paths filter every anchor through `_CHAPTER_HREF_RE` with `group(1) == bid` (rejects another book's anchors) and `group(4) is None` (rejects a sub-page URL, which is never a chapter of its own).

Why sorting is what makes the fallback safe rather than a hole in the policy: the duplicate block sits **first** in document order and runs **backwards**. Fixing the count without fixing the order would not save it — a `dict` keyed on `<n>` with `setdefault` and then `sorted()` fixes both at once, and every entry it can possibly contain is a real chapter of this book.

**The guard.** In `fetch_chapter_list`, after parsing:

```python
positions = chapter_positions(refs)
if positions != list(range(1, len(positions) + 1)):
    raise ScrapeError(
        f"Danh sách chương của novel543 không liền mạch từ chương 1 "
        f"({len(positions)} mục, cao nhất {max(positions) if positions else 0}) — "
        "app không lưu danh sách sai. Thử quét lại sau.",
        dir_url(url),
    )
```

This single check is worth more than everything else in the module, and the reason should be spelled out: because chapter URLs embed the reading position, `positions == [1 … N]` is a **proof** that the list is a dense, ascending prefix starting at chapter 1 — which is exactly the property `ChapterRef.index` needs. Every realistic degradation breaks it:

* the duplicate block leaking in → `[428, 427, …, 439, 1, 2, …]`, not ascending;
* losing `ul.all` and taking only the recent block → `[428 … 439]`, does not start at 1;
* a dropped middle entry → a gap;
* an anchor from another book → filtered out earlier, but would break density if it were not.

`replace_toc` preserves content across re-scans while updating title and URL, so a list that is wrong *in order* is not a transient error — it files chapter 439's body under index 0 and a later, correct scan quietly rewrites the title over it. Refusing is the only safe direction, and this is the same lesson as `timotxt.py:24`, `sto9`'s truncated page and `bqg5`'s reversed-list guard.

**`stated_total` is then a report, not a gate**, following timotxt's reasoning:

```python
total = stated_total(markup)
if total is not None and len(refs) != total:
    self._status(f"⚠️ novel543 trả về {len(refs)}/{total} chương. Quét lại sau để lấy đủ.")
```

A contiguity-proven prefix that is short is safe — a later re-scan simply extends it and nothing can be misfiled — so it must not fail the scan, but it must not be silent either. And a list *longer* than the stated total must equally not fail: the bqg5 lesson is that a stated number never gets to refuse a provably-good list. Do **not** promote this to a `raise`; the contiguity check is the gate.

`index` comes from `enumerate` and nothing else. Titles are the anchor text, stored verbatim — TOC titles are clean (no `(N/M)` suffix), and they are persisted, exported and read aloud, so a tidy-up normaliser here would silently rewrite them on the next re-scan.

**Explicitly rejected alternative, worth a comment:** the detail page's 開始閱讀 button reveals the internal id (`/<bid>/8096_1.html`), so one *could* synthesise `8096_1 … 8096_N` from `章節： N` without reading the TOC at all. That is rejected because it invents URLs the site never offered, has no titles, and would produce a plausible-looking list of 404s the moment the numbering is not dense. The TOC is the only source of chapters.

### 5.4 `page_count(markup, url) -> int` — the pagination decision

```python
def page_count(markup: str, url: str) -> int:
    """How many sub-pages this chapter has, per the page's own <h1> "(N/M)" suffix.

    Two signals, <h1> and <title>, and the LARGER wins — the twkan stated_total shape,
    for the same reason: under-estimating is silent data loss (half of most chapters on
    this site), while over-estimating is caught loudly one request later by the
    per-sub-page self-check in fetch_chapter. Losing text quietly is the worse failure.

    A chapter page with NO heading at all raises rather than defaulting to 1. An <h1>
    that exists and carries no suffix genuinely means one page (measured: ch 120, ch 301);
    an <h1> that has VANISHED means the layout changed, and quietly reading that as "one
    page" would drop the second half of every paginated chapter on the site with no error
    anywhere. That distinction is the whole point of this function.
    """
```

Return `1` when a heading exists with no suffix; raise `ScrapeError("Chapter page layout may have changed — no heading found", url)` when neither `SEL_HEADING` nor `<title>` is present; raise when `M > _MAX_SUB_PAGES` or `M < 1`.

The `<h1>` suffix is used for **nothing else**. Titles come from the TOC and are already clean, so there is no suffix-stripping code path and no risk of a stripped title diverging from the stored one.

`page_position(markup) -> tuple[int, int] | None` is the same parse exposed for `fetch_chapter`'s self-check.

### 5.5 `parse_chapter(markup, title, url) -> str` — one sub-page

Select `SEL_CONTENT`; missing → `ScrapeError("Chapter content not found — page layout may have changed", url)`. Decompose `SEL_CHROME` (insurance). Then:

```python
lines = [t for t in (p.get_text(strip=True)
                     for p in container.find_all("p", recursive=False)) if t]
```

**Direct-child `<p>` is the definition of a prose paragraph on this markup**, and it is what excludes the site's chrome *structurally* rather than by name:

* `div.adBlock` / `div.gadBlock` — empty ad slots, not `<p>`;
* the trailing unclassed `<div>` carrying the rotating 溫馨提示 notice. **A literal string blocklist is wrong here and the comment must say so**: the observed text varies per request (加入書架 / 跨設備保存書架 / 「站內信」功能已優化 …), and the wrapper has no class to name. `> p` drops it whatever it says today.

There is no indentation to handle: measured zero `<br>`, zero `　`, zero `\xa0`, zero `&emsp;` across five chapter pages. Do **not** copy sto9's `&emsp;` note or bqg5's NBSP note.

Keep timotxt's `container.select("p")` fallback when the direct-child rule yields nothing (a CMS that nests prose one level deeper costs at most one junk notice line; not falling back costs the whole chapter) — and record that the notice line is precisely what the fallback would let through, and that `translators/ads.py` is the downstream net for it.

Title-echo handling: drop at most one leading line when `_norm(lines[0]) == _norm(title)`. The `<h1>` lives outside `div.content`, so this normally never fires. **`fetch_chapter` passes `title` only for page 1 and `""` for sub-pages** — a sub-page whose first paragraph coincidentally matched the title would otherwise lose a real line of prose, and over-stripping is silent data loss while a duplicated heading is cosmetic.

Empty after all that → `ScrapeError("Chapter content is empty", url)`. Plain `ScrapeError`, **never `ObfuscatedContentError`**: nothing on this site is obfuscated (that is timotxt's problem, not this CMS's, and the two modules will sit next to each other looking similar). `ObfuscatedContentError` has GUI meaning — it is what the residual-character repair flow keys on — so mislabelling an empty page as obfuscated would offer the user a repair that cannot work. A test pins that the raised type is neither `ObfuscatedContentError` nor `RateLimitedError`.

## 6. The adapter

```python
@register
class Novel543Adapter(SiteAdapter):
    name = "novel543"
    display_name = "小說543 (novel543.com)"
    # Host-anchored, and the trailing (?:/|$) is what keeps the image host and the
    # site's non-novel pages out. ADAPTERS is first-match-wins by import order, so an
    # un-anchored pattern would be a silent, order-dependent theft of a neighbour's URLs
    # — the hazard sto9.py, twkan.py, timotxt.py and bqg5.py all document. One pattern
    # covers every accepted form: the bare landing page, /dir and a chapter URL all
    # contain "novel543.com/<digits>" followed by "/" or end-of-string.
    url_patterns = [r"novel543\.com/\d+(?:/|$)"]
    content_is_translated = False

    def __init__(self, client, *, headless: bool = False):
        super().__init__(client)
        # Headless is fingerprinted by Cloudflare and does not clear the challenge
        # (measured — see cf_browser). The flag exists in case that ever changes.
        self._headless = headless
        self._session: BrowserSession | None = None
        # Per-instance, never module-level: the app is long-lived and the user switches
        # novels, so a shared cache would answer one novel's questions with another's page.
        self._detail: tuple[str, str] | None = None   # (bid, markup)
```

`_get_html`, `close()` and the two exception translations are **twkan's, with the site name swapped** — same structure, same Vietnamese wording, so the three Cloudflare adapters read identically:

* lazy session; before constructing it, `self._status("🌐 Đang mở trình duyệt để vượt kiểm tra Cloudflare của novel543 — giữ cửa sổ mở…")`, because a Chrome window is about to appear and an unexplained one reads as the app misbehaving;
* `BrowserSession(headless=self._headless, delay_seconds=self.client.delay_seconds)` — `HttpClient`'s throttle is bypassed on this path, so the session's is the only politeness left, and this site will take **~800 navigations** for a 439-chapter novel (see §6.1), more than any other site in the app;
* `BrowserUnavailableError` → `ScrapeError("Cần trình duyệt để đọc novel543 (trang này có kiểm tra Cloudflare). Cài Google Chrome, hoặc chạy:  pip install 'noveltrans[browser]' && playwright install chromium", url)`;
* `BrowserSessionError` → `ScrapeError("Không đọc được trang novel543 — trình duyệt bị đóng hoặc không vượt được kiểm tra Cloudflare. Thử tải lại. ({exc})", url)`;
* `close()` idempotent, never raises. `ScanWorker` and `DownloadWorker` already call it in a `finally`, so no worker change is needed — but a leaked session here is a Chrome window the user has to force-quit, so `close()` gets its own tests.

**"Do not parallelise novel543"** goes in the module docstring in the same words twkan uses: N concurrent sessions is N Chromes, and hammering a CF-protected host is the fastest route to an IP block — which would kill the browser path too, and it is the only path this site has. That warning matters more here than on twkan because this site costs roughly twice the navigations per chapter.

### 6.1 `fetch_chapter` — the pagination loop

```python
def fetch_chapter(self, ref: ChapterRef) -> str:
    first = self._get_html(ref.url)
    pages = page_count(first, ref.url)
    bodies = [parse_chapter(first, ref.title, ref.url)]

    for k in range(2, pages + 1):
        url = sub_page_url(ref.url, k)
        markup = self._get_html(url)
        # The sub-page states its own position. If it does not say (k/pages) we did not
        # get the page we asked for — a site that redirects an out-of-range sub-page back
        # to page 1 would otherwise duplicate the opening prose into the middle of the
        # chapter, silently. Raising marks the chapter as an error, which is visible and
        # retryable; a half or doubled chapter is neither.
        if page_position(markup) != (k, pages):
            raise ScrapeError(
                f"novel543 trả về sai trang {k}/{pages} của chương — thử tải lại chương này.",
                url,
            )
        bodies.append(parse_chapter(markup, "", url))

    return "\n\n".join(bodies)
```

Three deliberate choices:

1. **Fail loudly on any sub-page problem.** `parse_chapter` raising on an empty sub-page propagates, so the chapter lands in `mark_error` and the row stays pending. The alternative — swallowing a failed sub-page and saving what we have — writes a half chapter that looks complete, and `DownloadWorker` will never revisit it because `pending_download` sees content.
2. **`""` as the title for sub-pages** (§5.5).
3. **Join with `\n\n`.** Whether the site ever splits a *paragraph* across a page boundary is unverified; if it does, the join adds a spurious paragraph break rather than losing text. That is the acceptable direction, and it is listed in §11.

Cost note for the docstring: the reference novel is 439 chapters of which most are 2 pages, so a full download is ~800 browser navigations at the configured delay. That is the price of the site, it is why the politeness delay must be honoured, and it is why the README row warns the user the download is long.

## 11. Risks and open questions

1. **Is `M` ever greater than 2?** Every paginated chapter measured is `(1/2)`. The design does not assume 2 — it reads `M` and loops — so a `(1/3)` chapter works unchanged. `_MAX_SUB_PAGES = 20` is a refusal ceiling, not an assumption. **Nothing to verify before shipping**, but `test_the_pagination_distribution_has_not_flipped` is the live canary.
2. **What does an out-of-range sub-page do?** Unverified: `8096_120_2.html` (a page that should not exist) may 404, may redirect to page 1, or may serve an empty body. All three are handled — 404 → `BrowserSessionError`/empty markup → raise; redirect → the `(k/M)` self-check raises; empty → `parse_chapter` raises. **Verify during implementation** with one `python -m noveltrans.scrapers` run, and if it redirects, keep the self-check (it is what catches it).
3. **Does the site ever split a paragraph across a page boundary?** Unverified. If it does, the `"\n\n".join` inserts a spurious break. Not data loss, and detectable only by reading; noted, not defended against.
4. **Trailing slash on the detail page.** `og:url` says `/<bid>/` is canonical but the probe used the bare form. If the slash form redirects, split `detail_url()` from `read_url()` — do **not** change the identity string.
5. **`property=` vs `name=` on the OG block.** Not recorded in the recon. The `og()` helper accepts both, which retires the question.
6. **Coverless novels.** Unobserved; no placeholder string appears in any captured page. If one turns up, the fix is one suffix constant in `sto9.py`'s shape — and `test_cover_url_is_stored_unmodified` is what forces whoever adds it to add a fixture too.
7. **Rate-limiting over a full ~800-navigation run.** Unmeasured. twkan self-heals a periodic 429 inside `cf_browser._settle_challenge`; the same machinery covers this site for free, but a run twice as long is twice the exposure. If novel543 turns out to challenge more aggressively, the lever is the app's configured delay, **not** a code change — and specifically not a lower `_CHALLENGE_WAIT_SECONDS`.
8. **The inner id (`8096`) is assumed stable per book.** It comes from the TOC on every scan, and stored `ChapterRef.url`s are refreshed by `replace_toc` on re-scan, so a site-side renumbering self-heals on the next scan. It would strand any chapter downloaded but not re-scanned in between — the same exposure every URL-storing adapter has.
9. **How this degrades if the site changes.** Losing `ul.all` → flat fallback, still guarded. Losing `div.chaplist` entirely → `ScrapeError`. Losing the `<h1>` → `page_count` raises (deliberately, rather than silently halving every chapter). Losing `div.content` → `ScrapeError`. The 溫馨提示 notice changing wording → unaffected, it is excluded structurally. The one change that would hurt quietly is the CMS moving prose out of direct-child `<p>`s, which drops into the `select("p")` fallback and admits the notice line as a trailing paragraph — visible in output, caught by `translators/ads.py` downstream, and not silent.
