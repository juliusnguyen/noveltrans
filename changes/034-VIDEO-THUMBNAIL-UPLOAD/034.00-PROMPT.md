# 034 — Update the thumbnail on an already-uploaded video

## The ask

> update the thumbnail for uploaded video

## Settled scope

- **Flow**: a *new* action, separate from the upload run. For a part that has already
  been uploaded (its `<stem>.upload.json` holds a `video_id`), drive YouTube Studio to
  the video's edit page and replace its thumbnail. This is the "I re-cut the cover
  after publishing" case — not a change to the in-upload thumbnail step of 033.
- **Source of the image**: the existing `<stem>.jpg` sidecar the cover editor (026)
  writes beside the video. No file picker — regenerate the cover in the editor, then
  push it.
- **Trigger**: an explicit, visible button — one click, fully automated, no manual
  Studio steps in between. Not a context-menu item, not a side effect of another action.

## What exists today

Feature 033 (`src/noveltrans/youtube_upload.py`, ~1276 lines) already provides
everything this builds on:

- `profile_dir()` / `_launch_context()` / `open_login()` — the persistent `.youtube-profile`
  Chrome session, one-time manual Google login, `needs_login` errors.
- `_first_present()`, `_click_any()`, `_click_by_text()`, `_fill_box()` — the
  Studio-DOM helper layer, written against `ytcp-*` ids and `[name=]` enum hooks.
- `_THUMBNAIL_INPUT_SEL` — the thumbnail file input, already scoped to
  `ytcp-thumbnails-compact-editor` so it isn't confused with the video uploader.
  Note 033 treats a *missing* input as "channel lacks thumbnail privileges" and skips
  silently; a standalone update action must treat that as a hard error instead.
- `read_upload_state()` / `write_upload_state()` / `is_published()` — the per-part
  `<stem>.upload.json` record (`started → draft → committed → published`, plus
  `video_id`).
- `gui/tab_video.py` — the video table with its "Đã tải lên" column and per-row
  actions, the upload box, and `gui/workers.py`'s `YouTubeUploadWorker`.

## Open questions for `/plan`

- Button placement: per-row in the "Thao tác" column, a batch button in the upload box,
  or both. Batch matters if a cover-style change is re-applied to every part. (That
  there *is* a button is settled above; only the placement is open.)
- Studio surface to drive: the video edit page (`studio.youtube.com/video/<id>/edit`)
  vs. the thumbnail editor dialog. Whichever has the stabler save affordance.
- What counts as eligible: `is_published()` only, or any record with a `video_id`
  (a scheduled-but-unpublished part still has an editable thumbnail).
- Confirmation before overwriting a live video's thumbnail, and what the record should
  note afterwards (e.g. a `thumbnail_updated` timestamp) so a re-run is visible.
- Failure handling, consistent with 033: never report success unless Studio confirmed
  the save; surface the failing step rather than guessing.

## Out of scope

- The cover/thumbnail *generation* pipeline (`tts/thumbnail.py`, the 026 editor).
- Re-uploading video bytes, or changing title/description/tags post-publish.
- Any Google Data API usage.
