## 1. The shape of the problem

The ask is "jump to the match so I can fix it by hand". Two ways to give it:

- **A — jump and close.** Keeps the dialog modal. But with 63 results the user re-opens
  and re-previews for every single fix. Rejected.
- **B — modeless.** The list stays up while the panes are edited. This is what the user
  is asking for, and it is the option that costs something: the docstring's invariant.

Take B, and pay for it explicitly (§3).

## 2. Steps

1. **`chapter_activated = Signal(int, str, str, bool)`** on the dialog — chapter index,
   field id, search text, case flag. Emitted from `itemDoubleClicked`; the row indexes
   `_matches` directly. Field = `match.changes[0].field`, which is the first *checked*
   field that matched, so a translated hit routes to the right-hand pane.
2. **`setModal(False)`**, and the tab switches `exec()` → `show()`, holding the dialog in
   `self._find_dialog`.
3. **`TranslateTab._jump_to_match`** — `selectRow` (which loads the panes through the
   normal flush-then-load path), then **re-find the text in the pane** rather than using
   an offset from the scan: the pane is `title\n\nbody`, so a raw field offset lands in
   the wrong place, and for a title match in the wrong text entirely.
4. **Repeat double-click walks the chapter.** Only reset the cursor to the top when the
   chapter actually changed; otherwise search on from the cursor and wrap on a miss. A
   chapter showing "2 khớp" must have both hits reachable.
5. **Focus.** `window().activateWindow()` then `view.setFocus()` — the dialog owns the
   keyboard at that moment, and the first keystroke otherwise lands in the search box.

## 3. What modeless costs, and the guard that pays for it

The text can now change between "Xem trước" and "Thay thế" — by hand, or by a worker.
`_apply` would then write `change.new`, computed from a `change.old` that is gone, quietly
undoing the user's edit. This is the exact failure the modality was preventing.

**`_is_stale()`**: before applying, re-read every scanned field and compare against
`change.old`. Any drift (or a chapter deleted outright) → invalidate and say so. It covers
*every* writer, not just the manual-edit path, which the modality never did either.

Three more lifecycle holes only a modeless dialog can have:

| Hole | Fix |
|---|---|
| `_preview_idx` frozen at construction → “Chương hiện tại” means the wrong chapter | `set_current_chapter`, called from `_on_row_selected`; re-scopes, and drops a *current-scope* preview only |
| A batch run starts underneath it | `_close_find_replace()` in both `_start_translate` and `_start_rewrite` |
| The novel is switched → dialog holds a closed handle | `_close_find_replace()` first thing in `_on_project_selected` |

`set_current_chapter` must **not** invalidate an all-scope preview — the jump moves the
open chapter on every double-click, and clearing the list the user is walking would make
the feature destroy itself.
