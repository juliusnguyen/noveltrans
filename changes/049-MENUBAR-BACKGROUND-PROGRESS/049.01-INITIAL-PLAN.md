# 049 — Menu-bar background running, with progress and pause/resume — implementation plan

_All line references verified against the working tree at 2026-07-31 (PySide6 6.11.1, baseline 1264 tests)._

## Goal

Let long jobs (download / translate / audio / merge / video / subtitles / uploads) keep running with the main window closed. Closing the window always hides the app to the macOS menu bar; clicking the menu-bar icon opens a popup panel with one row per running job — label, progress bar, `done/total`, and a `⏸ Tạm dừng` / `▶ Tiếp tục` toggle — plus `Mở cửa sổ` and `Thoát`. Pause holds the worker at the existing between-item checkpoint, so nothing is ever half-written and resume is instant.

---

## Design decisions

### D1 — A `JobRegistry` singleton, registered at the `track_worker` call sites

| Option | Verdict |
|---|---|
| Signal chain tab → `Workspace` → `MainWindow` | **Rejected.** Needs a new signal + relay in 5 tab classes, `workspace.py` and `main_window.py` (≈14 new plumbing points), and it pushes per-job state into `MainWindow`, whose module docstring (`main_window.py:1-6`) explicitly limits it to app-global concerns. It also can't answer "what is running" without walking the widget tree. |
| Reuse `keep_awake.track_worker` as the hook | **Rejected as the mechanism, adopted as the *location*.** `track_worker` (`keep_awake.py:81-89`) is called at exactly 10 sites and does see every long worker — but it also covers three short ones (`tab_video.py:1599` TagsWorker, `:1653` the image-prompt CompletionWorker), it has no novel/kind label to work with, and folding UI job tracking into a `caffeinate` wake-lock is the wrong seam. What it *proves* is that "one line next to `track_worker(...)`" is the right registration point: those lines already mark "a long batch is starting". |
| **Module-level `job_registry` in a new `src/noveltrans/gui/jobs.py`** | **Chosen.** One new line per launch site, no changes to `Workspace` or `MainWindow` plumbing, and the popup subscribes to one object instead of walking N workspaces × 5 tabs. Signals go worker → registry as ordinary queued cross-thread connections. |

`JobRegistry(QObject)` holds `Job` records only (`id: int`, `kind: str`, `novel: str`, `done`, `total`, `message`, `paused`, `worker`) and **never a widget reference** — so `_close_workspace`'s `ws.deleteLater()` (`main_window.py:143`) can't leave the registry holding a dead widget. It emits `job_added(Job)`, `job_changed(Job)`, `job_removed(int)`.

### D2 — `PauseGate` on a `threading.Event`, and `cancel()` always resumes it

```python
class PauseGate:                       # src/noveltrans/gui/pause.py — no Qt import
    def __init__(self): self._resume = threading.Event(); self._resume.set(); self._paused = False
    def pause(self):  self._paused = True;  self._resume.clear()
    def resume(self): self._paused = False; self._resume.set()
    @property
    def paused(self) -> bool: return self._paused
    def wait(self, cancelled) -> None:
        while not self._resume.is_set():
            if cancelled(): return          # cancel always wins
            self._resume.wait(0.2)          # bounded: cancel is seen within 200 ms
```

| Option | Verdict |
|---|---|
| `QWaitCondition` + `QMutex` | Rejected. Requires a `wakeAll()` inside every `cancel()` and inside app teardown or it deadlocks *by construction*; needs a live `QMutex` on `ThreadPoolExecutor` threads too (`AudioWorker._run_parallel`); and can't be unit-tested without a `QApplication`. |
| `while paused: time.sleep(0.2)` | Rejected. Same poll cost with no wake-up on resume — resume would lag up to 200 ms and the state would live in a bare bool with no memory barrier. |
| **`threading.Event` with a bounded `wait(0.2)`** | **Chosen.** Pure Python (testable with no Qt), works identically on QThreads and on the audio pool threads, resume is instant, and the bounded wait makes "paused then cancelled" impossible to hang *even if someone forgets the belt-and-braces below*. |

**Belt AND braces against the deadlock:** `cancel()` also calls `self._gate.resume()`. This is the single most important line in the feature — `ScrapeTab.shutdown` / `TranslateTab.shutdown` / `AudioTab.shutdown` / `VideoTab.shutdown` all do `worker.cancel(); worker.wait(30_000…120_000)` (`tab_scrape.py:687-693`, `tab_translate.py:550-556`, `tab_audio.py:623-630`, `tab_video.py:2989-3019`). Without it, quitting with a paused job blocks the GUI thread for up to 120 s **per worker** and then abandons a live QThread.

A shared `PausableWorker(QThread)` base in `workers.py` owns `_cancelled`, `_gate`, `cancel()`, `pause()`, `resume()`, `is_paused()` and `_checkpoint()`. The seven (Phase A: six) long workers change their class header and delete their duplicated `self._cancelled = False` / `def cancel` pairs (`workers.py:121-124, 524-527, 847-850, 995-998, 1174-1177, 1262-1265, 1510/1518-1519, 1726-1729, 1823-1826, 1892-1895`).

```python
def _checkpoint(self) -> bool:
    """Hold here while paused. True = the run should stop (cancelled)."""
    if self._cancelled: return True
    self._gate.wait(lambda: self._cancelled)
    return self._cancelled
```

### D3 — Gate only at the outer item boundary; never inside ffmpeg or TTS

Every existing `cancelled=lambda: self._cancelled` callback passed downward is polled inside a **deadline-bounded** loop:

* `tts/merge.py:175` — `deadline = time.monotonic() + max(1800, int(total))`, polled every 0.3 s while ffmpeg runs (`merge.py:186-197`).
* `tts/video.py:669` — `deadline = time.monotonic() + max(3600, int(total) * 6)`.
* `tts/base.py:151` — `synthesize_chapter` accumulates every chunk in a Python list (`pieces`) and only writes the WAV at `:171`. Pausing mid-chapter would hold hundreds of MB of `float32` samples resident for hours.

So gating inside those callbacks would either trip a hard timeout ("ffmpeg quá thời gian khi ghép") or pin RAM. **Consequence, accepted and to be documented in the README:** pausing during a single long ffmpeg merge or video encode takes effect only when that file finishes (tens of minutes for a full part); pausing during TTS takes effect after the current chapter (~a minute).

`DownloadWorker._fetch_with_backoff`'s 60 s × 8 rate-limit countdown (`workers.py:1524-1540`) is also left cancel-only: it is mid-item, and the outer checkpoint catches it within one chapter.

Exact checkpoints, all of them today's `if self._cancelled:` sites:

| Worker | `workers.py` line | Change |
|---|---|---|
| `TranslateWorker._run_identity` | `:150` | `if self._checkpoint(): break` |
| `TranslateWorker.run` | `:237` | `if self._checkpoint(): break` |
| `AudioWorker._run_sequential` | `:634` | `if self._checkpoint(): break` |
| `AudioWorker._run_parallel` | top of `while inflight:` at `:789` | **`self._checkpoint()` as a bare statement**, before `wait(...)` — never `break`, so the existing drain path (`submit_next` returns False when cancelled, `:772`) is byte-for-byte unchanged on cancel |
| `MergeWorker.run` | `:884` | `if self._checkpoint(): break` |
| `VideoWorker.run` | `:1046` | `if self._checkpoint(): break` |
| `SubtitleWorker.run` (per window) | `:1323` | `if self._checkpoint(): break` |
| `SubtitleWorker.run` (per chapter backfill) | `:1328` | `if self._checkpoint(): break` — each `_backfill` writes a complete `.cues` sidecar, so this is a real item boundary |
| `DownloadWorker.run` | `:1563` | `if self._checkpoint(): break` |

Leave alone: `:669` / `:746` (mid-chapter `TtsError` cancel detection), `:713` and `:772` (pool-thread paths), `:214` (one-shot meta translation), `:1528`/`:1531`.

### D4 — Browser workers: pause via one new `on_checkpoint` param, shipped last

`SubtitleUploadWorker` (`workers.py:1179-1215`), `YouTubeUploadWorker` (`:1731`), `PlaylistSyncWorker` (`:1828`) and `YouTubeThumbnailWorker` (`:1897`) have **no loop in `run()`** — the per-part loop lives in `youtube_upload.py` (`upload_batch:2810-2833`, `upload_subtitle_batch`, `update_thumbnail_batch:2934-2947`, `sync_playlist_batch:2038-2045`).

* Folding the gate into the existing `should_cancel` callback is **rejected**: `_check_cancel` is also polled mid-transfer inside `_wait_for_bytes_uploaded` (`youtube_upload.py:1170`), so a pause would freeze a live upload mid-byte-stream and invite a Playwright timeout.
* **Chosen:** add an optional `on_checkpoint: Callable[[], None] | None = None` to those four batch functions, called **only** at the per-part boundary next to the existing `_check_cancel(should_cancel)`. The workers pass `self._checkpoint`.

The brief lists `SubtitleUploadWorker` as pausable but not its three structural siblings; that asymmetry looks accidental — all four take the identical `should_cancel` + `on_part_done` shape, so covering all four is four identical two-line edits and one consistent rule. **Risk to state in the UI:** a paused browser job leaves a headed Chrome window and a Google session idle indefinitely; the row's tooltip says so. This is **Phase B / step 9** so the feature is shippable without it.

### D5 — A frameless `Qt::Popup` widget, not a `QMenu` of `QWidgetAction`s

Verified: `QSystemTrayIcon` exists in PySide6 6.11.1 with `activated`, `setContextMenu`, `showMessage`, `geometry`, `isSystemTrayAvailable` (False under `QT_QPA_PLATFORM=offscreen`, measured). `QMenu` does accept a `QWidgetAction` (measured).

| Option | Verdict |
|---|---|
| `tray.setContextMenu(QMenu)` with `QWidgetAction` rows | **Rejected.** On macOS Qt renders a tray menu as a **native NSMenu**; while it is open, AppKit owns the run loop in `NSEventTrackingRunLoopMode`, and queued cross-thread signal delivery (which is exactly how `worker.progress` reaches the GUI thread) is not reliably pumped there. The core requirement is a progress bar that *moves while the panel is open*. QSS styling of embedded views in a native menu is also a known soft spot. |
| **A frameless `QWidget` with `Qt.WindowType.Popup`, shown from `tray.activated`** | **Chosen.** An ordinary Qt window: Qt drives its event loop, live updates are plain repaints, the app's dark QSS (`style.py`) applies for free, `Qt::Popup` gives click-outside dismissal and Esc for free — and it is a plain widget, so it can be built and asserted in offscreen tests **with no tray at all**. |

Positioned from `tray.geometry()` (the NSStatusItem rect), clamped to `screen.availableGeometry()`; falls back to the cursor position when the rect is empty. After `show()`, call `raise_()` + `activateWindow()` so a click that doesn't activate the app still routes mouse events.

### D6 — Tray icon drawn at runtime as a macOS *template* image

`QIcon.setIsMask(True)` exists in 6.11.1 (measured). Draw a 22×22 + 44×44 monochrome glyph with `QPainter` in `gui/tray.py::build_tray_icon()` — pure black on transparent, `setIsMask(True)` so macOS inverts it correctly in light and dark menu bars and while the menu is highlighted. Precedents: `packaging/make_icon.py` (QPainter → PNG) and `style.py`, which already paints a pixmap at runtime.

**Consequence for packaging: `NovelTrans.spec` needs no change.** No new asset file exists to add to `datas`, and `collect_data_files("noveltrans")` would not have picked up a `packaging/` PNG anyway.

### D7 — Hide-on-close vs quit: one flag, one quit path, and a hard degrade rule

* `app.setQuitOnLastWindowClosed(False)` — **required**, in `app.py::main()` right after `apply_theme(app)`. Without it, hiding the only window quits the app instantly.
* `MainWindow.closeEvent` becomes: save geometry → if `self.hide_to_tray_enabled`: `event.ignore(); self.hide(); tray_hint_once()` → else the current behaviour (shutdown every workspace + `super().closeEvent`). **`ws.shutdown()` must not run on a hide** — it cancels and joins every worker (`workspace.py:119-122`), which is the exact opposite of the feature.
* **Degrade rule:** `hide_to_tray_enabled` defaults to **False** and is flipped to True only by `TrayController` once it has actually installed a tray icon. On a machine (or an offscreen test run) with no system tray, closing the window still really quits — the app can never become unquittable.
* **One quit path:** a new explicit `Thoát` `QAction` in `_build_menu()` with `MenuRole.QuitRole` and `QKeySequence("Ctrl+Q")` (Qt maps Ctrl→⌘ on macOS). Setting `QuitRole` makes *our* action the macOS app-menu Quit item, so ⌘Q, the popup's `Thoát`, and `app.quit()` all converge on `MainWindow._quit()` → `self._quitting = True; QApplication.instance().quit()`. This removes any need to reason about which internal path Qt's `applicationShouldTerminate:` takes.
* `app.aboutToQuit.connect(window.shutdown_all)` **before** the existing `app.aboutToQuit.connect(keep_awake.shutdown)` — slots fire in connection order, and killing `caffeinate` before a 120 s worker join could let the Mac sleep mid-teardown. This means moving the `keep_awake.shutdown` connect (`app.py:32`) below the `MainWindow` construction.
* **Dock-icon re-show:** a `DockActivateFilter(QObject)` installed on the app with `app.installEventFilter(...)`, handling `QEvent.Type.ApplicationActivate` (verified present) and `ApplicationStateChange` → if the window is hidden, `window.show_from_tray()`. A free-standing filter object rather than a `QApplication` subclass, so the session-scoped `qapp` fixture in `tests/conftest.py:66-76` keeps working and the filter can be fed a synthetic `QEvent` in a test.
* **No `LSUIElement`.** Say this explicitly in the plan and the history: the user wants a normal Dock app that *also* lives in the menu bar. `LSUIElement=1` would remove the Dock icon (breaking the badge in `notify.py` and the Dock-click re-show) and make the app's many `QMessageBox` modals awkward. `packaging/NovelTrans.spec`'s `info_plist` is untouched.

### D8 — Empty state, and finishing while hidden

* Popup with nothing running: one muted label `Không có tiến trình nào đang chạy.` above the two commands. The panel must never be blank — that reads as broken.
* Job finished while the window is hidden: reuse the existing `notify.set_dock_badge(1)` (`notify.py:20-21`) **and** `tray.showMessage("NovelTrans", "Đã xong: Tải truyện — Truyện A")`. The badge is the reliable one — `QSystemTrayIcon.showMessage` on macOS routes through the notification centre and can be silently dropped for an unsigned PyInstaller bundle. Nothing is shown when the window is visible (the tab's own status line already says it).
* Tray tooltip is rebuilt from a pure function `tray_tooltip(jobs) -> str`: `"NovelTrans — 2 tiến trình đang chạy (1 tạm dừng)"` / `"NovelTrans"`.
* `job.total == 0` (e.g. `AudioWorker`'s `progress.emit(0, 0, "Đang tải model VieNeu (~330 MB lần đầu)…")`, `workers.py:582`) → the row's bar goes indeterminate (`setRange(0, 0)`) and the counter cell shows `job.message` instead of `0/0`.

### D9 — Yes to a per-tab pause button, via one shared `PauseButton`

Recommend **yes**. A control reachable only by hiding the window is undiscoverable, and the user will want to pause a translate run while the window is open (e.g. to free the CPU for a video encode). Add `⏸ Tạm dừng` beside the existing `Dừng` in the four tabs that have one: `tab_scrape.py:160`, `tab_translate.py:154`, `tab_audio.py:147`, `tab_video.py:240`.

**They cannot fight**, by construction: both the tab button and the popup row are `PauseButton` instances bound to the same `Job`; both call `job_registry.toggle(job_id)`; both re-label from `job.paused` on `job_registry.job_changed`. `job.paused` is the single source of truth, and neither widget owns state. Likewise the tab's own `QProgressBar` and the popup row are two independent read-only observers of the same `worker.progress` signal — no shared mutable state at all.

`PauseButton(QPushButton)` lives in `gui/widgets.py` alongside the other reusable widgets (`ProjectPicker`, `RowButtonDelegate`, …).

### D10 — `has_running_workers` / `_close_workspace` semantics are unchanged

A paused worker is still `isRunning()`, so `has_running_workers()` (`workspace.py:112-117`) keeps returning True and closing that tab still asks for confirmation — correct: a paused job is unfinished work, and abandoning it silently would be worse. Only the wording changes (`main_window.py:137`): `"Truyện này đang tải/dịch/tạo audio (kể cả khi đang tạm dừng). Đóng tab và huỷ tiến trình?"`. On Yes, `ws.shutdown()` runs; `cancel()` resumes the gate (D2), the worker exits at its checkpoint, `worker.finished` fires and the registry drops the job — the popup row disappears on its own with no extra wiring.

## Implementation steps

Ordered so the app runs and the suite is green after every step.

### 1. `src/noveltrans/gui/pause.py` (new) — the gate, no Qt

`PauseGate` exactly as in D2. Module docstring must state the two rules: *cancel always wins*, and *the wait is bounded so a forgotten `resume()` in `cancel()` degrades to a 200 ms delay, never a hang*. Nothing else in the app imports it yet — write `tests/test_pause_gate.py` now (step 11) and this step is independently green.

### 2. `src/noveltrans/gui/workers.py` — `PausableWorker` base + the checkpoints

* Add `from noveltrans.gui.pause import PauseGate` at the top (no cycle: `pause.py` imports only `threading`).
* Define `PausableWorker(QThread)` after the `_RATE_LIMIT_*` constants (`:33`): `__init__(self, parent=None)` sets `_cancelled = False` and `_gate = PauseGate()`; `cancel()` sets `_cancelled = True` **and calls `self._gate.resume()`** (with a comment naming the shutdown-hang it prevents); `pause()`, `resume()`, `is_paused()` (`self._gate.paused and not self._cancelled`), `_checkpoint()`.
* Re-base `TranslateWorker`, `AudioWorker`, `MergeWorker`, `VideoWorker`, `SubtitleWorker`, `DownloadWorker` (Phase A) and `SubtitleUploadWorker`, `YouTubeUploadWorker`, `PlaylistSyncWorker`, `YouTubeThumbnailWorker` (Phase B) on `PausableWorker`; delete their `self._cancelled = False` lines and `def cancel` bodies. Each `__init__` keeps `super().__init__(parent)`.
* Apply the nine checkpoint edits from the D3 table.

App still behaves identically (nothing calls `pause()` yet).

### 3. `src/noveltrans/gui/jobs.py` (new) — `Job` + `JobRegistry` + the singleton

* `@dataclass class Job`: `id: int`, `kind: str`, `novel: str`, `done: int = 0`, `total: int = 0`, `message: str = ""`, `paused: bool = False`, `worker: object = None`, and a `label` property → `f"{kind} — {novel}"` (or just `kind` when `novel` is blank).
* `JobRegistry(QObject)` with `job_added = Signal(object)`, `job_changed = Signal(object)`, `job_removed = Signal(int)`, an `_id_counter`, and `_jobs: dict[int, Job]` (insertion-ordered → the popup's row order is start order).
  * `register(worker, *, kind: str, novel: str = "", pausable: bool = True) -> Job` — assigns an id, connects `worker.progress` → `_on_progress(job_id, done, total, message)` and `worker.finished` → `_on_finished(job_id)`, emits `job_added`. Guard `worker.isFinished()` (a synchronous worker that already ended) by not registering.
  * `_on_progress` updates the record and emits `job_changed`. Cross-thread → automatically queued onto the GUI thread; no locking needed anywhere in the registry.
  * `_on_finished` pops the record and emits `job_removed(job_id)`, dropping the worker reference.
  * `pause(job_id)` / `resume(job_id)` / `toggle(job_id)` — call `worker.pause()`/`worker.resume()`, set `job.paused`, emit `job_changed`. A job whose `pausable` is False, or whose worker lacks `pause`, is a no-op.
  * `jobs() -> list[Job]`, `running_count()`, `paused_count()`.
* Module singleton `job_registry = JobRegistry()`, plus a `reset()` used only by tests.

### 4. `src/noveltrans/gui/widgets.py` — `PauseButton`

`PauseButton(QPushButton)`: constructed with a `job_id`, listens to `job_registry.job_changed`/`job_removed`, labels itself `⏸ Tạm dừng` / `▶ Tiếp tục`, tooltips `Dừng lại sau khi xong mục đang chạy` / `Chạy tiếp`, `clicked` → `job_registry.toggle(job_id)`, hides/disables itself when its job disappears. A `set_job(job_id | None)` so a tab can rebind it across runs.

### 5. Tab wiring — registration + the in-window pause button

For `tab_scrape.py`, `tab_translate.py`, `tab_audio.py`, `tab_video.py`: add `self.pause_button = PauseButton()` next to `cancel_button` in the same row layout (`tab_scrape.py:170`, `tab_translate.py:164`, `tab_audio.py:164`, and the video tab's button row near `:240`), disabled/hidden until a job is registered, rebound on each launch, cleared in each `_reset_*_ui()` / `_on_*_finished`.

### 8. `src/noveltrans/gui/main_window.py` + `src/noveltrans/app.py` — quit semantics

* `def show_from_tray(self)`: `showNormal(); raise_(); activateWindow(); clear_dock_badge()`.
* `def shutdown_all(self)`: save geometry if `self.isVisible()`, then the existing `ws.shutdown()` loop; idempotent (guard with a `_shut_down` flag) so it's safe on both the `aboutToQuit` and the no-tray `closeEvent` paths.

* `_close_workspace`'s confirm text per D10.

## Edge cases & risks

1. **Pause → cancel → hang (the headline risk).** `cancel()` must call `_gate.resume()`. Every `shutdown()` in the four tabs does `cancel(); wait(30_000…120_000)`. Pinned by a parametrized test over all ten worker classes.
2. **Pause → quit.** `app.aboutToQuit` → `window.shutdown_all()` → per-tab `shutdown()` → `cancel()` → gate released. Same mechanism as (1); test it via `shutdown_all` on a `MainWindow` whose workspace holds a fake paused worker.
3. **Hide must not shut down.** The single largest regression risk: `closeEvent` currently calls `ws.shutdown()` on every workspace (`main_window.py:224-228`), which cancels and joins. Test asserts `ws.shutdown` is **not** called on a hide.
4. **Unquittable app.** If a tray fails to install and `hide_to_tray_enabled` were True anyway, the red button would hide the only window forever with `quitOnLastWindowClosed(False)`. The flag is owned by `TrayController` and set only after `tray.show()`. Test the False branch.
5. **`AudioWorker` parallel pause holds partial results.** Pausing at the top of `while inflight:` lets up to `n_workers - 1` in-flight chapters finish; their WAVs are on disk but not yet committed to sqlite. They commit on resume. On cancel-while-paused the existing `finally: pool.shutdown(wait=True)` drains them and the `"cancelled"` results are skipped without a write (`workers.py:794-795`) — unchanged semantics.
6. **Deadline blowout if anyone gates inside ffmpeg.** `merge.py:175` and `video.py:669` compute their deadline *before* the wait loop. Add an explicit comment at both `cancelled` call sites saying "do not gate pause here" so a future reader doesn't 'fix' D3.
7. **Registry vs `deleteLater`.** `_close_workspace` deletes the workspace widget; the registry holds only the `QThread` and strings, and drops the thread on `finished`. Assert "no widget references" in a test.
8. **`worker.finished` during teardown.** On `aboutToQuit` the event loop is winding down, so a queued `job_removed` may never be delivered. Harmless (we're exiting), but `JobPopup` must tolerate a stale row on teardown — it never dereferences `job.worker`.
9. **Two workspaces, same tab kind, same novel name.** Rows are keyed by `job.id`, not by label; duplicates are fine and expected.
10. **`tray.geometry()` empty** (rare, or offscreen) → `popup_at` falls back to the cursor position, clamped to the screen.
11. **`showMessage` silently dropped** on an unsigned PyInstaller bundle. The dock badge is the reliable signal; never rely on the notification alone.
12. **`ScrapeTab._resume_timer`** (`tab_scrape.py:70-74`) fires `_launch_download` 6 s after a Discord unlock. If the user pauses during that window, the timer relaunches a *new* worker which registers a *new* job that is not paused. Acceptable (it's a fresh batch), but note it — the alternative, propagating paused-ness across the unlock resume, is scope creep.
13. **Popup shown from a background app on macOS.** `raise_()` + `activateWindow()` after `show()`; verify manually — offscreen can't tell you.
14. **Session-wide `setQuitOnLastWindowClosed(False)`.** The `qapp` fixture is session-scoped; any test that flips it must restore it. Keep the call in `app.main()` only, never in `MainWindow`.

## Test plan

Plain pytest, no pytest-qt; session-scoped offscreen `qapp` from `tests/conftest.py:66-76`; widgets built directly and private methods called; `_isolate_app_config` is autouse. Model the fake-worker pattern on `tests/test_keep_awake.py::test_track_worker_acquires_and_releases_on_finished` (a `QObject` with the right signals). Baseline **1264**; expect **≈+60**.

**`tests/test_pause_gate.py` (new — pure, no Qt)**
* Not paused → `wait()` returns immediately.
* `pause()` then a background thread calling `wait()` blocks; `resume()` releases it within ~0.3 s.
* **`wait()` returns while paused as soon as `cancelled()` becomes True** (the deadlock case) — assert it returns inside 1 s with the gate still paused.
* Double `pause()` / double `resume()` are idempotent; `resume()` on a never-paused gate is a no-op.
* `paused` reflects state.

**`tests/test_workers_pause.py` (new)**
* Parametrized over all ten pausable worker classes: construct with minimal args, `w.pause(); assert w.is_paused(); w.cancel(); assert not w._gate.paused` — **pins "cancel resumes the gate" forever**.
* A tiny `PausableWorker` subclass whose `run()` iterates a list calling `_checkpoint()`: it stops progressing while paused, resumes where it left off (no item repeated, none skipped), and exits promptly when cancelled while paused.
* `is_paused()` is False once cancelled.

**`tests/test_job_registry.py` (new)**
* `register` adds a job, emits `job_added`, assigns increasing ids.
* `progress(done, total, msg)` updates the record and emits `job_changed`.
* `finished` removes the record, emits `job_removed`, and drops `job.worker`.
* `toggle` flips `job.paused` and calls the worker's `pause`/`resume`.
* `toggle`/`pause` on an unknown or already-finished id is a no-op.
* `pausable=False` job is never paused.
* `jobs()` preserves start order; `running_count`/`paused_count` are right with a mix.
* Registering a worker that is already finished does nothing.

**`tests/test_job_popup.py` (new)**
* One row per job; row label is `"Tải truyện — Truyện A"`; counter reads `142/200`.

* `job_added` inserts a row, `job_removed` deletes it, `job_changed` updates in place without rebuilding.
