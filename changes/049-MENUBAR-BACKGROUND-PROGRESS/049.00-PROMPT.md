# 049 — Menu-bar background running, with progress and pause/resume

> close the app as the bar in the macmini, when click on the app on the bar, it will
> show the progress bar; add the pause and continue to pause and continue the progress

## Reading of the request

Running on a Mac mini, long jobs (download / translate / audio / video) take hours. The
window should not have to stay open in the way for that whole time.

1. **Closing the window sends the app to the macOS menu bar** instead of quitting — the
   running job keeps going.
2. **Clicking the menu-bar icon shows the progress** of whatever is running.
3. **Pause and continue** — the running job can be paused and resumed.

## Decisions (answered 2026-07-31)

* **Menu-bar icon opens a popup panel.** One row per running job — label, progress bar,
  counter, and a `⏸ Tạm dừng` / `▶ Tiếp tục` button — plus `Mở cửa sổ` and `Thoát`:

  ```
  ☰ NovelTrans
  ┌──────────────────────────────┐
  │ Tải truyện — Truyện A        │
  │ ████████░░░░░  142/200       │
  │            [⏸ Tạm dừng]      │
  ├──────────────────────────────┤
  │ Nghe audio — Truyện B        │
  │ ██░░░░░░░░░░░   12/95        │
  │            [▶ Tiếp tục]      │
  ├──────────────────────────────┤
  │ Mở cửa sổ                    │
  │ Thoát                        │
  └──────────────────────────────┘
  ```

* **Pause holds after the current chapter**, it does not interrupt mid-item. The worker
  finishes the chapter it is on, then waits at the existing between-chapter checkpoint.
  Nothing is half-written and resuming is instant; the cost is that pause isn't always
  immediate (a TTS chapter can take ~a minute).

* **Closing the window ALWAYS hides to the menu bar**, whether or not a job is running.
  Quitting is only via `Thoát` in the popup. (Chosen over "only while running" — accepted
  trade-off: the app can sit idle in the menu bar unnoticed.)

* Pause/resume covers the long batch workers (download, translate, audio, merge, video,
  subtitles) — not the short metadata fetches.
