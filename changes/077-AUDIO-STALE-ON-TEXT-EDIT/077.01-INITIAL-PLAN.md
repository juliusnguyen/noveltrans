# 077 — Audio goes stale when its text changes — Implementation Plan

## 1. The gap, in code

- `NovelProject.edit_translation` writes only `translated` / `translated_title`. It never
  touches `audio_path`, so a generated file keeps narrating the old text.
- `NovelProject.pending_audio` treats a chapter as done unless it has **no** audio, a
  **different voice**, or a **different source**. There is no notion of the text having
  changed, so even "Tạo audio tất cả" skips it.
- It cannot be derived from what is stored: `edit_translation` and `save_audio` both stamp
  the same `updated_at` column, so "was the text edited after the audio was made?" is
  unanswerable today.
- `AudioWorker._title_text_for` returns `(title, text)` and `synthesize_chapter` voices
  **both**, so a title edit invalidates audio exactly as a body edit does. `slugify(title)`
  is also in the audio filename.

## 2. Approach — fingerprint what was voiced, not "who edited it"

Record, at generation time, a hash of the exact `(title, text)` pair the audio was made
from. A chapter is stale when its **current** text hashes differently.

The alternative — set a `needs_audio` flag from each edit site — was rejected. The text
reaches the DB through `edit_translation`, `save_translation`, `save_rewrite`,
`restore_translation`, `apply_replacements`, `edit_content` and `edit_title`, and the
next feature will add an eighth. A flag needs every one of them to remember; a fingerprint
needs none of them to know it exists, and is automatically right for writers that do not
exist yet. It is also correct for the edit-then-undo case, which a flag gets wrong.

## 3. Changes

### `src/noveltrans/models.py`

- `Chapter.audio_text_hash: str = ""` — the fingerprint of what the audio was voiced from.
- `Chapter.audio_fingerprint(use_translation=None) -> str` — hash of the `(title, text)`
  pair for a source. `None` means "use `self.audio_source`", so a row can judge itself.
  It must return the **same pair** `AudioWorker._title_text_for` builds; that function
  becomes a thin call into this one so the two cannot drift.
- `Chapter.audio_is_stale -> bool` — `has_audio` and not downloaded and
  `audio_text_hash` non-empty and `audio_text_hash != audio_fingerprint()`.

**An empty stored hash means "unknown", never "stale".** Every row in every existing
library has one, and flagging them would tell the user their whole novel needs re-voicing.

### `src/noveltrans/storage/project.py`

- Schema + `_migrate`: `audio_text_hash TEXT NOT NULL DEFAULT ''`.
- `save_audio(..., text_hash="")` records it. Narration downloaded from the source site is
  not made from this text, so that path stores nothing and can never go stale.
- `pending_audio` gains the staleness arm. The hash cannot be computed in SQL, so:
  1. today's query → chapters with no audio / wrong voice / wrong source;
  2. a second query over rows that *have* audio with a non-empty hash → keep those whose
     fingerprint no longer matches;
  3. union, ordered by `idx`.
  Step 2 reads text only for already-voiced chapters, and `pending_audio` runs once per
  job — `project.chapters()` already loads every body on each tab switch.
- `clear_audio` clears the hash with the rest.

### `src/noveltrans/gui/workers.py`

`AudioWorker` passes `chapter.audio_fingerprint(self.use_translation)` to `save_audio`,
computed from the text it actually handed to the engine.

### `src/noveltrans/gui/widgets.py`

- `_audio_status` gains `"Cần tạo lại"` between `"Đã tạo"` and the not-done labels, with
  the `STATUS_DOWNLOADED` colour — it is actionable, not an error.
- `_AUDIO_RANK` renumbered so pipeline order holds: `Lỗi` 0, `Chưa dịch`/`Chưa tải` 1,
  `Chưa tạo` 2, `Cần tạo lại` 3, `Đã tạo` 4, `Đã tải` 5. Sorting by status must group the
  two "needs a TTS run" states together.

## 4. What deliberately does not change

- **No auto-regeneration.** Per the user's decision: editing marks stale, the next run
  picks it up. The old file stays playable meanwhile and no TTS starts mid-edit.
- **Downloaded narration is never stale.** It is a different edition, not a render of this
  text; `pending_audio` already excludes it and `save_audio` will not fingerprint it.
- **Existing audio is never retroactively stale** — see the empty-hash rule above.

## 5. Tests

- `tests/test_audio_staleness.py` — `Chapter.audio_fingerprint` / `audio_is_stale`:
  title-only edit, body-only edit, edit-and-undo (not stale), original-vs-translation
  sources, downloaded audio, and the empty-hash rule.
- `tests/test_project_pending_audio_stale.py` — a stale chapter reappears in
  `pending_audio`, a fresh one does not, a legacy row with no hash does not, downloaded
  narration never does, and `clear_audio` resets it.
- Extend the audio-model tests for the new label and the sort rank.
- A worker-level test that `save_audio` is called with the fingerprint of the text that was
  actually voiced.

## 6. Verification

- `QT_QPA_PLATFORM=offscreen python -m pytest`
- `ruff check src tests`
- Dry run on a **copy** of the real library: confirm zero chapters become stale purely by
  upgrading (the empty-hash rule), and that a simulated edit makes exactly one stale.
