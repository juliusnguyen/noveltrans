# 045 — Remember previously-used library folders — history

## The ask

> save the link of used `Thư mục thư viện`

Clarified: keep the folders that have been used, so switching between libraries doesn't
mean browsing for the path each time.

## [IMPLEMENTATION] — 2026-07-29

1091 tests pass (1081 before, +10), ruff clean.

### `config.py`

`library_dir_history` (most recent first, deduped, capped at `MAX_LIBRARY_HISTORY = 8`),
and `forget_library_dir`.

Recording happens **inside the `library_dir` setter**, not in the settings dialog, so the
history cannot drift from what was actually used: every path that becomes the library ends
up in the list, whatever set it.

Two guards worth naming:
- An empty value is ignored entirely. Saving the dialog with a blank box must not strand
  someone with no library at all, nor put `""` in the list.
- `QSettings` collapses a one-item list to a bare string on read. Without the `isinstance`
  check that string iterates into single characters, and the dropdown fills with `/`,
  `U`, `s`, `e`, `r`…

### `gui/settings_dialog.py`

The field becomes an **editable** `QComboBox` seeded from the history — a path not in the
list can still be typed or pasted, exactly as before. Same call as the playlist picker in
039: the list is an aid, not a gate.

## The pre-existing bug this uncovered

After adding the history I printed what the dropdown would show on this machine. Every
entry was a **pytest temp directory**, and the active library was one too.

`tests/test_tab_scrape.py::_tab_with_project` builds a real `AppConfig()` — which is
`QSettings("noveltrans", "noveltrans")` — and assigns `config.library_dir`. So **running
the test suite silently repointed the real app at a directory that ceases to exist the
moment pytest cleans up.**

That behaviour predates this feature by a long way. It was invisible because a single
overwritten path looks like nothing; the history made it show up as eight obviously-wrong
entries at once.

### The fix, and a false start

`QSettings.setDefaultFormat(IniFormat)` + `setPath` was the obvious approach and **does not
work here** — measured directly:

```
format: Format.NativeFormat   fileName: ~/Library/Preferences/com.noveltrans.noveltrans.plist
leaked into native?: hello
```

The format stays native and the write still lands in the real plist. So `conftest.py` now
patches `AppConfig.__init__` to point at a per-test ini file instead. Per-test rather than
per-session, so settings written by one test cannot leak into the next either.

Verified by resetting the real settings, running the full suite, and re-reading them:
`library_dir` unchanged, history empty.

The developer's real settings were also repaired: `library_dir` restored to
`~/NovelTrans` (12 projects), the junk history removed, and a stray `probe` key from the
diagnostic cleaned up.

### Why this is worth recording

The feature that found it had nothing to do with tests. It surfaced because a new UI
element **displayed state that had always been wrong**, and wrong state is much easier to
see than absent state. Making something visible is its own kind of test.
