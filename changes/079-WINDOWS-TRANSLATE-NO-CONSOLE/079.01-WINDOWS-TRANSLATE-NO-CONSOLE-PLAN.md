# Implementation Plan: Windows Console Flash on Translate (079-WINDOWS-TRANSLATE-NO-CONSOLE)

## Root cause and existing pattern to reuse

`src/noveltrans/runtime_env.py` (lines 126-138) already defines the exact helper needed:

```python
def no_console_kwargs() -> dict:
    """Extra `subprocess.run`/`Popen` kwargs to stop a spawned console app flashing a window."""
    if sys.platform == "win32":
        return {"creationflags": getattr(subprocess, "CREATE_NO_WINDOW", 0x08000000)}
    return {}
```

This was added in `changes/052-TAG-LIMIT-AND-FFMPEG-CONSOLE` (see `changes/052-TAG-LIMIT-AND-FFMPEG-CONSOLE/052.01-HISTORY.md` lines 21-35) and threaded into all 8 ffmpeg/ffprobe call sites across `tts/convert.py`, `tts/subtitles.py`, `tts/video.py`, `tts/merge.py`. Critically, that same history file explicitly flags the gap this feature is closing (lines 40-42):

> "Explicitly out of scope (flagged, not touched): `src/noveltrans/translators/cli_agent.py`'s `subprocess.run` call shares the same console-flicker root cause but wasn't named in the original request — a natural follow-up using the same `no_console_kwargs()` helper."

So this is a pre-planned follow-up, not a new design decision. The fix is: import `no_console_kwargs` into `cli_agent.py` and spread `**no_console_kwargs()` into its `subprocess.run` call, exactly like the ffmpeg call sites do. No new helper, no new pattern — reuse verbatim.

## Step-by-step implementation

1. **`src/noveltrans/translators/cli_agent.py`** (smallest diff, ships the reported fix):
   - Add `from noveltrans.runtime_env import no_console_kwargs` to the imports.
   - In `complete()`, add `**no_console_kwargs()` to the `subprocess.run(...)` call at line 162-170 (same kwarg-spread style already used in `tts/convert.py`/`tts/subtitles.py`/`tts/video.py`).
   - No platform `if` needed in this file — `no_console_kwargs()` itself is the Windows-only guard, returning `{}` on macOS/Linux.

2. **`src/noveltrans/gui/workers.py`** (audit-driven follow-up, same defect class):
   - `CliModelsWorker.run()` currently does a local `import subprocess` (line 552) rather than a module-scope import; check whether `subprocess` is deferred there for a reason (e.g. avoiding a slow import at module load). Import `no_console_kwargs` at module scope if consistent with other fixed files, or co-located with the local `import subprocess` if there's a reason it's deferred.
   - Add `**no_console_kwargs()` to the `subprocess.run(...)` call at line 555-562.

3. **Tests** — extend `tests/test_translators.py::TestCliAgent`:
   - Follow the exact existing mocking pattern (`patch("noveltrans.translators.cli_agent.subprocess.run")`, `mock_run.call_args.kwargs[...]`, `_result()` helper) — see `test_translate_runs_command_with_prompt` (lines 163-178), which already asserts on `mock_run.call_args.kwargs["cwd"]`.
   - Add `test_passes_no_console_kwargs_on_windows`:
     - `monkeypatch.setattr("noveltrans.runtime_env.sys.platform", "win32")` — note `cli_agent.py` doesn't import `sys` itself; `no_console_kwargs()` reads `runtime_env.sys.platform`, so patch that target (matching `tests/test_runtime_env.py::TestNoConsoleKwargs`, lines 191-192, 200-201).
     - Patch `subprocess.run`, call `engine.translate(...)`/`engine.complete(...)`, assert `mock_run.call_args.kwargs["creationflags"] == getattr(subprocess, "CREATE_NO_WINDOW", 0x08000000)`.
   - Add a companion test asserting no `creationflags` key when platform is `"darwin"`, mirroring `TestNoConsoleKwargs.test_empty_on_other_platforms`.
   - Optionally add a small test for `CliModelsWorker` (check `tests/test_workers_*.py` naming convention, e.g. `test_workers_rewrite.py`) verifying `no_console_kwargs()` is spread into its `subprocess.run` call the same way. Secondary since it's not the reported symptom.
   - Do NOT add a new test to `tests/test_runtime_env.py` — `no_console_kwargs()`'s own win32/non-win32 branches are already fully covered there (`TestNoConsoleKwargs`, lines 186-203); new tests only need to prove the two new call sites *pass it through*.

4. **Verification**:
   - Run the full test suite (`pytest -q`) to confirm no regressions; run `ruff check` on every changed file, matching the verification pattern in `052.01-HISTORY.md`.
   - Actual console-window suppression is OS chrome and not unit-testable — flag manual verification (run from source or a Windows build, translate a chapter/batch via a CLI engine, confirm no console flash) as a follow-up manual check, consistent with how 052 handled the same limitation for ffmpeg.

## Ordering rationale

Step 1 (`cli_agent.py`) is the smallest, most targeted diff and directly fixes the reported bug — ship it first/independently. Step 2 (`gui/workers.py`) is the audit-driven follow-up for the same defect class. Tests should land with each corresponding code change rather than batched at the end, so each commit is independently verifiable.
