# 075 — Dịch: multi-select + right-click "Dịch" — Implementation Plan

## 1. Current behaviour and the gap

Tab: `src/noveltrans/gui/tab_translate.py` (`TranslateTab`).

- The chapter table (`self.table`) is a `QTableView` over `ChapterTableModel` behind a sort
  proxy, `SelectionBehavior.SelectRows`.
- `enable_cell_copy(self.table, extra_actions=self._table_context_actions)`
  (`widgets.py:896`) already sets `SelectionMode.ExtendedSelection`, so drag / Ctrl+click /
  Shift+click multi-row selection **already works** — and `focus_index_keeping_selection`
  (added by feature 057) already keeps that selection alive when the right-click lands
  inside it.
- `_table_context_actions` already builds its items from `source_rows(self.table)`, so a
  multi-row menu is an established shape in this very method — it just has no translate item.
- Translation entry points today:
  - `Dịch tất cả` → `_start_translate()` (pending only)
  - `Dịch lại từ đầu` → `_retranslate_all()` (clear everything, then all)
  - per-row `↻ Dịch lại` delegate button → `_retranslate_row(index)` → `_start_translate(indices=[i])`
  - `NameGlossaryDialog` → `_retranslate_indices(indices)` (clear those, reload, translate those)
- `TranslateWorker` with an explicit `indices` list (`workers.py:227-229`) resolves them via
  `project.chapter(i)`, keeps only those with `content`, and **overwrites regardless of an
  existing translation** — it bypasses `pending_translation` entirely.

**The gap:** nothing offers the selection to the translator. Re-translating twenty chapters
means twenty clicks on the per-row button.

## 2. Design

Mirror feature 057 (audio) one-for-one, because the two tabs' tables are the same widget with
the same helpers — a second shape here would be gratuitous.

### `src/noveltrans/gui/tab_translate.py`

1. **`TRANSLATE_CONFIRM_FROM = 5`** (module level). Batches of 5+ confirm first; 1-4 do not,
   so the per-row `↻` button stays a one-click action. Same constant name/value as
   `tab_audio.REGENERATE_CONFIRM_FROM`.

2. **Explicit `setSelectionMode(ExtendedSelection)`** on the table. Redundant with
   `enable_cell_copy` today, but the tab now *depends* on it, so state it at the point of use
   (this is what 057 did for the audio table).

3. **`_selected_rows() -> list[int]`** — `source_rows(self.table)`; model rows, ascending,
   deduped (`selectedIndexes()` yields one index per *cell*). `_table_context_actions`
   switches to it so there is one accessor.

4. **`_translatable_indices(rows) -> tuple[list[int], int]`** — the only place that converts
   table rows to `chapter.index`. Drops chapters with no `content` (the worker drops them
   anyway, so counting them would overstate the job and leave `progress.setMaximum` lying)
   and returns how many were dropped. Sorted ascending: `TranslateWorker` walks `indices` in
   order.

5. **`_translate_rows(rows)`** — the shared path:
   - guard: no project → the tab's standard `QMessageBox.information`
   - guard: `self._busy()` → `self.status_label.setText(self._busy_message())`
     (`_busy` already covers *both* the translate and rewrite workers — the two must not
     overlap, they write the same rows)
   - nothing translatable → status line telling the user to download the chapters first
   - `len(indices) >= TRANSLATE_CONFIRM_FROM` → confirm, wording the overwrite
   - report skipped chapters on the status line
   - `self._start_translate(indices=indices)`

6. **`_retranslate_row`** becomes a one-line wrapper over `_translate_rows`, so the per-row
   button and the batch cannot drift apart. This also gives the button the status-line
   feedback it lacks today (it currently returns silently on a chapter with no content).

7. **`_table_context_actions`** gains the translate item, added **before** the rewrite items —
   translating is the tab's primary verb, and 057 established that a tab's menu lists its
   actions in the same order the button row does.
   - Built from the selection with the same "right-clicked outside the selection → act on
     that row" rule the rewrite items already use.
   - Hidden when nothing in the selection has source text.
   - Disabled with a tooltip while `_busy()`.
   - Label follows what the action will actually do:
     - every target already translated → `↻ Dịch lại chương này` / `↻ Dịch lại N chương`
       (matches the per-row button)
     - otherwise → `🔤 Dịch chương này` / `🔤 Dịch N chương`
   - The rows are snapshotted and re-resolved at trigger time, so `_translatable_indices`
     stays the single authority on eligibility.

**No `clear_translations()` step, deliberately.** `TranslateWorker` with explicit `indices`
already overwrites — which is what the existing per-row retranslate relies on. Clearing first
would blank good rows that then fail (leaving "Chưa dịch" and a lost translation) and would
force a `set_chapters()` model reset that drops the user's selection mid-batch.
`_retranslate_indices` (the glossary path) clears on purpose — it is undoing a *name* change
and wants the rows visibly pending — and is left alone.

## 3. Tests — `tests/test_tab_translate_multiselect.py` (new)

Following `tests/test_tab_audio_multiselect.py`:

- `_selected_rows` dedupes cells and returns model rows under a sort.
- `_translatable_indices`: row→chapter.index conversion, drops chapters with no content and
  counts them, sorted output.
- Menu: label singular vs. plural; `Dịch lại` vs. `Dịch` per translated state; absent when
  nothing has content; disabled while a translate worker runs; disabled while a *rewrite*
  worker runs; right-click inside the selection acts on all of it, outside collapses to the
  clicked row.
- `_translate_rows`: one worker for N rows with the right `indices`; skip-and-report; both
  confirm paths (accept and decline); the busy guard; the no-project guard.
- `_retranslate_row` still translates exactly the clicked chapter through the shared path.

Drive `focus_index_keeping_selection` directly rather than emitting
`customContextMenuRequested`: the real path ends in a modal `menu.exec()`, and
`monkeypatch.setattr(QMenu, "exec", ...)` does not take on a PySide6 class — the run hangs
(recorded in 057's history).
