## [IMPL] Multi-select translate in the Dịch tab — 2026-09-03

Implemented the plan. Much of the groundwork was already in place from feature 057 (the
audio tab's equivalent): `enable_cell_copy` puts the table in `ExtendedSelection`,
`focus_index_keeping_selection` stops a right-click from collapsing the selection, and
`RowButtonDelegate.editorEvent` already ignores right-clicks. Nothing in those files
needed touching — this feature is confined to `tab_translate.py` plus its new test file.

### `src/noveltrans/gui/tab_translate.py`

- `TRANSLATE_CONFIRM_FROM = 5` (module level). 5+ chapters confirm first; 1-4 just run, so
  the per-row `↻ Dịch lại` button stays a one-click action. Same value and role as
  `tab_audio.REGENERATE_CONFIRM_FROM`.
- Explicit `setSelectionMode(ExtendedSelection)` on the table. Redundant with
  `enable_cell_copy` today, but the menu now *reads* that selection, so it is stated at
  the point of use rather than left as an implicit gift from a helper.
- New `_selected_rows()` — `source_rows(self.table)`; model rows, ascending, deduped
  (`selectedIndexes()` yields one index per *cell* under `SelectRows`).
- New `_translatable_indices(rows) -> (indices, skipped)` — the only place converting table
  rows to `chapter.index`. Drops chapters with no downloaded `content` and counts them:
  `TranslateWorker` filters those out anyway, so including them would overstate the job and
  leave `progress.setMaximum` lying. Sorted, because the worker walks `indices` in order.
- New `_translate_rows(rows)` — the shared path: no-project guard, `_busy()` guard,
  "nothing has source text" status line, confirm at 5+, skip report, then
  `_start_translate(indices=...)`.
- `_retranslate_row` is now a one-line wrapper over it, so the per-row button and the batch
  cannot drift apart on the guards. Side effect worth keeping: the button used to `return`
  silently on a chapter with no content and now says why on the status line.
- `_table_context_actions` split into `_menu_rows(index)` + `_add_translate_action` +
  `_add_rewrite_actions`. The clicked-row-vs-selection rule lived inline and was about to
  be needed twice; `_menu_rows` is that rule, named once.
- Translate is added **before** the rewrite items — it is the tab's primary verb, and the
  button row below lists it first too.
- Label follows what the click will actually do: `↻ Dịch lại …` (matching the per-row
  button) only when every target already has a translation to replace, otherwise
  `🔤 Dịch …`. A mixed selection is a first pass for at least one chapter, and calling that
  "Dịch lại" would be simply wrong.
- Disabled with a tooltip while `_busy()` — which covers the **rewrite** worker too, not
  just translation. The two write the same rows and must never overlap.

**No `clear_translations()` step, deliberately.** `TranslateWorker` with an explicit
`indices` list re-translates regardless of an existing translation (`workers.py:227-229`
bypasses `pending_translation`) — which is what the existing per-row retranslate already
relies on. Clearing first would blank good rows that then fail, and the `set_chapters()`
reset it needs would drop the user's selection mid-batch. Recorded as a code comment so it
does not get "fixed" later. `_retranslate_indices` (the name-glossary path) still clears on
purpose — it is undoing a *name* change and wants those rows visibly pending — and is
untouched.

### `tests/test_tab_translate_multiselect.py` (new, 28 tests)

Covers the selection helpers, the row→index conversion and its skip count, the menu's
label/verb/ordering/visibility/disabled state (both workers), the tooltip, one-job-for-N-rows,
skip-and-report, all three confirm paths, both guards, and the per-row button both when it
works and when the chapter has no text.

Built over a real `Library` project rather than a fake, like `test_tab_translate_rewrite.py`,
because the label logic reads `chapter.translated` and the skip logic reads `chapter.content` —
a stub would only be testing the stub.

Menu tests call `_table_context_actions` directly rather than emitting
`customContextMenuRequested`: the real path ends in a modal `menu.exec()`, and
`monkeypatch.setattr(QMenu, "exec", ...)` does not take on a PySide6 class — the patch is
silently ignored and the run hangs (recorded in 057's history).
