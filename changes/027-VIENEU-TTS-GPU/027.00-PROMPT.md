# 027 — VieNeu-TTS on GPU

## Request

Support running VieNeu-TTS on GPU, as an alternative to the current CPU/ONNX path.

Upstream describes the option as:

> **GPU — v3 Turbo on GPU (PyTorch)**
>
> Requires a CUDA NVIDIA GPU (CUDA ≥ 12.8) or Apple Silicon MPS. NVIDIA Toolkit
> recommended. Adds the PyTorch stack so v3 Turbo runs on GPU — inference is
> batched automatically on CUDA (same API, no code change).

Two things to deliver:

1. **Check whether this machine can run the GPU option.**
2. **Expose CPU and GPU as two options in Settings.**

## Machine capability check (done up front)

| | |
|---|---|
| Chip | Apple M4 (10-core GPU), arm64 |
| Memory | 24 GB unified |
| OS | macOS 26.5.2 |
| Python | 3.12.13 (`.venv`) |
| NVIDIA / CUDA | none — Apple Silicon has no CUDA |
| PyTorch installed | no (`torch` not in the venv today) |

**Verdict: yes, via the Apple Silicon MPS path — not CUDA.**

Consequences to keep in mind while implementing:

- MPS is the only GPU backend available here. The "batched automatically on
  CUDA" speedup in the upstream blurb does **not** apply to this machine;
  expect single-sample GPU inference.
- `torch` is not currently a dependency. The GPU option means adding the
  PyTorch stack as an *optional* extra — it must not become a hard requirement
  for the existing CPU users, and it must not bloat the packaged `.app` by
  default (see `packaging/`, `make app`).
- Current engine (`src/noveltrans/tts/vieneu.py`) is explicitly documented as
  "torch-free ONNX runtime", and `pyproject.toml` declares the `tts` extra as
  `vieneu>=3.0`. Both need a second, GPU-flavoured path rather than a rewrite.

## Scope

- Settings: a CPU / GPU choice for the TTS engine, persisted via
  `src/noveltrans/config.py`.
- Detect at runtime what the machine actually supports (CUDA / MPS / neither)
  and surface that in the UI — don't let the user pick GPU on a box that can't
  do it, or at least fail loudly and fall back to CPU.
- Wire the selection through `src/noveltrans/tts/vieneu.py` and the audio
  worker path (`src/noveltrans/gui/workers.py`, `tab_audio.py`).
- Optional-dependency plumbing in `pyproject.toml` so the PyTorch stack is
  installed only when the user wants GPU.
- Reflect the parallel-worker behaviour (see 014) — GPU + N CPU workers may
  need different defaults.

## Open questions

- Should GPU be auto-selected when available, or stay opt-in with CPU default?
- Does the packaged `.app` ship the GPU path at all, or is it install-from-source only?
