index page and three chapter pages into the scratchpad (nothing from the probe is

* **Cloudflare.** `curl` with our desktop UA → HTTP 403, `cf-mitigated: challenge`.
  `BrowserSession` cleared it on the first navigation and served 4 URLs with no
  interstitial. Same transport as `twkan.py` / `novel543.py`; there is no token to replay.
* **One page is both detail and TOC**: `/novel/chapters/<slug>/index.html`. Chapters are
  `/novel/chapters/<slug>/<n>.html`, where `<n>` is the 1-based reading position.
* **Full OpenGraph block** on the index page. But `og:description` is SEO boilerplate, not
  a synopsis — the real blurb is the visible `div.description p` (site-truncates it).
* **Two `div.chapters_frame` blocks**, each after an `h3.chapters_title`: `最新章節`
  (latest ~16, *descending*) and `全部章節` (all 925, ascending). A flat `a[href]` scrape
  returns 942 links — 925 real, 16 duplicates and one `index.html` self-link. No
  pagination: the whole TOC ships in one document.
* **Two `div.content`** on a chapter page: the body (~93 `<p>`, with `div.txtad`,
  `a.anchor_bookmark`, `<script>`, `div.div_feedback`, `div.social_share_frame` interleaved
  *mid-prose*) and the prev/next nav (`div.prev_page` + `div.next_page`). No chapter
  pagination.
* **An injected site promo sits inside one prose `<p>` per chapter**, behind `<br/><br/>`,
  with the site's domain written in Unicode mathematical-alphanumeric letters that vary per
  chapter. Measured: `unicodedata.normalize("NFKC", …)` folds every observed variant to the
  same plain ASCII domain, and because the promo is behind `<br>` it lands on its own line
  under `get_text("\n")` — so line-level stripping cannot eat prose.
* **No truncation or paywall signals.** Bodies render complete; nothing is lazy-loaded.
  No 字數-style completeness guard will be built (see `twkan.py` and commit `1f9eb6f`).

## [IMPL] The adapter — 2026-09-11

New `src/noveltrans/scrapers/ttks.py`, registered in `scrapers/__init__.py`, with
`tests/test_scrapers_ttks.py` (100 offline tests + 5 live) and hand-built fixtures in
`tests/fixtures/ttks/`. Transport ported from `twkan.py`, TOC handling from `novel543.py`.

**One page is both the detail page and the full TOC**, so a whole scan is *one* browser
navigation — `fetch_metadata` and `fetch_chapter_list` share a cached fetch. That matters on
a Cloudflare host, where each navigation is another chance at an interstitial.

**Trap 1 — the decoy chapter block.** The index carries two `div.chapters_frame` with
*identical* classes, separated only by the text of a preceding `h3` (最新章節 / 全部章節), and
the first runs backwards. A flat scrape returns 942 links for 925 chapters, last-first.
*Anchoring on the heading text was considered and rejected*: novel543 can anchor on `ul.all`
because that is a class, a semantic token; here the only discriminator is site copy, and the
decoy's length is no better an anchor (bqg5 measured its equivalent at 9 entries once and 5
the next time). Ported novel543's answer instead — key every anchor by the reading position in
its own URL. Dedupe, ascending order, the `index.html` self-link and a foreign novel's
recommendation link all fall out of the key, then `positions == [1..N]` proves the result is a
dense prefix. Live: 925 chapters, contiguous.

**Trap 2 — two `div.content` per chapter**, the second being prev/next navigation. The body
comes first today, so `select_one` is right by luck. Rule used instead is conjunctive and
non-positional: holds a `<p>`, holds no `div.prev_page`/`div.next_page`.

**Trap 3 — an advert spliced into the middle of a real paragraph**, behind `<br/><br/>`, with
the domain written in a Unicode mathematical alphabet that changes per chapter (three
spellings observed). Measured: NFKC folds all three to plain `ttk.tw`, and because the advert
sits behind a `<br>` it lands on its own line under `get_text("\n")` — so it is removable a
whole line at a time and can never take prose with it. **`novel543.py:398`'s
`p.get_text(strip=True)` must not be ported**: it glues the advert onto the prose sentence,
and a filter that has to cut a clause out of a line is where over-deletion starts.

*Stripped at scrape time rather than left to `translators/ads.py`*, so the stored original is
clean and the translator never sees the line. Measured both directions: `ads._is_ad_line` is
**True** for all three real Chinese adverts (so `ads.py` remains a genuine second net) but
**False** for a plausible Vietnamese translation of one, because `ads.py:189` folds with NFKC
*before* testing whether the domain survived de-obfuscation — so NFKC obfuscation is invisible
to its obfuscation conjunct. That gap is documented and left to `ads.py`'s own feature.

**Two bugs the tests caught, both of which had been silently passing:**

1. *`og:` tags are written `name=`, not `property=`.* This is a Nuxt/AMP page and emits
   `<meta data-hid="og:x" name="og:x" content="…">` with no `property` attribute anywhere. The
   `meta[property=…]` selector every sibling adapter uses matched **nothing** live — and it did
   not look like a failure, because the visible-box fallbacks still produced the right title
   and author while `cover_url` went quietly empty and `latest_position` returned `None`. Only
   the live run exposed it; the offline fixtures had been written with `property=` and so
   agreed with the bug. Fixed with a helper accepting both spellings, fixtures respelled the
   site's way, and `index_og_property.html` added so the other spelling stays covered.
2. *The gap fixture had no gap.* `index_gap.html` cut position 21, which the decoy block
   (20…14) then filled, leaving the union contiguous — the contiguity test was passing against
   a list with nothing wrong with it. Gap moved to position 5, outside the decoy's range.

**Decisions recorded as refusals** (all in the module docstring, so they are not "fixed" back
in): no 字數/length completeness guard (`twkan.py:52-62`, commit `1f9eb6f`);
`og:novel:latest_chapter_name` is a *title* whose 章 number drifts from position and is never a
count, while `og:novel:latest_chapter_url` is positional and is used **report-only, never as a
gate**; `og:description` is SEO boilerplate on this site so the visible `div.description` wins;
the wider ttkan family (`ttkan.co`, …) is unmeasured and deliberately not claimed.

**No minimum-delay floor — measured, not assumed.** novel543 pins 3 s on the strength of a
14-chapter walk; the equivalent walk here (index + 10 consecutive chapters at the default
1.5 s, ~18 s total) saw no interstitial and no 429, so the floor it needs, this site does not.

Full suite green (3675 + the new tests), ruff clean. Live suite green against the real site.
Fixtures are hand-built with invented filler text — nothing captured from the live site is
committed.
