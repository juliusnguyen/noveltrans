# 087 — TTKS (天天看小說, ttks.tw) scraper — implementation plan

## 0. Design in one paragraph

One new pure-parsing module plus a browser-transport adapter, cloned in *shape* from
`twkan.py` (transport) and `novel543.py` (TOC), with one thing neither sibling has: a
scrape-time promo-line filter. `ttks.tw` serves **one page that is both the detail page and
the complete TOC** (`/novel/chapters/<slug>/index.html`), so a full scan costs **exactly one
browser navigation** — cache it per-adapter and both `fetch_metadata` and
`fetch_chapter_list` read the same markup. Everything above the adapter class is
`markup -> values`, so the whole parsing surface is testable with no Chrome.

**The three traps it defends against:**

1. **The duplicate `最新章節` frame.** Two `div.chapters_frame` blocks with no class to tell
   them apart; the first is the newest ~16 chapters *descending*. A flat `a[href]` scrape
   yields 942 links for 925 chapters, in an order that puts the last chapters first.
   Defence: key a dict by the numeric position parsed out of each chapter href, sort by it,
   then assign `ChapterRef.index` by `enumerate`, and finally *prove*
   `positions == [1..N]`. Dedupe and ordering both fall out of the key; the self-link to
   `index.html` falls out because it has no numeric position.
2. **Two `div.content` on every chapter page.** The body first, the prev/next nav second.
   `select_one("div.content")` is right today by accident. Defence: a non-positional
   predicate (below).
3. **The NFKC-obfuscated inline promo.** One `<p>` per chapter is
   `<prose sentence><br/><br/><site advert>`, with the domain written in Unicode
   mathematical-alphanumeric letters that change per chapter. Defence: read paragraphs with
   `get_text("\n")` (never `get_text(strip=True)`), then drop whole lines with a
   conjunctive, domain-anchored, NFKC-folding predicate in the spirit of `translators/ads.py`.

## 1. Facts measured while planning (do not re-probe, but pin them in tests)

**(a) `get_text(strip=True)` glues the promo onto the prose; `get_text("\n")` does not.**

```
p.get_text("\n")       -> '<prose>\n<promo>'
p.get_text(strip=True) -> '<prose><promo>'
```

`novel543.parse_chapter` uses `p.get_text(strip=True)` (`src/noveltrans/scrapers/novel543.py:398`).
**Porting that line verbatim would merge the advert into the prose line and make line-level
stripping impossible** — the filter would then have to cut a clause out of a line, which is
exactly where over-deletion lives (`translators/ads.py:157` pins that as a documented
limitation). The separator argument is load-bearing and needs its own test.

**(b) `translators/ads.py` catches the *Chinese* promo but NOT a plausible *translated* one.**

| line | `_is_ad_line` |
|---|---|
| all three measured Chinese promo forms (NFKC-folded, math-alphanumeric domain) | **True** — via the `bare` conjunct (`ads.py:201-202`): `_fold` deletes CJK, so after removing the domain almost no ASCII alnum is left |
| a realistic Vietnamese translation of the same line | **False** |

Why the translated form escapes: `ads.py:189` computes
`plain = unicodedata.normalize("NFKC", line).casefold()` *before* testing whether the domain
survived de-obfuscation, so **NFKC-style obfuscation is invisible to `ads.py`'s obfuscation
conjunct** (it was built for an emoji standing in for a character, which is *deleted* rather
than folded). Once translated, accents fold to plenty of ASCII so `bare` is false, and no
`_STRONG_CUES`/`_CJK_CUES` entry matches the site's wording.

Consequence: **strip at scrape time** (§2.6). The side effect is real defence-in-depth — if
the scrape-time filter ever misses a form and the translator leaves it in Chinese, `ads.py`
still drops it.

## 2. Decisions

### 2.1 Identity

| | value | why |
|---|---|---|
| module | `src/noveltrans/scrapers/ttks.py` | one file per site, per `scrapers/__init__.py:25-39` |
| class | `TtksAdapter` | |
| `name` | `"ttks"` | matches the module, and it is what lands in `NovelMeta.site` and the project folder |
| `display_name` | `"天天看小說 (ttks.tw)"` | the twkan/novel543 form: native name + the host the user pastes |
| `url_patterns` | `[r"ttks\.tw/novel/chapters/[A-Za-z0-9][A-Za-z0-9_-]*"]` | **Host-anchored, escaped dot, and it must require the `/novel/chapters/` path.** One pattern covers every paste form: `…/<slug>/index.html` and `…/<slug>/<n>.html` both contain `ttks.tw/novel/chapters/<slug>`. `ADAPTERS` is first-match-wins by import order (`scrapers/__init__.py:16-20`), so a loose pattern steals silently — same reasoning as `novel543.py:431-437` and `twkan.py:345-350`. |
| `content_is_translated` | `False`, written explicitly | Chinese source; flipping it lands Chinese in `translated` and marks chapters done (`base.py:98-101`) |
| `source_lang` | `"zh"` written explicitly in `parse_metadata` | Traditional Chinese; never inherited from the dataclass default (`models.py:46`), per `twkan.py:246-248` |

**`ORIGIN = "https://ttks.tw"`, pinned, not taken from the pasted URL** — same argument as
`twkan.py:102-107` and `novel543.py:112-115`. This is what makes `http://`, `https://www.`
and the bare host canonicalise to one string. It is also the explicit decision **not** to
claim the wider ttkan family (`ttkan.co`, `wa01.ttkan.co`, …): those hosts are not measured,
and widening must be a deliberate edit (see §6).

### 2.2 URL helpers

```
_SLUG_RE          = r"/novel/chapters/([A-Za-z0-9][A-Za-z0-9_-]*)"
_CHAPTER_HREF_RE  = r"/novel/chapters/([A-Za-z0-9][A-Za-z0-9_-]*)/(\d+)\.html"
```

* `slug(url)` -> group 1, or `ScrapeError("Could not extract novel slug from URL", url)` —
  `twkan.book_id`'s shape (`twkan.py:166-171`).
* `read_url(url)` -> `f"{ORIGIN}/novel/chapters/{slug(url)}/index.html"`. **This is the
  site's own `og:novel:read_url`.** Justification is `novel543.py:185-198` verbatim:
  `Library.find_by_url` is exact string equality and `ScanWorker` looks a project up by both
  the pasted URL and `meta.url`, so echoing the paste would make one novel several projects,
  each with its own translation progress, tags and video settings.
* `chapter_url(url, n)` -> `f"{ORIGIN}/novel/chapters/{slug(url)}/{n}.html"`. Used only to
  **normalise** hrefs the TOC already gave us, never to synthesise a list. Synthesising would
  invent URLs the site never offered and carry no titles.

`_CHAPTER_HREF_RE`'s group 1 is a filter, not decoration: a recommendation widget pointing at
another novel must not contribute chapters (`novel543.py:296-299`). Its `(\d+)` requirement is
what silently drops the `index.html` self-link.

### 2.3 TOC: position-keyed only — **no `全部章節` primary path**

**Decision: go position-keyed only, over `div.chapters_frame a[href]`, with a flat `a[href]`
fallback if that selector yields nothing. Do not anchor on the `全部章節` heading.**

* novel543 anchors its primary path on `ul.all` — a **class**, i.e. a semantic token in the
  markup (`novel543.py:156-158`). ttks gives us nothing equivalent: the two frames carry the
  *same* class and are distinguished only by the **text** of a preceding `h3.chapters_title`.
  Anchoring on heading text is a literal-string dependency on site copy — precisely what
  `bqg5.py` rejects for its rotating notice and `novel543.py:392-396` rejects for 溫馨提示.
* The position key makes the discriminator unnecessary. `by_position.setdefault(n, ref)`
  dedupes the 最新章節 block for free (the duplicates carry the same `<n>`), `sorted(...)`
  fixes the descending order for free, and neither depends on which frame is which or how
  long the duplicate block is today. That block's length varies site-to-site and
  probe-to-probe (bqg5 saw 9 then 5 — `bqg5.py:44-50`), so any count- or order-based rule is
  wrong by construction.
* The contiguity proof (`positions == list(range(1, N+1))`) is what makes this *safe* rather
  than merely convenient, and it is strictly stronger than "I picked the right frame": every
  realistic degradation breaks it. Reasoning verbatim from `novel543.py:506-517`:
  `replace_toc` preserves content across re-scans while rewriting title and URL, so an
  order-wrong list is not a transient error — it permanently files chapter 925's body under
  index 0.

Scoping the selector to `div.chapters_frame` is belt-and-braces only; the href regex plus
contiguity would carry it alone, which is why the flat fallback is safe.

Failure message mirrors `novel543.py:522-528`:
`"Danh sách chương của ttks không liền mạch từ chương 1 (N mục, cao nhất M). Thử quét lại sau."`

### 2.4 `stated_total`: **none. No gate, and only a report-only cross-check.**

* **No length/字數/completeness guard of any kind.** Recon measured complete DOM bodies with
  nothing lazy-loaded. `twkan.py:52-62` records why the repo treats length heuristics as a
  false-positive trap, and feature 061 shipped exactly that on bookqq and had to be reverted
  (commit `1f9eb6f`). `bqg5.py:52` makes the same call.
* **`og:novel:latest_chapter_name` must NOT be used as a count.** It is a chapter *title*
  (`第N章`), and 章 numbering drifts from reading position — novel543's position 439 is 第438章
  (`novel543.py:42-44`), and bqg5 measured 37 of 439 titles not even matching `第\d+章`
  (`bqg5.py:52-59`).
* **`og:novel:latest_chapter_url` is a legitimate signal here — report-only.** It has the
  same `/<slug>/<n>.html` shape as a real chapter URL, so its `<n>` is a *position*, i.e. a
  count. Implement `latest_position(markup) -> int | None` returning group 2 of
  `_CHAPTER_HREF_RE` **only when the URL's slug matches this novel's**. When it disagrees with
  `len(refs)`, emit a status line and continue:
  `"⚠️ ttks trả về {len(refs)}/{latest} chương. Quét lại sau để lấy đủ."`
  A report, never a gate — contiguity already proves the list is a dense prefix, so a short
  list is safe and a *longer* list must never be refused (`novel543.py:530-537`).
  **The advertised URL is never fetched** (novel543's is a 404 — `novel543.py:36-40`); pin
  that with a test.

### 2.5 Chapter container: the non-positional rule

```
SEL_CONTENT   = "div.content"
SEL_NAV       = "div.prev_page, div.next_page"
SEL_CHROME    = ("a.anchor_bookmark, div.txtad, div.div_feedback, "
                 "div.social_share_frame, amp-social-share, amp-img, "
                 "script, style, ins, iframe")
```

**Rule: the body container is the first `div.content` that contains at least one `<p>` and
contains no `div.prev_page`/`div.next_page`.** Conjunctive and non-positional: the negative
conjunct rejects the nav div by what makes it the nav div, the positive conjunct rejects an
empty or chrome-only `div.content`. Raise
`ScrapeError("Chapter content not found — page layout may have changed", url)` when nothing
qualifies.

Rejected — "the body div is the one whose previous sibling is `div.title`": true today, but
sibling position is exactly what a theme refresh rewrites, and it identifies the body by
something *outside* the body. Also rejected: bare `select_one("div.content")` (positional,
right by luck).

`SEL_CHROME` is **named per element, never a blanket `<div>` decompose** — `twkan.py:134-138`
records why a blanket rule silently eats prose, and here the chrome sits *mid-prose*, so the
risk is live rather than theoretical. It runs *before* paragraph collection, so a `<p>` inside
a `div.txtad` never reaches the body.

### 2.6 Paragraph extraction and promo stripping — **in the adapter, at scrape time**

```python
for junk in container.select(SEL_CHROME): junk.decompose()

blocks = []
for p in container.find_all("p"):            # any depth: chrome is already gone
    lines = [ln.strip() for ln in p.get_text("\n").split("\n") if ln.strip()]
    lines = [ln for ln in lines if not _is_promo_line(ln)]
    if lines:
        blocks.append("\n".join(lines))      # a paragraph never splits in two
if not blocks:                               # the CMS stopped using <p>
    ...                                      # container.get_text("\n"), same filter
```

* `get_text("\n")`, **never `strip=True`** — §1(a). A comment must say so, naming
  `novel543.py:398` as the line not to copy.
* `find_all("p")` at any depth rather than novel543's `recursive=False`: the equivalent junk
  is named in `SEL_CHROME` and decomposed first, and a future CMS change that wraps prose one
  level deeper would silently lose everything under a `> p` rule.
* The fallback to whole-container `get_text("\n")` costs at most a junk line (which `ads.py`
  is the downstream net for) while not falling back costs the whole chapter
  (`novel543.py:400-404`).
* Title echo: drop **at most one** leading line when it whitespace-normalises equal to
  `ref.title` (`twkan.py:326-329`).
* Empty body -> plain `ScrapeError("Chapter content is empty", url)`. **Never
  `ObfuscatedContentError`** — that exception has GUI meaning and offers the user a repair
  that cannot help (`novel543.py:414-418`).
* Output: `"\n\n".join(blocks)`.

**The predicate** (module-level in `ttks.py`, modelled on `ads.py:170-204`):

```python
_PROMO_DOMAINS = ("ttk.tw", "ttks.tw")   # measured; the extension point if the site rotates
_MAX_PROMO_LINE_CHARS = 120              # every observed form is well under this
```

A line is dropped **iff all** of:

1. `len(line.strip()) <= _MAX_PROMO_LINE_CHARS` — a real paragraph survives on length alone;
2. **a `_PROMO_DOMAINS` token appears in `unicodedata.normalize("NFKC", line).casefold()`** —
   the load-bearing conjunct. No site domain, no deletion. This is what makes "the filter ate
   my story" structurally impossible for anything not about this exact site;
3. **and** one corroborating signal:
   * *obfuscation*: the token is absent from the **raw, unnormalised** line — i.e. it only
     exists after folding. Primary signal, and exactly what the site does (all three measured
     variants). This is the conjunct `ads.py:189-191` cannot express, because it normalises
     before comparing;
   * *or bare*: after removing the domain token, an `ads.py`-style fold of the remainder
     leaves fewer than ~4 ASCII alphanumerics — covers a future plain-ASCII promo line.

No literal slogan list, no cue list — that would be the literal blocklist `ads.py` exists to
avoid.

Residual false-positive surface, stated honestly: a Chinese prose line under 120 chars that
names the site's domain plainly. That line *is* a watermark by construction, so the trade is
accepted. Bias is to under-delete throughout — `ads.py:21-25`.

**Safety valve:** if stripping would leave the chapter empty, keep the unstripped lines rather
than raising or returning `""` (`ads.py:226-228`). A surviving ad line is a nuisance; a blanked
chapter is data loss.

**Why the adapter and not `ads.py`:** `ads.py` runs only on fresh translator output and *never
touches the stored original `content`* (`ads.py:28-30`). This promo is in the Chinese source,
so (a) stripping at scrape time keeps the stored original clean — which is what the user edits,
exports and re-translates from; (b) the translator never sees it, so it cannot be paraphrased
into a form no filter recognises — and §1(b) shows that is not hypothetical; (c) it saves
tokens on every chapter. `ads.py` stays untouched and remains the downstream net.

### 2.7 Metadata

* OG first, from the index page: `og:novel:book_name` (-> `og:title`), `og:novel:author`,
  `og:image`, with a visible fallback to `div.novel_info h1` and the
  `<li><span>作者：</span>…` rows (split on `[:：]`, the `twkan.py:230-235` shape). No title
  anywhere -> `ScrapeError("Novel title not found — page layout may have changed", url)`.
* **Description: `div.description p` first, `og:description` only as fallback.**
  `og:description` is SEO boilerplate, not a synopsis. Same treatment as
  `novel543.py:74-77`: the rendered markup beats the metadata. The visible blurb is
  site-truncated and **no prefix-stripping recovers a tail the site never sent** — store it
  as-is; feature 065 caps length downstream anyway.
* `cover_url` stored unmodified — **no placeholder-blanking rule**, on `twkan.py:72-76`'s
  argument: no `nocover`/`noimage` form is observed, and inventing a filename is either dead
  code or a rule that eats a real cover.
* `url=read_url(url)`, `site=self.name`, `source_lang="zh"`.

### 2.8 Transport

Straight `twkan.py:356-412` port, with the index page cached instead of a detail page:

* `__init__(self, client, *, headless: bool = False)`; `self._session: BrowserSession | None`;
  `self._index: tuple[str, str] | None` keyed by slug, **per-instance never module-level**
  (`twkan.py:363-364`).
* `_get_html` is the single browser seam. Emits the pre-Chrome status line *before* the window
  appears: `"🌐 Đang mở trình duyệt để vượt kiểm tra Cloudflare của ttks — giữ cửa sổ mở…"`
* `BrowserUnavailableError` -> Vietnamese `ScrapeError` naming Chrome and
  `pip install 'noveltrans[browser]' && playwright install chromium`.
* `BrowserSessionError` -> Vietnamese `ScrapeError` containing `"Thử tải lại"`.
* `close()` idempotent, never raises.
* `delay_seconds=self.client.delay_seconds` — **no `_MIN_DELAY_SECONDS` floor.** twkan's
  shape, not novel543's: novel543's 3.0 s floor is backed by a measured 14-chapter walk
  (`novel543.py:135-145`) and no such measurement exists for ttks. Adding an unmeasured floor
  would slow every user for a guess. Record the lever in the docstring; the live test walks
  enough consecutive chapters to find out.
* `headless` defaults `False` (`cf_browser.py:13-15`).
* `fetch_metadata` and `fetch_chapter_list` both read `_index_page(url)` -> **a full scan is
  one navigation**, which matters on a CF host (`cf_browser.py:21-24`).
* `fetch_chapter` fetches `ref.url` and parses. **No next/prev link is ever followed** —
  chapter 1's 上一章 points at `index.html` (`novel543.py:59-64`).

## 5. Implementation order

1. **Fixtures first.** Building them first forces the traps to be encoded deliberately rather
   than captured by luck, and every later step has something to run against.
2. **`ttks.py` skeleton + docstring.** Write the docstring before the code — it is the design
   record, and the rejected alternatives belong in it so the next reader does not "fix" them
   back in.
3. **URL layer.** Green: `TestUrlDerivation`.
4. **`parse_metadata` + `latest_position`.** Green: `TestMetadata`.
5. **`parse_chapter_list` + `chapter_positions`.** Green: `TestChapterList`.
6. **Promo predicate `_is_promo_line`** as a standalone pure function, tested in isolation
   **before** it is wired into `parse_chapter` — this is the piece where a bug is silent data
   loss.
7. **`parse_chapter`.** Green: `TestChapterContainer`, `TestChapterContent`, rest of
   `TestPromoStripping`.
8. **`TtksAdapter`.** Green: `TestContiguityGuard`, `TestAdapterWiring`, `TestBrowserPath`.
9. **Register** in `scrapers/__init__.py`. Green: `TestRegistry`.
10. **Full offline suite** (`pytest -q`) — the registry change touches every adapter's routing,
    so the *other* scrapers' url-theft tests are part of the signal. Then `ruff` (line-length
    100).
11. **Live run**: `pytest -m live tests/test_scrapers_ttks.py`, then a real scan + a ~20-chapter
    download. Decide `_MIN_DELAY_SECONDS` here, with numbers, or record in the docstring that it
    was measured unnecessary.
12. **README row** and the `087.01-HISTORY.md` `[IMPL]` entry.

## 6. Out of scope

* **The rest of the ttkan family** — `ttkan.co`, `wa01.ttkan.co`, `cn.ttkan.co` and any other
  mirror. Not probed, not claimed by `url_patterns`, not aliased in `ORIGIN`. A mirror later is
  a deliberate edit to `url_patterns` **and** a revisit of `read_url`.
* **Any completeness / 字數 / length guard.** Explicitly refused — `twkan.py:52-62`, commit
  `1f9eb6f`.
* **Gating on `og:novel:latest_chapter_*`.** Report-only, never a refusal.
* **Changes to `translators/ads.py`.** The gap measured in §1(b) is documented in the new
  module's docstring and in one test; closing it is its own feature.
* **Simplified/Traditional conversion**, cover placeholder blanking, chapter pagination (the
  site has none), a `_MIN_DELAY_SECONDS` floor (unless step 11 measures one), and
  parallel/threaded downloading of a Cloudflare host.
* **GUI changes.** Registration is the only wiring.
* **Committing anything captured from the live site.** Fixtures are hand-built; the scratchpad
  captures stay in the scratchpad.
