# Plan: let the user move the small photo in Video export → Xem trước (feature 116)

I checked everything you listed against the code. One finding changes the design: with today's centre crop, a typical 16:9 background can only move sideways, because the photo slot is wider than it is tall (about 1.30:1). So zoom needs to be in v1, not left for later. Details are under "Design decisions".

## What I confirmed

- **The crop.** `player_skin.py:211` `_cover_fit` scales the image to cover the slot and crops at `(slack)//2`. That is the "auto focus". `PlayerLayout.of()` lines 102–105: `photo_*` does not depend on `title_scale`.
- **Who calls `_cover_fit`.** `build_player_skin` (line 269) and also `tts/thumbnail.py:225`, which uses it for the full-frame cover. New parameters must have defaults so the thumbnail is unchanged. I agree the thumbnail should keep its own framing; it has its own editor.
- **Who calls `build_player_skin`.** Only `video.py:1201` (`render_video`) and `video.py:1323` (`render_preview_frame`).
- **Who calls `render_video` / `render_preview_frame`.** Only `workers.py:3080` (`VideoWorker`) and `workers.py:3480` (`VideoPreviewWorker`).
- **Who builds the workers.** `VideoWorker(` is built only at `tab_video.py:4154`. `VideoPreviewWorker` is built only in `_start_preview` (`tab_video.py:3752`).
- **No render cache.** No hashing or fingerprint covers the look settings. `skip_existing` only checks that the file exists or was marked "đã tạo". So the new setting affects new renders only; parts already rendered keep their old crop until re-rendered. This should go in the UI tooltip.
- **Stored values are not clamped.** `effective()` reads identity keys straight from `meta.json` and skips AppConfig's clamping. `_normalise` only converts lists back into tuples. A hand-edited `meta.json` could therefore send any value to the renderer, so the new keys must be clamped in `_normalise` and again in the renderer.
- **AppConfig property is required.** `test_every_key_is_a_real_config_property` enforces it, and `snapshot()` needs it. Copy the `video_thumbnail_title_pos` pattern (separate `_x`/`_y` QSettings keys, `_clamp`).
- **Preview label geometry.** `_on_preview_ready` scales the PNG to fit 900×520, which gives 900×506 for 16:9. The `QLabel` sits in a `QVBoxLayout` under a wide controls row, so the label can be wider than the pixmap (default alignment is left + vertically centred). Mouse-to-frame mapping must use the pixmap's real rectangle, not the label's.
- **Busy preview drops requests.** `_start_preview` silently returns while a preview worker is running. Today that is safe only because `_preview_controls` are disabled during a render. The drag surface must follow the same rule.
- **Drag pattern to reuse.** `thumbnail_editor._DragPreview` (fixed-size label, `moved` signal, mouse press/move) plus `_pil_to_pixmap`.

## Design decisions

1. **Two new per-novel (identity) keys.**
   - `video_photo_focus`: `(fx, fy)` in [0, 1], default `(0.5, 0.5)`.
   - `video_photo_zoom`: float in [1.0, 3.0], default `1.0`.
   - Both are per-novel, like `video_bg_color`, because framing depends on that novel's image.
2. **Zoom is included in v1.** Most backgrounds are 16:9, since the same image doubles as the full-frame thumbnail base. At zoom 1.0 a 16:9 image covering the slot has zero vertical slack, so "move it up or down to show the face" is impossible. Only zoom above 1.0 creates vertical room. Without zoom the feature would look half-broken.
3. **Existing novels render identically.** Use `int(fx * slack)` (floor). At `fx = 0.5` this equals `slack // 2` for both even and odd slack. `round()` would not: banker's rounding turns 1.5 into 2. Keep "resize the whole image, then integer crop" rather than `resize(box=...)`, so output is bit-identical at the defaults.
4. **Interaction: grab and pan.**
   - Dragging inside the photo rectangle moves the picture with the hand (drag right shows more of the left side).
   - While dragging, a cheap local Pillow overlay updates the photo area of the last preview image. No ffmpeg runs.
   - On mouse release: save, then run one full re-render.
   - A zoom spin box (`%`, keyboard tracking off, same style as "Cỡ chữ tiêu đề") and a "Căn giữa" reset button are the non-mouse fallback.
   - The mouse wheel over the photo changes the zoom spin by ±10%.
   - Clicks outside the photo rectangle do nothing.
   - The live overlay is worth doing: it is about 30 lines and reuses `_cover_fit`. Without it the user drags blind and waits about 2 s after every release.
5. **Pan math works at any scale.** It runs in slot units at whatever scale the display uses. The GUI needs only the source image size, the slot rectangle on screen, the focus and the zoom. It does not need the frame resolution, and fractions behave the same across the 720p and 1080p presets.

### Step 1. `src/noveltrans/tts/player_skin.py` (pure, no Qt)

```python
DEFAULT_PHOTO_FOCUS: tuple[float, float] = (0.5, 0.5)
DEFAULT_PHOTO_ZOOM = 1.0
MIN_PHOTO_ZOOM = 1.0
MAX_PHOTO_ZOOM = 3.0

class CoverCrop(NamedTuple):
    scaled_w: int; scaled_h: int; left: int; top: int

def clamp_photo_focus(value) -> tuple[float, float]   # bad/non-pair/NaN → DEFAULT_PHOTO_FOCUS; each axis clamped to [0,1]
def clamp_photo_zoom(value) -> float                   # bad/NaN → DEFAULT; clamp to [MIN, MAX]

def cover_crop(src_w: int, src_h: int, w: int, h: int, *,
               focus=DEFAULT_PHOTO_FOCUS, zoom=DEFAULT_PHOTO_ZOOM) -> CoverCrop:
    scale = max(w / src_w, h / src_h) * clamp_photo_zoom(zoom)
    sw, sh = max(1, round(src_w * scale)), max(1, round(src_h * scale))
    fx, fy = clamp_photo_focus(focus)
    left = min(max(int(fx * (sw - w)), 0), max(sw - w, 0))
    top  = min(max(int(fy * (sh - h)), 0), max(sh - h, 0))
    return CoverCrop(sw, sh, left, top)

def pan_photo_focus(src_size: tuple[int, int], slot_size: tuple[float, float],
                    focus: tuple[float, float], zoom: float,
                    dx: float, dy: float) -> tuple[float, float]:

    Per axis: slack = src*scale - slot; slack <= 0 → that axis unchanged; else f - d/slack, clamped."""

                        rect: tuple[int, int, int, int], radius: int,
                        focus, zoom) -> Image.Image:

class PhotoPanLabel(QLabel):
    panned = Signal(float, float)        # live focus while dragging
    pan_finished = Signal(float, float)  # on release (only if it actually moved)
    zoom_step = Signal(int)              # wheel: +1 / -1

    def set_frame(self, png_path: str, display_size: tuple[int, int],
                  image_path: str, focus, zoom) -> None
        # loads the PNG → keeps a PIL copy at display size; computes the slot rect in display px
        # from PlayerLayout.of(frame_w, frame_h) × (display_w / frame_w); loads a downscaled
        # source via load_photo() + Image.thumbnail(≈2× slot size × MAX zoom cap) and keeps the
        # ORIGINAL source size for the pan math; setFixedSize(display_size) so label px == pixmap px.
        # If the image can't be opened → pan disabled (no rect), tooltip explains.
    def set_focus_zoom(self, focus, zoom) -> None
    # mousePress inside rect → start drag (ClosedHandCursor); mouseMove → pan_photo_focus(...) with
    # the delta since press against the focus at press time, repaint via compose_pan_overlay,
    # emit panned; mouseRelease → emit pan_finished; hover (setMouseTracking) → OpenHandCursor
    # over rect, ArrowCursor elsewhere; wheelEvent over rect → zoom_step.
```

Getting the frame size: read `Image.open(png_path).size` from the rendered PNG, which is exactly the preset's W×H. That avoids passing the preset through.

For `pan_photo_focus`, pass the original source size scaled to the slot. Because the math works at any scale, the downscaled copy is used only for drawing the overlay.

## Edge cases to handle

| Case | Expected behaviour |
|---|---|
| Source aspect equals slot aspect, zoom 1.0 | Slack is 0 on both axes, so dragging does nothing; the tooltip hint explains zoom. |
| 16:9 source, zoom 1.0 | Only x moves; y slack is 0, so `fy` is stored but has no effect. |
| Very wide panorama (e.g. 10:1) or tall portrait (1:5) | Large slack on one axis; clamping keeps the crop inside the image. |
| Tiny source (1×1, 3×2) | `max(1, …)` keeps sizes valid and the crop is exactly w×h. |
| Odd slack at focus 0.5 | `int()` floor equals `//2`, so output is bit-identical to today. |
| Unreadable or missing image | The renderer draws the placeholder as now; the GUI disables panning and the spin still saves. |
| `meta.json` holds `[0.2, 0.9]`, `[5, -1]`, `"abc"`, `null`, zoom `99` or `0` | Normalised and clamped, or reset to the default. |
| Novel without these keys / `snapshot()` migration | Falls back to the defaults, so the current look is kept. |
| Quality preset changes (720p and 1080p) | Fractions and relative zoom give the same framing. |
| Drag released outside the label | Qt still delivers the release to the grabbing widget; the final value is clamped. |
| Drag that starts outside the photo rect | Ignored. |
| Preview render in flight | The label is disabled with the other controls, so no input is lost. |
| Switching novel while the dialog is open | `_apply_video_settings` syncs the spin and label. |
| Thumbnail | Unchanged: `thumbnail.py` calls `_cover_fit` with the defaults. |
| Vinyl label | Unchanged (fixed asset, out of scope). |

## Open questions for the user

1. When you pick a different background image (ảnh nền), should the framing reset to centre and 100%? I recommend yes, since the old position belonged to another picture.
2. Is a zoom range of 100–300% right? Above roughly 200% a 1080p frame may start to look soft, depending on the source resolution.
3. Should the framing also apply to the thumbnail (ảnh bìa)? I recommend no: the thumbnail fills the whole frame and has its own editor.
4. Phone photos with EXIF rotation are drawn unrotated today, both in the video and in the thumbnail. Should that be fixed too (`ImageOps.exif_transpose`)? It would change how those existing novels render.
5. Is "render only on mouse release, with a quick local preview while dragging" acceptable? The alternative is fine-nudge buttons (←↑↓→), which I left out of v1.
6. Videos already rendered keep their old crop and must be re-rendered ("Tạo lại") to pick up the new framing. Is the tooltip note enough, or should the dialog warn more visibly?
