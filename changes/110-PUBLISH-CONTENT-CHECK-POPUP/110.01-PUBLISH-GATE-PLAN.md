# 110.01 PUBLISH-GATE-PLAN

Feature: fix the failure when Studio shows "We're still checking your content" on publish.

## 1. Root cause

- `src/noveltrans/youtube_upload.py` ~L172-175: `_STILL_CHECKING_PUBLISH_ANYWAY_SEL` combines "Got it", "Publish anyway" and their Vietnamese equivalents into one selector.
- `_finish` (~L1801-1812) clicks `.last` of that match. Which button that is depends on DOM order, which is unverified. Either result is wrong:
  - If "Got it" is last: the gate is dismissed without publishing. The upload dialog stays open and `_finish` times out (~L1820) with "không xác nhận".
  - If "Publish anyway" is last: the app publishes content YouTube flagged as possibly limited, without the user choosing that.
- The loop has no cap on gate clicks, so a re-shown gate can trigger repeated publish clicks.
- The module comment at L165-166 ("Publish anyway" / "Go back") is stale. The screenshot shows "Got it".
- The existing test `test_still_checking_content_dialog_is_dismissed_then_confirms` (`tests/test_youtube_upload.py` ~L856) uses a fake page that treats both buttons as one clickable target, so it cannot catch the wrong-button bug.
- `upload_one` writes `STATE_COMMITTED` (~L3190) before `_finish` (~L3205). A failure at the gate leaves the part `committed`, which needs manual review. This fails safe and stays unchanged.

## 2. Decided behaviour

User decision: click "Publish anyway" automatically when the gate appears. The app must click that exact button, never "Got it".

- When the gate heading is visible, click the "Publish anyway" button (EN: "Publish anyway", VI: "Vẫn xuất bản" / "Cứ xuất bản"), selected by its accessible name, not by DOM position.
- Click it at most once per publish attempt. If the gate reappears after that, stop and raise `YouTubeUploadError` saying the video is NOT published (chưa xuất bản) and the user should review it in Studio. This avoids repeated publish clicks.
- After the click, keep waiting for the real confirmation (existing loop in `_finish`).

Trade-off the user accepted: a video YouTube flagged as possibly limited is published without a further prompt.

Not chosen: (c) wait-then-error (fails safe, no auto-publish); (b) poll with no limit (can hang).

## 3. Implementation steps

1. Live probe first (see section 5). Record DOM order and each button's text. This decides whether the bounded wait is worth keeping.
2. `youtube_upload.py` L165-175: split the combined selector. Keep a detection constant for the gate heading (EN and VI). Add a separate constant for the "Publish anyway" button only. Drop "Got it" from the gate-clicking path entirely.
3. `_finish` L1801-1812: when the gate heading is visible and the click budget is unused, click the "Publish anyway" button by accessible name and count the click. If the gate shows again after one click, raise `YouTubeUploadError` with the video id and "chưa xuất bản".
4. Keep `upload_one` and the state machine unchanged. The part stays `committed`.
5. Update the stale comment at L165-166 to match the new behaviour and the observed labels.

## 4. Test changes (`tests/test_youtube_upload.py`)

- `_FakeStudioPage` (~L590-650): model "Got it" and "Publish anyway" as distinct buttons. Record the clicked label. Keep the gate heading as a separate state.
- Replace `test_still_checking_content_dialog_is_dismissed_then_confirms` (~L856-864) with:
  - Gate appears, "Publish anyway" clicked once, confirmation follows: `_finish` returns; clicked labels are exactly ["Publish anyway"]; "Got it" never clicked.
  - Gate reappears after the click: `_finish` raises with "chưa xuất bản"; "Publish anyway" clicked exactly once.
  - Gate heading present and "Publish anyway" missing: `_finish` raises; nothing else is clicked.
- Existing confirm-path tests stay unchanged.

## 5. Live verification (user runs; read-only, nothing clicked)

- Use a throwaway video on a channel you own. Publish while the copyright check is still running so the gate appears.
- With the gate open, log for `:text("Got it"), :text("Publish anyway")`: `count()`, then each `nth(i)`'s text, tag and bounding box. Also log `.last` text, the `get_by_role("button", name=...)` counts, and the gate heading text. Do not call `.click()`.
- Use the results to confirm the root cause and pick final scoped locators.
- Do not retry the upload until the fix lands, since a retry hits the same gate.
