# 046 — `tieuthuyetmang.com` site adapter — implementation plan

_Generated 2026-07-31. Reconnaissance in §0/§1 is measured against the live site, not guessed._

## 0. Summary of the shape

`tieuthuyetmang.com` is a Next.js App Router site served over plain `requests` (no Cloudflare, no browser). The **landing page alone carries the entire TOC** inside React Server Component flight data — so `fetch_metadata` *and* `fetch_chapter_list` cost **one** HTTP request between them, which is the single biggest politeness win available here. 119 of 122 chapters on the sample novel are `isLocked: true`; they are read with the user's own session cookie via the existing `HttpClient.set_cookies`, exactly as `medoctruyen` does.

The one thing that is **not** known is the chapter reader URL. Nothing below step 1 may be built on a guess about it.

**The closest analogue is `medoctruyen`** (Vietnamese, cookie-gated, `"isLocked":true`, `AuthRequiredError`), and **the structural model is `webtruyendich`** (pure module-level parse functions above the adapter class, tested against trimmed saved fixtures with no network). This plan takes auth semantics from the first and file structure from the second.

## 1. STEP ONE — the observation script. Nothing else starts until this has run.

The recorded lesson from `changes/044-YOUTUBE-SUBTITLE-UPLOAD/044.01-HISTORY.md` is *build the observation tool before the interaction*: four rounds of selector guessing cost four round trips through the user, and one diagnostic settled it. Seven chapter-URL shapes have already been guessed and all seven 404'd. **Do not guess an eighth.**

Create `scripts/diagnose_tieuthuyetmang.py`, modelled on `scripts/diag_medoctruyen.py` (reads the stored cookie out of `AppConfig`, fetches, prints a verdict) but wider. The user runs it on their own machine, logged in.

```
Run:  .venv/bin/python scripts/diagnose_tieuthuyetmang.py [--chapter <URL copied from your browser>]
```

It must not write files and must not be part of the shipped package (like the two existing scripts, it lives in `scripts/` outside `src/`).

### 1a. What it does with no arguments (cheap, automatic, zero human effort)

1. **Cookie report** — same block as `diag_medoctruyen.py` lines 18–25: character count, cookie names present. If empty, say so and stop.
2. **Fetch the landing page** and dump: status, byte length, number of `self.__next_f.push` tags, reconstructed stream length.
3. **Story anchoring proof** — print *every* JSON object in the stream that has a `chapters_count` key, each with its `slug`, `title` and `chapters_count`, in stream order. This is the trap made visible: the implementer needs to see with their own eyes that the page's own story is **not** necessarily the first one, and which field reliably distinguishes it.
4. **Chapter-object census** — count objects carrying `chapterNumber`; print min/max/duplicates/gaps; print the first three and last three verbatim; print the count of `isLocked: true` vs `false`.
5. **Route-shape evidence, in this order** (each is a fact, not a guess):
   - `GET /robots.txt` and any `Sitemap:` lines it names; fetch the first sitemap and print any URL whose path is not `/truyen/…` — a sitemap that lists reader URLs settles the question outright.
   - Grep the landing HTML for `<script src="/_next/static/chunks/app/…">` and `<link rel="preload" as="script" href="/_next/static/chunks/app/…">`. **Next.js App Router names these chunks after the route segments**, e.g. `chunks/app/doc/%5BchapterId%5D/page-<hash>.js`. Print every distinct `chunks/app/...` path found, URL-decoded. This alone very often reveals the reader route and its parameter name.
   - Download each `chunks/app/**` JS file and grep it for template literals building a path: `` /`\/(doc|nghe|truyen)\/[^`]*\$\{/ `` plus plain occurrences of `"/doc/"`, `"/nghe/"`. Print each match with 80 characters of surrounding context.
   - Only *after* the above, probe a small candidate matrix built from the evidence — `/doc/<chapterId>`, `/doc/<slug>/<chapterId>`, `/truyen/<slug>/<chapterId>`, `/doc/<slug>/chuong-<n>` — printing status code and byte length for each. Cap at ~10 probes with the polite delay on.
6. **RSC probe** — refetch the landing page with header `RSC: 1` and report whether the response is a bare flight stream. If it is, the adapter has a cheaper fetch path available, and it also tells us the reader page's text can be pulled the same way.

### 1b. What it does when the user passes `--chapter <URL>`

If 1a doesn't settle the route, the cheapest remaining observation is **one paste from the human**: open the novel in the logged-in browser, click chapter 1, copy the address bar. The script then does the generalising, which is the part a human is bad at:

1. Print the URL decomposed into path segments.
2. Say which segments correspond to known values — the story slug, the chapter's ULID `id`, its `chapterNumber`, a slugified chapter title — and therefore **print the inferred template** (e.g. `https://tieuthuyetmang.com/doc/{chapter_id}`).
3. **Verify the template** by building it for chapters 2 and 3 (free) and one known-locked chapter, fetching each, and printing status + length for all four. A template that only works for the pasted URL is not a template.
4. For each of those four responses, print:
   - `__next_f` push count and stream length;
   - whether the stream contains a long run of Vietnamese prose (report the longest string value in the stream and its length) — this answers **"is chapter text server-rendered in the flight data, or fetched from an API?"**;
   - whether there is server-rendered `<p>`/`<article>` markup, and how many characters of text it holds;
   - all `isLocked` / `isFree` / `isPreview` / `hasAudio` occurrences with 60 characters of context;
   - if the text is *not* in the response, print any `/api/...` string literal in the reader route's JS chunk, so the API endpoint is named rather than guessed.
5. **Print the free-vs-locked diff explicitly**: side by side, the fields that differ between an unlocked chapter response and a locked one. This is what `fetch_chapter`'s gate will be built on, and it must be a field that is *actually different*, not one that merely exists — this is precisely the mistake `medoctruyen.py` lines 213–216 documents (`previewLoginHref` is on every page, so it cannot signal gating).

### What the implementation needs out of it — the exact checklist

Do not start §3 onward until all six lines below can be filled in from real output:

|---|---|---|

## 2. Language flags — recommendation and the evidence that would change it

**Recommend: `source_lang="vi"`, and do NOT set `content_is_translated`.**

This is the `medoctruyen` / `giatocvuongtai` model, not the `webtruyendich` one, and the distinction is not about what language arrives — all three arrive in Vietnamese — but about **who produced the text**:

- `webtruyendich` sets `content_is_translated=True` because *the adapter itself drives* an on-page AI translation and must record *which model* produced it in `Chapter.translator` (`translator_label = "webtruyendich (Gemini Flash 3.5)"`). The download worker then writes `translated` directly (`src/noveltrans/gui/workers.py` lines 1566–1580).
- `medoctruyen` and `giatocvuongtai` just set `source_lang="vi"`. `TranslateWorker.run` sees `project.meta.source_lang == self.target_lang` and takes `_run_identity` (workers.py lines 136–181), copying `content` into `translated` with translator `"(nguyên bản)"`. That path is already covered by `tests/test_workers_identity.py`.

tieuthuyetmang delivers finished Vietnamese prose that this app did not produce, so it belongs with the second group. Following it costs nothing new and reuses a tested path.

**Evidence that would change this:** if the diagnostic shows the flight data carries a translation-group field (the site has a `/nhom-dich/` route, so a `translationGroup`/`team` object is plausible) *and* the user wants that group credited per chapter in the Translate tab, then `content_is_translated=True` with `translator_label` derived from the group name becomes justified. Note the cost before choosing it: `content_is_translated` skips the Translate tab entirely, so the user loses the identity-pass column they currently edit by hand for medoctruyen novels. Whether the underlying work is a Chinese original or a Vietnamese original **does not** change the flag — either way the bytes we fetch are Vietnamese and `source_lang="vi"` is correct. It only changes the description text.

## 3. The pure flight parser (no network, fully unit-testable)

All of §3 goes at **module level in `src/noveltrans/scrapers/tieuthuyetmang.py`, above the adapter class**, exactly like `webtruyendich.py` lines 73–175. The adapter class below it does nothing but fetch and delegate. This is what makes the whole parsing surface testable against a saved fixture with no network, and it is the convention this repo has settled on for its two most recent adapters.

### 3.1 `flight_payload(markup: str) -> str`

Reconstruct the RSC stream:

- Find every `self.__next_f.push([1,<js-string>])` occurrence.
- Each `<js-string>` is a **JSON string literal** — decode it with `json.JSONDecoder().raw_decode(markup, idx_of_quote)` rather than a regex, so escaped quotes and `\u` sequences inside chapter titles survive intact. A regex like `push\(\[1,"(.*?)"\]\)` will truncate on the first escaped quote in a Vietnamese title and is the single most likely silent bug in this file.
- Concatenate the decoded strings in document order and return.
- Return `""` when there are no pushes; callers raise, so this function never raises.

Ignore `push([0,…])` and `push([2,…])` entries — only `1` carries stream chunks.

### 3.2 `_iter_json_objects(stream, needle, required_keys) -> Iterator[dict]`

The reconstructed stream is **not valid JSON** — it is line-prefixed flight rows (`2:I[…]`, `a:["$","div",…]`) with `"$"` and `"$undefined"` sentinels embedded. Do not attempt `json.loads` on the whole thing.

Instead: scan for occurrences of `needle`, walk left to candidate `{` positions, and try `json.JSONDecoder().raw_decode(stream, pos)`. Yield each object that decodes cleanly and contains every key in `required_keys`. Bound the leftward walk (a few KB) so a pathological stream can't go quadratic. This one helper serves both the story lookup and the chapter census.

### 3.3 `find_story(stream: str, slug: str) -> dict` — **the anchoring trap**

The stream contains sidebar "recommended story" objects with *identical field names*. Reading the first `chapters_count` in the stream returned `97` for a different novel during reconnaissance. Anchor deliberately:

1. **Primary — anchor on the slug.** Search for the literal `"slug":"<slug from the URL>"` and return the enclosing object, requiring it to also carry `title` and `chapters_count`. The page's own story is the only object whose slug equals the slug in the URL the user pasted; every recommendation has a different one.
2. **Fallback — anchor on the chapter array.** If (1) finds nothing (the field could be named `storySlug`, or absent), take the story object nearest to the 122-element chapter run, since the sidebar entries carry no chapter array.
3. **Cross-check, never a hard gate** — if the landing page also emits `og:title` / schema.org JSON-LD (the diagnostic answers this; both `medoctruyen.py` `_book_jsonld` and `webtruyendich.parse_metadata` already have reusable code for it), compare titles and prefer the anchored object. Disagreement is not fatal — layouts drift and a hard failure here would take the whole adapter down over a cosmetic mismatch.
4. If nothing anchors, `raise ScrapeError("Không tìm thấy dữ liệu truyện — trang có thể đã đổi giao diện", url)`.

### 3.4 `parse_metadata(markup, url, site) -> NovelMeta`

From the anchored story object only:

- `title`, `author` → `author["name"]` when it's a dict, the string itself when it's a string (`medoctruyen.py` lines 98–103 has this exact defensive shape — copy it),
- `description` ← `excerpt`, `cover_url` ← `coverUrl`,
- `url=url` **echoed unchanged**, not rewritten to the landing page. `webtruyendich.parse_metadata`'s docstring explains why: the library keys projects off the URL the user gave, and rewriting it orphans them. (`medoctruyen` does rewrite; follow `webtruyendich` here, it is the later and better-reasoned decision.)
- `source_lang="vi"`.
- Missing title → `ScrapeError("Novel title not found — page layout may have changed", url)`, matching the message both existing adapters use.

### 3.5 `parse_chapter_list(markup, url) -> list[ChapterRef]`

- Census every object with `chapterNumber` **and** at least one of `isLocked`/`isFree` (that pairing excludes `latestChapter` stubs on sidebar stories, which carry a number but not the flags — confirm against the diagnostic's census output).
- Dedupe by `id`; sort by `chapterNumber`, tie-broken by first-seen order.
- Build `ChapterRef(index=i, title=…, url=chapter_url(...))` with `index` a 0-based dense reading order — never the site's `chapterNumber`. The project DB keys chapters by `index`.
- Title: use the object's `title` as-is. Unlike medoctruyen there are no badge suffixes to strip (badges are rendered client-side from the boolean flags), so no `_BADGE_TAGS` equivalent is needed. **Do not append "🔒" or "VIP" to the title** — the title is persisted, exported, and read aloud by TTS.
- Empty result → `ScrapeError("Chapter list not found — page layout may have changed", url)`.
- Compare `len(refs)` against the anchored story's `chapters_count` and, on mismatch, emit a status line rather than raising — `chapters_count` is routinely stale on aggregator sites.

### 3.6 `parse_chapter(payload, url) -> str` and `chapter_is_locked(payload) -> bool`

Bodies deferred to the diagnostic (Q2/Q3). Whatever the shape, keep the signature taking **markup or a JSON string**, never a URL, so it stays fixture-testable. Output contract is fixed by the ABC: paragraphs joined with `"\n\n"`, empty paragraphs dropped, and a leading paragraph equal to the chapter title dropped (`medoctruyen.py` lines 235–236).

## 4. URL matching, slug extraction, and the three ABC methods

```python
_ORIGIN = "https://tieuthuyetmang.com"
_SLUG_RE = re.compile(r"tieuthuyetmang\.com/truyen/([a-z0-9-]+)")
```

The sample slug is lowercase-and-hyphens only, so this is safe. `slug(url)` and `landing_url(url)` mirror `webtruyendich.py` lines 73–85 verbatim.

```python
url_patterns = [r"tieuthuyetmang\.com/truyen/[a-z0-9-]+"]   # + the reader route, once Q1 is answered
```

Both `giatocvuongtai` and `webtruyendich` deliberately require the `/truyen/`-style prefix so category and author pages don't match; do the same. Add the reader-route pattern only after Q1, so a user pasting a chapter URL still resolves to this adapter.

Then:

- **`fetch_metadata(url)`** — `parse_metadata(self._fetch_flight(landing_url(url)), url, self.name)`.
- **`fetch_chapter_list(url)`** — `parse_chapter_list(...)` on the *same* landing page. **One request; no pagination, no second fetch.** Call this out in the module docstring — it is the feature that makes this adapter far politer than `medoctruyen`, which walks up to 500 TOC pages.
- **`fetch_chapter(ref)`** — fetch `ref.url`, check the lock gate first (§5), then `parse_chapter`.
- **`close()`** — inherit the no-op. Nothing is held; no browser. Do not override.

`_fetch_flight(url)` is the only private fetch helper: `flight_payload(self.client.get_html(url))`, raising `ScrapeError("Không đọc được dữ liệu trang (không tìm thấy dữ liệu Next.js)", url)` when the stream is empty. If Q6 says `RSC: 1` returns a bare stream, add that header and skip reconstruction when the response doesn't look like HTML.

## 5. Locked chapters

### 5.1 `fetch_chapter` raises `AuthRequiredError`, with medoctruyen's wording

Mirror `medoctruyen.py` lines 218–228, which already splits the two cases the user can actually act on differently — keep that split (pending Q4):

```python
# missing/expired cookie
"Chương này cần đăng nhập. Cookie phiên đăng nhập bị thiếu hoặc đã hết hạn — "
"vào Cài đặt và dán lại cookie tieuthuyetmang.com"

# logged in, but this account has not unlocked the chapter
"Chương bị khoá (trả phí) — tài khoản của bạn chưa mở khoá chương này trên "
"tieuthuyetmang.com"
```

Do not add anything that attempts to read a locked chapter. The adapter fetches only what the user's own account can already read, and reports the rest.

`AuthRequiredError` subclasses `ScrapeError`, so `DownloadWorker` catches it as a `NovelTransError`, marks that one chapter as an error row, and continues the batch (workers.py lines 1591–1594). That is the correct behaviour and needs no worker change. Critically it is **not** a `RateLimitedError`, so `_fetch_with_backoff` will not retry it 8 times at 60-second intervals — a 119-locked-chapter novel must not spend two hours re-asking for chapters it cannot have.

### 5.2 `fetch_chapter_list` should list **all** chapters, including locked ones

Recommended, for four reasons:

1. **Index stability.** `ChapterRef.index` is the project DB key. If the list were filtered by lock state, then buying membership — or merely refreshing the cookie — would produce a different list on the next scan, and `project.replace_toc(refs)` (workers.py line 66) would silently re-map every existing chapter's index onto different content. That is data corruption, not an inconvenience.
2. **Lock state is a property of the account at fetch time, not of the novel.** The scan may run cookie-less and the download logged in.
3. **Precedent.** `medoctruyen` lists everything and fails per chapter; the GUI is built around visible error rows the user can retry.
4. **The user can see what they are missing.** A TOC of 122 with 119 error rows is honest; a TOC of 3 looks like a broken scraper.

The mitigation for "why did 119 rows fail?" is a **status line, not a filter**. `fetch_chapter_list` should call

```python
self._status(f"🔒 {locked}/{total} chương đang khoá — cần cookie tài khoản có quyền đọc")
```

`ScanWorker` already wires `adapter.on_status = self.progress.emit` (workers.py line 62), so this lands in the GUI status label for free. This is exactly what `SiteAdapter._status` exists for.

### 6.2 Delivering the right cookie to the right site — reuse, don't duplicate the special case

`ScanWorker` and `DownloadWorker` both currently do `if adapter.name == "medoctruyen": client.set_cookies(self.cookies)` (workers.py lines 61 and 1549). Adding a second `if` and a second kwarg does not scale and doubles the wiring for every future cookie site.

**Recommended:** move the site→cookie decision into `AppConfig`, where the mapping belongs, and delete the name check from both workers.

```python
# config.py
SITE_COOKIES = {  # substring of the novel URL -> QSettings key
    "medoctruyen.vn": "medoctruyen_cookies",
    "tieuthuyetmang.com": "tieuthuyetmang_cookies",
}

def cookies_for_url(self, url: str) -> str:
    for host, key in SITE_COOKIES.items():
        if host in url:
            return str(self._s.value(key, ""))
    return ""
```

Then in `tab_scrape.py`:
- line ~230 → `cookies=self.config.cookies_for_url(url)` (the scan URL is already in hand),
- line ~327 → `cookies=self.config.cookies_for_url(self.project.meta.url)`.

And in `workers.py`, replace both `if adapter.name == "medoctruyen":` blocks with an unconditional `client.set_cookies(self.cookies)`. This is safe because `HttpClient.set_cookies` already ignores blank input (base.py lines 45–47), and it is a **net deletion** of a special case. Verified: nothing outside `tab_scrape.py` constructs either worker, and no existing test passes `cookies=` to them, so no test breaks.

*Alternative if you dislike resolving by URL:* pass a `dict[str, str]` keyed by adapter name and do `client.set_cookies(self.cookies.get(adapter.name, ""))`. Cleaner conceptually, but it changes a public kwarg's type. The URL form is the smaller diff.

## 8. Test plan

New file `tests/test_scrapers_tieuthuyetmang.py`; fixtures under `tests/fixtures/tieuthuyetmang/`. Use `from conftest import load_fixture` and `responses` for the two adapter-wiring tests, matching `test_scrapers_medoctruyen.py`.

### 8.1 Fixture capture — trim it

Two precedents exist: `medoctruyen/novel.html` is a raw 134 KB capture; `webtruyendich/landing.html` is a trimmed 3.6 KB one. **Follow webtruyendich and trim**, for three reasons: the raw page carries 122 copyrighted chapter titles plus the excerpt; 42 KB of flight stream is undiffable in review; and a trimmed fixture can be *engineered* to contain the trap, which a raw capture only contains by luck.

`landing.html` should be hand-built from the real capture and contain:

- 3–4 `__next_f.push` tags (proving multi-push reconstruction), at least one with an **escaped quote inside a chapter title** (proving §3.1's raw_decode is needed),
- the page's own story object with `slug` matching the test URL and a distinctive `chapters_count`,
- **two decoy recommended-story objects, at least one appearing *before* the real one in the stream**, with different slugs and different `chapters_count` values — this is the anchoring trap, encoded,
- ~8 chapter objects: numbers out of document order, a duplicate `id`, a mix of `isLocked` true/false, and one sidebar `latestChapter` stub that has `chapterNumber` but no lock flags (which must be excluded).

Plus `chapter_free.html` (or `.json`) and `chapter_locked.html`, both trimmed to the smallest markup that still exercises the gate — the medoctruyen `chapter_full.html` is 586 bytes and that is the right scale.

## 9. Politeness and rate limiting

- **Keep `DEFAULT_REQUEST_DELAY = 1.5`** — do not add a per-adapter override. The delay is the user's setting (`config.request_delay` → `HttpClient(delay_seconds=…)`), and no existing adapter overrides it.
- **Recommend ≥ 2.0 s in the module docstring.** At 2 s a 122-chapter novel is ~4 minutes of requests; there is no reason to go faster.
- **The structural win: `fetch_metadata` + `fetch_chapter_list` = one request.** Cache the landing page's reconstructed stream on the adapter instance keyed by slug so a scan (which calls both back to back, workers.py lines 63–64) genuinely makes one round trip. Keep the cache to a single entry and clear it in nothing — the adapter is per-batch and holds no external resource, so `close()` stays the inherited no-op.
- **Never parallelise.** Put the warning in the docstring in the same terms `webtruyendich.py` uses ("**Do not parallelise downloads.**"). `DownloadWorker` is sequential today; the note is for whoever changes that.
- **State plainly in the docstring that this site is paywalled**, that the adapter fetches only what the user's own logged-in account can already read, and that it reports anything still locked rather than working around it.
- No retry storm: `AuthRequiredError` is deliberately not a `RateLimitedError` (§5.1). If the diagnostic reveals a genuine throttle signal, add `RateLimitedError` — `_fetch_with_backoff` already handles it and needs no changes.

## Open questions — answerable in one pass from the diagnostic output

**Blocking (the adapter cannot be finished without these):**

1. **Q1 — What is the chapter reader URL template, and which field feeds it?** Seven shapes have already 404'd; `/doc/` is the lead. Either the `chunks/app/**` route names or one URL copied from the browser address bar settles it.
2. **Q2 — Is the chapter text server-rendered in the reader page's flight stream, in plain `<article>`/`<p>` markup, or fetched from an `/api/...` endpoint?** If it is an API, which endpoint, and does it need a `Referer` or an anti-CSRF header the cookie alone does not supply?
3. **Q3 — Which single field differs between an unlocked and a locked chapter response?** It must differ, not merely exist (`medoctruyen`'s `previewLoginHref` is the cautionary case).
4. **Q4 — Are "no cookie" and "logged in but not a member" distinguishable in the response?** If not, collapse §5.1's two messages into one that covers both.

**Non-blocking (defaults are chosen; confirm or override):**

5. **Q5 — Does the page's own story object carry a `slug` field matching the URL?** If yes, §3.3's primary anchor is correct as written. If not, the fallback becomes primary.
6. **Q6 — Does `GET` with header `RSC: 1` return a bare flight stream?** Purely an optimisation; the HTML path works either way.
7. **Does `https://tieuthuyetmang.com/dang-nhap` return 200?** It is the "Mở trang đăng nhập" button target in the settings help dialog.
8. **Does the flight data carry a translation-group / `/nhom-dich/` field?** Only relevant if you want the group credited per chapter (§2) — the recommendation is not to.
9. **Are `chapters_count` and the actual chapter-object count equal on the sample novel?** Decides whether the §3.5 mismatch check is a status line (recommended) or can be tightened.
10. **Does the site emit any rate-limit or daily-quota signal?** Nothing suggests it does, and the plan assumes none — but if the diagnostic shows one, `RateLimitedError` plugs straight into the existing backoff.
11. **Does the user want the trimmed fixture (recommended, follows `webtruyendich`) or a raw capture (follows `medoctruyen`)?** Trimming avoids committing 122 copyrighted chapter titles and lets the anchoring trap be encoded deliberately rather than by luck.
