# 042 — Backfill + standalone `.srt` — PLAN

## Design decisions

| Decision | Rationale |
| --- | --- |
| **Recover boundaries by detecting the silence gaps, not by estimating.** | The gaps are `np.zeros` — true digital silence at a known length — so `silencedetect` finds them exactly. Verified end to end at **0.0 ms error**. Proportional estimation drifts tens of seconds mid-chapter and is not offered. |
| **Refuse unless the detected gap count is exactly `len(chunks) - 1`.** | That equality is the entire safety argument: it says the silence pattern in the file matches the text we believe produced it. Any mismatch — settings changed since voicing, a chapter edited afterwards, a pause the engine rendered inside a sentence — breaks it. Skipping one chapter beats shipping subtitles that are confidently wrong. |
| **The detection threshold is derived from `gap / speed`.** | `apply_tempo` rescales the whole chapter, silence included: a 0.4 s gap written at speed 1.15 is 0.348 s on disk. The user's speed is 1.15, so a hardcoded 0.4 would find nothing in their entire library. |
| **Silences of the wrong length are discarded before counting.** | A long pause inside a sentence, or trailing silence at the end of a file, must not masquerade as a chunk boundary — it would shift every subsequent cue. |
| **Backfill never overwrites cues written during synthesis.** | Real timings beat recovered ones, and re-running the button must not quietly downgrade them. |
| **The button writes to the same path the render would.** | Same slug, same `<stem>/<stem>.srt`. If the two disagreed, a render would silently replace a good sidecar with a different one — or leave two. |
| **One button, both jobs.** | Writing sidecars alone produces nothing for legacy audio; backfilling alone produces cues nobody asked to become a file. Neither is what the user wants on its own. |

## Implementation

1. `tts/subtitles.py` — `detect_silences`, `expected_gap`, `chunks_for_text`,
   `backfill_cues`.
2. `gui/workers.py` — `SubtitleWorker`: plans the same windows as `VideoWorker`,
   backfills each chapter that lacks cues, then writes each part's `.srt` using
   `_with_real_durations` exactly as the render does.
3. `gui/tab_video.py` — a "Tạo phụ đề (.srt)" button beside "Mở thư mục video", progress
   and a finish line naming how many parts were skipped.

## Test plan

- `expected_gap` scales with speed and survives a zero.
- `chunks_for_text` reproduces what the engine actually chunked (asserted against a real
  `synthesize_chapter` run).
- `backfill_cues` returns `None` for too few gaps, too many gaps, a zero duration and an
  empty chapter; ignores a wrong-length silence; and bounds cues by the gaps it accepted.
- `detect_silences` parses ffmpeg's stderr and returns `[]` when ffmpeg is absent.
- `SubtitleWorker` writes one `.srt` per part, **no `.mp4`**, at the same path the render
  would use, and does not re-backfill chapters that already have real cues.

## Risks

1. Real TTS audio may contain a genuine near-silent pause of gap length inside a sentence,
   producing an extra detection and a refusal. Fails safe — the chapter is skipped and
   reported, never mistimed.
2. Very quiet speech could fall under the −50 dB threshold. Same failure mode: refusal.
3. The chunk re-derivation depends on the cleaning/chunking settings being unchanged since
   the audio was made. A change breaks the count equality, so it refuses rather than
   mistimes.
