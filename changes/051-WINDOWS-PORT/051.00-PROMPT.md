# 051 — Windows version of NovelTrans

> make the windows version of this app

The app (PySide6 desktop, `noveltrans`) has so far only been packaged and polished for
macOS: `make app` / `make dmg` in the Makefile shell out to `sips`/`iconutil`/`hdiutil`,
`packaging/NovelTrans.spec` builds a macOS `.app` bundle with an `.icns` icon, and several
GUI modules have macOS-specific behavior:

- `gui/dock.py` — hide/show the Dock icon via `NSApplication.setActivationPolicy:`
  (ctypes/libobjc). Already guarded to no-op (`available()` → False) off `darwin`.
- `gui/keep_awake.py` — wake-lock via `caffeinate`. Already guarded to no-op off `darwin`.
- `gui/notify.py` — Dock badge via `QApplication.setBadgeNumber`. No-ops where the
  attribute doesn't exist.
- `gui/tray.py` — `QSystemTrayIcon` is cross-platform, but the icon is drawn as a
  macOS "template" mask (`setIsMask(True)`, pure black glyph) that macOS recolors per
  theme; other platforms don't recolor it, so the glyph may look wrong (e.g. invisible
  or low-contrast) against a dark Windows taskbar.
- `runtime_env.py` — augments PATH with macOS/Linux tool dirs (Homebrew, MacPorts,
  `~/.local/bin`) so bundled `ffmpeg`/`ffprobe` are found when launched outside a
  terminal. Windows has no equivalent and a frozen `.exe` launched from Explorer/Start
  Menu may not find `ffmpeg` on PATH either.

## Goal

Get NovelTrans running and packaged as a proper Windows app:

1. Confirm/fix the GUI runs correctly on Windows (tray icon looks right, keep-awake has
   a Windows implementation instead of silently doing nothing, close-to-tray still
   works, no macOS-only code paths crash or are silently relied upon).
2. Add Windows packaging: a PyInstaller build producing `NovelTrans.exe` (with a proper
   `.ico` icon), plus a way to get it onto a user's machine (installer or a zipped
   portable folder — decide in planning).
3. Update `Makefile`/docs so a Windows dev can `make run`/`make app`-equivalent without
   needing Unix-only tools (`.venv/bin/...` vs `.venv/Scripts/...`, `sips`, `iconutil`,
   `hdiutil` are all macOS/Unix-specific).

Out of scope: code-signing the Windows build (matches the current unsigned macOS
situation — README already tells users to work around Gatekeeper for the unsigned .app).
