# 051.02 — Initial plan: Windows port

## Current-state findings (this Windows machine)

- `make` is **not** installed. `uv` is available. No `.venv` exists yet.
- `py -3.12` is available — use that (matches the Makefile's `python3.12`/`uv venv --python 3.12` convention), not the default `py`/`python` (3.14.x).
- `.gitignore` already excludes `build/`, `dist/`, `.venv/` — no changes needed.
- `tests/test_tray.py::TestIcon::test_it_is_a_template_image` currently asserts `icon.isMask()` unconditionally — will need to become platform-conditional once `tray.py` branches by platform.
- `gui/main_window.py` (`show_from_tray`, `closeEvent`, `shutdown_all`) already calls `hide_dock_icon()`/`show_dock_icon()`/`clear_dock_badge()` unconditionally — these are safe no-ops off macOS, so close-to-tray logic itself needs **no changes**, only the tray icon glyph and keep-awake backend do.
- `dock.py` establishes this repo's testability pattern for platform-native calls: wrap the OS call in a small private function, `try/except Exception` guard, return a bool/None on failure rather than raise, expose a test reset hook. The new Windows keep-awake path should follow the same shape — `ctypes.windll` doesn't exist as an attribute at all off real Windows, so the OS call must be isolated behind a wrapper function that tests can monkeypatch wholesale.

## Decisions (confirmed with user 2026-07-31)

1. **Distribution: portable onedir zip** (`dist/NovelTrans-windows.zip`) — no installer for now.
2. **Bundle ffmpeg.exe.** The Windows build ships `ffmpeg.exe`/`ffprobe.exe` inside the app folder so MP3 export/speed-adjust work with zero setup. The binaries are NOT committed to git (gitignored); `packaging/NovelTrans-windows.spec` picks them up from a local `packaging/ffmpeg/win/` folder if present, and README documents how to fetch them (e.g. gyan.dev static build) before running `make.ps1 app`. `runtime_env.py`'s "check next to the frozen exe" fallback still applies for anyone who drops their own build there instead.
3. **onedir** build mode (fast startup, no self-extraction on every launch).
4. **Tray glyph color for non-macOS**: reuse the app icon's blue accent as a filled (non-mask) glyph.
5. Target Windows interpreter: Python 3.12 (matches macOS Makefile convention; `requires-python` floor is 3.11).

## Ordered implementation steps

1. **Baseline** — `uv venv --python 3.12 .venv`, `uv pip install -e ".[dev]"`, run `.venv\Scripts\noveltrans.exe` to confirm the app launches on Windows before any code change (baseline screenshot of the current, unfixed tray icon).

2. **`make.ps1`** — Windows-parity build script mirroring the Makefile's targets (`run`, `setup`, `test`, `test-live`, `lint`, `icon`, `app`, `zip`, `clean`) using `.venv\Scripts\...` instead of `.venv/bin/...`. Existing `Makefile` stays untouched/authoritative for macOS/Linux. Verify `.\make.ps1 run` launches the GUI — first checkpoint.

3. **`gui/tray.py`** — branch `build_tray_icon()` on `sys.platform == "darwin"`:
   - macOS: unchanged (black glyph + `setIsMask(True)`).
   - Elsewhere: same glyph filled with a solid accent color, no `setIsMask`. Add smaller pixmap sizes (16/32) for Windows' tray size. Update docstring. Fix `test_tray.py`'s unconditional `isMask()` assertion + add a non-macOS branch test. Manual check: run the app, trigger a job, screenshot the Windows taskbar tray icon.

4. **`gui/keep_awake.py`** — Windows branch using `ctypes.windll.kernel32.SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)` (not `ES_DISPLAY_REQUIRED`, matching `caffeinate -i`'s "block idle sleep, not display sleep"), released via `ES_CONTINUOUS` alone. Wrap the real call behind a small private function so tests can monkeypatch it without touching `ctypes.windll` (which doesn't exist off Windows). Track active state. Update docstring. Add `TestWindows` cases to `test_keep_awake.py`. Manual check: run a long job, confirm via `powercfg /requests` that NovelTrans appears under `SYSTEM` while running and clears after.

5. **`runtime_env.py`** — add Windows tool-dir candidates (Chocolatey, Scoop shims, winget Links) and a check of the frozen exe's own directory (and an `ffmpeg` subfolder) for a manually-dropped `ffmpeg.exe`/`ffprobe.exe`. Platform-branch `_TOOL_DIRS`; keep macOS/Linux behavior unchanged. Update docstring. Extend `test_runtime_env.py` with Windows cases. Manual check: confirm graceful WAV-only fallback with no ffmpeg, then confirm winget-installed ffmpeg is found.

6. **Icon assets** — new `packaging/make_ico.py` (Pillow, already a core dep) generating `packaging/NovelTrans.ico` from the existing PNG at multiple sizes. Wire into `.\make.ps1 icon`.

7. **Packaging** — new `packaging/NovelTrans-windows.spec` (sibling to the untouched macOS spec, since PyInstaller's `BUNDLE` step is macOS-only): same `collect_all` block for the TTS/parsing deps, `EXE(..., icon="NovelTrans.ico")` + `COLLECT(...)` (onedir, no `BUNDLE`). `.\make.ps1 app` builds `dist/NovelTrans/NovelTrans.exe`; `.\make.ps1 zip` produces `dist/NovelTrans-windows.zip`. Manual check: run the actual frozen `.exe` from Explorer (not the venv) and re-verify tray icon, keep-awake, close-to-tray, and ffmpeg discovery in that frozen context.

8. **`pyproject.toml`** — no planned changes; flag during step 7 if any TTS-extra package lacks Windows wheels.

9. **README.md** — Windows install block alongside the macOS one, new "Đóng gói thành app Windows" section (SmartScreen workaround, parallel to the Gatekeeper note), `.venv\Scripts\...` dev commands, winget/scoop ffmpeg alternative to `brew install ffmpeg`.

10. **Final QA** — `.\make.ps1 test` and `.\make.ps1 lint` green; full manual run-through of the frozen exe (launch, run a job, minimize to tray, keep-awake engage/release, close-to-tray then quit-from-tray, confirm library dir defaults to `%USERPROFILE%\NovelTrans`).
