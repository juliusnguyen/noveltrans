# 092-QC-SAVE-BUTTON — History

## [FEAT] Kiểm tra chất lượng can save without running — 2026-09-14

Asked for directly: *"in Kiểm tra chất lượng, add the save button so I can save it when I
made a change (change the cli agent), for now, it will back to previous setting until I
try Bắt đầu kiểm tra or Thử 3 chương."*

Accurate diagnosis on the user's part. `_remember_choices()` — which writes `qc_enabled`,
`qc_use_llm_judge`, `qc_ai_engine`, `qc_ai_model` and `qc_engine_chain` — was called from
exactly two places, `_request_start()` and `_request_results()`, both of which also
`accept()` the dialog. So the only way to keep a change was to start a scan over a
thousand chapters, and closing with Đóng silently discarded it.

### Changes

- `gui/qc_dialog.py`: `SAVE_LABEL` / `SAVED_LABEL` / `SAVED_FLASH_MS` module constants and
  a **💾 Lưu cài đặt** button in the action row, between "Xem chương lỗi đã tìm được" and
  Đóng. `_save_settings()` calls the existing `_remember_choices()` and deliberately does
  **not** call `accept()` — saving a setting and launching a scan are different acts, and
  only the first was asked for. The button then reads "✓ Đã lưu" disabled for
  `SAVED_FLASH_MS`, restored by `_restore_save_button()`, so there is feedback that it
  landed.
- The flash timer is a `QTimer(self)`, parented to the dialog: a bare
  `QTimer.singleShot` would still fire after the user closed the dialog and call a method
  on a deleted widget.
- `_restore_save_button()` re-enables against `not self._blocked`, so a timer that
  outlives a blocked state cannot quietly enable a button the blocked path disabled.
- The button joins the widgets disabled when `self._blocked` is set — with nothing above
  editable there is nothing to save.

Đóng deliberately still discards. That is what makes it a way to back out of a change, the
user did not ask for it to change, and a test now pins it.

### Verification

4 new tests (saves without starting or closing; the label flashes and goes back; closing

to 2.

Full suite with `test_tts.py` and `test_workers_pause.py` excluded (see 090): **3527

### Not done / noted

- **GUI automation is not reliable here and should not be trusted blind.** `PrintWindow`
  renders a window's own pixels even when another app covers it, but a synthesized click
  goes to whatever is physically topmost at that screen point — so screenshots kept
  looking correct while clicks were landing in another application. The restore of the
  test value was finished with the app closed and `reg.exe`, then re-read through
  `AppConfig` to confirm. Anyone scripting this app's GUI should verify the *effect* of
  every click, never the screenshot alone.
- No "unsaved changes" prompt on Đóng. It would be the thorough answer, but it changes
  what Đóng means and was not asked for; the explicit button plus its tooltip (which says
  changes are otherwise only written on start / thử N chương) covers the reported problem.
- `uv.lock` stays uncommitted, as in 088–091.
