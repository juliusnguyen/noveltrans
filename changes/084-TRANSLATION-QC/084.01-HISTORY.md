# 084 — Quản lý chất lượng bản dịch (translation QC + auto re-translate) — History

## [FEATURE] 084-TRANSLATION-QC — 2026-09-08
Scaffolded on branch `changes/084-TRANSLATION-QC` (off `main` at `5cc48f4`, right after
083-VIDEO-SOUNDWAVE merged). Prompt: `084.00-PROMPT.md`.

Reported by the user: agent translations are inconsistent — sometimes the output comes back
entirely in English, sometimes in dense Hán-Việt ("convert" style) rather than everyday
Vietnamese. Asked for a quality-control stage in the translate flow with its OWN selectable
agent (QC: `agy`, translation: `claude`), and for a failed chapter to be re-translated
automatically until the problems are gone.

Existing ground the plan must build on, noted at scaffold time so `/plan` starts from the
code rather than from scratch: `Translator._translate_with_retry` (`translators/base.py`)
already retries on leftover CJK / refusals / implausible titles but has no notion of "wrong
language" or "too Hán-Việt", and deliberately returns its least-dirty attempt;
`translators/rewrite.py` is the closest existing shape (pure, `send(prompt)`-driven,
testable against a deliberately misbehaving fake LLM, and never returns an attempt that
fails validation — its docstring explicitly warns against harmonising the two loops);
`CliAgentTranslator` already drives both `agy` and `claude` headless and exposes
`complete(prompt)`; and `video_ai_engine`/`video_ai_model` is the precedent for a feature
picking its own engine independently of the tab's main one.

Open questions carried into planning: heuristic vs LLM detection (and what each costs per
chapter), the retry ceiling and what happens at it, whether the QC verdict is fed back into
the next prompt, which layer owns the loop, where the QC engine setting lives, whether
already-translated chapters get re-checked, and keeping today's behaviour byte-identical
until QC is switched on.

## [DECISIONS] Settled before planning — 2026-09-08
User answered the prompt's open questions:

1. **Dịch lại có phê bình.** Not a blind identical retry — the QC verdict goes into the next
   prompt ("bản trước ra tiếng Anh — hãy dịch sang tiếng Việt phổ thông"), so each attempt
   knows what was wrong with the last one.
2. **Danh sách engine + số lần thử theo từng engine.** Settings hold an ordered list of
   translation engines (claude, agy). An engine that keeps failing QC hands over to the next
   one automatically (agy → claude). Each agent has its own attempt count, adjustable in
   settings, **default 2** — so the budget is per engine, not one global number.
3. **Cả hàng loạt lẫn một chương.** The loop must work identically for a batch run and for a
   single re-translated chapter.
4. **Chương đã dịch rồi.** A button to QC every already-translated chapter, and multi-select
   rows + right-click → QC. The check produces a **result view**: the failed chapters with
   what was wrong, for the user to review, select, and re-translate.

## [PLAN] 084.01-TRANSLATION-QC-PLAN — 2026-09-08
Generated plan: `084.01-TRANSLATION-QC-PLAN.md`.

The plan was written against **measured data, not guesses**: all 4896 translated chapters
in the user's library were opened read-only and every candidate detector run over them.
Three findings changed the design:

- **The Hán-Việt class cannot be caught by a cheap heuristic.** The lowest Vietnamese
  function-word scores in the whole library belong to *good* tiên hiệp chapters — the genre
  is Hán-Việt. Any threshold that catches "convert" prose flags whole cultivation novels, so
  that class needs an LLM judge with a load-bearing NEGATIVE few-shot example.
- **A third failure mode exists and is the only one with real positives**: 4 chapters stored
  as translated are wholly Chinese or Chinese/Vietnamese interleaved. "Toàn tiếng Anh" has
  zero real positives in this library, so its threshold is calibrated on negatives only.
- **The prompt's assumption that leftover CJK is already handled is wrong** in practice:
  `_translate_with_retry` checks it and then returns the least-dirty attempt anyway, and 580
  stored chapters carry leftover CJK.

Structure: a pure `translators/qc.py` (detectors + judge + loop, `rewrite.py` discipline), an
opt-in `retry_hint` channel through the engines, four `qc_*` chapter columns, six config keys
(QC **off** by default), and a `QcDialog` + `QcResultDialog` + `QcScanWorker` on tab 2 whose
result view feeds the existing `_retranslate_indices`. 13 ordered steps; the pure ones land
first. Six judgement calls flagged for the user before implementation starts.

## [DECISIONS] Plan review — 2026-09-08
Three judgement calls from the plan answered:

1. **Hết lượt thử → lưu bản tốt nhất + đánh dấu lỗi** (§3.4 as recommended). A fresh
   translation keeps its least-bad attempt, the row goes red with the verdict in `error`, and
   the chapter is listed in the QC result view. Re-translating an EXISTING translation keeps
   the opposite (strict) policy: it may not overwrite unless the new attempt passes.
2. **AI chấm văn phong BẬT mặc định** (`qc_use_llm_judge = True`), against the plan's
   suggestion of a heuristics-only default — Hán-Việt is the failure the user actually
   reported, so it is on from the start. This makes the judge's negative few-shot example and
   the "👁 Thử 3 chương" dry run load-bearing rather than optional, and it puts the +1 agent
   call per chapter on by default: the dialog must state that cost plainly.
3. **Implement all 13 steps** in one pass rather than landing the pure half first.

## [STEP 1-13] Implemented — all thirteen steps — 2026-09-08
Plan 084.01, in order. QC is **off by default**; with `qc_enabled` false `TranslateWorker`
takes today's path with today's arguments and writes no `qc_*` column at all.

- **`scripts/qc_calibrate.py`** (step 1) — read-only distribution report over the library.
  Run against the real 4896 chapters BEFORE the constants were written, and again after:
  the shipped detectors flag **5 chapters (0.10%)** — four genuinely broken (Chinese and
  Vietnamese interleaved, all from one source site) and one refusal false positive, exactly
  as predicted. The report also prints the ten LOWEST `vietnamese_word_rate` chapters as a
  standing check: they are good tiên hiệp chapters, which is the evidence that no cheap
  threshold can catch "đặc Hán-Việt".
- **`translators/qc.py`** (steps 2-4) — pure, `rewrite.py` discipline. Seven verdict codes,
  a severity order, five measured thresholds each carrying its figure, the LLM judge
  (task-framed, one-line reply, **unparseable ⇒ OK**, sample-not-chapter, and the
  load-bearing NEGATIVE few-shot example), Vietnamese retry hints per code, and
  `translate_with_qc` — engine chain, per-engine budget, `should_stop` between attempts, and
  the two opposite exhaustion policies documented as such.
- **`retry_hint` channel** (step 5) — `Translator.supports_retry_hint`, keyword-only,
  defaulted, and **built into a kwargs dict outside the loop** so the no-hint call is
  provably identical to today's. CLI agent / Claude / LM Studio opt in; Google does not.
- **Storage** (step 6) — five columns (`qc_status`, `qc_code`, `qc_reason`, `qc_text_hash`,
  `qc_attempts`) in `_SCHEMA` *and* `_migrate`; `save_qc_verdict` (touches only `qc_*`),
  `mark_qc_failed` (the one path that reddens a row, called AFTER `save_translation` because
  that clears `error`), `pending_qc`, `qc_failures`, `counts()`, and `clear_translations`
  blanking all five. `qc_code` was added beyond the plan: the result view groups by error
  class, and recovering a class from a Vietnamese sentence by substring match would break
  the first time a reason is reworded.
- **Config** (step 7) — six keys. `qc_engine_chain` stores `"engine|model|attempts"` and is
  validated on read: one-item collapse, unknown engine dropped, attempts clamped.
- **Workers** (steps 8-9) — shared `engine_label()` (one spelling of an engine name, since
  it is written into `chapters.translator`), `QcEngineSpec`/`QcSettings`, lazy per-engine
  construction (a chain entry that will not build is SKIPPED, not fatal — only an entirely
  dead chain fails), `TranslateWorker(qc=…)`, and `QcScanWorker`, which writes verdicts and
  never text.
- **GUI** (steps 10-12) — `QcDialog` + `QcResultDialog`, the tab button, the right-click
  action, all six lifecycle sites, and ✅/⚠️ as a SUFFIX on the existing translator column
  (a ninth column would shift `RETRANSLATE_COLUMN`). The result view's selection feeds the
  existing `_retranslate_indices` — "review then re-translate" is one connection.
- **Docs** (step 13) — a README section and a note on `PausableWorker`'s docstring recording
  why QC checks its stop flag between attempts rather than only at chapter boundaries.

### Known limits, stated plainly
- The judge flagging good tiên hiệp prose is the live risk; the negative few-shot example
  and **👁 Thử 3 chương** are the mitigations, and neither can be unit-tested.
- With the judge on (the user's choice) every clean chapter costs one extra agent call.
- `MIN_DIACRITIC_RATIO` has zero real positives to calibrate against — its false-positive
  rate is measured, its miss rate cannot be until an English chapter actually appears.

## [FIX] Dialog rendering — 2026-09-08
User screenshot: the engine names in the "Dịch lại bằng" table were cut in half vertically.
Rendered the dialog offscreen (`QWidget.grab()`) to see it, which surfaced three bugs at
once — two of them not in the report:

1. **Clipped rows.** A `QTableWidget` cell widget does not drive the row height, so the
   default section size cropped every combo box. Fixed by sizing each row from the widgets'
   own `sizeHint`, not a hard-coded number that would break at another font size or DPI.
2. **A swallowed character.** `QCheckBox("Tự động kiểm tra & dịch lại…")` — Qt reads a bare
   `&` as a keyboard mnemonic, so it rendered as "kiểm tra _dịch lại". Now "và".
3. **A clipped intro label.** No `setWordWrap`, so the long explanation ran off the edge of
   a resizable dialog. Two labels fixed.

Two regression tests added (row tall enough for its combo; no widget label hides a character
behind a mnemonic). 3478 passing.
