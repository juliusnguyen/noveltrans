## [IMPL] Multi-select regenerate in the Audio tab — 2026-08-19

Implemented the plan. Files touched:

### `src/noveltrans/gui/widgets.py`

- Added `focus_index_keeping_selection(table, index)` and called it from
  `enable_cell_copy`'s `show_menu` in place of the bare `table.setCurrentIndex(index)`.
  That call issued `ClearAndSelect`, so right-clicking collapsed any multi-row selection to
  the row under the cursor — which would have made "Tạo lại N chương" unreachable. The
  `NoUpdate` branch still moves the *current* index, so `Ctrl+C` and
  `AudioTab._preview_text` keep following the cell actually clicked.
- Added `QItemSelectionModel` to the `PySide6.QtCore` import (reflowed to a parenthesised
  block).
- `RowButtonDelegate.editorEvent` now requires `event.button() == LeftButton`. Pre-existing
  bug: right-clicking the `🔊 Tạo lại` cell fired the row's job *and* opened the context
  menu. This feature made it acute — right-clicking the button column of a 20-row selection
  would have started a one-chapter job and then offered a greyed-out "Tạo lại 20 chương".

### `src/noveltrans/gui/tab_audio.py`

- `REGENERATE_CONFIRM_FROM = 5` (module level) — batches of 5+ confirm first; 1-4 do not, so
  the per-row `🔊` button stays a one-click action.
- Explicit `setSelectionMode(ExtendedSelection)` on the table. Redundant with
  `enable_cell_copy` today, but the tab now depends on it, so it is stated at the point of use.
- `enable_cell_copy(self.table, extra_actions=self._add_regenerate_actions)`.
- New `_add_regenerate_actions(menu, index)` — builds the item from the *selection*, falling
  back to the clicked row when that row is outside the selection. Hidden when nothing is
  voiceable, disabled (with a tooltip) while a job runs. Label counts the chapters that will
  actually run: `🔊 Tạo lại chương này` / `🔊 Tạo lại N chương`.
- New `_selected_rows()` — dedupes `selectedIndexes()` (one index per *cell* under
  `SelectRows`) into sorted rows.
- New `_regenerable_indices(rows) -> (indices, skipped)` — the only place that converts table
  rows to `chapter.index`. Drops chapters with no source text for the current radio, sorted
  ascending because `AudioWorker` iterates `indices` in order.
- New `_regenerate_rows(rows)` — the shared path. `_regenerate_row` is now a one-line wrapper
  over it, so the per-row button and the batch cannot drift apart.

**No per-chapter clear step, deliberately.** `AudioWorker` with an explicit `indices` list
bypasses `pending_audio` and overwrites, which is what the existing single-row regenerate
already relies on. Clearing first would blank good rows that then fail (leaving "Chưa tạo"
plus an orphaned file) and would force a `set_chapters()` model reset that drops the user's
selection mid-batch. Recorded as a code comment so it does not get "fixed" later.

### `tests/test_tab_audio_multiselect.py` (new, 18 tests)

Covers the selection helpers, the menu labels/visibility/disabled state, one-job-for-N-rows,
skip-and-report for chapters without text, both confirm paths, the running-job guard, the
`Bản gốc` branch, both halves of the right-click selection rule, and the right-click-on-button
fix.

Tests 15/16 drive `focus_index_keeping_selection` directly rather than emitting
`customContextMenuRequested`: the real path ends in a modal `menu.exec()`, and
`monkeypatch.setattr(QMenu, "exec", ...)` does **not** take on a PySide6 class — the patch is
silently ignored, a real modal event loop opens and the run hangs. Hit this during
implementation; extracting the helper is what makes the behaviour testable.
