# 057 — Audio: multi-select + right-click "Tạo lại" — Implementation Plan

## 1. Current behaviour and the gap

- The chapter table (`tab_audio.py`, `self.table`) is a `QTableView` over
  `AudioChapterTableModel` with `SelectionBehavior.SelectRows`.
- `enable_cell_copy(self.table)` already sets `SelectionMode.ExtendedSelection`
  (`widgets.py:535`), so drag / Ctrl+click / Shift+click multi-row selection **is already
  functional** — it is just invisible and nothing reads it.
- Three regeneration entry points exist:
  - per-row `🔊 Tạo lại` delegate button → `_regenerate_row(row)` → `_start_generate(indices=[chapter.index])`
  - `Tạo lại từ đầu` → `_regenerate_all()` → `project.clear_audio()` + `model.set_chapters(...)` + `_start_generate()`
  - `Tạo audio tất cả` → `_start_generate()` (pending only)
- `_start_generate(indices=None)` already accepts an explicit chapter-index list and wires
  progress, the job registry and button state. `AudioWorker` with explicit `indices`
  (`workers.py:643-651`) resolves them via `project.chapter(i)` and keeps only those with
  source text — it deliberately bypasses `pending_audio`, so it **re-synthesizes and
  overwrites regardless of existing audio**.

**The gap:** nothing in the tab reads `self.table.selectionModel()`. `_preview_text` reads
`self.table.currentIndex()` — one row. There is no context-menu hook on the audio table
(unlike `tab_scrape.py:148`). And `enable_cell_copy`'s `show_menu` calls
`table.setCurrentIndex(index)`, which **destroys any multi-row selection the moment you
right-click** — so even after adding a menu item, the selection would be one row.

### Why there is no per-chapter clear step

The prompt says "clear audio state for the selected chapters then run". Do **not** implement
that. Reasons:

1. Unnecessary — the worker overwrites unconditionally, which is exactly what the existing
   single-row `_regenerate_row` already relies on.
2. There is no per-chapter clear API; `NovelProject.clear_audio()` is all-or-nothing.
   Adding `clear_audio_for(indices)` would be new storage surface for no behavioural gain.
3. It would be actively worse: it blanks `audio_path`/`audio_voice`/`audio_seconds` for
   every selected chapter, so any chapter that then fails (or a cancelled batch) is left
   showing "Chưa tạo" with an orphaned file on disk. Regenerating in place degrades
   gracefully — a failed chapter keeps its old, still-playable audio.
4. Clearing forces a `model.set_chapters(...)` refresh, which does `beginResetModel()` /
   `endResetModel()` and **drops the user's selection** — the opposite of the point of this
   feature. Staying on `update_chapter` (dataChanged only) keeps the selection alive across
   the whole batch.

Item 3 of the prompt is therefore satisfied implicitly. This must be stated in a code
comment so a future reader does not "fix" the missing clear.

## 2. The `enable_cell_copy` / `setCurrentIndex` selection collapse

`QAbstractItemView::setCurrentIndex` issues `ClearAndSelect | selectionBehaviorFlags()`,
i.e. it collapses the selection to the clicked row. Qt's own `mousePressEvent` already does
the right thing for right-clicks (an already-selected item yields `NoUpdate`), but
`customContextMenuRequested` is emitted from `contextMenuEvent`, **after** the press — so
this line clobbers what Qt preserved.

### Decision: fix it in `enable_cell_copy`, for all three tabs, unconditionally

Extract the rule as a testable module-level helper in `widgets.py`:

```python
def focus_index_keeping_selection(table: QTableView, index) -> None:
    selection = table.selectionModel()
    if selection is not None and selection.isSelected(index):
        selection.setCurrentIndex(index, QItemSelectionModel.SelectionFlag.NoUpdate)
    else:
        table.setCurrentIndex(index)
```

Needs `QItemSelectionModel` added to the `PySide6.QtCore` import.

The `NoUpdate` branch matters: it still **moves the current index**, so `Ctrl+C` and
`AudioTab._preview_text`'s `table.currentIndex()` both follow the cell actually
right-clicked. A naive "just skip setCurrentIndex when inside the selection" would leave the
current index stranded wherever a drag ended, silently changing which chapter
`Xem trước văn bản` previews — a regression against prompt item 4.

Extracting it as a named function rather than inlining the `if` in the closure is
deliberate: the closure is untestable (it ends in a modal `menu.exec()`), this is directly
unit-testable.

### Blast radius: the three `enable_cell_copy` callers

| Caller | Reads selection? | Effect |
|---|---|---|
| `tab_audio.py` | `_preview_text` reads `currentIndex()` only | Target of the feature. `currentIndex` still tracks the clicked cell, so preview is unchanged. |
| `tab_translate.py` | `selectionModel().currentRowChanged` → `_on_row_selected` | `currentRowChanged` still fires in the `NoUpdate` branch (the *current* index does change), so the preview save/load still runs as today. Only difference: a multi-row selection now survives a right-click. Nothing depends on it collapsing. |
| `tab_scrape.py` | `_add_download_actions` uses only the clicked `index`; `rename` calls `table.edit(...)` | No behavioural change. |

Verified by grepping every `currentIndex` / `selectionModel` / `selectedRows` /
`selectedIndexes` / `selectRow` use across `src/noveltrans/gui/`.

**Rejected alternatives:**
- *A `keep_selection=True` flag, opt-in for the audio tab only.* Minimum blast radius, but
  it enshrines a bug in two tabs. Collapsing a deliberate multi-selection on right-click is
  never intended. (Two-line fallback if review pushes back.)
- *A second slot on `customContextMenuRequested` in `tab_audio` that snapshots the
  selection first.* Correctness would depend on connection order. Reject.
- *Subclass `QTableView` / event filter.* Far more machinery than a three-line rule.

### Bonus fix in the same file: `RowButtonDelegate` fires on right-click

`editorEvent` checks `MouseButtonRelease` and the rect but **not which button**. So
right-clicking the `🔊 Tạo lại` cell today emits `clicked` and starts a single-chapter job,
*and then* opens the context menu. Pre-existing in both the audio and translate tabs, and
this feature makes it acute: right-clicking the button column of a 20-row selection would
kick off a one-chapter job and then hand you a disabled `Tạo lại 20 chương`. Add
`and event.button() == Qt.MouseButton.LeftButton`.

## 3. Changes in `tab_audio.py`

### 3.1 Wire the hook and make multi-select explicit

- After `setSelectionBehavior`, add an explicit
  `self.table.setSelectionMode(QTableView.SelectionMode.ExtendedSelection)` — redundant
  with `enable_cell_copy` today, but this tab now *depends* on it, so spell out the
  requirement at the point of use rather than inheriting it from a helper named "cell copy".
- Change to `enable_cell_copy(self.table, extra_actions=self._add_regenerate_actions)`.
- Add `QMenu` to the `PySide6.QtWidgets` import block for the hook's type hint.

### 3.2 New selection helpers

```python
def _selected_rows(self) -> list[int]:
    """Distinct table rows in the current selection, top to bottom."""
```

Deliberately `selectedIndexes()` + a set rather than `selectedRows()`: `selectedRows()` only
counts rows where *every* column is selected — true under `SelectRows`, but it would quietly
return `[]` if the behaviour ever changed or a column were hidden.

```python
def _regenerable_indices(self, rows: list[int]) -> tuple[list[int], int]:
    """(chapter indices to re-voice, rows dropped) for `rows`, in chapter order."""
```

- **Rows are table positions; `AudioWorker` wants `chapter.index`** — not the same number
  once a novel has gaps. This is the *only* place that converts.
- **Ordering:** sort ascending. `AudioWorker` iterates `self.indices` in the given order, so
  ascending order makes the progress line read as a forward march instead of jumping around
  after a Ctrl+click spree. Dedupe via `dict.fromkeys` is a no-op under `SelectRows` but
  makes the helper safe to call with hand-built row lists.
- **Chapters with no source text: skip, and report in one line.** Silent skipping is wrong —
  a user who drag-selects rows 1-50 on a half-translated novel and sees "Xong: 30 chương"
  needs to know why. But a modal per skip, or refusing the whole batch, is worse. So filter
  them out and set `status_label` to `Bỏ qua N chương chưa có nội dung.` If *everything* was
  skipped, say so and do nothing. This mirrors what the table already shows — those rows
  read "Chưa dịch"/"Chưa tải" and have no `🔊` button at all.

### 3.3 One shared path: `_regenerate_rows`

`_regenerate_row` becomes a thin wrapper over a new batch method, so the per-row button and
the menu provably share one code path (prompt item 3's "reuse, don't write a new flow"):

```python
REGENERATE_CONFIRM_FROM = 5

def _regenerate_rows(self, rows: list[int]) -> None:
    # project guard → running-worker guard → eligibility → confirm → _start_generate
def _regenerate_row(self, row: int) -> None:
    self._regenerate_rows([row])
```

Two intentional behaviour deltas versus the old `_regenerate_row`, both safe:
- The `project is None` case now shows the standard "Chưa chọn truyện" modal instead of
  returning silently. Unreachable from the button (no project ⇒ no rows), correct for the
  menu path.
- The running-worker check now precedes the source-text check. Unreachable difference from
  the button, since `RowButtonDelegate` neither paints nor accepts clicks on a row whose
  `UserRole` is falsy.

`_regenerate_all` is untouched — it keeps its own `clear_audio()` + `set_chapters()` +
confirm, which is right for "wipe the novel and start over".

### 3.4 The context-menu hook

Modelled on `tab_scrape._add_download_actions`:

- **The clicked-row fallback.** With the `widgets.py` fix, a right-click inside the
  selection preserves it and a right-click outside collapses to that row, so
  `_selected_rows()` is already correct in both cases. The `index.row() not in rows` guard
  is cheap belt-and-braces for a stale selection model and makes the hook independently
  testable without real mouse events.
- **Snapshot `rows`, not `indices`.** The lambda captures a copy of the row list and lets
  `_regenerate_rows` recompute chapter indices at trigger time, so `_regenerable_indices`
  stays the single authority (and a source-radio flip between build and trigger cannot
  produce a stale index list).
- **Hide vs disable.** Hide (`return`) when there is nothing voiceable; add-but-disable
  while a job runs, exactly as `tab_scrape` does for `from_here`/`only_this`. A disabled
  item teaches the user the feature exists and the tooltip says why it is off; an item for a
  chapter with no text would be a dead end with no explanation. The prompt's "hidden when
  nothing is selected" case is effectively unreachable — `show_menu` returns early on an
  invalid index, so the menu never opens over empty space.
- **The label.** `🔊 Tạo lại chương này` for one, `🔊 Tạo lại {n} chương` for many, counting
  the chapters that will *actually* be regenerated rather than the raw row count — an item
  that says "5 chương" and then does 3 is a bug report waiting to happen. The discrepancy is
  explained in the tooltip. `menu.setToolTipsVisible(True)` is required or the action tooltip
  never appears.
- **Confirmation: yes, but only from 5 chapters up** (`REGENERATE_CONFIRM_FROM = 5`). TTS is
  minutes per chapter and a large model load, and it overwrites files on disk — a mis-dragged
  200-row selection is both plausible and expensive, the same logic behind
  `_regenerate_all`'s confirm. But a dialog on 1-4 chapters would be pure friction and would
  regress the per-row `🔊` button into a two-click action, so keep the threshold above the
  "I meant this" range. Module-level constant so a test can read it.

## 4. Test plan

New file `tests/test_tab_audio_multiselect.py` (repo convention is one file per concern).
Style: `qapp` fixture, direct calls to private methods, `monkeypatch` on `QMessageBox`, and a
`_start_generate` recorder so nothing touches the real `AudioWorker`.

1. `test_table_allows_multi_row_selection` — mode is `ExtendedSelection`; three selected rows
   come back as `[1, 3, 4]`.
2. `test_selected_rows_dedups_the_cells_of_one_row` — `SelectRows` hands back one index per
   *cell*; the helper must not count a row twice.
3. `test_menu_action_names_the_selected_count` — `🔊 Tạo lại 3 chương`.
4. `test_menu_action_is_singular_for_one_row` — `🔊 Tạo lại chương này`.
5. `test_menu_falls_back_to_the_clicked_row_when_nothing_selected`.
6. `test_menu_offers_nothing_when_no_chapter_has_source_text` — no separator, no dead item.
7. `test_regenerate_rows_starts_one_job_for_every_selected_chapter` — the core assertion:
   **one** call, `indices == [1, 2, 4]`, chapter order not click order.
8. `test_regenerate_rows_skips_chapters_without_source_text` — `[1, 3]` and a
   `Bỏ qua 1 chương` status.
9. `test_regenerate_rows_reports_when_nothing_is_regenerable`.
10. `test_regenerate_rows_confirms_a_large_batch` — declined ⇒ no job, and the prompt names
    the count.
11. `test_regenerate_rows_does_not_confirm_a_small_batch` — `QMessageBox.question`
    monkeypatched to `pytest.fail`.
12. `test_row_button_and_batch_share_one_path` — prompt item 4.
13. `test_regenerate_refuses_while_a_job_runs` — guard fires *and* the menu item is greyed
    out (so the guard does not rely on the disabled item alone).
14. `test_regenerate_uses_the_original_source_when_that_radio_is_on` — guards the
    `_use_translation()` branch.
15. `test_right_click_inside_a_selection_keeps_it` — selection survives, current index moves.
16. `test_right_click_outside_a_selection_reselects_that_row` — locks in the unchanged half,
    so the fix cannot over-reach.
17. `test_menu_acts_on_the_clicked_row_when_it_is_outside_the_selection`.
18. `test_row_button_ignores_a_right_click` — right-click returns `False` and never fires
    `clicked`; the left-button mirror still does.

**Note on 15/16:** they drive `focus_index_keeping_selection` directly rather than emitting
`customContextMenuRequested`. The real path ends in a modal `menu.exec()`, and
`monkeypatch.setattr(QMenu, "exec", ...)` does **not** take on a PySide6 class — the patch is
ignored, a real modal event loop opens, and the test run hangs indefinitely. Extracting the
helper is what makes this behaviour testable at all.

## 5. Sequencing

1. `widgets.py`: the helper + the `show_menu` swap + the `QItemSelectionModel` import + the
   `editorEvent` button check. Run the full suite green before touching `tab_audio` — this is
   the only step with cross-tab reach.
2. `tab_audio.py`: explicit `ExtendedSelection`, `QMenu` import, `_selected_rows`,
   `_regenerable_indices`, `_regenerate_rows`, `_regenerate_row` reduced to a wrapper,
   `REGENERATE_CONFIRM_FROM`.
3. `tab_audio.py`: `_add_regenerate_actions` + the `extra_actions=` wiring.
4. `tests/test_tab_audio_multiselect.py`.
5. Manual pass, since none of the above exercises real synthesis: drag-select 3 chapters →
   right-click inside → the label reads `Tạo lại 3 chương` and the selection visibly
   survives; run it and watch the progress bar cap at 3; right-click a single unselected row
   (label flips to `chương này`); press the per-row `🔊` with 5 rows selected and confirm only
   that one runs; right-click *on* the `🔊` cell and confirm no job starts.

## 6. Risks and edge cases

- **Job already running.** Guarded twice on purpose: the menu item is disabled at build time
  and `_regenerate_rows` re-checks at trigger time — a job can be started from another tab
  while the menu is open, and `_start_generate` would otherwise overwrite `self._worker`
  mid-run and orphan the live thread.
- **Empty project / no chapters.** `show_menu` returns on an invalid index, so the menu never
  opens over an empty table; `_regenerate_rows` still guards `project is None` for the
  direct-call path.
- **Source radio `Bản gốc` vs `Bản dịch`.** `_regenerable_indices` reads `_use_translation()`
  fresh, so the eligible set always matches the table and what `AudioWorker` will filter with.
  Flipping the radio calls `model.set_source` → full model reset, which drops the selection —
  acceptable and consistent (the whole eligibility picture changed), but worth knowing before
  someone reports it as a bug.
- **`_start_generate`'s own modals fire for batches too.** With `Bản dịch` on an untranslated
  novel it shows "Chưa có bản dịch" even though `indices` was explicit. Pre-existing for the
  single-row path; in practice unreachable because `_regenerable_indices` returns nothing first.
- **Model refresh after regen.** No action needed: `chapter_done`/`chapter_error` →
  `_on_chapter_updated` → `model.update_chapter` emits `dataChanged` per row, so rows update
  live and the selection is preserved for the whole batch. This only holds because we do not
  clear/reset.
- **Cancel mid-batch** leaves the not-yet-reached chapters with their old audio and the
  reached ones regenerated. Correct, and strictly better than a clear-first design where
  cancelling would leave a run of rows blank.
- **Very large selections.** `AudioWorker` materializes `pending` as a list from a generator,
  so a 5000-chapter selection is fine memory-wise; the confirm dialog is the real guard.
- **Row vs chapter index** is the one genuinely easy bug here. `_selected_rows` returns rows,
  `_regenerable_indices` is the only converter, and everything downstream is chapter-index.
  `AudioChapterTableModel` has no `row_for_index` — nothing here needs the reverse direction.
