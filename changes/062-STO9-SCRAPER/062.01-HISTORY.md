# 062 — sto9.com scraper — history

## [PLAN] 062.01-INITIAL-PLAN — 2026-08-25
Generated plan: `062.01-INITIAL-PLAN.md`

Live reconnaissance was done first (the planning pass had no network and took it as
given); plan claims about existing code were spot-checked against the tree — see the
plan's §0 table (33 rows).

Findings that shaped the plan:

- **The chapter-list page is truncated and nothing in its markup admits it.**
  `/book/13908/index.html` ships 36 of 187 entries: the first 15, a
  `點擊展開全部187章節目錄` button calling `LoadMore()`, then the last 21. An adapter
  written against that page passes every smoke test a developer would think to run
  (metadata correct, TOC non-empty, chapters 1 and 36 both download) and loses 151
  chapters silently. The complete list is a plain HTML fragment at
  `/ajax_novels/chapterlist/<id>.html` — no auth, no `X-Requested-With`, no Referer.
- **Those 36 are not a prefix**, which is what makes the trap corrupting rather than
  merely lossy. Their `data-num` jumps 15 → 167, and `ChapterRef.index` is dense and
  positional (`models.py:117`) with nowhere to record the site's own number. Entry 16
  would be stored as `idx=15` while actually being chapter 167; `replace_toc` upserts by
  `idx` **preserving content** (`project.py:273`), so a later successful re-scan rewrites
  the title and URL and leaves the wrong body underneath. Hence the decision that a
  known-truncated page is *never* an acceptable fallback — it raises instead.
- **Three pages carry three different things**, so a scan is genuinely 3 requests. The
  TOC page has **0** `og:` tags (the detail page has 14), so reading metadata off
  whichever URL the user pasted would yield a title-only novel for the *most common*
  paste form. The truncation signal exists only on the TOC page; the chapters only in the
  fragment.
- **Same CMS as 69shuba** — `div.txtnav`, `<br>`-separated body, OpenGraph metadata — so
  `shuba69.py:134-159` transfers almost verbatim and `xbanxia`'s blanket
  `span, div, script, ins` decompose is explicitly not copied (`shuba69.py:37-39`
  documents why).
- **No paywall, no login, no JS payload, no obfuscation, no rate limit.** Cloudflare is
  present but issues no challenge. The entire risk surface of this feature is the TOC.

### Decisions carried out as planned

- **Canonical URL is `/book/<id>/index.html`** (the site's own `og:novel:read_url`), from
  all three paste forms. `Library.find_by_url` is exact string equality, so echoing the
  pasted URL would make three projects for one novel.
- **`ORIGIN` is pinned**, not derived from the pasted URL (diverging from `shuba69.py:67`,
  which preserves the host for its mirror). No sto9 mirror is known, and pinning is what
  guarantees `http://`, `www.` and the bare host all fold to one string. Commented so a
  future mirror is a deliberate edit.
- **`fetch_chapter_list` prefers the ajax fragment and raises when the page is known
  truncated.** Error is Vietnamese and names both counts — matching `bookqq`'s convention
  that user-actionable errors are Vietnamese while structural ones stay English.
- **Placeholder cover → `""`**, matched by path suffix so a CDN host or cache-buster
  can't defeat it. Tested in both directions: a one-sided test passes with the check
  deleted.
- **`&emsp;&emsp;` indents need no code at all** — U+2003 is whitespace, so `.strip()`
  already removes them, and a blanket replace would eat the em-spaces the CMS uses
  *inside* lines. Pinned by a test asserting no residue.
- **`index` from `enumerate()`, never `data-num`**; titles keep the site's own text minus
  the trailing space (no colon/width normalisation — titles are persisted, exported into
  the EPUB and read aloud by TTS).
- Fixtures are hand-built to the measured structure (unclosed `<li>`s, the double space
  in `<a  target>`, mid-prose `div.txtcenter` ad slots, the stray triple-`<br>`) with
  **invented filler prose** — the repo's existing convention, so no novel text lands here.

### One deviation from the written plan

The plan's §2.3 defines `stated_total` as "`max()` of whatever is available" across two
signals (the `#loadmore` text and `max(data-num)`), but its §5 test list also asserted
`stated_total(index_full.html) is None`. Those contradict each other — with the max-of-both
design a 4-chapter page returns 4, not `None`. Implemented §2.3's design (it is the one the
adapter's safety argument rests on) and wrote the test as
`stated_total(index_full) == len(refs)`, which preserves the property that actually
mattered: nothing signals truncation, so the safe page-fallback branch stays reachable.
