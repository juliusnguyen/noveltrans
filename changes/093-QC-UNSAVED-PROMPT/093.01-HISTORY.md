# 093-QC-UNSAVED-PROMPT — History

## [FEAT] Đóng asks before throwing a QC change away — 2026-09-14

The follow-up offered at the end of 092 and taken up: the Save button gave the user a way
to keep a change, but Đóng still discarded one silently, which is the half of the original
complaint that a button alone does not fix.

### Changes

- `gui/qc_dialog.py`: `reject()` is overridden. When the current settings differ from the
  saved baseline it asks, and acts on the answer — "save" writes through
  `_remember_choices()` and closes, "discard" closes untouched, "cancel" returns without
  closing or writing. `accept()` is deliberately not touched, so starting a scan or opening
  the results (both of which save first) never asks.
- Covers Đóng, Esc and the window's X at one stroke: `QDialog.closeEvent` rejects.
- `_ask_unsaved()` builds the box with explicit Vietnamese labels
  (`CLOSE_SAVE_LABEL` / `CLOSE_DISCARD_LABEL` / `CLOSE_CANCEL_LABEL`) instead of
  `QMessageBox.StandardButton`, whose text arrives in English unless a Qt translation is
  loaded — a lone "Save / Discard / Cancel" row in this app would read as another program.
  It is also the seam the tests drive, so no test has to poke at a live modal.
  `setDefaultButton` is the save button: Enter keeps the work, never throws it away.
- `_current_settings()` returns exactly what `_remember_choices` would write, as one
  comparable tuple. `_remember_choices()` now also moves the baseline — it is the single
  place anything is written, so every caller (Save button, scan, results) is covered by
  the one line.

### The baseline is a snapshot of the widgets, not of the config

Taken at the end of `__init__`, deliberately. `qc_ai_engine` defaults to the translator,
which can be Google — an engine the judge combo never offers — and the combo then falls
back to its first item. Comparing widgets against config would call that mismatch a change
the user made and prompt when closing a dialog they had only looked at. A test pins the
Google case.

### Verification

6 new tests: an untouched dialog (with the Google fallback armed) asks nothing; a change
offers to save and saving writes it; discard closes without writing; cancel leaves the
dialog open and writes nothing; closing after the Save button asks nothing; starting a scan
never asks. Closing is observed through `done()`, which is where `QDialog.reject` ends, so
"did it actually close" is asserted rather than assumed. QC modules: 79 passed.

Also driven through the real code path against an INI copy of the user's settings: switched
the chain row's engine, called `reject()`, and grabbed the modal while it was up —
buttons rendered as `['Lưu rồi đóng', 'Quay lại', 'Đóng, bỏ thay đổi']` with "Lưu rồi đóng"
default, and cancelling left the dialog open with the config untouched. (The grab used a
`QTimer` against `activeModalWidget()` rather than OS-level clicks — see 092's note on why
synthesized clicks here cannot be trusted.)

Full suite with `test_tts.py` and `test_workers_pause.py` excluded (see 090): **3533
passed** — 092's 3527 plus these 6 — 4 skipped, the same 43 pre-existing environmental
failures, none outside them. Ruff: 9 findings on the touched files before and after.
