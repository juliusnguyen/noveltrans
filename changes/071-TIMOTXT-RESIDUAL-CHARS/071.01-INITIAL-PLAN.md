# 071.01 — Initial plan: timotxt residual characters

## Summary

Four changes, in dependency order:

1. **`scrapers/timotxt.py`** — two new pure helpers below the `parsing` line (`bodies_align`,
   `merge_bodies`) plus a bounded re-fetch loop in `TimotxtAdapter.fetch_chapter`
   (`timotxt.py:400-407`). The common case stays at exactly one request.
2. **`scripts/build_timotxt_table.py`** — remove the hardcoded `376`, allow more than one
   cross-check novel, re-run with a wider sample, paste the extended `_SUBSTITUTIONS`.
3. **Repair path** — `NovelProject.clear_translations`/`clear_audio` gain an optional index
   filter; `DownloadWorker` gains `indices`; `ScrapeTab` gains a timotxt-only detector, a
   count+confirm dialog and a scoped forced re-download.
4. **Tests** — a pure merge suite, request-count assertions on the retry, the `꿫`→`仍`
   regression, detector/repair GUI tests, and **one required change to a 070 live test**.

## Corrections to the feature prompt's framing

**A. The 070 "~p² residual" objection does not transfer to a targeted retry — it is much
better than assumed.** 070 measured "~40 chars garbled in both" over *all* substituted
characters, pre-decode (≈60-120 per body). Composed with the table, the merge's residual base
is not that population — it is only the **unmapped** characters, of which chapter 376 carried
exactly **1**. So p² applies to a base of ~1: expected post-merge residue ≈ 0.03/chapter, not
40. The retry is not "half the problem at double the cost"; it is essentially all of the
remaining problem at ~1.3× cost.

**B. 070's per-chapter Hangul counts are not available to reason from.** The build script
prints them to stdout and they are pre-decode anyway; nothing in `070.01-HISTORY.md` recorded
them. The evidence that bears on cost is: the 070 live test's `residual_hangul(body) <= 3`
*slack* bound (chosen over `== 0`); the user's six fetches of ch376 (2 dirty / 4 clean); and
the plan's two draws (1 dirty / 1 clean, residue 1).

**C. `DownloadWorker(force=True)` cannot take a scattered set of chapters.**
`_select_chapters` (`gui/workers.py:2200-2204`) offers `chapters_in_range(start, end)` only.
Residue chapters are scattered, so "the missing piece is a DETECTOR" is *nearly* right —
there is also a small worker/storage gap. `TranslateWorker` already has the needed shape
(`indices: list[int] | None`, `workers.py:161/173/221-224`), so this copies an existing
precedent rather than inventing one.

**D. Clearing the translation is not enough — there is a third stale layer.**
`pending_audio` (`project.py:437-472`) re-queues on `audio_path = ''`, a voice mismatch or a
source mismatch. Blanking `translated` changes none of those, so a repaired-and-re-translated
chapter would keep audio rendered from the *bad* translation, and the video pipeline would
consume it silently. The repair must clear the audio row too.

**E. One 070 test must change or it silently stops testing anything.**
`TestLive::test_the_deobfuscation_table_has_not_drifted` calls `adapter.fetch_chapter`, which
after this feature retries until residue is 0. It will keep passing — for the wrong reason —
and the drift detector for an empirical table evaporates. It must be rewritten to measure a
**single draw** via `parse_chapter(client.get_html(ref.url), …)`. This is the one place
"070's tests pass unchanged" is the wrong goal.

## Design decisions

### 1. The targeted re-fetch and positional merge

Two pure helpers below the `parsing` line + a thin loop in `fetch_chapter`. Cap at 2 extra
draws. Stop on misalignment. Never catch the first parse.

```python
def bodies_align(a: str, b: str) -> bool:
    """True when two draws of one chapter are the same text with different scrambling.

    The substitution is strictly 1:1, so equal paragraph counts AND equal per-paragraph
    lengths is what "same text" means here. Anything else means the chapter was edited
    between the two requests, and any alignment would be fiction.
    """
    pa, pb = a.split("\n\n"), b.split("\n\n")
    return len(pa) == len(pb) and all(len(x) == len(y) for x, y in zip(pa, pb))


def merge_bodies(a: str, b: str) -> str:
    """Take the readable character at EACH position — not the better of two bodies.

    The two draws scramble different random subsets, so neither is "the good one".
    Only ever replaces a residual Hangul syllable in `a` with a non-Hangul character
    from `b`: the same under-correct-only asymmetry `deobfuscate` guarantees, so a
    clean character in `a` can never be overwritten however wrong `b` is.
    Returns `a` unchanged when the two do not align.
    """
    if not bodies_align(a, b):
        return a
    return "".join(
        y if _HANGUL_RE.match(x) and not _HANGUL_RE.match(y) else x for x, y in zip(a, b)
    )
```

Alignment by paragraph implies equal total length, so the character-wise `zip` over the
joined bodies is safe and the `\n\n` separators line up by construction.

**Why the replacement is unambiguous:** the table is fixed, so a given source character
always becomes the *same* Hangul key. After `deobfuscate`, `b[i]` at a position where `a[i]`
is residual Hangul is either the identical unmapped Hangul or the true Han character. There
is no third case, so "take `b` if it is not Hangul" cannot pick up a wrong glyph.

| Question | Choice | Why |
|---|---|---|
| Where does the merge live? | Pure helpers, loop in the adapter | Matches the module's stated contract. Every interesting case is testable with two hand-written strings and no `responses`. |
| How many retries? | 2 extra draws | Draw 2 clears ~95-97% of residue; draw 3 clears the rest to ~1e-4/char. A 4th buys nothing and turns a pathological chapter into 4× cost. |
| Exhausted? | Best merged body + the existing `_status` warning | Raising would refuse a chapter ≥99.9% clean, which `errors.py:16` reserves for undecodable content. |
| Draws don't align? | `break`; return draw 1 verbatim | Do not guess-align, and do not spend a third request: the accumulator is anchored on draw 1, so once the site's copy moved on, every further draw misaligns too. |
| Retry fetch fails? | Catch `ScrapeError`, keep what we have | `ObfuscatedContentError` subclasses `ScrapeError`, so a mid-batch rotation on draw 2 also lands here — correct, we already hold a good body. |
| Learn new mappings at runtime? | **No** | A process-local cache would make output depend on fetch order, break `deobfuscate`'s pure/total/idempotent contract, and make fixtures non-deterministic. Learning stays offline. |

**The `_OBFUSCATION_ALARM_RATIO` path is not bypassed** — the raise is inside `parse_chapter`
(`timotxt.py:336-342`), which runs on *every* draw, and the first `parse_chapter` call is
deliberately **outside** the `try`. A wholesale rotation drives residue past 0.20 on draw 1
and raises before the loop is entered. Worth an explicit test, because a careless refactor
wrapping everything in one `try/except ScrapeError` would convert the loudest failure mode
into a silent one.

### 2. Cost

**1.2-1.4× requests, not 1.0×, and it is a function of table coverage.**

- Instance-level coverage of the 122-entry table is already ~99.3-99.5%: 60-120 substituted
  characters pre-decode, **1** residual in 3728 characters post-decode.
- P(residue > 0) per draw: 2/6 and 1/2 pooled ≈ **0.3-0.4**, consistent with the 070 live
  test's `<= 3` slack bound.
- Expected requests ≈ `1 + 0.35 + 0.35·0.03` ≈ **1.36**. For a 376-chapter novel: ~510
  requests instead of 376 — against the 752 that 070 rejected. Roughly 3 extra minutes.

**The load-bearing consequence:** the retry rate *is* the table's incompleteness. Extending
the table is not "a mitigation we do anyway" — it is the cost optimisation for item 1, and the
only lever on it.

Caveat: chapters containing legitimate Korean text would trigger the retry every fetch and
never clear. None observed; bounded at 3 requests and a warning.

### 3. Extending the table

Primary novel 60 chapters, two cross-check novels at 15 each, 2 fetches per chapter ≈ 180
requests at `--delay 1.5`. Item 1 makes a *very* large sample unnecessary — correctness no
longer rests on the table, only the request budget does — so the target is "cut the retry rate
~3×", not "prove completeness" (which no sample can).

Two script defects to fix first:

- **`step = max(1, 376 // count)` hardcodes the reference novel's length** (line 133). For a
  shorter second novel most sampled `n` are 404s, silently swallowed by
  `except requests.RequestException: continue` (line 140) — very likely why the second novel
  contributed only "+1 and +2 new mappings". Fix: derive each novel's length from `/dir`.
- **The secondary count is hardcoded to 8** (line 131) with no flag. Add `--second-chapters`
  and let `--second` take a comma-separated list.

Both invariants gate shipping: `conflicts` empty (a key resolving to two values invalidates
the fixed-table premise) and cross-novel agreement printing `SITE-WIDE`.

### 4. Repairing already-downloaded chapters

**The core decision: a chapter with residual Hangul in `content` must have its translation
invalidated unconditionally — the damage is not detectable in the translation.** In this
report the translator did *not* leave Hangul or an obviously broken word; it emitted `渺`, a
plausible Han character appearing nowhere in the source. It could as easily have emitted a
plausible *Vietnamese* word, which no scan can find. So "flag translations containing leftover
CJK" is insufficient, and re-fetching the source alone is exactly the silent wrongness the
prompt identified. The only defensible rule: **residue in `content` ⇒ the translation derived
from it is untrustworthy ⇒ drop it and re-translate.** Per correction (D), the same argument
runs one step further into audio.

| Layer | Function | Change |
|---|---|---|
| Detect | `residual_hangul` (`timotxt.py:177`) | none — add `needs_refetch(content) -> bool` for readability |
| Select | `NovelProject.chapters()` (`project.py:354`) | none |
| Drop translation | `clear_translations` (`project.py:975-987`) | add `indices=None`; `None` = whole novel so `_retranslate_all` is unchanged. Already blanks `translated_raw` — correct, a rewrite backup of a discarded translation goes with it. |
| Drop audio | `clear_audio` (`project.py:800-819`) | same optional `indices`; keeps its "spare downloaded narration" default |
| Re-fetch | `DownloadWorker._select_chapters` (`workers.py:2200-2204`) | add `indices`; a straight copy of `TranslateWorker.run`'s shape. `indices` implies force. |
| Re-translate | `TranslateWorker(indices=…)` | **none.** Blanking `translated` puts chapters back into `pending_translation`, so the user presses "Dịch" and only the repaired chapters queue. |

**Placement.** A `QPushButton("Sửa chương lỗi ký tự")` on `download_row` in `tab_scrape.py`,
hidden by default, shown in `_apply_project_ui` only for a timotxt project. Rejected: a
context-menu item (only reachable over a valid row; this is novel-wide), an automatic modal on
open (not the house style), folding it into `_start_scan` (a scan is about the TOC; this is a
local scan of stored text).

The dialog follows `_delete_chapter` and `_retranslate_all` — count first, consequences
enumerated, `QMessageBox.question`, naming that manual edits and rewrites go too. Zero found →
an information dialog matching the existing "Đã đủ" shape.

**Ordering — clear before, not after the download.** Clearing up front is one transaction on
the GUI thread with no cross-thread SQLite writes. The alternative (clearing in
`_on_chapter_done`) has better semantics but writes from the GUI thread while the worker
writes. The deciding argument is the failure asymmetry: if the re-download fails after an
up-front clear, the chapter has bad content and an **empty** translation — a state nothing
downstream can silently consume and which the detector still flags. Keeping the translation
and never clearing keeps the wrongness silent. Loud beats silent.

**Scope plumbing.** `_begin_download` gains `indices`, stored as `self._dl_indices` and reset
on ordinary paths. `_selected_pending()` and `_launch_download()` must both honour it —
otherwise a repair interrupted by the daily-limit unlock resumes via `_resume_timer` with the
wrong scope and re-downloads the whole novel.

### 5. Detector: timotxt-specific

- **The signal is not general.** "Hangul in a chapter body" is meaningful *only* because
  timotxt substitutes Hangul for Han. Elsewhere it is just text — a novel quoting Korean, or a
  future Korean-source adapter — and the detector would offer to destroy good translations.
- **`NovelMeta.site` is available and reliable.** First-class field (`models.py:38`), written
  at creation from `parse_metadata(..., site=self.name)` and refreshed by every re-scan
  (`refresh_meta`). A *chapter* row records no adapter, but it need not: a project has exactly
  one site and `replace_toc` never mixes them.
- **Belt and braces:** `read_url` pins `meta.url`, so `TimotxtAdapter.matches(meta.url)` is an
  independent second signal. Gate on either — covers a legacy project whose `site` predates a
  rename.
- Promotion is mechanical if a second site ever needs it.

## Step-by-step changes

1. **`timotxt.py` — pure layer.** `_RESIDUE_REFETCH_MAX = 2` near `_OBFUSCATION_ALARM_RATIO`;
   `bodies_align`, `merge_bodies`, `needs_refetch` after `residual_hangul`. No change to
   `deobfuscate`, `parse_chapter` or the alarm path.
2. **`timotxt.py` — `fetch_chapter`.** The bounded loop; first parse outside the `try`.
3. **`timotxt.py` — docstring.** The table is empirical *and one missed character is enough to
   corrupt a translation*, so the adapter re-fetches and merges positionally rather than only
   warning; the merge takes the best character at each position; a character garbled in every
   draw survives; a chapter edited between draws is not merged; `_OBFUSCATION_ALARM_RATIO`
   fires inside `parse_chapter` on every draw and must never be wrapped by the retry's
   `except`. Cite `changes/071-TIMOTXT-RESIDUAL-CHARS`.
4. **`scripts/build_timotxt_table.py`.** Derive each novel's length from `/dir`; add
   `--second-chapters` and comma-separated `--second`. Re-run wide. Verify `0 conflicting
   keys` and `SITE-WIDE`.
5. **`timotxt.py` — `_SUBSTITUTIONS`.** Paste; update the provenance comment with the new
   date/novels/counts and the `꿫`→`仍` note.
6. **`storage/project.py`.** `clear_translations(indices=None)` and
   `clear_audio(include_downloaded=False, indices=None)`; return `rowcount` so the GUI can
   report what it did.
7. **`gui/workers.py` — `DownloadWorker`.** `indices: list[int] | None = None` plus the
   `_select_chapters` branch, documented as "explicit chapters, regardless of status".
8. **`gui/tab_scrape.py`.** `_dl_indices`; `repair_button`; `_is_timotxt()`;
   `_residue_chapters()`; `_repair_residue()`; `_begin_download(..., indices=None)` with
   `_selected_pending()` and `_launch_download()` honouring it.
9. **`README.md`.** The timotxt row: the app re-downloads a chapter automatically when a
   character is left undecoded, and there is a repair button for chapters downloaded earlier.

## Tests

Use `TimotxtAdapter(HttpClient(delay_seconds=0))` in retry-wiring tests (precedent:
`test_scrapers_medoctruyen.py:27`) or three draws cost 4.5 s of real sleep.

**`TestPositionalMerge`** (pure): garbled in A / clean in B → recovered; garbled in B / clean
in A → A kept; **garbled in both → survives verbatim, never invented**; ★ **a clean non-Hangul
character in A is never replaced by a differing one in B** (the never-over-correct guarantee);
★ **the merge is not "pick the cleaner body"** (A dirty at i, B dirty at j → merged clean and
equal to neither); mismatched paragraph counts → A unchanged; equal count but differing
paragraph length → same; structure preserved; identical clean bodies → no-op.

**`TestResidueRefetch`** (`@responses.activate`, asserting call counts): ★ **a clean chapter
still costs exactly ONE request** (fails if anyone makes the merge the default path); cleared
by draw 2 → 2 calls, no warning; persisting → capped at `1 + _RESIDUE_REFETCH_MAX`, body
returned, `⚠️` emitted; misaligned draw 2 → 2 calls not 3, draw 1 returned verbatim; draw 2
raises → 2 calls, draw 1 returned, nothing raised; ★ **`ObfuscatedContentError` on draw 1
propagates with exactly 1 call**.

New fixtures: `chapter_residue_a.html` / `chapter_residue_b.html` (A dirty in paragraph 1, B
dirty in a *different* paragraph, so neither alone is clean) and
`chapter_residue_misaligned.html`.

**Regression:** `deobfuscate("꿫") == "仍"`; `"꿫" in _SUBSTITUTIONS`. Re-run every
`TestDeobfuscation` invariant against the extended table — unchanged and must stay green;
they prove the bigger table introduced no over-correcting entry.

**Storage/worker:** `clear_translations([i])` blanks only row i including `translated_raw`;
`clear_translations()` still clears everything; `clear_audio(indices=[i])` narrows and still
spares downloaded narration; `DownloadWorker(indices=[0,3])._select_chapters` returns exactly
those rows in idx order despite both having content.

**Detector / repair:** the button is hidden for non-timotxt and shown for timotxt; the
detector finds only chapters whose stored `content` has residue; ★ **confirming clears the
translations *and* audio of exactly those chapters and launches a download scoped to those
indices**; cancelling changes nothing; zero residue → information dialog, no worker; a
non-timotxt project's repair path is a no-op even with Hangul in its chapters.

**Live:** ★ **rewrite `test_the_deobfuscation_table_has_not_drifted` to a single draw** via
`parse_chapter`, with a comment saying why; new `test_the_refetch_clears_residue_live`; new
`test_single_draw_residue_stays_rare` as the retry-cost monitor.

## Risks / out of scope

**Risks**

1. **The retry rate is proportional to table incompleteness.** A *partial* table rotation
   (below the 0.20 alarm) would make every chapter take 3 draws and still warn — 3× requests,
   no error. The single-draw live test is the monitor; the `⚠️` status is the user-visible
   signal.
2. **A chapter with legitimate Korean text** costs 3 requests every fetch and always warns.
   None observed; bounded and non-fatal.
3. **Up-front clearing is destructive if the repair download then fails** — a manually-edited
   or rewritten translation is gone. The dialog must say so, in the user's own words
   ("sửa tay").
4. **Two SQLite handles.** The repair clears on the GUI thread *before* the worker opens its
   own — safe only because of the ordering choice. A refactor moving the clear into
   `_on_chapter_done` reintroduces the hazard.
5. **`_dl_indices` and the unlock-resume path.** Forgetting it in `_launch_download` turns an
   interrupted repair into a full-novel re-download.
6. **The extended table is still empirical** — unchanged from 070, and now much less
   load-bearing: an incomplete table costs requests, not correctness.

**Out of scope:** no general leftover-CJK safety net; no change to
`Translator._translate_with_retry` (its "keep the cleanest dirty attempt" is a real but
separate issue); no change to `SiteAdapter`, `HttpClient`, `models.py`, `errors.py`,
`translators/ads.py` or any exporter; no automatic re-translation kicked off from tab 1; no
re-render of audio or video (the repair clears the rows so the existing pipelines re-queue
them; deleting files stays with the cleanup dialog).
