Findings that shaped the plan during verification:

- **The three engines' `complete()` signatures differ.** Claude and LM Studio take a
  `system=` kwarg; `CliAgentTranslator.complete(prompt)` (`cli_agent.py:94`) cannot —
  it appends the prompt as the final argv entry of a subprocess. Calling
  `complete(prompt, system=...)` uniformly would raise `TypeError` at runtime on the
  engine most users pick, and only there, so it would pass every Claude/LM Studio test.
  Decision §2.2: one self-contained prompt, `complete(prompt)` positionally — which is
  what both shipped completion features already do (`workers.py:422`, `:493`).
- **`_translate_with_retry` must not be reused** (§5.5). Beyond calling `self.translate()`
  (the wrong prompt entirely), `base.py:90-91` returns the least-dirty attempt rather
  than raising — correct for translation, where the alternative is no text, but for a
  rewrite the alternative is the good text already in the database. Reusing it would
  commit truncated chapters over working translations. Recorded as the feature's
  single hard rule (§2.5) and pinned by a dedicated anti-regression test.
- **A rewrite silently desynchronises existing audio/subtitles/video** (§5.6).
  `pending_audio` (`project.py:402-438`) gates on paths, voice and source — never on the
  text — so a chapter with an mp3 is not re-pending after its text changes. Plan warns
  loudly and deletes nothing; per-chapter `clear_audio` is deferred.
- **`clear_translations` must clear the new raw columns** (§5.1), or "Dịch lại từ đầu"
  leaves every chapter flagged as rewritten with a backup belonging to a translation
  that no longer exists.
- **`tests/test_storage.py:262-291` DROPs a hard-coded column list**, so the migration
  stays unpinned unless that list is extended — the test would keep passing while the
  migration rotted.

No source files changed in this turn — planning only.

**Deviations from the plan, and why**

- **`RewriteRejected` was not created.** The plan lists it in §2.5 alongside a
  `check_rewrite` that returns a reason *string*, which leaves the exception with no
  caller. Worse, it was specified as `Exception`, not a `NovelTransError` subclass — so
  `RewriteWorker`'s `except NovelTransError` (the shape `TranslateWorker` uses at
  `workers.py:300`) would not have caught it, and a rejected rewrite would have killed
  the batch instead of skipping one chapter. `rewrite_chunk` raises `TranslateError`
  instead, which the worker's existing except clause already handles.
- **`build_rewrite_prompt` gained `retry_reason=""`.** The plan has the retry nudge
  appended by the caller; folding it into the pure prompt builder makes it directly
  testable (`test_the_retry_prompt_names_the_measured_failure`) instead of only
  observable through the retry loop.
- **`check_rewrite` gained `is_title=False`.** The length-ratio checks are meaningless
  for a one-line title — "Đệ nhất chương: Xuống núi" → "Chương 1: Xuống núi" is a
  legitimate 70% cut that `MIN_LENGTH_RATIO` would reject. Titles keep the non-empty,
  no-new-CJK and proper-noun checks.
- **The `min(engine_limit, 3000)` cap moved inside `rewrite_chapter`**, rather than
  being applied by the worker as §2.4 has it. One place enforces the ceiling and the
  guarantee is testable in the pure module
  (`test_the_engines_chunk_limit_is_capped_to_the_rewrite_ceiling`).
- **`first_line` is public.** Titles need the first-line reduction after normalisation;
  exposing it keeps `rewrite_chunk` readable and pins the behaviour with its own test.

**Notes on the implementation**

- `proper_nouns` is the piece with real judgement in it. Runs of ≥2 capitalised words
  are names; a run that starts a sentence loses its first word (Vietnamese capitalises
  there anyway), so "Phó Thanh Từ nhíu mày." at a paragraph start yields `"Thanh Từ"`,
  not the full name. Weaker than the full name, but still unsatisfiable by a model that
  renames the character — verified by `test_a_renamed_character_fails`. Trailing
  punctuation and line breaks end a run, so "Phó Thanh Từ, Giang Dư" correctly yields
  two names rather than one glued run.
- The `test_a_truncating_engine_never_yields_a_best_effort_string` test is the
  anti-regression pin for §2.5's hard rule, and says so in a comment naming
  `base.py:90-91`.

**How the tests pin the things that would silently rot**

- `_FakeEngine.complete(self, prompt)` takes exactly one positional parameter, so a
  worker that ever passed `system=` raises TypeError — caught as a chapter error, which
  turns `finished == [(2, 0)]` red. §5.12 is pinned without a test that mentions it.
- `_FakeEngine.translate` raises `AssertionError`, so the rewrite pass accidentally
  routing through the translation path fails the same assertion.
- `test_a_summarising_engine_leaves_the_translation_intact` is the end-to-end half of
  §2.5: `translated` byte-identical, `translated_title` untouched, `is_rewritten` false,
  status `error` carrying "số đoạn", `finished_ok(0, 2)`, and — the part that is easy to
  get wrong — `errors == [0, 1]`, proving the batch continued past the first failure.
- `test_a_failed_preview_does_not_mark_the_chapter_errored` separates "tell the user"
  from "write to the database"; a preview must leave the row exactly as it found it.
- `test_force_re_rewrites_but_keeps_the_first_backup` exercises §2.1's capture-once rule
  through the worker rather than through SQL.

**Note on `_summarise` in the tests**: it drops the last paragraph only for
multi-paragraph text, so a one-line chapter title passes through untouched. That keeps
the *body* the thing that fails, which is both the realistic shape and what makes the
"batch continues" assertion meaningful.

**Still unmeasured — the plan's two "inferring" items (§6.1, §6.2).** Neither is
verifiable without running a real engine on real chapters, and both are exactly what the
preview flow was built first to answer:

1. **Does a coding-agent CLI do this task well?** `cli_agent.py:29-30` established that
   agent CLIs accept task framing for *translation*; a monolingual Vietnamese style
   rewrite is a different ask, and a coding assistant's instinct is to improve rather than
   preserve. Run `👁 Xem thử 1 chương` on ~10 real chapters before committing a novel.
2. **Is `MIN_LENGTH_RATIO = 0.60` right?** It is derived from one example sentence
   measuring 0.75, plus headroom. Too tight wastes retries on good rewrites; too loose
   lets a partial chapter through. Paragraph-count equality is the real guard and is
   exact, so this is only a backstop — but the constant should be re-tuned from observed
   ratios once real data exists.
