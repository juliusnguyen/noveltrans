## 1. Summary of the approach

The app already carries every piece this feature needs; almost nothing new has to be
invented.

- **Auth already exists and is wired.** `AppConfig.SITE_COOKIES` (`config.py:23-26`)
  already maps `tieuthuyetmang.com` → `tieuthuyetmang_cookies`, `cookies_for_url`
  resolves it, `settings_dialog.py` already has the field (password echo) plus a help
  dialog, and the scan/download workers already inject it into `HttpClient.set_cookies`.
  The "user-supplied session" route is **not hypothetical — it is shipped**.
- **A persistent-login browser pattern already exists**, used three times:
  `discord_unlock.open_login`, `onedrive_upload.open_login`, and the session classes
  `cf_browser.BrowserSession` / `webtruyendich_browser.WtdBrowserSession`. All sit on
  `browser.launch_persistent_context` (real Chrome, anti-automation args, dedicated
  profile dir under `DEFAULT_LIBRARY_DIR`).

So: **a cheap path reusing the shipped cookie, and a browser escalation reusing the
shipped login pattern** — the escalation paid for only when the cheap path comes up
empty. Parsing lives in `scrapers/tieuthuyetmang.py` as pure functions; the byte-fetch
and file-write live in a new `AudioDownloadWorker` structurally copied from
`AudioWorker`; the UI is one button in `AudioTab`, invisible unless
`project.meta.site == "tieuthuyetmang"`.

The riskiest assumption is §2.1: **do not pre-filter on the landing page's
`audioLocked` flag.**

## 2. Decisions

### 2.1 Auth route — two-tier (cookie first, dedicated-profile browser as escalation)

Keep the existing `tieuthuyetmang_cookies` paste as tier 1. Add a dedicated Playwright
profile at `DEFAULT_LIBRARY_DIR / ".tieuthuyetmang-profile"` as tier 2, entered from a
new login button in Settings, mirroring `discord_unlock.open_login` (headed real Chrome,
blocks until the logged-in URL appears, session persists in the profile).

Rationale:

1. **The cookie tier is free.** Already built, already tested, already documented in the
   tab's help dialog; `parse_chapter`'s error strings already tell the user to re-paste
   it (`tieuthuyetmang.py:435-437`). If the entitled `/nghe/N` response carries the media
   URL, plain `requests` at the adapter's 2s throttle beats launching Chrome — fewer
   moving parts, no optional Playwright dependency, works in the packaged build.
2. **The browser tier is the only thing that can answer the unknown.** The site is a
   Next.js App Router app with no server-rendered chapter markup. If the media URL is
   minted client-side — an XHR to a signing endpoint after hydration, the normal shape
   for a paid-media gate — then *no* cookie-plus-`requests` fetch can ever see it,
   however valid the session. A real browser sees the request the `<audio>` element
   actually issues. This is decisive, and why the escalation is not optional.
3. **It reuses `browser.py` verbatim.** No new auth mechanism, no new dependency, no new
   credential store. `discord_unlock` and `onedrive_upload` prove the pattern survives
   real login gates because it drives the *installed* Chrome, not bundled Chromium.
4. **Expiry stops being a treadmill.** A pasted cookie expires and the user redoes the
   DevTools dance; a persistent profile re-authenticates itself.

**Fallback if the browser tier cannot be built** (Playwright is an *optional* extra):
degrade to cookie-only, with a message saying exactly that plus the install command —
the shape `discord_unlock._require_playwright` already uses.

**⚠️ The trap that would ship a feature that downloads nothing.** All 21 audio items read
`audioLocked: true` *on the anonymous landing page*, while the user's account **is**
entitled. So `audioLocked` there means "this needs VIP", **not** "you cannot have it". If
the worker pre-filters on `not entry["audioLocked"]`, an entitled VIP user downloads
**zero files** and the feature looks broken. The rule:

- `hasAudio` decides **whether to attempt** an item.
- Entitlement is decided **only** by what the entitled `/nghe/N` fetch returns.
- `audioLocked` is used **only** for the pre-run status line, never as a gate.

The semantics are *inferred* from the numbers (21 items, all flagged, user is VIP).
Designing the other way is unrecoverable; designing this way costs one wasted request per
un-entitled item.

**Credential storage.** Do **not** put a new secret in `AppConfig` — `config.py`'s
docstring is explicit that QSettings storage is unencrypted. The existing cookie already
lives there; that is a pre-existing documented decision this feature need not
re-litigate. The *new* credential — the browser session — lives inside the Chromium
profile, protected by Chrome's own machinery, which is strictly better.

The only new `AppConfig` key is a **non-secret** marker, `tieuthuyetmang_account: str`,
mirroring `onedrive_account`, inheriting its caveat verbatim: **the profile directory
existing is not evidence of a login**, because `launch_persistent_context` mkdirs it
before anything is typed (`config.py:224-232` records this being got wrong once already).
Write the marker only after `open_login` returns successfully.

### 2.2 Media format — format-agnostic, sniffed at download time, ffmpeg for HLS

`ffmpeg` is already a dependency-in-practice (`tts/convert.py`, `tts/merge.py`; the tab
already disables MP3 and merge when `ffmpeg_available()` is False). So:

- Direct media (`.mp3`/`.m4a`/`.aac`, or `Content-Type: audio/*`) → stream to disk with
  `requests` in chunks. No ffmpeg.
- HLS (`.m3u8`, or `application/vnd.apple.mpegurl` / `application/x-mpegURL`) → remux
  `ffmpeg -y -i <url> -c copy <dest>.m4a`. `-c copy` because segments are already AAC;
  re-encoding a 40-minute volume is minutes of CPU for no gain. Cookies/UA via `-headers`.
- **Duration** comes from `_probe_duration` (`tts/video.py:126`, ffprobe, 0.0 on failure),
  needed for `save_audio(seconds=)` and M4B markers. Lift it into `tts/convert.py` as
  `probe_duration(path)`, leaving `_probe_duration = probe_duration` in `video.py`.
- Follow existing subprocess conventions: `**no_console_kwargs()`, explicit `timeout=`,
  stderr tail truncated to ~300 chars (`convert.py:53-55`).

If ffmpeg is missing and the asset is HLS, report and skip with the message shape the
format combo already uses.

### 2.3 Volume-to-chapter mapping — attach to the row that carries `hasAudio`

**No new "volume" concept enters the data model.** `parse_chapter_list`
(`tieuthuyetmang.py:309-327`) already emits one `ChapterRef` per `story_chapters` entry —
*including* audio-bearing entries — and `replace_toc` gives each a row in `chapters.db`.
The audio item **already has a chapter row**; the download fills that row's
`audio_path` / `audio_voice` / `audio_seconds` / `audio_source`.

This rule is correct under **both** readings of the 21-vs-122 mismatch:

- If "YTB TẬP n" volumes are their own TOC rows (122 = text chapters + 21 volume rows),
  each volume row gets its own file.
- If `hasAudio` is instead set on ordinary chapter rows every ~5th one, the flag marks
  the first chapter of the volume's range and the file attaches there.

Same code, same result — which is the point of choosing this rule.

**Filename**, mirroring `AudioWorker._run_sequential` (`workers.py:683`) so both kinds
sort together in `exports/audio/`:

```
{chapter.index + 1:04d}-{slugify(title)}-tieuthuyetmang.{ext}
```

The trailing `-tieuthuyetmang` occupies the slot the TTS filename uses for the voice, so
a later TTS pass writes a *different* filename and cannot clobber the download.

### 2.4 Coexistence with TTS audio

**(a) `audio_source` is the discriminator.** The column exists (`project.py:57`), the
migration table handles it (`:126`), and `merge.chapter_marker_title` already branches on
it. Downloaded rows get `audio_source = "downloaded"`. **No schema change needed.**

**(b) `audio_voice = "tieuthuyetmang"`** — a sentinel naming the narration source. It
renders in the existing "Giọng" column for free (`widgets.py:340-341`) and is what merge
selection keys off.

**(c) The merge step does *not* treat them alike today — a real bug this feature must
fix.** `plan_merge_windows` (`merge.py:55-58`) filters
`c.audio_path and c.audio_voice == voice`, and `_start_merge` takes `voice` from
`self.voice_combo` — the *TTS synthesis voice*. Downloaded audio would be silently
invisible to merge. (Latent bug already: you cannot merge audio made with any voice other
than the one currently selected.)

**Fix:** add `self.merge_source` `QComboBox` to `_build_merge_box`, populated in
`_on_project_selected` from the distinct `audio_voice` values present, defaulting to the
current TTS voice. `_start_merge` reads from it instead of `voice_combo`. ~15 lines, fixes
the latent bug, makes downloaded audio mergeable identically.

**(d) A downloaded file must never be deleted by a TTS pass.** `_run_sequential` unlinks
the stale file whenever `chapter.audio_path != rel_path` (`workers.py:707-710`). Because a
TTS pass produces a different filename, this would **delete the downloaded file**.

> **Sharpened during verification.** `pending_audio` (`project.py:333-352`) binds
> `audio_source != ?` to `"translated"`/`"original"`. A `"downloaded"` row therefore
> *always* satisfies that clause and is **permanently pending** — so "Tạo audio tất cả"
> would re-voice every downloaded chapter on every run and the unlink above would destroy
> the file. This is not a hypothetical edge case; it is the default path.

Two guards:

- `pending_audio` gains `include_downloaded: bool = False`, adding an explicit
  `AND audio_source != 'downloaded'` term **alongside** the existing clause (not
  replacing it — the existing `audio_source != ?` term stays, since it does different
  work).
- Guard the unlink: skip when `chapter.audio_source == "downloaded"`. Leaving an orphan
  file is cheap; losing a file the user may no longer be entitled to re-fetch is not.

### 2.5 Feature 057's multi-select regenerate must not apply to downloaded rows — verified

Checked against `_regenerable_indices` (`tab_audio.py:444-466`): a row is dropped **only**
when its source text is empty. So:

- A volume row with empty `content` is *already* dropped, and `_add_regenerate_actions`
  already returns when nothing is eligible (`:411-412`). Partly safe by accident.
- But an *ordinary* chapter with both text and downloaded audio **would** be offered, and
  re-voicing replaces narration with TTS. Wrong by default.

**To implement:**

1. `_regenerable_indices` skips `audio_source == "downloaded"`, counting it into `skipped`.
2. Tooltip distinguishes the two skip reasons ("chưa có nội dung" vs "đang dùng audio tải
   về").
3. `AudioChapterTableModel.data` returns `False` for `UserRole` on `REGENERATE_COLUMN` of
   downloaded rows, so `RowButtonDelegate` paints no 🔊 button and ignores clicks
   (`widgets.py:228`, `:246` already gate on `UserRole`).
4. Add a **symmetric** action — "⬇️ Tải lại audio" — routed to
   `_start_audio_download(indices=...)`. That is what "regenerate" means for these rows.

### 2.6 Failure / un-entitled surface — no schema change; report into `audio_error`

The table already has an "Lỗi" column with hover tooltip (`widgets.py:344-349`),
`_audio_status` already renders `audio_error`, and `mark_audio_error` already exists.

All outcomes are *report-and-skip* — never retry, never probe an alternate URL, never
touch a paywall:

| Situation | Behaviour |
|---|---|
| No `hasAudio` | Not attempted. Not an error, not counted. |
| Session missing/expired | `AuthRequiredError` → "Cần đăng nhập tieuthuyetmang.com…". Batch continues. |
| Account **not entitled** | `AudioUnavailableError` → "Mục này cần VIP…". Skipped, counted, never retried. |
| Entitled, no media URL found | `ScrapeError` naming the diagnostic script, per `parse_chapter`'s pattern (`:471-476`). |
| HLS but no ffmpeg | "Cần ffmpeg để tải audio dạng HLS (brew install ffmpeg)." |

Deliberate trade-off, stated so nobody "fixes" it later: the tab cannot pre-colour rows as
has-audio before a run, because `hasAudio` is not persisted. Persisting it means a new
column *and* a new `ChapterRef` field *and* a `replace_toc` change — three layers for a
cosmetic gain. Instead the worker fetches the landing page once per run (`_page` caches)
and emits a summary line: `"21 mục có audio, 0 đã tải, N cần VIP"`.

`counts()` gains `"downloaded_audio"` so `_update_status_line` can distinguish the kinds.

## 3. Implementation steps, in order

### Step 1 — `src/noveltrans/errors.py`

Add below `AuthRequiredError`:

```python
class AudioUnavailableError(ScrapeError):
    """This item has no audio, or the signed-in account is not entitled to it.

    Distinct from AuthRequiredError: the session is valid, it simply does not cover
    this item. The correct response is to report and skip — never to retry, and never
    to look for another way in.
    """
```

### Step 2 — `src/noveltrans/scrapers/tieuthuyetmang.py` (pure functions first)

All new functions take markup or a decoded stream, never a URL — preserving the split that
keeps the parsing surface fixture-testable with no network.

- `audio_page_url(novel_slug, number)` → `f"{_ORIGIN}/truyen/{novel_slug}/nghe/{number}"`.
  The shape is documented at line 5 as "(unused)"; delete that annotation.
- `audio_entries(stream, novel_slug)` → entries from `story_chapters` where `hasAudio` is
  truthy. Preserves reading order (`_ordered` already sorts).
- `audio_locked_count(entries)` → count of `audioLocked`. **Status line only** — add a
  comment saying so, referencing §2.1's trap.
- `find_audio_media(markup) -> str` — discovery. Search order:
  1. `<audio src>` / `<audio><source src>` in the soup.
  2. Any string in `flight_payload(markup)` matching `\.(mp3|m4a|aac|m3u8)(\?|#|$)` or on
     the site's media origin. Reuse the `raw_decode`-over-every-quote technique from
     `_longest_flight_string` (`:360-376`) rather than a regex over raw text — the module
     docstring explains why regexes over the flight stream are the likeliest silent bug.
  3. Return `""` when nothing found; callers decide fatality, matching `flight_payload`.
- `audio_gate_reason(markup, entry) -> str` → `"auth"` for the logged-out/preview state
  (reuse the `isPreview` signal `parse_chapter` trusts, `:433`), `"vip"` for
  entitled-shaped but gated, `""` for clear. Structural rather than field-named, matching
  `_longest_prose`'s reasoning.

On `TieuthuyetmangAdapter`:

- `fetch_audio_manifest(url) -> list[dict]` — `audio_entries(flight_payload(self._page(
  landing_url(url))), slug(url))`, plus a `self._status(...)` line with the VIP count.
  Reuses the cached landing page.
- `fetch_audio_url(ref) -> str` — `find_audio_media(self.client.get_html(audio_page_url(
  slug(ref.url), chapter_number(ref.url))))`; raises per §2.6. This is tier 1.
- Do **not** widen `SiteAdapter` (`scrapers/base.py`). These are adapter-specific; the
  worker resolves the concrete class. The ABC stays three abstract methods, and the ask is
  explicitly single-site.

### Step 3 — `src/noveltrans/tieuthuyetmang_browser.py` (new, tier 2)

Modelled on `cf_browser.py` (the smaller session module) and `discord_unlock.open_login`.

```
profile_dir() -> DEFAULT_LIBRARY_DIR / ".tieuthuyetmang-profile"
open_login(timeout_ms: int = 300_000) -> str
class TtmBrowserSessionError(Exception)
class TtmBrowserSession:
    __init__(profile=None, *, headless=False, delay_seconds=2.0,
             timeout_ms=60_000, sync_playwright=None)
    __enter__ / __exit__ / close()          # idempotent, never raises
    capture_audio_url(url: str) -> str
    cookie_header() -> str
```

- Lazy launch (constructing must never start Chrome — `cf_browser.py:82-83`: sessions are
  built for cancelled runs and in tests). `sync_playwright` injectable for the same reason.
- `_LAUNCH_LOCK` module-level `threading.Lock`, per `cf_browser.py:57`.
- `capture_audio_url` registers `page.on("response", …)` **before** navigating, collects
  the first media-looking response, navigates, waits up to `timeout_ms`. `""` on timeout.
- **⚠️ Do not copy `_block_heavy_subresources`.** Both `cf_browser._BLOCKED_TYPES:53` and
  `webtruyendich_browser._BLOCKED_TYPES:56` include `"media"` — which would abort the exact
  request this module exists to observe. Omit the route, or use
  `{"image", "font", "stylesheet"}`. Comment the set explaining why `"media"` is absent,
  or someone will "harmonise" it back in.
- `cookie_header()` joins the context's cookies for the origin, as
  `scripts/capture_69shuba.py::cookie_string` does (`:87-91`), so the byte-fetch runs over
  plain `requests`.
- `open_login` opens `settings_dialog._TIEUTHUYETMANG_LOGIN_URL` and blocks until a
  logged-in signal appears. Blocking → must run in a worker thread; say so in the
  docstring, as `discord_unlock.open_login` does.

### Step 4 — `src/noveltrans/tts/convert.py`

- Add `probe_duration(path) -> float` — move the body of `video.py:_probe_duration` here;
  leave `_probe_duration = probe_duration` in `video.py`.
- Add `download_media(url, dest, *, cookies="", headers=None, cancelled=None) -> Path`:
  - Direct → `requests.get(stream=True)` in chunks, polling `cancelled` between chunks
    (the shape `merge_chapters` uses, `merge.py:164`).
  - HLS → `Popen` + stderr-to-file + poll loop copied from `merge_chapters` (`:206-223`),
    *not* `subprocess.run`, so a long remux stays cancellable.
  - Raises `TtsError`; the worker translates to `audio_error`.

### Step 5 — `src/noveltrans/gui/workers.py`

Add `class AudioDownloadWorker(PausableWorker)` after `AudioWorker`, with **identical
signal signatures** so `AudioTab` reuses `_on_progress` / `_on_chapter_updated` verbatim:

```python
progress      = Signal(int, int, str)
chapter_done  = Signal(int)
chapter_error = Signal(int, str)
failed        = Signal(str)
finished_ok   = Signal(int, int)
```

`__init__(project_path, delay, cookies="", indices=None, headless=False, parent=None)`.

`run()`:
1. Open its own `NovelProject` from the path (never share a sqlite connection across
   threads — module docstring).
2. `HttpClient(delay_seconds=max(delay, 2.0), cookies=cookies)` — the 2s floor is the
   adapter's stated politeness rule (`tieuthuyetmang.py:22-24`). Then the adapter.
3. `fetch_audio_manifest` → emit the summary line.
4. Resolve manifest entries to rows by `chapterNumber` → `chapter_url` → matching
   `Chapter.url`. Intersect with `indices` when given.
5. **Sequential only.** `_checkpoint()` between items (pause/cancel at item boundaries per
   `PausableWorker`). Do not parallelise — the adapter docstring is explicit.
6. Per item: tier 1 `fetch_audio_url(ref)`; on `""`, escalate **once per batch** to
   `TtmBrowserSession`, launched lazily and reused, harvesting `cookie_header()` into the
   `HttpClient` on first success.
7. `download_media` → `probe_duration` → `save_audio(idx, rel_path, "tieuthuyetmang",
   seconds, source="downloaded")` → `chapter_done.emit(idx)`.
8. `AudioUnavailableError` / `AuthRequiredError` → `mark_audio_error` + `chapter_error`,
   **continue the batch**.
9. `finally:` close the browser session **and** `project.close()`.
   `tests/test_workers_adapter_close.py` pins this discipline — extend it.

## 4. Testing strategy

Matching repo conventions: pure functions against **hand-built** fixtures
(`test_scrapers_tieuthuyetmang.py`'s docstring explains why built beats captured),
`responses` for adapter wiring, injected fake Playwright for browser code
(`test_cf_browser.py`: "No test here launches a browser"), offscreen `qapp` for widgets.

**New fixtures** in `tests/fixtures/tieuthuyetmang/` — every string invented:
`nghe_mp3.html`, `nghe_audio_tag.html` (proves both discovery branches), `nghe_hls.html`,
`nghe_vip.html`, `nghe_anon.html`, `nghe_noaudio.html`.

The existing `landing.html` already carries `hasAudio`/`audioLocked`, so `audio_entries`
and `audio_locked_count` need no new fixture.

**`test_scrapers_tieuthuyetmang.py`** — add `class TestAudioDiscovery`:

- `_regenerable_indices` skips downloaded rows and counts them separately.
- `_add_regenerate_actions` offers no 🔊 action when all selected rows are downloaded, and

- `has_running_workers` / `shutdown` account for the new worker.

## 5. Risks and genuinely open items

These cannot be closed without a live authenticated session. Step 10's diagnostic script is
the instrument for all of them — run it **before** writing Step 2's `find_audio_media`
body, not after.

1. **`audioLocked` semantics.** §2.1. Designed defensively, so a wrong guess costs one
   wasted request per item rather than a feature that downloads nothing. **Highest-impact
   unknown.**
2. **Where the media URL lives.** In the entitled `/nghe/N` HTML, its flight stream, or a
   client-side XHR. Decides whether tier 1 ever fires. If it is a signed short-lived URL,
   the byte-fetch must follow discovery immediately — do **not** batch-discover-then-
   batch-download. Structure the loop discover-then-download per item from the start;
   that ordering is free and is the only one that survives signed URLs.
3. **Format.** MP3 vs HLS vs other. Handled by sniffing, but HLS with encrypted segments
   (`#EXT-X-KEY`) needs the key URL too, which `-c copy` handles only if ffmpeg can fetch
   the key with the same cookies. **If the site uses DRM proper, the feature is not
   implementable and the plan stops there** — flag it to the user rather than looking for
   a way around it.
4. **The 21-vs-122 shape.** §2.3 is correct under both readings, but if audio is addressed
   by a separate id space with no TOC row at all, the mapping needs rework — the one
   unknown that could change the data model. The diagnostic's chapter census answers it.
5. **Login-page URL and logged-in signal.** `/dang-nhap` is confirmed; the post-login
   URL/DOM signal `open_login` should wait for is unobserved. Verify before Step 3.
6. **VIP session longevity in a Playwright profile.** The site may bind the session to a
   device fingerprint. Mitigated by keeping the cookie fallback.
7. **Politeness.** 21 volume-length files is a lot of bytes from a small paid site. Keep
   the ≥2s delay, keep it sequential, consider a cumulative-MB status line. The adapter
   docstring is emphatic about this and this feature should not erode it.
