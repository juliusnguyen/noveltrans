**Deviations from the plan**

1. **`clear_audio` also had to be guarded.** The plan named `pending_audio` and the
   unlink; it missed that `_regenerate_all` calls `clear_audio()`, which would wipe the
   downloaded rows' state and orphan the files. Same bug family, now guarded the same way.
2. **There are *two* unlink sites, not one.** The plan named the sequential path
   (`workers.py`); the parallel path has its own at the `_AudioResult` handler and could
   not see `audio_source` at all. Required adding `prev_audio_source` to the dataclass.
   Both are pinned by tests, because a refactor is liable to drop the extra field.
3. **`pending_audio` was worse than described.** The existing clause binds
   `audio_source != ?` to `"translated"`/`"original"`, so a `"downloaded"` row *always*
   matched and was permanently pending — the destructive path was the default, not an
   edge case. Recorded in the method's docstring.
4. **Introduced `AUDIO_SOURCE_*` constants** rather than the plan's bare `"downloaded"`
   literal. `STATUS_DOWNLOADED = "downloaded"` already exists in `models.py` meaning
   *chapter text downloaded*; sharing the literal across two unrelated namespaces was an
   invitation to compare the wrong pair. The constants carry a comment saying so.
5. **`_start_merge` now reads the new combo, not `voice_combo`.** This fixes a latent
   pre-existing bug: audio made with any voice other than the currently-selected one was
   silently unmergeable. Pinned in `test_merge.py`.
