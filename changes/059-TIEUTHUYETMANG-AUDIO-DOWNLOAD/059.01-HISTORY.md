## [IMPLEMENT] 059.02 — audio discovery + download, unblocked by a live session — 2026-08-24

The user added their tieuthuyetmang cookie in Cài đặt, which unblocked the observation
step §5 required. `scripts/diagnose_tieuthuyetmang.py` was run against the reference novel
with that session, and the measurements overturned four assumptions the plan was built on.

**What the live session showed**

1. **The media URL is on `/nghe/<n>`, not `/doc/<n>`.** The plan knew the listen route only
   as "(unused)" in the module docstring. The `/doc/` reader page carries no media URL at
   all, cookie or not; `/nghe/` carries it as the `audioUrl` prop of the player component,
   server-rendered into the flight stream.
2. **No browser automation is needed — Step 3 is deleted, not deferred.** Plain HTTP with
   the account cookie returns the URL. `tieuthuyetmang_browser.py`, the tier-2 escalation
   and the whole `_BLOCKED_TYPES`/`"media"` trap the plan warned about no longer exist as
   problems, because nothing drives a browser.
3. **The media host is not gated.** `img.tieuthuyetmang.com` serves the file to an
   anonymous ranged GET — no cookie, no referer, `206` with `Accept-Ranges`. So only
   *discovery* needs the session, and resume comes for free.
4. **`audioLocked` is now false for all 21 entries**, where the prompt recorded all 21 as
   true and no URL observable. The account is VIP-entitled; the flag describes the
   anonymous view. It is a status line only — `audio_locked_count` says so in its docstring.

**Two measurements that changed the design**

- **Audio is published in two container formats.** 13 of the 21 volumes are `.mp3`, 8 are
  `.aac`. This was missed twice during observation because the first probes regexed for
  `\.mp3` and duly reported those 8 as "not uploaded yet". `_MEDIA_RE` covers both (plus
  m4a/ogg/wav/m3u8), the saved filename takes its suffix from the URL, and
  `test_finds_an_aac_url_too` exists specifically to keep that regression from returning.
- **The files are large: 1.70 GB for the novel, 203 MB for the biggest single volume.**
  `download_media` therefore streams to a `.part` sibling in 256 KiB chunks and renames
  into place only when complete. A truncated file that *looks* finished is the worst
  outcome available here, because 059.01's guards then protect it from being replaced.

**Done**

- **`scrapers/tieuthuyetmang.py`** — `audio_page_url`, `audio_entries`, `audio_locked_count`,
  `find_audio_media`, `audio_gate_reason`, `_MEDIA_RE`; adapter `fetch_audio_manifest`
  (reuses the cached landing page, so a scan still costs one request) and `fetch_audio_url`.
- **`tts/convert.py`** — `probe_duration` (moved from `video.py`, which keeps
  `_probe_duration` as an alias) and `download_media` with resume, progress and cancel.
- **`gui/workers.py`** — `AudioDownloadWorker`, signal-compatible with `AudioWorker`.
- **Tests** — 42 new (2076 total, ruff clean): 5 hand-built listen-page fixtures covering
  every observed state, plus `test_audio_download.py` and `test_workers_audio_download.py`.

**Deviations from the plan**

1. **Step 3 dropped entirely** (see above). `AuthRequiredError` is raised where the plan
   would have escalated to a browser: if the cookie cannot see the URL, neither can a
   headless Chrome without one.
2. **`audio_gate_reason` keys off the player prop, not a field name or the upsell copy.**
   Measured: entitled sessions get `audioUrl` whether or not the file exists yet; signed-out
   sessions get no player at all, just Vietnamese upsell text. Keying on the prop
   distinguishes "not entitled" from "not published" without parsing presentation strings.
3. **HLS is refused, not implemented.** The plan wanted an ffmpeg remux branch. No `.m3u8`
   has ever been observed from this site, so that branch would be untestable and
   unexercised; `download_media` raises a clear error instead.
4. **A real bug was found and fixed while testing `download_media`.**
   `requests.RequestException` subclasses `IOError`, so the `except OSError` clause placed
   before it swallowed every network failure and reported a dropped connection as a disk
   error. The ordering is now inverted with a comment saying why, and pinned by
   `test_a_dropped_connection_reports_the_network_not_the_disk`.

**Verified against the live site**

One full volume (TẬP 12, 47.2 MB `.aac`) downloaded end to end through the real adapter:
valid ADTS, 131.2 min by ffprobe, no `.part` left behind. Resume was then verified by
seeding a 20 MB `.part` and re-running — the result is byte-identical (sha256) to the clean
download. No audio is kept in the repo or the scratchpad.

**Not done**

Steps 9 (login UI) and 11 (README) remain, and `AudioTab` has no button wired to
`AudioDownloadWorker` yet — the worker is complete and tested but nothing in the GUI starts
it. Step 10 (extending `diagnose_tieuthuyetmang.py` with the `/nghe/` probes) is also still
open; the probes were written ad hoc for this turn rather than added to the script.

## [IMPLEMENT] 059.05 — skip what is already downloaded, and a per-row re-fetch — 2026-08-24

**Done**

- **`AudioDownloadWorker(skip_downloaded=True)`.** A release is 50–200 MB and its bytes
  never change, so a batch no longer re-fetches one already on disk. Skips are **counted,
  not silently dropped** (`worker.skipped`), and the tab's summary says so — without that,
  a batch over a finished novel reports "0 chương" and reads as a failure.
- **The skip is checked against the disk, not just the row.** A chapter marked downloaded
  whose file has since vanished IS fetched again; trusting the DB alone would leave the
  project permanently missing audio it believes it has. Only `AUDIO_SOURCE_DOWNLOADED`
  counts — a TTS row is still offered.
- **A per-row "⬇️ Tải lại" button** in the audio view, on every release that maps to a
  chapter — deliberately including rows already downloaded, since those are exactly the
  ones the batch now skips. It is the only affordance that overrides the skip rule, along
  with the "Tải lại audio" context action, which now forces too.

**The trap this turn**

`RowButtonDelegate.paint` returns early when `UserRole` is falsy and **does not chain to
the default painter**. The source model's button column (6) is the chapter model's "Lỗi"
column, so installing the delegate once and leaving it would have blanked every error
message in the chapter view — a silent, view-dependent data loss that no existing test
would have caught. `_on_view_changed` now swaps it against a plain `QStyledItemDelegate`,
and `test_the_button_delegate_is_removed_in_the_chapter_view` pins both directions.

**Tests** — 13 new (2115 total, ruff clean), including the vanished-file case, the
TTS-is-not-downloaded case, and that the batch button does not force while both re-fetch
affordances do.

**Still open**

No confirmation or free-space check before a large batch — though this turn removes most
of the risk, since a re-run now costs only the releases still missing. Steps 9 (login UI),
10 (`/nghe/` probes into the diagnostic) and 11 (README) remain.

## [IMPLEMENT] 059.06 — downloaded narration reaches the video tab — 2026-08-24

**The bug**

The video tab never synthesizes anything: it only consumes audio already on disk. But its
"Giọng" combo was filled from the **TTS engine's catalogue** (`TtsVoicesWorker`), while
downloaded narration is stored under `audio_voice = "<adapter name>"`. Since
`plan_merge_windows` filters `c.audio_voice == voice`, downloaded audio was *structurally
unreachable* from this tab — it could not be selected, so no video could ever be made from
it. Selecting an engine voice simply planned zero windows.

Same family as the merge step's bug (059.01 deviation 5), fixed the same way: list what
the project actually holds.

**Done**

- **`widgets.audio_source_label(voice, pretty=None)`** — labels a downloaded source as
  `"<name> (tải từ trang)"`. The set of adapter names comes from the **registry**
  (`ADAPTERS`, filtered on `fetch_audio_url`) rather than a hardcoded `== "tieuthuyetmang"`,
  so a second site that grows audio support is labelled right without touching this.
  `tab_audio._refresh_merge_sources` now uses it too, retiring its duplicate of the rule.
- **`tab_video._refresh_audio_sources()`** — fills the combo from the project's real
  `audio_voice` values, falling back to the engine catalogue only when the project has no
  audio at all, so the combo is never empty before the first chapter is voiced. Called on
  every project change.
- **`_on_voices_listed` no longer writes to the combo.** It stores the catalogue and
  delegates. Both inputs (async worker, project selection) now converge in one place —
  previously whichever landed second won, so a late worker could overwrite a
  project-derived list.

**Nothing else needed changing, which was worth verifying rather than assuming**

- No `.wav` assumption anywhere in `video.py` / `merge.py`; `_concat_audio` decodes per
  file and its comment already states mixed inputs are fine, so `.mp3` and `.aac` pass.
- Subtitles degrade correctly: `part_cues` lets a chapter without cues contribute nothing
  while **still advancing the offset**, and the `.srt` sidecar is written only when
  non-empty. Downloaded audio has no cues, so a part simply renders without them.
- Durations are real: the download worker stores `probe_duration` output at save time.

**Tests** — 12 new (2127 total, ruff clean), including the late-arriving-voice-list race
and the end-of-chain check that `plan_merge_windows` yields windows for the downloaded
voice and zero for the engine voice.

**Still open**

No confirmation or free-space check before a large batch. Steps 9 (login UI), 10 (`/nghe/`
probes into the diagnostic) and 11 (README) remain.

## [IMPLEMENT] 059.07 — site audio is its own edition, not chapter audio — 2026-08-24

**The correction**

Everything up to 059.06 stored a downloaded release on a chapter row. That was wrong at
the modelling level, not just visually: a release covers a chapter RANGE (21 releases
against 122 chapters, "[ YTB TẬP 1 ] Chương 1-5") and belongs to a different edition of
the work. Landing one on chapter N made a five-chapter volume look like that chapter's
narration, and put site audio in the chapter list where it does not belong.

**Done**

- **New `source_audio` table** keyed by the site's own `chapterNumber`, with `ord` for
  reading order. `models.SourceAudio` carries it, plus the narrow Chapter-shaped protocol
  (`index`, `audio_path`, `audio_seconds`, `audio_source`, `translated_title`) that
  `chapter_marker_title` and the renderers already read — so a release flows through the
  whole merge/render pipeline unchanged.
- **A migration that MOVES, never drops.** Existing `audio_source='downloaded'` chapter
  rows are copied into `source_audio` (number recovered from the chapter URL, which is
  what wrote it) and only then cleared. Those files are 50–200 MB and may no longer be
  re-fetchable. TTS rows are untouched; a URL with no number is left alone rather than
  guessed at; re-running is a no-op.
- **`AudioDownloadWorker` writes releases**, keyed by number, with `item_done`/`item_error`
  replacing the chapter-shaped signals. It no longer resolves manifest entries to chapters
  at all.
- **`plan_source_windows`** in `merge.py`, alongside `plan_merge_windows`; the slicing both
  share moved into `_group_windows`. Availability is "the file is on disk" (a release has
  no voice), and numbering counts RELEASES — "phần 1..21", not the chapter numbers the
  volumes happen to cover.
- **Merge and Video** offer the edition as a `SOURCE_AUDIO_KEY` sentinel entry rather than
  a voice, and pass `source_audio=True` to their workers.
- **The audio view reads the stored list first** and only fetches the manifest when it has
  none, so opening it offline still shows every volume and which are on disk.

**Consequences worth stating**

- The chapter list can no longer show "Đã tải", because nothing writes it there.
- 059.01's guards on `pending_audio` / `clear_audio` / the unlink sites are now unreachable
  in normal use. They are deliberately KEPT: they cost nothing and would catch a
  regression that put site audio back on a chapter row. `TestChaptersStayClean` pins the
  new invariant directly.
- The per-row 🔊 TTS button is available on every chapter again — there is no longer
  anything on a chapter row that a re-voice could destroy.
- "⬇️ Tải lại audio" is now audio-view only: "re-download this chapter" is not a thing
  that can be asked of a range-covering release.

**Tests** — three feature test files rewritten against the new model, plus
`test_source_audio_storage.py` covering the table and all four migration cases. 2125 pass,
ruff clean. (Slightly fewer than 059.06's 2127: several old tests described chapter-stored
downloads, a state the app can no longer produce, and were replaced rather than kept.)

**Still open**

No confirmation or free-space check before a large batch. Steps 9 (login UI), 10 (`/nghe/`
probes into the diagnostic) and 11 (README) remain.
