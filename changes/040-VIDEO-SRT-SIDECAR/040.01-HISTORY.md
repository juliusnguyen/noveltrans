## [IMPLEMENTATION] — 2026-07-29

1019 tests pass (984 before, +35), ruff clean.

### `tts/subtitles.py` (new, pure)

`Cue`, `format_srt_time`, `build_srt`, `scale_cues`, `shift_cues`, `cues_path`,
`write_cues`, `read_cues`, `part_srt`.

`read_cues` returns `([], 0.0)` for a missing or corrupt file rather than raising — the
same posture as `read_upload_state`. A missing sidecar is the normal case for any chapter
voiced before this feature, and a subtitle file must never be able to fail a video render.

### `tts/base.py`

`synthesize_chapter(..., cues_out=None)` fills one `Cue` per chunk from inside the
concatenation loop. Offsets are counted in **samples**, not by summing float durations, so
they are exactly the offsets the concatenation produces. An out-parameter rather than a
changed return type: three callers depend on the `float`, and two are previews that would
unpack a value only to discard it.

### `gui/workers.py`

`AudioWorker._write_cues` scales the cues and writes the sidecar beside the **final** audio
path. The rescale is the reason it lives in the worker rather than the engine, and the
factor is derived from `seconds / raw_seconds` rather than from `self.speed` — so it stays
correct when `_apply_speed` silently no-ops because ffmpeg is missing, which is exactly the
case where a hard-coded `1 / speed` would desync everything. `_drop_cues` removes stale
cues when a re-voice replaces the audio file: cues describing a take that no longer exists
are worse than none, because the subtitles would be confidently wrong rather than absent.

### `tts/video.py`

`render_video` writes `<stem>.srt` next to the `.mp4` and `.txt`, and only when some
chapter in the part has cues — an empty `.srt` beside a video looks like subtitles that
failed rather than audio that predates them.

**Better than planned:** the plan assumed offsets would come from the stored
`audio_seconds`, and worried about accumulated drift. In fact `render_video` already runs
`_with_real_durations(segments)` (line 625) before the SRT is built (line 668), so offsets
use ffprobe's real file durations. The drift risk in the plan's Risks section does not
apply.

### `gui/tab_video.py`

`_subtitle_coverage()` and a note on the render's finish line when coverage is partial.
Legacy audio has no cues; saying so is the point, since silence would read as a broken
feature rather than as old audio.

### A vacuous test, caught the same way as in 039

The first `TestSynthesizeChapterCues` used two 8-character paragraphs. `FakeTtsEngine` has
`max_chunk_chars == min_chunk_chars == 30`, so `merge_short_chunks` fused them into a
**single** chunk — and every pairwise assertion (gap spacing, contiguity) became a `zip`
over one element: vacuously true. The fixture now uses paragraphs long enough that merging
would exceed the max, and `test_the_fixture_really_produces_several_chunks` guards the rest
of the class against the same failure returning.

That is twice in two features that a fake made tests pass for the wrong reason. Both times
the tell was the same: an assertion that could not fail given the fixture.

### Known limits

- **Only newly-voiced audio has cues.** Existing chapters produce no subtitles until their
  audio is regenerated. Surfaced in the status line, never hidden.
- **A cue is a chunk, not always a sentence.** `merge_short_chunks` may have built one from
  several short sentences, so some lines run long. The alternative is re-splitting text
  whose audio boundaries would then be guesswork.
- **Uploading the `.srt` to YouTube is not part of this.** That is another Studio surface,
  and this session's record with those says it deserves its own change — and its own
  verification.
