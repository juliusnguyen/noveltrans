# 040 — `.srt` sidecar timed from TTS — PLAN

## Design decisions

| Decision | Rationale |
| --- | --- |
| **Cues are captured in `synthesize_chapter` via a `cues_out` list parameter.** | The exact sample offsets exist only inside that loop and cannot be recomputed afterwards. An out-parameter rather than a changed return type because three callers depend on the `float`, and two of them (the previews) don't want cues at all — a richer return would force both to unpack something they'd discard. |
| **One `<audio>.cues.json` beside each chapter's audio file.** | Cues belong to a *chapter's audio*, not to a part: re-voicing one chapter must invalidate exactly its own cues, and parts are re-cut freely by changing the batch size. Sitting beside the `.mp3` means the existing "delete stale audio on re-voice" path already keeps them honest. |
| **Written by `AudioWorker` *after* `_apply_speed`, scaled by the same factor.** | This is the one thing that would silently ruin every subtitle. `apply_tempo` rescales the audio and the worker returns `seconds / speed`; cues are in pre-speed time and need the identical division. Doing it in the worker — where `speed` lives — keeps the engine ignorant of a GUI setting. |
| **Part offsets are the cumulative sum of `MergeSegment.seconds`.** | Exactly what `build_ass_subtitles` already does for chapter titles, so the subtitles and the on-screen chapter title agree with each other by construction. `_concat_audio` inserts no gaps, so the sum is the real offset. |
| **A part with only some chapters covered still gets an `.srt`, and the count is reported.** | Legacy audio has no cues and re-synthesising 75 parts is not an option. Silence for the covered 80 % would be worse than partial subtitles, and a silent partial would be worse still — hence the count surfaces in the status line. |
| **The `.srt` is written by the video render**, next to the `.mp4` and `.txt`. | It is a per-part artefact like the description and the thumbnail, and the render is where the part's segment list already exists. |
| **`build_ass_subtitles` is untouched.** | It carries the novel/chapter title block that the player skin is designed around. Narration text does not belong burned into that layout — the whole point of choosing a sidecar. |

## Implementation

### 1. `src/noveltrans/tts/subtitles.py` (new, pure)

```python
@dataclass
class Cue:
    start: float
    end: float
    text: str

def format_srt_time(seconds: float) -> str:      # "HH:MM:SS,mmm", clamped at 0
def build_srt(cues: Iterable[Cue]) -> str:       # numbered blocks, blank-line separated
def cues_path(audio_path: Path) -> Path:         # <stem>.cues.json
def write_cues(audio_path, cues, *, seconds) -> Path
def read_cues(audio_path) -> tuple[list[Cue], float]   # ([], 0.0) when absent/corrupt
def scale_cues(cues, factor) -> list[Cue]        # the _apply_speed correction
def shift_cues(cues, offset) -> list[Cue]        # the chapter-offset-within-a-part
def part_srt(segments) -> tuple[str, int, int]   # (srt text, chapters covered, total)
```

`read_cues` returning `([], 0.0)` for a corrupt file rather than raising follows
`read_upload_state`'s posture: a subtitle sidecar must never fail a render.

### 2. `src/noveltrans/tts/base.py`

`synthesize_chapter(..., cues_out: list | None = None)`. Inside the existing loop, track the
running sample offset and append a `Cue` per chunk. Nothing else changes; `cues_out=None`
is byte-identical to today.

### 3. `src/noveltrans/gui/workers.py` — `AudioWorker`

Collect cues, scale by `1 / speed` when `_apply_speed` did something, and write the sidecar
beside the **final** audio path (post-mp3-conversion). Re-voicing already unlinks a stale
audio file; unlink its cues too.

### 4. `src/noveltrans/tts/video.py` — `render_video`

After the description, write `out_path.with_suffix(".srt")` from `part_srt(segments)`.
Skipped silently when no chapter in the part has cues — an empty `.srt` beside a video is
worse than none.

### 5. `gui/tab_video.py`

The render's finish line reports coverage when it is partial, e.g.
`"⚠️ Phụ đề: 6/10 chương (các chương cũ chưa có mốc thời gian — tạo lại audio để bổ sung)."`

## Test plan

`tests/test_subtitles.py` (new):

- `format_srt_time` — the SRT comma, zero-padding, hours past 1, negatives clamped.
- `build_srt` — numbering from 1, blank-line separation, a trailing newline, `\n` inside a
  cue preserved as a real line break.
- Round-trip `write_cues`/`read_cues`; a corrupt file reads as empty, never raises.
- `scale_cues` — **the `_apply_speed` regression**: at speed 1.25 a cue at 100 s becomes
  80 s, and the last cue's end still matches the reported duration.
- `part_srt` — chapter 2's cues are offset by chapter 1's duration; a chapter with no cues
  contributes nothing but still advances the offset for the ones after it.

`tests/test_tts.py` — `synthesize_chapter` fills `cues_out` with one cue per chunk, the
first starts at 0, each cue's start equals the previous end plus the gap, and the last end
equals the returned duration.

## Risks

1. **Accumulated drift.** Offsets come from stored `seconds`; if a chapter's real file
   duration differs slightly (mp3 encoder padding is ~26 ms), the error accumulates across
   a part. Bounded and small, and it is the same arithmetic the existing chapter markers and
   description timestamps already use — so subtitles will drift *with* them, not against them.
2. **Legacy chapters have no cues**, so most existing parts get partial or no subtitles
   until their audio is regenerated. Surfaced, not hidden.
3. A cue is a *chunk*, which `merge_short_chunks` may have built from several short
   sentences — so some subtitle lines will be longer than one sentence. Acceptable; the
   alternative is re-splitting text whose audio boundaries we would then be guessing at.
