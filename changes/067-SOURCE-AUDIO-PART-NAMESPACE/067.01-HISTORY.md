### The finding that was not in the prompt

`cleanup.covered_chapters` reads a part folder's trailing `-NNNN-MMMM` as chapter numbers
via `part_range` (`cleanup.py:102`). A source part's numbers are *release ordinals*, so a
rendered source part `truyen-0001-0010` authorised `plan_audio_cleanup` to delete chapter
audio 1-10 that no video contains — a data-loss path in the module whose entire doctrine is
"refuse unless the replacement is present and checkable". Verified directly against the
source before planning. Guarded now, and deliberately scoped to *chapter coverage* only: a
published source `.mp4` is still a legitimate **video** deletion candidate, which
`test_a_published_source_part_is_still_a_video_candidate` pins.

### Verified by reverting, not by assertion

- Without `tts/video.py`: 8 naming/scan tests fail.

- Two scan tests pass either way *by design* — the chapter scan already ignored

### Migration: none, deliberately

Chapter audio keeps its names byte-for-byte, so nothing on disk moves and no published part
is touched. The one hazard is a source part rendered *before* this change (possible via
per-row "Tạo" or "Toàn bộ" — only batch was broken until 066): it keeps the chapter name and
now reads as a chapter part, so its `.upload.json` stops participating and a re-render could
publish the same episode to YouTube twice. Nothing in a folder records which planner made
it, so this is undecidable and is **reported, never renamed** — an automatic move would be a
coin flip with a live video id at stake. `TestLegacySourcePartWarning::test_it_never_touches_a_single_file`
pins that.

### 066's D4, revisited

Its reason 3 ("a release is atomic, so commit-locking has no meaning") was **wrong** and is
retracted in the code comment: a source window *does* grow retroactively when later releases
arrive after an earlier part was rendered — exactly what locking exists for. 067 removes the
namespace obstacle, so `discover_committed_video_windows(..., source_audio=True)` is now well
defined. What still blocks source commit-locking is narrower and concrete:
`plan_locked_video_windows` filters on `c.audio_voice`, which `SourceAudio` does not have.
Deferred. Manual split/merge stays chapter-only (the map has no room for two number spaces).
