# 068 — Vertical novel bar, hover names, and one naming rule

## Ask (user)

> - support vertical bar (set in setting)
> - when move the mouse to the bar, it will show all the name of novel
> - novel name should be `[trans-name] + [actual name] + [source]`

## What "the bar" is

The **outer workspace tab bar** — `MainWindow.workspaces`, a `QTabWidget` in
`src/noveltrans/gui/main_window.py:132`. One tab per open novel. Labels start as
`Truyện N` and are replaced by the novel title via `_set_ws_title`
(`main_window.py:169-175`), truncated to `_MAX_TAB_LABEL = 24` chars
(`main_window.py:29`). Not the inner five-tab stack in `workspace.py`, and not the macOS
menu bar.

## Decisions taken with the user

| question | answer |
|---|---|
| Hover behaviour | **Tooltip per tab.** Hovering one tab pops that novel's full name. Not an expanding drawer, not one tooltip listing every novel. |
| Where the name format applies | **Everywhere novels are listed** — tab label, tooltip, and the novel picker / recent list. One rule, one helper. |
| Vertical by default? | **Yes, vertical becomes the default**, with a setting to go back to horizontal. |

## Scope

### 1. Vertical bar, default on, with a setting

`QTabWidget.setTabPosition(QTabWidget.TabPosition.West)` on `MainWindow.workspaces`.
Add an `AppConfig` property (the class starts at `src/noveltrans/config.py:96`; properties
are `QSettings`-backed) and a control in `gui/settings_dialog.py`. Default vertical;
horizontal is the opt-out.

Things to work out rather than assume:

- **Tab text orientation.** Qt rotates the label 90° for West/East tabs by default, which
  reads badly for Vietnamese and Chinese. Decide whether to keep it rotated, or set a
  custom `QTabBar` / stylesheet so text stays horizontal in a fixed-width column.
- **The close button.** `_add_workspace` puts a `QToolButton` at
  `QTabBar.ButtonPosition.RightSide` (`main_window.py:140`). Check where that lands on a
  vertical bar and whether it still looks right.
- **`_MAX_TAB_LABEL = 24`.** A vertical column has a different width budget than a
  horizontal strip. The cap probably wants to change, or become width-derived.
- **Applying the setting live.** Does flipping it take effect immediately, or on next
  launch? Immediate is nicer; confirm nothing in the tab bar needs rebuilding for it.
- **`gui/style.py`** may carry rules keyed to the horizontal bar (`tabCloseButton` is
  styled by object name) — check before assuming the stylesheet is orientation-agnostic.

### 2. Tooltip per tab

Set a tooltip on each workspace tab carrying the full, untruncated name. Must be kept in
sync wherever the label is — `_set_ws_title` is the one place today, but confirm nothing
else calls `setTabText` on this bar.

### 3. One naming rule: `[trans-name] · [actual name] · [source]`

**This reverses the existing order.** Today two helpers exist and both put the ORIGINAL
first:

- `NovelMeta.bilingual_title()` (`src/noveltrans/models.py:93-110`) returns
  `"{title}  —  {translated_title}"` — original, then translation. Used by
  `gui/widgets.py:81` (the picker) and `gui/tab_scrape.py:632` (the "Thông tin truyện"
  header).
- `_picker_label()` (`gui/widgets.py:72-83`) appends `source_host()`
  (`models.py:112-125`, a bare hostname, `""` for a local novel), giving
  `"原文  —  Bản dịch — site.com"`.

The ask is translated-first. Decide whether to change `bilingual_title()`'s order in place
or add a new helper beside it, and say why — `bilingual_title`'s docstring explicitly
justifies the current order ("the Chinese is how the user recognises the novel on the
source site"), so reversing it is a deliberate reversal of a documented choice, not a
tidy-up. Whichever way, there should be **one** function that all four call sites use
(tab label, tab tooltip, picker, scrape header).

Also settle:

- **Missing parts.** An untranslated novel has no `translated_title`; a local novel has no
  `source_host()`. Both already degrade gracefully in the current helpers — keep that, and
  don't leave a dangling separator.
- **Separator.** Existing conventions differ: `bilingual_title` uses `  —  ` (two spaces
  around an em dash), `_picker_label` uses ` — `. Pick one.
- **Truncation.** The three-part name is long. The tab label needs a cap; the tooltip and
  picker do not.
- **`display_title`.** `NovelMeta.display_title` is a user override used by
  `display_name()` for video output. Decide whether it participates here — it is the
  user's own name for the novel, so arguably it should win as `[trans-name]`.

## Out of scope unless it falls out naturally

Reordering or restyling the inner five-tab stack (`workspace.py`), and the menu-bar /
tray novel list (`gui/tray.py`).

## Test plan sketch

The GUI suites (`tests/test_main_window*.py`, `tests/test_widgets*.py` — check actual
names) build real widgets under the `qapp` fixture, so orientation, tooltip text and label
formatting are all assertable without a screenshot. The naming helper is pure and should
be covered directly: translated + original + source, each part missing in turn, and a
local novel.
