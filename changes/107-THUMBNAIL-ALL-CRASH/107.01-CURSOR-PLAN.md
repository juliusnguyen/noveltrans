# Plan: 107 — stop WaitCursor from crashing under a modal

## Cause (verified)
- `setOverrideCursor(Qt.CursorShape.WaitCursor)` makes Qt convert the cursor to a CGImage on macOS. Under a modal `QDialog.exec()` on macOS 27 / Qt 6.11 that crashes with SIGTRAP in `QImage::toCGImage`.
- Repro (`cursor_repro.py`, click inside a modal dialog): WaitCursor exits 133; BusyCursor and ArrowCursor exit 0.
- Triggered by "Áp dụng cho tất cả" in `ThumbnailEditorDialog`, which calls `_regen_all_thumbnails` from inside `exec()`.

## Steps
1. `src/noveltrans/gui/tab_video.py` (`_regen_all_thumbnails`): `WaitCursor` → `BusyCursor`, with a comment. The try/finally restore is unchanged.
2. `src/noveltrans/gui/tab_translate.py` (`_name_fix_proposals`): same change. It has the same risk, since the same call happens on the QC path.
3. Regression tests that assert the recorded cursor shape is not WaitCursor (Qt cannot be caught from Python, so the shape is the thing to guard):
   - `tests/test_tab_video.py::test_regen_all_never_sets_a_wait_cursor`
   - `tests/test_tab_translate_qc.py::test_name_fix_scan_never_sets_a_wait_cursor`
4. Verify: mutation check (WaitCursor → test fails, BusyCursor → passes); repro with BusyCursor exits 0; full suite.

## Alternatives considered
- Remove the override entirely: no crash risk, but the user loses the busy cursor. The status label still reports progress. Kept as the fallback if BusyCursor ever crashes.

## Not covered
- A real SIGTRAP cannot run under pytest offscreen, so the crash itself is confirmed only by the standalone repro, not by a test.
- Manual smoke test in the real app on macOS 27 (open thumbnail editor, press "Áp dụng cho tất cả" with several parts) is still needed.
