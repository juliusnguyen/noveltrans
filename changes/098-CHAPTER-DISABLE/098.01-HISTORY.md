### Video batching — corrected mid-implementation

The plan's first draft for `tts/merge.py`/`tts/video.py` sliced batches by a disabled
chapter's *position* among all enabled chapters. Running the full suite caught a real
regression this introduced: `test_local_novel.py`'s
`test_merge_windows_still_batch_by_chapter_number_across_a_gap` pins that a **deleted**
chapter must leave a true gap on the number grid (`delete_chapter`'s own docstring:
"nothing renumbers... a missing chapter can't shift later boundaries"). Position-based
slicing conflated "chapter doesn't exist" (deleted — must NOT shift the grid) with
"chapter is disabled" (must skip over — the opposite).

Fixed by walking the chapter NUMBER line one integer at a time (as the code always
did), counting every number toward a batch's `size` quota *unless* it's in a
`disabled_numbers` set — a missing number still counts (preserves the deleted-chapter
behavior byte for byte), a disabled number doesn't (the new feature). Landed as:

- `tts/merge.py` — new `_batch_window_end(lo, size, max_num, disabled_numbers)` helper,
  used by `_group_windows`'s `"batch"` branch (replacing the old fixed-arithmetic
  `hi = lo + size - 1`) and reused by `tts/video.py`. `plan_merge_windows` now passes a
  `disabled_numbers` set instead of the earlier (incorrect) `enabled_all` list.
  `part_number()` gained an optional `disabled_numbers` parameter using the same
  "count skips disabled, not missing" rule; omitted, it's byte-identical to before.
- `tts/video.py` — `plan_locked_video_windows` rewritten the same way, plus explicit
  handling for committed/manual-locked spans: a frozen span is never resized or
  filtered by `enabled` (it's a fact about an already-rendered/uploaded video), and a
  fresh window's walk is capped so it can never cross past an upcoming frozen span's
  start — otherwise a disabled chapter earlier in the novel could shift the walk past a
  frozen span without ever landing on it. `SubtitleWorker.run()`'s `part_number(...)`
  call now passes `disabled_numbers` too, for label consistency with the render.
