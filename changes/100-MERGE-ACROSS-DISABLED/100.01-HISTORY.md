### Why the predicate owns the message, not just the rule

The bug existed because one rule was spelled out in two places. Returning the *reason
string* from the pure function (rather than a bool) means the menu's tooltip and
`merge_windows`'s `ValueError` cannot disagree about either the rule or the wording, and
the tooltip names the offending chapter for free. `video_part_numbers.plan_renumber`
(feature 099) set the precedent for dialog-ready text living in a pure module.

### The trap the plan caught

Checking only "every chapter in the gap is disabled" passes **vacuously** for a reversed
or overlapping pair, because `range(last_a + 1, first_b)` is empty — which would have
silently broken the existing `test_rejects_overlapping_windows`. The `first_b > last_a`
clause is load-bearing, and `test_still_rejects_overlapping_windows_when_the_gap_is_skipped`
pins it.

### Deliberately still refused

A gap holding a chapter that is **enabled but not yet voiced**, or a chapter number with
**no chapter at all** (deleted / never scraped). Both can start rendering later and would
then be swallowed into a part that may already be uploaded, whereas disabling is an
explicit per-chapter choice. This is the first question a future reader will ask, so:
`test_rejects_a_gap_holding_a_chapter_that_does_not_exist` documents the decision.

Consequence worth knowing: two parts split by a merely *un-voiced* chapter still cannot be
merged. Fixing that generally means gating on grid slots rather than displayed spans, i.e.
`plan_locked_video_windows` returning each window's `(lo, hi)` — a return-type change with
two production consumers and ~15 test call sites. Not taken.

### Feature 099 interaction — verified, no code change

Merging away the window an offset was anchored at orphans the anchor.
`effective_part_number` sums deltas with `anchor <= first_num`, so the merged part keeps
`first_a` and does **not** pick up the orphaned delta (right answer — it is the earlier
part, extended), while every part after it still does, preserving the user's correction.
`TestMergeAcrossDisabled::test_a_merge_does_not_move_a_part_number_correction` pins it.
