# Feature: stop the YouTube profile from hoarding a copy of every uploaded video

## Request (original)

> why the `./.youtube-profile` cost so much storage?
> both, delete now and add the cleanup in the new /feature, plan and implement

## Verified behaviour (measured 2026-10-10)

`~/NovelTrans/.youtube-profile` was **13 GB**:

| Path | Size |
|---|---|
| `Default/IndexedDB/https_studio.youtube.com_0.indexeddb.blob` | 12 GB (12 files, ~1–1.3 GB each — one per uploaded video) |
| `Default/Cache` | 742 MB |
| `Default/Code Cache` | 179 MB |

YouTube Studio keeps the file handed to `set_input_files` in IndexedDB (resumable upload).
The automation closes the browser soon after each upload, and the blobs are never reclaimed,
so the persistent profile grows by the size of every video uploaded.

Deleting those three directories manually (no browser open) brought the profile to 28 MB;
the Google login lives in cookies, not in these directories.

## Goal

After the uploader closes the persistent context, delete those disposable directories
(Studio's IndexedDB blob store + HTTP/code caches) so the profile stays small — without
touching the login (cookies, Local Storage, other origins' IndexedDB), and never while a
browser is still holding the profile. Studio's IndexedDB origin is removed whole (`.blob` and
`.leveldb`) so no metadata is left pointing at deleted blobs — Studio only keeps upload
drafts there.
