# Plan: keep the YouTube profile small (feature 102)

## Verified facts this plan rests on

| Claim | Evidence |
|---|---|
| Every YouTube browser session opens through one function | `open_login`, `fetch_playlists`, `sync_playlist_batch`, `upload_subtitle_batch`, `upload_batch`, `_edit_batch` all call `_launch_context` (`youtube_upload.py:858`) |
| …and closes through one name in `finally` | `_close(context, playwright)` at 1078/1975/2180/2789/2972/3140; `_close` is the import alias `from noveltrans.browser import close as _close` (`:48`) |
| `browser.py` is shared (cf, webtruyendich, onedrive, discord) | so the change stays in `youtube_upload.py` |
| `browser.close` never raises | `browser.py:93` |
| Chrome's `SingletonLock` is a symlink to `host-pid` | `Path.exists()` follows it and lies; use `os.path.lexists` |
| `TestLaunchContext` does not patch `profile_dir()` | `tests/test_youtube_upload.py:882-905` — must be patched or the suite would prune the developer's real profile |

## Design

### D1. What to delete — the whole Studio IndexedDB origin + caches

```python
_DISPOSABLE_PROFILE_PATHS = (
    ("Default", "IndexedDB", "https_studio.youtube.com_0.indexeddb.blob"),
    ("Default", "IndexedDB", "https_studio.youtube.com_0.indexeddb.leveldb"),
    ("Default", "Cache"),
    ("Default", "Code Cache"),
)
```

Blob-only would leave leveldb metadata pointing at missing files. Studio only stores upload
drafts there; the login lives in `Cookies`, which is never touched.

### D2. When — before launch and after close

- `_launch_context`: prune before `launch_persistent_context` → reclaims anything left by
  earlier versions or crashes.
- Local `_close` wrapper: `_close_browser(...)` then `prune_profile_caches()` → every run
  leaves the profile small. All call sites already use `try/finally`, so failures prune too.

### D3. Safety — `prune_profile_caches(path=None) -> int` never raises

1. `path = path or profile_dir()`; not a directory → 0.
2. Must look like a profile (`Default` or `Local State` present), mirroring `clear_profile`,
   but return 0 instead of raising.
3. `SingletonLock` / `lockfile` present (`os.path.lexists`) → 0: a browser still holds it.
4. Fixed relative paths only; skip missing, symlinks, non-dirs, and anything resolving outside
   the profile.
5. Sum sizes, `shutil.rmtree(..., ignore_errors=True)`; whole body under `try/except Exception`.
6. Return bytes freed (for tests).

## Steps

1. `youtube_upload.py`: constants + `_profile_in_use` + `prune_profile_caches` after `profile_dir()`.
2. `youtube_upload.py:48`: import as `_close_browser`; define local `_close` that prunes after.
3. `_launch_context`: call `prune_profile_caches()` first.
4. Tests (`tests/test_youtube_upload.py`):
   - autouse `profile_dir` patch on `TestLaunchContext`;
   - `TestPruneProfileCaches`: removes the four targets and keeps Cookies / Local Storage /
     other-origin IndexedDB / Local State; skips while `SingletonLock` (dangling symlink) or
     `lockfile` exists; refuses a non-profile dir; missing dir → 0; never raises when
     `rmtree` raises; does not follow a symlinked `Cache`; `_close` order is
     close → stop → prune; `_launch_context` prunes before launching.

## Out of scope

- The OneDrive profile (`onedrive_upload.py`) may accumulate the same way — separate follow-up.
- Chrome moving IndexedDB under `Default/WebStorage/<n>/IndexedDB/` in future builds — revisit
  if the profile grows again.
