# 048 — Manual chapter authoring (own novel, no scraping) — implementation plan

_All line references verified against the working tree at 2026-07-31._

## Goal

Let the user create a novel that has no source website: a **"Truyện tự viết"** project created from Tab 1 with chapters added by name, whose original text is typed or pasted into the `Bản gốc` pane in Tab 2, and whose audio is generated in Tab 4 exactly as for a scraped novel. Nothing about scraped projects changes; the scrape/download paths simply become unreachable for a local project rather than failing inside them.

---

## Design decisions

### D1 — Project identity: `site="local"` + `url="local://<uuid4hex>"`

`NovelProject.create` derives the folder from `sha1(meta.url)[:8]` (`storage/project.py:144`) and `Library.find_by_url` keys on the URL string (`storage/library.py:35-39`).

| Option | Verdict |
|---|---|
| `url=""` | **Rejected — actively destructive.** `sha1("")` is the same `da39a3ee` for *every* local novel, so two local novels with the same slugified title land in the *same folder*; `folder.mkdir(exist_ok=True)` (project.py:146) succeeds silently and the second novel's `replace_toc` merges into the first one's `chapters.db`. Separately, `find_by_url("")` matches the first blank-URL project, so a later scan of an unrelated URL could attach to a hand-written novel. |
| `url="local://<slugified-title>"` | Rejected. Collides whenever two hand-written novels share a title, needs a dedup loop, and a title rename would make the URL a lie. |
| **`url=f"local://{uuid.uuid4().hex}"`, `site="local"`** | **Chosen.** Unique by construction; distinct sha1 → distinct folder; no `SiteAdapter.matches` will ever accept `local://` so `adapter_for_url` returns `None`; `AppConfig.cookies_for_url` (config.py:196-208) finds no host match and returns `""`; and the user can never paste it into the URL box in a way that resolves. The folder is still `<slug-of-title>-<hash8>`, so the library folder stays human-readable. |

`site` carries the *behaviour* flag and the URL carries *identity*, so `NovelMeta.is_local` checks both (`site == "local" or url.startswith("local://")`) — belt-and-braces against a hand-edited `meta.json`.

Additionally **harden `Library.find_by_url` to return `None` for a blank URL**. It costs one line and permanently closes the "every blank-URL project matches" class of bug.

### D2 — Tab 1 affordances: a create button, a bulk "add chapters" dialog, delete via context menu

* **"✍️ Truyện tự viết"** button placed in the URL row, right of **Quét** (`tab_scrape.py:91-97`). It is the same visual level as "start a novel from a URL", which is exactly what it is. It opens a small modal (`LocalNovelDialog`) asking **Tên truyện** (required), **Tác giả**, **Mô tả**, **Ngôn ngữ gốc** (combo, default `vi`). Alternatives considered: a menu item in MainWindow (too far from where novels are created, and MainWindow is deliberately app-global only — see its module docstring); a blank-URL "Quét" (invisible, and would need the scan path to branch).
* **"＋ Thêm chương"** button, added to the `download_row`, **visible only when the loaded project is local**. It opens a dialog with one multi-line box: *one chapter name per line*. This single affordance covers "add one chapter", "add ten chapters", and "paste a chapter list from my outline" — which is why it beats a plain `QInputDialog` for a single name.
  * Why not a context-menu item only: `enable_cell_copy`'s handler returns early when the click isn't on a valid index (`widgets.py:530-531`), so a **brand-new local project with zero chapters has no right-click menu at all**. It must be a button.
* **Chapters append at `max(idx)+1`**, never filling a gap. Reusing a deleted chapter's `idx` would resurrect its audio filename slot (`{index+1:04d}-…`, workers.py:640/711) and its position in an already-rendered video part.
* **Delete** via right-click → "Xoá chương" (with a confirm naming the chapter), local projects only.
* **No reorder.** `idx` is the PRIMARY KEY and every downstream artifact — audio filenames, `plan_merge_windows` windows, `video_part_name(slug, first_num, last_num)`, and the `<stem>.upload.json` YouTube records keyed to that name (`tab_video.py:560-573`) — is keyed to the 1-based chapter number. Reordering would strand all of them silently. Append + rename covers authoring, which is inherently sequential.
* **Add/delete are local-only, deliberately.** On a scraped project, a hand-inserted row at `idx=N` would be overwritten by `replace_toc` the moment the site publishes its chapter N+1: `title_custom` protects only the *title*, while `url` and `title_source` are overwritten unconditionally (`project.py:211-218`). The user would end up with the site's chapter carrying their own text. Refusing is the honest answer.

### D3 — Deleting leaves an index gap; do not renumber

`plan_merge_windows` documents and tests exactly this: *"Ranges/batches are by 1-based chapter number (`index + 1`), so boundaries are predictable and a missing chapter doesn't shift later batches"* (`tts/merge.py:49-52`). Gaps are already a supported shape. Renumbering, by contrast, would invalidate every existing `audio_path` (the filename embeds the old number), every rendered video part name, and every upload record. `delete_chapter` therefore returns the deleted `Chapter` so the caller can unlink that chapter's now-unreachable audio file and its cue sidecar; nothing else on disk references it.

### D4 — Guard the scrape path by *state*, not by disabling the URL box

For a local project we **blank the URL box rather than showing `local://…`**, and leave it enabled. That preserves the existing flow "open a novel, then paste a different novel's URL to scan it", which disabling would break. `_start_scan` additionally refuses a `local://` string outright, so nothing can reach `UnsupportedSiteError`.

Every place that assumes a scrapable project, and its disposition:

| Place | Disposition |
|---|---|
| `tab_scrape._load_project` sets `url_edit` from meta (`:214`) | blank it when local |
| `_load_project` enables download/range (`:219-220`) and prints "Bấm 'Quét' nếu truyện có chương mới" (`:223`) | disable both, and give a local status line |
| `_on_scanned` (`:258-259`) | unreachable for local (a scan never produces a local project) — no change |
| `_download_all` / `_download_range` / `_begin_download` | buttons disabled; add a `meta.is_local` early return as the backstop |
| `_add_download_actions` (`:290-297`) | omit "Tải từ chương N" / "Chỉ tải lại chương N" for local; add "Xoá chương" instead |
| `showEvent` (`:524-531`) | only calls `reload_meta()` — **no network, safe as-is** |
| `DownloadWorker.run` (`workers.py:1547-1550`) | already `finished_ok.emit(0, 0)` when `adapter_for_url` returns `None` — **keep as the final backstop** |
| Discord auto-unlock | reachable only from `DailyLimitError` inside a download — unreachable |
| `config.cookies_for_url(local://…)` | returns `""` — safe |
| `SubtitleWorker._backfill` (`workers.py:1267`) | reads audio + DB only — safe |

### D5 — `Bản gốc` becomes editable, for **all** projects

`original_view` is read-only today (`tab_translate.py:116`). Make it editable, mirroring the existing `translated_view` save-on-blur machinery (`:306-324`) exactly.

* **All projects, not just local ones.** `FIELD_CONTENT` is already an editable find-and-replace target (`find_replace.py`, whitelisted in `project.EDITABLE_COLUMNS:39`), so the app already lets the user rewrite original text project-wide; a per-project read-only rule here would be inconsistent and would need a second code path. On a scraped project an accidental edit is recoverable by re-downloading that chapter ("Chỉ tải lại chương N").
* **The first line is the chapter title**, mirroring the translated pane, because on a local project it is the only way to name a chapter from Tab 2. It routes to `project.edit_title(idx, …)`, which stores `title_source` so the rename stays undoable (`project.py:380-404`). Tab 2's `ChapterTableModel` does **not** opt into inline title editing (`set_title_editable` is False there — asserted by a 047 test), so there is no conflict with `title_edited`.
* **`edit_content` gets a monotone status promotion.** `pending_translation`, `pending_audio`, `counts()` and `AudioChapterTableModel._audio_status` all gate on `content != ''`, so they work already — but `ChapterTableModel`'s "Trạng thái" column reads `STATUS_LABELS[chapter.status]` (`widgets.py:424`) and would show **"Chưa tải" for a chapter that visibly has text**. Fix inside `edit_content`: promote `pending`/`error` → `downloaded` when the new text is non-empty; never demote a `translated` row (which is the case its docstring at `project.py:421-424` is protecting). `edit_content` currently has **zero production callers** (verified by grep — only `save_content` is used), so this is a near-zero-risk change.

### D6 — Audio needs no new code; the identity-translation path is a free bonus

Verified end-to-end for a local `source_lang="vi"` project:

* `_on_source_changed`'s "Bản gốc không phải tiếng Việt" warning is gated on `meta.source_lang != "vi"` (`tab_audio.py:288`) → **suppressed**, because the create dialog defaults to `vi`.
* `_start_generate`'s `counts["downloaded"] == 0` guard (`:329`) counts `content != ''` → **passes** once text is pasted.
* `pending_audio(voice, use_translation=False)` gates on `content != ''` (`project.py:289`) → works.
* `_title_text_for` returns `(chapter.title, chapter.content)` (`workers.py:620-623`); `slugify` handles Vietnamese diacritics and `đ` (`project.py:72-78`), so the filename is fine.
* **Bonus, already implemented:** with `source_lang == target_lang == "vi"`, Tab 2's "Dịch tất cả" takes `TranslateWorker._run_identity` (`workers.py:180-182`), copying `content` → `translated` with translator `"(nguyên bản)"` **and** filling `meta.translated_title/author/description` via `save_meta_translation`. So a local Vietnamese novel works with *either* radio button in Tab 4, and Tab 5's video slug (`slugify(translated_title or title)`) gets a proper value. This needs no code — only a status-line hint and a test pinning it.

Export/video implications, checked:
* **`cover_url` is never read outside the scrapers and `refresh_meta`** (grep: `models.py:17`, `project.py:530`, and seven scrapers) — a local project's empty cover breaks nothing; the thumbnail editor uses a user-supplied image.
* `meta.display_name()` falls back to `title`, which the dialog requires → video titles fine.
* The three exporters print `Nguồn: {meta.url}` (`markdown.py:37`, `docx.py:52`, `epub.py:51`), which would leak `local://3f9c…` into the user's own book. Suppress the line when there is no http(s) source. `epub.set_identifier(meta.url or meta.title)` (`epub.py:36`) stays — a UUID is a *better* unique identifier than a title.

### D7 — No schema change, therefore no migration

Nothing new is stored per chapter (`add_chapters` writes `url=''` into the existing NOT NULL column) and nothing new per novel (`site` and `url` already exist and `NovelMeta.from_dict` already filters unknown keys). `_migrate()` (`project.py:117-136`) is **untouched**, and existing projects are byte-for-byte unaffected. This is a deliberate constraint on the design, not an accident — it is why `site="local"` was preferred over a new `meta.json` boolean.

Ordered so the app is runnable and the suite green after every step.

### 1. `src/noveltrans/models.py` — the local marker

Add near the `STATUS_*` constants:

```python

LOCAL_URL_PREFIX = "local://"

```

Add to `NovelMeta` (after `display_name`):

```python
@property
def is_local(self) -> bool: ...   # site == LOCAL_SITE or url.startswith(LOCAL_URL_PREFIX)
```

Docstring must say *why* the URL is synthetic (folder hash + `find_by_url`), citing the blank-URL collision.

### 2. `src/noveltrans/storage/project.py` — chapter add/delete + status promotion

* **`add_chapters(self, titles: list[str]) -> list[int]`** — one transaction. `next_idx = (SELECT MAX(idx) FROM chapters) + 1` (or `0` when the table is empty; note `MAX` of an empty table is `NULL`). For each non-blank stripped title, `INSERT INTO chapters (idx, title, url, updated_at) VALUES (?, ?, '', ?)`. Returns the new indices. Docstring: appends only, never fills a gap, and why (audio filenames / video part numbers).
* **`delete_chapter(self, idx: int) -> Chapter | None`** — read the row first (return it so the caller can unlink `audio_path`), then `DELETE`. Returns `None` if absent. Docstring: gaps are intentional and `plan_merge_windows` tolerates them.
* **`edit_content`** — change the UPDATE to
  `status = CASE WHEN ? != '' AND status IN ('pending','error') THEN 'downloaded' ELSE status END`
  and extend the docstring: still never demotes a translated chapter, but a chapter that *gains* text must stop reading "Chưa tải" in the Tab 1/Tab 2 status column.

### 3. `src/noveltrans/storage/library.py` — local project creation

* **`create_local_project(self, meta: NovelMeta) -> NovelProject`** — force `meta.site = LOCAL_SITE`, fill `meta.url = new_local_url()` when blank, then `NovelProject.create(self.root, meta, [])`.
* **`find_by_url`** — `if not url: return None` at the top, with a comment naming the failure it prevents.

At this point storage is complete and independently testable; write the step-9 storage tests now.

## Edge cases & risks

1. **Zero-chapter project.** `NovelProject.create(..., refs=[])` → `replace_toc([])` is a no-op; folder + `exports/` still created; `counts()` all zero; `_sync_range_bounds` computes `top = max(1, 0) = 1` and is safe. The table is empty, hence the "Thêm chương" **button** (a context menu is unreachable — `widgets.py:530-531`).
2. **`MAX(idx)` on an empty table returns `NULL`, not 0.** `add_chapters` must coalesce, or the first insert crashes on a fresh local project. Highest-probability bug in the whole feature — pin it with a test.
3. **First-line-as-title mis-parse.** A user who deletes the title line and pastes prose starting with a blank-line-separated first paragraph will rename the chapter to that paragraph. The translated pane has carried this hazard since it was built; mitigations are (a) the tooltip states the convention, (b) `edit_title` records `title_source` so right-click → "Lấy lại tên gốc" undoes it, (c) blank titles are refused. Accepted, documented, not solved.
4. **`title_custom` tooltip lies on a local project** — it says "quét lại sẽ không ghi đè" (`widgets.py:449`) and there is no scan. Cosmetic; note it and leave it, or gate the parenthetical on a `local` flag passed to the model. Lowest priority.
5. **Orphaned audio when a chapter is deleted.** Handled by unlinking in step 5. If the unlink is skipped the file is merely unreachable clutter (`plan_merge_windows` iterates DB rows, not the directory) — never a correctness problem.
6. **Two workspaces, same project.** Unchanged: `_create_local_novel` goes through `can_open_project`, and the created project is registered by `project_changed` → `Workspace._on_scrape_project` → `project_opened` → `MainWindow._claim_project`.
7. **Save-on-blur ordering.** `_save_original_edits` must run *before* `_load_preview` replaces the pane on a row change, and *before* `FindReplaceDialog` scans (`:434`) — otherwise a later focus-out overwrites the replacement. This is exactly the trap the existing `_open_find_replace` comment describes; follow it.
8. **A user pastes a real URL while a local project is open.** Works: the URL box is blank-but-enabled, the scan creates/opens a separate project and swaps `self.project`. Deliberate (D4).
9. **`Chapter.url` is NOT NULL.** `add_chapters` must pass `''`, never `None`.
10. **Find & replace on a local project.** Already works: `FIELD_CONTENT`/`FIELD_TITLE` are in `EDITABLE_COLUMNS` and `apply_replacements` never touches status. The dialog's "replace in title" warning about a TOC re-scan reverting titles is inapplicable to a local project — harmless.
11. **`edit_content`'s status promotion and `clear_translations`.** `clear_translations` recomputes `status` from `content` (`project.py:583`), so the two agree. No interaction risk.

## Test plan

The suite is plain `pytest` — **no pytest-qt**. GUI tests use the session-scoped `qapp` fixture in `tests/conftest.py` (offscreen `QApplication`), build the widget directly, and call private methods; `tests/test_tab_scrape.py::_tab_with_project` is the model to copy. `AppConfig` is auto-isolated per test by the `_isolate_app_config` autouse fixture. Baseline is 1211 tests.

**`tests/test_local_novel.py` (new — storage/library)**
* Two local projects with identical titles get **different folders** (the blank-URL collision, stated as the reason).
* `create_local_project` fills `site == "local"` and a `local://` URL; `meta.is_local` is True; a scraped meta's `is_local` is False.
* `find_by_url("")` returns `None` even when a project exists; `find_by_url(local_url)` finds exactly that project.
* `adapter_for_url(local_url, client) is None` (pins that no adapter ever claims the scheme).
* `add_chapters` on an **empty** project starts at idx 0 (the `MAX(idx) IS NULL` trap).
* `add_chapters` appends at `max+1`, blank lines dropped, titles stripped, returns the new indices.
* `add_chapters` after a delete does **not** reuse the freed idx.
* `delete_chapter` removes the row, returns it, leaves a gap; `delete_chapter` on a missing idx returns `None`.
* `plan_merge_windows` over a gapped chapter list still batches by chapter number (regression-pins D3).
* `edit_content` promotes `pending` → `downloaded`; does **not** demote a `translated` chapter; writing `""` leaves status alone.
* `counts()["downloaded"]` reflects a chapter whose content arrived via `edit_content`.
* `pending_audio(voice, use_translation=False)` includes such a chapter.
* Round-trip: create local → `add_chapters` → `edit_content` → reopen from disk, all intact.

**`tests/test_tab_scrape.py` (extend)**
* Loading a local project: `download_button`/`range_button` disabled, `add_chapter_button` visible, `url_edit` blank (not `local://…`).
* Loading a scraped project: `add_chapter_button` hidden, download enabled (no regression).
* `_add_download_actions` on a local project offers **no** "Tải từ chương"/"Chỉ tải lại" and **does** offer "Xoá chương"; on a scraped project, the inverse (extend the existing context-menu test).
