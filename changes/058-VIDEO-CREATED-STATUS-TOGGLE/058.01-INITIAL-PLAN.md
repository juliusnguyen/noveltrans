# Plan: Manual tick for video "Trạng thái" (đã tạo) column

## Current architecture (verified)

- **Status source**: `exists = self._part_output_path(window, whole_novel=whole_novel).is_file()` — `src/noveltrans/gui/tab_video.py:765`. Purely derived, never stored.
- **Display**: non-checkable `QTableWidgetItem("✅ Đã tạo" / "⬜ Chưa tạo")` at `tab_video.py:777-779`, column 4 of a 7-column table (header `tab_video.py:322-325`).
- **Pattern to mirror — column 5 "Đã tải lên" (upload status)**:
  - Sidecar state in `noveltrans/youtube_upload.py:604-789` — `upload_state_path()` (639-642, `<stem>.upload.json`), `read_upload_state`/`write_upload_state` (645-686, atomic temp-file + `os.replace`, **merge** not overwrite), plus predicates (`is_published`, `needs_attention`, `mark_uploaded_by_hand`, `clear_upload_state`, `has_remote_draft`).
  - UI builder `_upload_item` (`tab_video.py:785-841`): builds text+tooltip from state, sets `ItemIsUserCheckable`, `setCheckState`, stashes `.mp4` path via `setData(UserRole, str(path))`.
  - Toggle handler `_on_upload_toggled` (`tab_video.py:843-907`): checks `item.column() != 5` + re-entrancy guard `self._suppress_upload_toggle` (init `tab_video.py:92`, set during rebuild `tab_video.py:662-666`), confirms via `QMessageBox.question`, reverts via `_set_check_silently` (`tab_video.py:909-917`) if declined.
  - Header bulk toggle: `CheckableHeaderView` (`widgets.py:113-176`) wired at `tab_video.py:332-334`, handler `_on_upload_header_toggled` (`tab_video.py:699-752`).
  - Wiring: `self.video_list.itemChanged.connect(self._on_upload_toggled)` (`tab_video.py:354`).
- **Row actions** (`_build_row_actions`, `tab_video.py:919-1000`): real `exists` drives "Tạo"/"Tạo lại" label (line 926) and gates "Tải lên" `setEnabled` (line 963), because `UploadRequest.validate()` (`youtube_upload.py:475-488`) requires the `.mp4` to actually exist.
- **Refresh point**: `_on_video_finished` (`tab_video.py:2267-2269`) → `_refresh_video_list()` → `_rebuild_video_rows` (`tab_video.py:754-783`) under the suppress guard.
- **Module convention**: flat `noveltrans/*.py` per feature (`youtube_upload.py`, `video_settings.py`, `onedrive_upload.py`); a new `noveltrans/video_state.py` fits this.
- **Tests**: `tests/test_youtube_upload.py` (`TestUploadStateRoundTrip`, `TestCorruptStateIsNeverMistakenForUnattempted`, `TestClearUploadState`) is the pure-function test model; `tests/test_tab_video.py` (~1296-1416) is the UI toggle/header test model.

## Design decisions

1. **Persistence: new dedicated sidecar `<stem>.created.json`, not folded into `.upload.json`.**
   Rationale: "created" is unrelated to YouTube upload state — a video can be created with no upload attempted. Keeping them separate avoids `clear_upload_state` (which deletes `.upload.json` wholesale) silently erasing a manual "created" tick too.
   *(Assumption to confirm: a second sidecar file type per rendered part is acceptable. Alternative: fold a `created_override` key into `.upload.json` and reuse its read/write helpers directly — simpler, but couples two independent concerns.)*

2. **Interaction semantics — override, not replacement; untick supported.**
   ```
   effective_status = manual_override if manual_override is not None else file_exists
   ```
   - Sidecar stores `{"created": true|false}` **only** when the value disagrees with `file_exists` at toggle time. Toggling back into agreement with disk clears the override (deletes the sidecar key/file) rather than persisting a redundant value — so a later real render or file deletion "just works" without a stale override fighting it.
   - No sidecar file at all is the common case (status matches disk) — mirrors `.upload.json`'s "no record == default" convention.

3. **UI — checkable column 4, mirrors `_upload_item`.**
   - New `_created_item(self, window, whole_novel) -> QTableWidgetItem` replacing the inline construction at `tab_video.py:777-779`.
   - Compute `exists`, `override = video_state.created_override(path)`, `effective = exists if override is None else override`.
   - Text/icon unchanged: `"✅ Đã tạo"` / `"⬜ Chưa tạo"`, based on `effective`.
   - When `override is not None and override != exists`, add a tooltip: `"Đánh dấu thủ công — không khớp với file trên đĩa."` (parallel to the `⚠️ Dở dang` tooltip at `tab_video.py:816-820`).
   - `ItemIsUserCheckable`, `setCheckState`, `setData(UserRole, str(path))` — same shape as `_upload_item`.

4. **Toggle handler `_on_created_toggled`.**
   - Wired via a second `itemChanged` connection at `tab_video.py:354` (Qt supports multiple slots; both handlers branch on `item.column()`).
   - Reuses the existing suppress-flag mechanism (rename `_suppress_upload_toggle` → shared `_suppress_status_toggle`, set in the same `try/finally` at `tab_video.py:662-666`) rather than adding a second, easily-desynced flag.
   - No-op if the requested state already matches the effective status.
   - Confirmation dialogs (Vietnamese, matching existing tone from `tab_video.py:872-892`):
     - Tick when file missing: *"Đánh dấu phần này là ĐÃ TẠO dù chưa có file video?\n\nDùng khi bạn tự quản lý video này ở nơi khác. Ứng dụng sẽ không tự sửa lại trạng thái này cho tới khi bạn tạo video hoặc bỏ tick."*
     - Untick when file exists: *"Bỏ đánh dấu ĐÃ TẠO dù file video vẫn còn trên đĩa?\n\nChỉ làm vậy nếu bạn muốn coi phần này là chưa hoàn tất (ví dụ cần tạo lại). File .mp4 sẽ KHÔNG bị xoá."*
     - Toggling back into agreement with disk (clearing the override): **no confirmation** — it's the safe/undo path.
   - Decline → `_set_check_silently(item, not wanted)`. Accept → `video_state.set_created_override(path, wanted, file_exists=exists)` then `self._refresh_video_list()`.

5. **No header bulk-toggle for column 4 in this iteration.**
   - `CheckableHeaderView` is hard-wired to one column/one indicator; a table has only one header view, so a second independent checkable column needs a real (if small) refactor to track multiple `{column: state}`.
   - Semantic mismatch: bulk-marking "created" for videos absent from disk is riskier than bulk-marking "uploaded" (can mass-hide genuinely missing renders) and has no analogous batch-discovery workflow.
   - Ship per-row tick only; flag header bulk-toggle as a possible follow-up.
   *(Assumption to confirm: no header bulk-toggle for "Trạng thái" is acceptable for v1.)*

6. **Row actions stay driven by real `exists`, not `effective` status.**
   - `_build_row_actions` (`tab_video.py:919-1000`) keeps `exists` as the sole driver for the "Tạo"/"Tạo lại" label and "Tải lên" `setEnabled` — rendering/uploading operate on the actual file; a manual tick must not fake-enable "Tải lên" against a nonexistent `.mp4` (would violate `UploadRequest.validate()`).
   - Add a tooltip on the `make` button when `override is not None and override != exists`, e.g. *"Đang đánh dấu thủ công là đã tạo — bấm để tạo file video thật."* so the UI isn't visually contradictory.
   - A real render completing makes `exists == True`; per decision 2, any stale `created=False` override self-clears the next time `_created_item` recomputes (no special-case needed in `_on_video_finished`). A `created=True` override survives a render that fails to produce the file — the user's manual intent isn't silently discarded.

7. **Edge cases.**
   - **Renamed/moved video**: mirror `.upload.json` — no special handling; sidecar is keyed by the same `slugify(...)` stem (`tab_video.py:614`), so orphaning is pre-existing, accepted behavior kept consistent with uploads.
   - **Whole-novel vs per-part**: `_part_output_path`'s `whole_novel` param already resolves to one unambiguous path; `video_state` functions just take that `Path`, no extra branching.
   - **First run / no sidecar**: `created_override(path)` returns `None`, so `effective_status` degrades cleanly to `exists` — zero behavior change for anyone who never uses the new tick.
   - **Legacy flat-folder videos**: `_part_output_path`'s legacy fallback resolves to a concrete path before `video_state` sees it; sidecar sits next to whichever path was resolved, same as `.upload.json` today.

## Files to change/create, in implementation order

1. **`src/noveltrans/video_state.py` (new)** — data layer, built + tested first.
   - `_STATE_EXT = ".created.json"`, `state_path(video: Path) -> Path`.
   - `read_state(video) -> dict` / `write_state(video, **fields) -> dict` — atomic temp-file + `os.replace`, copied from `youtube_upload.py:645-686`; corrupt read falls back to `{}` (safe = automatic), since there's no "unresolved" concept to protect here.
   - `created_override(video) -> bool | None` — `None` if no sidecar / no `created` key.
   - `set_created_override(video, wanted: bool, *, file_exists: bool) -> None` — writes `{"created": wanted}` if `wanted != file_exists`, else deletes the sidecar if present.
   - `effective_created(video) -> bool` — combines `created_override` + `video.is_file()`.

2. **`tests/test_video_state.py` (new)** — mirror `TestUploadStateRoundTrip` / `TestCorruptStateIsNeverMistakenForUnattempted` (`tests/test_youtube_upload.py:68-158`): round-trip write/read, corrupt-file handling, override clears when it matches disk, `effective_created` combination, no sidecar written when state agrees with disk.

3. **`src/noveltrans/gui/tab_video.py`** — UI layer, after data layer is solid.
   - `tab_video.py:92` — rename/extend suppress flag to cover both toggles.
   - `tab_video.py:354` — add `self.video_list.itemChanged.connect(self._on_created_toggled)`.
   - `tab_video.py:662-666` — ensure the shared suppress flag covers `_rebuild_video_rows`.
   - `tab_video.py:777-779` — replace inline item with `self._created_item(window, whole_novel)`.
   - New `_created_item` (near `_upload_item`, `tab_video.py:785-841`).
   - New `_on_created_toggled` (near `_on_upload_toggled`, `tab_video.py:843-907`).
   - `tab_video.py:919-1000` (`_build_row_actions`) — add the manual-override tooltip on `make`; verify `exists` stays the enablement gate (no functional change expected, verify during review).

4. **`tests/test_tab_video.py`** — add tests mirroring the existing toggle/header tests (~1296-1416): tick with missing file → override written + icon/tooltip update; untick with existing file → override written; toggle back into agreement → sidecar cleared; decline confirmation → reverts via `_set_check_silently`; real render clears a stale `created=False` override; `created=True` override survives `_refresh_video_list` while file still missing.

## Implementation order

1. `video_state.py` + unit tests (pure logic, no Qt).
2. `_created_item` builder + wire into `_rebuild_video_rows`.
3. `_on_created_toggled` + `itemChanged` wiring + shared suppress-flag handling.
4. Row-action tooltip tweak in `_build_row_actions` (cosmetic, low risk).
5. Verify `_refresh_video_list`/`_on_video_finished` integration — confirm override auto-clears on real completion via the generic `_created_item` rebuild path (no `_on_video_finished`-specific code expected).
6. Tests in `test_tab_video.py`.
7. Manual smoke test: tick a not-yet-rendered part → survives tab switch/app restart (sidecar persists) → "Tạo" button still renders for real → rendering clears a conflicting override → untick-to-agreement removes the sidecar file from disk.

## Assumptions to confirm before implementation

- New dedicated `.created.json` sidecar vs. folding a `created` key into the existing `.upload.json` (recommended: new dedicated file).
- No header-level bulk toggle for the "Trạng thái" column in this iteration (recommended: skip for v1).
- "✅ Đã tạo" / "⬜ Chưa tạo" text/icons stay unchanged; only a tooltip is added on override-mismatch (vs. a distinct icon like "🖊️ Đã tạo (thủ công)").
- No confirmation dialog when a toggle merely reverts to the automatic/matches-disk state (recommended: no dialog — non-destructive).
