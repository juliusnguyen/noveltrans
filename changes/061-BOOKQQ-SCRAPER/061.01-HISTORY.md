## [PLAN] 061.01-INITIAL-PLAN — 2026-08-25
Generated plan: `061.01-INITIAL-PLAN.md`

Plan claims about existing code were spot-checked against the tree before filing; see the
plan's §0 table (27 rows). The site reconnaissance in `061.00-PROMPT.md` was measured
against the live site in the previous turn and is taken as given — the planning pass had
no network.

Findings that shaped the plan:

- **The error type is load-bearing on `DownloadWorker`'s control flow, not cosmetic.**
  `RateLimitedError` would be retried 8× at 60 s each (`workers.py:33-34`, `:2077-2092`)
  — 149 paid chapters × 8 minutes ≈ **20 hours** of pointless waiting per run.
  `DailyLimitError` `break`s the whole batch (`workers.py:2140-2148`), which would
  permanently lose the free chapters interleaved after the paid run begins. Plan settles
  on `AuthRequiredError`, whose docstring already reads "the chapter is paywalled for
  this account" (`errors.py:20-22`).
- **Both failure directions are silent, and they are opposites** (§4.1, §4.2). Saving a
  teaser passes `pending_download`'s `content = ''` check forever after (`project.py:371`)
  and flows into translation, TTS, video and EPUB with nothing ever looking wrong.
  Returning `""` instead re-queues the chapter on every run with no error recorded.
  Hence: gate before extraction, and always raise — never return empty.
- **`登录` cannot be a paywall signal.** It is in the header of every anonymous page,
  free chapters included; using it would refuse all 226. This is the same trap
  `medoctruyen.py:211-213` records having hit with `previewLoginHref`. The gate is
  therefore scoped to short CTA elements inside the content container, and
  `chapter_free.html` deliberately **retains** the real header so the false positive is
  pinned by a test.
- **A whole-page `"订阅" in html` check would also match free chapters**, because the
  `__NUXT__` payload embeds all 226 chapter names and the site's i18n strings. The brief's
  "5,431 CJK chars on the paid page" figure must not be read as body length for the same
  reason — on a 283 KB Nuxt page that count is dominated by the payload.
- **`ChapterRef` has exactly three fields** (`models.py:116-121`), so `cid` is dropped
  deliberately rather than smuggled into the URL as a query parameter. The plan records
  the consequence (§4.6): positional `<n>` URLs silently re-point every later row if
  Tencent ever inserts a chapter.
- **A latent bug in `ScanWorker` affects `giatocvuongtai` today** (§2.6): it looks up
  `find_by_url(self.url)` — the pasted URL — not `meta.url`, so re-scanning a
  canonicalising adapter by a chapter URL falls into `create_project` and overwrites
  meta.json wholesale (`project.py:227-234`), losing `translated_title`, `tags` and
  `video_settings`. Plan Step 7 is a one-line fix, kept separable.

No source files changed in this turn — planning only.

**Step 1 paid for itself immediately — three plan assumptions were wrong**

The plan made fixture capture Step 1 precisely so the unverifiable parts got *read* rather
than guessed. All three "inferring" items came back different:

1. **The chapter array key is `bookChapters`.** The plan guessed `chapterList`, then
   `chapters`, then `catalog` — none of which exist. Code written to the plan's guess
   would have parsed an empty TOC and silently fallen back to the HTML path on every scan.
2. **`SEL_CONTENT` is `#article`** (`div#article.chapter-content.isTxt`), identical on free
   and paid pages — not the four-candidate chain the plan proposed.
3. **The `og:` tags are all present** (`og:novel:book_name`, `og:novel:author`,
   `og:description`, `og:image`), so metadata is tier-1 throughout and the DOM/payload
   fallbacks are belt-and-braces rather than load-bearing.

**The most important correction: the CTA is OUTSIDE the content container**

Measured: the subscribe button is `<div class="btn-login">登录订阅本章 ></div>`, and it sits
**outside** `#article`. The plan's §2.3 said to strip chrome and scan "what remains", which
is right — but its neighbouring advice to "count only inside the content container" would,
if applied to the marker scan, have missed the CTA completely and let every teaser through.
`is_paywalled` therefore scans the whole body minus `<script>`/`<style>`/`<head>`, and
says so in a comment naming the measurement.

Also measured, and better than the plan feared: a free chapter's server HTML carries **no**
paywall marker at all (0 `btn-login`, 0 订阅). The plan expected 登录 in every page header.
登录 is still deliberately excluded from `_PAYWALL_MARKERS`, and `chapter_free.html` still
retains a header login link, so the false positive stays pinned even though the live free
page does not currently exhibit it.

**Deviations from the plan**

- **Fixtures are hand-built to measured structure, not captured-and-trimmed.** Same
  reasoning `test_scrapers_tieuthuyetmang.py:1-6` already records: a built fixture encodes
  the traps deliberately (escaped quote in a `chapterName`, a free chapter *after* a paid
  run, a `free=0 purchased=1` entry) where a captured one contains them only by luck. It
  also keeps Tencent's prose out of the repo entirely — the filler is invented.
- **Status line says "tải được N chương", not "N chương miễn phí".** Caught by a test: a
  purchased chapter is downloadable without being free, so the old wording mis-described
  the `free=0 purchased=1` case. The count is "neither free nor bought", which is exactly
  what the user cannot get.
- **`_arg_table` reads the argument list with a dedicated `_read_arg_list`** rather than
  the plan's implied reuse of the array reader — the payload's arrays are
  bracket-delimited while the IIFE's argument list is paren-delimited.

**Not done — both optional and separable in the plan**

- **Step 7**, the one-line `ScanWorker` hardening (`find_by_url(self.url) or
  find_by_url(meta.url)`). It fixes a real latent metadata-clobber that affects
  `giatocvuongtai` today, but it touches shared code and the plan explicitly wants it as
  its own commit. Left for a follow-up so this feature stays revertable on its own.
- **Step 8**, `scripts/diagnose_bookqq.py` — only warranted if a live run disagrees with
  the fixtures, which has not happened yet.

**Verified against the live site.** Both `live`-marked tests were run
(`pytest -m live -o addopts=""`) and pass, so the feature is proven end to end and not only
against hand-built fixtures:

- metadata parses, `source_lang == "zh"`;
- the real 226-entry `bookChapters` payload parses — TOC length > 200, so the minified
  reader handles the full argument table and identifier resolution at real scale, not just
  the 8-entry fixture;
- chapter 1 fetches and extracts > 2000 characters of real text;
- **the last chapter raises `AuthRequiredError`** — the gate fires on a genuinely paid
  chapter on the real site, which is the assertion the whole feature rests on.

Cost: 4 requests at the default 1.5 s delay.
