# 061 — Scraper for `book.qq.com` (QQ 阅读)

## The ask

> hộ trợ cho trang `https://dichtienghoa.net/truyen/2709`

**The target changed during reconnaissance, with the user's agreement.** `dichtienghoa.net`
turned out to be a Chinese-*learning* site, not a novel-translation site, and it mirrors
only a fraction of its upstream. The user chose to support the upstream —
**`book.qq.com`** — instead. See "Why not dichtienghoa" below; that finding is the whole
reason this feature exists in this form.

Reference novel: `https://book.qq.com/book-detail/58625737`
(《开局相亲女神捕，获独孤九剑》, 226 chapters), which `dichtienghoa.net/truyen/2709`
mirrors chapter-for-chapter via its own `sourceUrl` field.

## What this is

A **Chinese-source** adapter, the same class as `ixdzs`, `xbanxia` and `shuba69`:
`fetch_chapter` returns the original Chinese, `source_lang = "zh"`, and tab 2 translates it
with the app's own engines. It is explicitly **not** a `content_is_translated` adapter
(`base.py:101`) like `medoctruyen` / `webtruyendich`.

That was a deliberate choice by the user over the alternative of reading dichtienghoa's
per-word gloss: reconstructing prose from that gloss would produce exactly the
word-by-word "convert" text that feature 060 was just built to repair. Going through the
Chinese and letting Claude/CLI translate skips the problem entirely.

## Reconnaissance (measured 2026-08-24, anonymous unless noted)

All of the following was verified against the live site before this feature was opened.

### Access

- **No Cloudflare challenge, no login needed** for free chapters. Plain `requests`-level
  GETs returned HTTP 200 on the detail page and on chapter pages.
- Response sets `logTrackKey` / `secToken` cookies on `.qq.com`; neither was required for
  any fetch that succeeded here.

### URL shapes

| Page | Shape | Verified |
|---|---|---|
| Novel detail / TOC | `https://book.qq.com/book-detail/<bid>` | 200, 283 KB |
| Chapter | `https://book.qq.com/book-read/<bid>/<n>` | 200; `<n>` is the 1-based chapter position, **not** the `cid` |

### Payload

Nuxt **2** — `window.__NUXT__ = (function(a,b,c,…){…}(…))`, a minified IIFE, *not* the
`__NUXT_DATA__` JSON island that `tieuthuyetmang` uses. Values are single-letter
parameters resolved from the invocation's argument list; a parser must map them back.

**The detail page carries the entire TOC** — all 226 chapters, no pagination — with these
per-chapter keys: `cid`, `chapterName`, `free`, `purchased`, `publishTime`.

### Chapter content

Server-rendered into the HTML as `<p>` elements. No XHR, no encryption, no obfuscation
(unlike `ixdzs`, which needs the `?challenge=` dance, `ixdzs.py:34-42`).

| Chapter | `<p>` count | CJK chars | Paywall markers |
|---|---|---|---|
| 1 (`free:1`) | 114 | 10,621 | none |
| 226 (`free:0`) | **5** | 5,431 | 订阅, 登录 |

### The paywall — the thing most likely to be got wrong

**A paid chapter still returns HTTP 200.** It serves a short teaser plus a subscribe
prompt. Nothing about the status code says the fetch failed.

An adapter that just concatenates `<p>` text will therefore **save the teaser as the
chapter body** — silent corruption, exactly the class of bug feature 059 hit. Detection
must be positive and explicit (markers `订阅` / `登录`, and/or the `free` flag from the
TOC), and the correct response is to raise `AuthRequiredError` (`errors.py`) so the
download worker records an error instead of writing junk.

### Free/paid split — set expectations honestly

- **77 free, 149 paid** of 226.
- The first **65 are contiguous** from chapter 1; after that it is mostly paid with
  occasional single free chapters.
- `purchased: 0` on all 226 for an anonymous session.

`dichtienghoa.net` reports the *same* 77/149 split, which is what confirmed it is a
mirror.

**226 chapters is not obtainable for free from either source.** The remaining 149 are
content Tencent sells. Buying them is the user's own affair on their QQ account; this
feature does not attempt to circumvent the paywall and must not.

## Why not dichtienghoa (recorded so it isn't re-litigated)

- Its two content fields are `content` — the **Chinese original**, clean plain text — and
  `translatedContent` — 160 KB of `<i ch="…" hv="…" v="…">` per-word gloss markup for
  language learners. It publishes **no Vietnamese prose**.
- Only **33 of 226** chapters have any text at all; 193 return `None`.
- **Logging in changes nothing.** Verified with the user's own session: chapter 21
  (`free`, no content) stayed `None`, and chapter 66 (paid) had no chapter object at all.
  The 33 is a "the site has not translated it yet" limit, not an auth limit.

So the upstream yields 77 chapters against dichtienghoa's 33, in clean plain text, with a
contiguous run from chapter 1.

## Scope

- One new adapter, `src/noveltrans/scrapers/bookqq.py`, subclassing `SiteAdapter` and
  registered with `@register` — plus its entry in `_import_adapters` (`scrapers/__init__.py:26-36`).
- Metadata, TOC, chapter fetch, and honest paywall reporting.
- A README row in the Chinese-source table.

## Out of scope

- Any attempt to read paid chapters without the user having bought them.
- A `dichtienghoa.net` adapter (decided against; findings above).
- Logged-in QQ sessions / cookie support. Worth a follow-up **only** if the user buys
  chapters and asks for it; nothing here should make that harder to add later.
