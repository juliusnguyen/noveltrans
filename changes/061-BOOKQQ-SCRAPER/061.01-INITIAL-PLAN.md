## 1. Summary of the approach

One new file, `src/noveltrans/scrapers/bookqq.py`, one line in `_import_adapters` (`scrapers/__init__.py:25-33`), one test module, one fixture directory, one README row. No changes to `SiteAdapter`, no changes to the models, no schema change, no new dependency, no browser. This adapter joins the Chinese-source family (`ixdzs`, `xbanxia`, `shuba69`) and is a strict `SiteAdapter` implementation: three abstract methods and nothing else.

Three decisions carry the feature:

1. **Hybrid extraction.** The 226-entry TOC comes from the Nuxt 2 `window.__NUXT__` payload (the brief measured it complete and unpaginated there); chapter *bodies* come from the server-rendered `<p>` elements in plain HTML, exactly like `ixdzs.py:102-108` and `medoctruyen.py:229-234`. Neither side is asked to do the other's job. Metadata prefers the HTML and falls back to the payload.
2. **The paywall gate runs before extraction and can refuse without fetching at all.** This is the whole feature. The failure mode being designed against — a teaser silently persisted as chapter content — is unrecoverable in this app's data model (§4.1), so the gate is designed to fail *loudly and closed*, and it is proven by a fixture pair rather than argued for.
3. **`AuthRequiredError`, deliberately, and not any of the four alternatives.** The choice is load-bearing on `DownloadWorker`'s control flow, not cosmetic (§2.3).

The only shared-code change proposed is one optional hardening line in `ScanWorker` (§2.6 / Step 7), which fixes a latent bug that already affects `giatocvuongtai`.

The riskiest part is §2.1's payload parser. It is written to degrade to an HTML TOC rather than to fail the scan, and — critically — the paywall gate does **not** depend on it.

## 2. Decisions

### 2.1 Payload parsing — hybrid, with a bounded object-literal reader and an HTML fallback

**Recommendation: take the TOC from `window.__NUXT__`, take chapter bodies from the HTML, and never the reverse.**

The payload is a minified IIFE:

```
window.__NUXT__=(function(a,b,c,d,…){return {data:[{…,chapterList:[{cid:a,chapterName:"…",free:b,purchased:b,publishTime:c},…]}]}}(58625737,0,1,…));
```

Values inside the body are single-letter identifiers resolved positionally from the invocation's argument list. It is not JSON and can never be `json.loads`-ed.

**Which side each piece comes from, and why:**

| Piece | Source | Why |
|---|---|---|
| Chapter list (226 × `cid`, `chapterName`, `free`, `purchased`, `publishTime`) | **Payload** | Measured complete and unpaginated there. The rendered DOM's TOC is a Nuxt-hydrated list whose *shipped* markup may be partial or virtualised, and — decisively — the `free`/`purchased` flags are data, not text. Nothing in the DOM is guaranteed to carry them. |
| Chapter body | **HTML `<p>`** | Measured server-rendered, unobfuscated. Reading it out of the payload would mean running the minified reader on a 5–10 KB prose blob with escaped quotes — all downside. |
| Paywall state of the chapter being fetched | **HTML (primary) + payload `free`/`purchased` (secondary)** | See §2.3. Two independent gates on purpose. |
| Title / author / description / cover | **HTML first, payload fallback** | §2.4. |

**How the payload is parsed.** Not a JS evaluator, not per-field regexes. A small, pure, bounded reader:

1. `_payload_source(markup)` — slice from `window.__NUXT__` to the end of that `<script>`. Bounded work; no scanning of the other 280 KB.
2. `_arg_table(source)` — read the parameter names between `(function(` and the first `)`, then read the invocation's argument list (the text between the **last** `}(` and the trailing `))`), split at top level respecting quotes and brackets, and parse each argument as a JS literal. Zip into `{name: value}`.
3. `_read_object(source, at, args)` — a ~70-line tolerant JS **object-literal** reader that handles: bare identifier keys, single- and double-quoted strings with escapes, numbers, `true`/`false`/`null`, `!0`/`!1` (minifier booleans), `void 0`, nested objects and arrays, and **bare identifiers resolved through the argument table** (unknown identifier → `None`, never a crash).
4. `chapter_entries(markup)` — locate the chapter array by its key (try `chapterList`, then `chapters`, then `catalog` — the exact key is **inferring** and gets pinned from the fixture), brace-match it, and read it with (3).

**Be honest: this is the fragile part.** It breaks if Tencent changes the minifier's boolean encoding, renames the chapter-list key, or moves to Nuxt 3's `__NUXT_DATA__` JSON island (the shape `tieuthuyetmang` already handles differently, `tieuthuyetmang.py:94-116`). Three things contain that fragility:

- **The reader is pure and takes markup, never a URL** — the split `shuba69.py:16-18` and `tieuthuyetmang.py:26-28` both document. The whole surface is fixture-tested with no network.
- **`fetch_chapter_list` falls back to the rendered HTML** when the payload yields nothing: collect `a[href]` matching `/book-read/<bid>/<n>`, dedupe, order by `<n>`. That loses the `free` flags and nothing else — which is survivable *precisely because* the paywall gate does not depend on them (§2.3). Only if **both** paths come up empty does it raise `ScrapeError("Chapter list not found — page layout may have changed")`, matching `xbanxia.py:66` and `shuba69.py:123`.
- **`fetch_chapter` never touches the payload at all**, so a payload format change cannot corrupt a single chapter body.

**Explicitly rejected:** targeted per-field regexes over the payload. `chapterName` values are Chinese strings that may contain escaped quotes and full-width punctuation; a `\{cid:(\w+),chapterName:"(.*?)"` shape truncates at the first escape and silently drops the tail of the TOC — the same class of bug `tieuthuyetmang.py:96-102` documents having reasoned its way out of. Also rejected: parsing the TOC from the rendered DOM as the *primary* path, because it cannot supply `free`/`purchased` and those are what make the pre-emptive skip (§2.3) and the honest status line possible.

### 2.2 Chapter-body extraction — container-scoped, matching the family

Follow `ixdzs.py:96-108` almost exactly, because that is the shape this family uses:

```
soup.select_one(SEL_CONTENT)  →  [p.get_text(strip=True) for p in container.select("p")]
                              →  drop blanks
                              →  drop a leading line equal to the chapter title
                              →  "\n\n".join(lines)
```

Three deliberate details:

- **`SEL_CONTENT` is a tuple of candidate selectors, tried in order**, not a single string. The exact class name is **inferring**; the fallback chain is `("#chapterContent", ".chapter-content", "article", ".content")` narrowed to whatever the saved fixture actually shows, with the last entry a structural one. `xbanxia.py:79-80` decomposes chrome bluntly; `shuba69.py:40-43` names it precisely and explains why blunt removal is dangerous. Follow `shuba69`: name the chrome, do not blanket-decompose `<div>`.
- **Title de-duplication biases to under-strip.** Drop at most one leading line, and only when it equals `ref.title` after normalisation — `shuba69.py:148-153` states the reasoning (a duplicated heading is cosmetic; an eaten opening line is invisible data loss). Reuse a `_clean_title` in the same spirit as `shuba69.py:54-56` if the fixture shows an index prefix; do not invent one speculatively.
- **Empty extraction raises**, never returns `""` — `ixdzs.py:106-107`, `xbanxia.py:86-87`, `shuba69.py:155-156` all do this, and §4.2 explains what returning `""` would cost here specifically.

### 2.3 Paywall detection — the load-bearing decision

**Recommendation: two independent gates, either of which refuses; both evaluated before any extraction; the error is `AuthRequiredError`.**

#### The gates

**G1 — the site's own flags, checked before the request is made.**

The adapter holds a per-instance, lazily-populated TOC cache keyed by book id (the pattern `tieuthuyetmang.py:575-597` uses for its landing page, and for the same reason: a scan calls `fetch_metadata` then `fetch_chapter_list` back to back). `fetch_chapter` consults it for the `<n>` in `ref.url`:

```
free == 0 and purchased == 0  →  refuse, without fetching the chapter page
```

Both conditions, not just `free`. With no cookie, `purchased` is 0 on all 226 (measured), so this is exactly the 149. If bookqq cookie support is ever added (explicitly out of scope, but the brief asks that nothing make it harder), a purchased chapter has `purchased == 1` and this gate stands aside without a code change. That is why the rule is a conjunction.

The cache is **best-effort**: if `fetch_chapter` has no cached TOC and the one lazy detail-page fetch fails or parses to nothing, G1 simply does not fire, and G2 carries the load. A TOC fetch failure must never fail a chapter that G2 would have let through.

Two payoffs beyond correctness: the batch makes ~77 requests to Tencent instead of 226, and the adapter can emit an honest status line through `self._status` (`base.py:111-114`), which `DownloadWorker` routes to the progress signal (`workers.py:2114`).

**G2 — a scoped, positive marker on the fetched page.**

G1 cannot be the only gate, because `DownloadWorker` calls `fetch_chapter` with nothing but a `ChapterRef` (`workers.py:2076`, `:2121`) and the TOC may be stale, unavailable, or wrong. So the page itself must be able to refuse.

The rule, stated precisely:

> Remove `<script>`, `<style>`, `<head>`, and the site header/nav from the soup. Within what remains, refuse if an element exists whose **own** text is short (< 200 chars) **and** contains one of `订阅` / `购买` / `付费章节` / `阅读全文`.

Why this shape and not the obvious one:

- **`登录` alone is disqualified.** It appears in the header of *every* anonymous page on the site, free chapters included. Using it as a signal refuses all 226. It is retained only as a corroborating token inside an already-matched short CTA element, never as a trigger. This is precisely the trap `medoctruyen.py:211-213` documents having hit — `previewLoginHref` is emitted on every page, so it cannot signal gating.
- **Whole-page text search is disqualified.** The `__NUXT__` payload embeds all 226 chapter names and the site's own i18n strings; a bare `"订阅" in html` would match on free chapters too. This is also why the brief's "5,431 CJK chars on the paid page" figure must **not** be read as body length — a whole-page CJK count on a 283 KB Nuxt page is dominated by the payload. **Count only inside the content container**, never over the page.
- **Short-element scoping is what separates a CTA from prose.** A subscribe button is a handful of characters; a paragraph that happens to mention subscribing is not.

#### Why this cannot confuse a short chapter with a teaser (and vice versa)

- **Short free chapter → not refused.** G1 sees `free == 1`. G2 fires on the *presence of a CTA element*, not on length. Length is never a refusal criterion. A 400-character free chapter passes both gates.
- **Long paid chapter → refused.** G1 sees `free == 0, purchased == 0`. G2 sees the CTA. Neither depends on the teaser being short. The brief's measurement (5 `<p>` vs 114) informed the design; the code does not encode it.
- **Both gates wrong simultaneously → still not corrupted.** G3, the existing family-wide `if not lines: raise` (`ixdzs.py:106-107`), catches total extraction failure. What remains uncovered is: TOC unavailable **and** the CTA markup redesigned **and** a teaser still extractable. That residual is why the `live`-marked test in §5 exists — it is the drift detector, and it is the honest answer rather than pretending the residual is zero.

**The selector and the marker set are derived from the fixture pair, not from this document.** The two tests that pin them are the contract:

- `chapter_free.html` (which **retains the real site header, including its 登录 link**) must extract a body and must **not** refuse.
- `chapter_paid.html` (which retains the real subscribe block markup verbatim) must refuse, and must refuse *before* extraction — pinned the way `test_scrapers_tieuthuyetmang.py:262-268` pins it, by asserting the fixture demonstrably contains extractable text and the call still raises.

If the first live run shows the scoping is wrong in either direction, the fix is a selector edit plus a fixture, not a redesign.

#### Ordering

Gate, then extract. Never extract, then judge. `tieuthuyetmang.py:426-429` states the rule in its docstring and `parse_chapter` implements it at `:437-448`; the regression test at `test_scrapers_tieuthuyetmang.py:262-268` exists specifically so a refactor cannot quietly reorder them. Mirror both.

#### Which error, and why not the other four

**`AuthRequiredError`** (`errors.py:20-22`), whose docstring already reads "…or the chapter is paywalled for this account".

| Alternative | Why not |
|---|---|
| `RateLimitedError` | `_fetch_with_backoff` retries it 8 times at 60 s apiece (`workers.py:33-34`, `:2077-2092`). 149 chapters × 8 minutes ≈ **20 hours** of pointless waiting per download run. Pin with a subclass assertion, exactly as `test_scrapers_tieuthuyetmang.py:270-276` does. |
| `DailyLimitError` | `break`s the whole batch (`workers.py:2140-2148`). The brief measured that free chapters appear *after* the paid run begins ("occasional single free chapters"), so aborting at the first paid chapter would permanently lose them. |
| `ObfuscatedContentError` | Semantically false. `base.py:141-143` reserves it for content that "cannot be decoded into readable text". Here the text is decodable; it was never sent. `ixdzs` — the one adapter with a real decode step — does not raise it either. |
| Plain `ScrapeError` | Works (it is `AuthRequiredError`'s parent and `DownloadWorker` handles both identically at `workers.py:2149`), but throws away the distinction. Cookie support is an explicitly-contemplated follow-up, and `AuthRequiredError` is the type that already means "this needs an entitled session". |

Message text, Vietnamese to match the app (`tieuthuyetmang.py:438-448`, `medoctruyen.py:219-226`), and self-explanatory because 149 rows will carry it into `chapters.error` and the table tooltip:

> `Chương trả phí của QQ 阅读 — tài khoản QQ của bạn chưa mua chương này. NovelTrans không vượt tường phí.`

The last sentence is there on purpose: it tells the user this is a policy outcome, not a bug to report.

### 2.4 `fetch_metadata` — HTML first, payload as fallback, explicit `source_lang`

**Availability is unverified for this site** (the brief measured `<p>` counts and paywall markers, not head tags), so the implementation is a tiered fallback chain rather than a single selector, and the tiers get pinned to whatever `detail.html` actually contains:

| Field | Tier 1 | Tier 2 | Tier 3 |
|---|---|---|---|
| title | `og:title` / `og:novel:book_name` | `<h1>` | payload book object (`bookName` / `title`) |
| author | `og:novel:author` | author link/label in the DOM | payload (`author` / `authorName`) |
| description | `og:description` | the intro/blurb block | payload (`intro` / `desc`) |
| cover | `og:image` | `<img>` on the site's cover CDN | payload (`coverUrl` / `bookCover`) |

Notes and non-negotiables:

- **Title is the only required field.** Missing title → `ScrapeError("Novel title not found — page layout may have changed", url)`, the wording `ixdzs.py:60`, `xbanxia.py:41`, `shuba69.py:107` and `tieuthuyetmang.py:240` all share. Every other field degrades to `""` — the family's convention, and the GUI renders blanks fine.
- **JSON-LD is a legitimate tier and worth checking for** in the saved fixture (`<script type="application/ld+json">`). If present it is more stable than any class name and should slot in as tier 2. **Inferring** that it exists; do not write speculative code for it — look at the fixture, then decide.
- **Total chapters is not a metadata field.** It is `len(fetch_chapter_list(...))`, and `ScanWorker` already reports it (`workers.py:110`, `:122`). Do not add a count to `NovelMeta`.
- **`source_lang="zh"` is passed explicitly**, even though it is the dataclass default (`models.py:42`). `tieuthuyetmang.py:264` sets its `"vi"` explicitly for the same reason: intent should be readable at the construction site, and a future default change must not silently reclassify this site. One test asserts it, and asserts the reference title `开局相亲女神捕，获独孤九剑` survives round-tripping unmangled (a cheap but real guard on the encoding path at `base.py:80-87`).
- **`site = self.name = "bookqq"`.**

### 2.5 `fetch_chapter_list`, and `<n>` vs `cid`

**Recommendation: `ChapterRef.url = https://book.qq.com/book-read/<bid>/<n>` where `<n> = index + 1`. Do not preserve `cid`.**

`ChapterRef` is exactly three fields (`models.py:116-121`). There is nowhere to put a `cid` without widening a shared model for one site — the same restraint that kept `SiteAdapter` at three abstract methods when feature 059 wanted two more (`workers.py:1105-1108` records that call). And there is nothing to spend it on:

- The reader route takes `<n>`, measured. `cid` addresses nothing this adapter fetches.
- The `free`/`purchased` lookup keys on the **same positional index** as the URL, because both derive from the TOC array's order. `cid` adds nothing there either.
- If a `cid`-keyed API ever becomes necessary, it is one detail-page request away. Leave a comment saying exactly that, so the next person does not have to rediscover that `cid` was dropped deliberately.

Rejected: smuggling it as `?cid=…` on the URL. The URL is persisted (`project.py:287-297`) and is what the user sees in the chapter table; a query parameter the site ignores is noise now and a liability if the site ever stops ignoring it.

Two invariants to encode as comments and tests:

- **`index` stays dense and 0-based.** It is the project DB primary key (`project.py:287-297` conflicts on `idx`). `tieuthuyetmang.py:326-329` carries the warning verbatim; reuse the reasoning.
- **`<n>` comes from array position, not from parsing `第N章` out of `chapterName`.** Web-novel chapter numbering skips, repeats and carries volume prefixes. Position is what the route means.

Paid chapters are **listed, never filtered**. `test_scrapers_tieuthuyetmang.py:168-173` explains why in terms this project has already paid for: a TOC whose length varies with entitlement re-maps existing `idx` values onto different content on the next `replace_toc`. That is corruption, not inconvenience. Likewise, titles carry **no** 🔒/VIP decoration — titles are persisted, exported into the EPUB, and read aloud by TTS (`test_scrapers_tieuthuyetmang.py:181-185`).

At the end of `fetch_chapter_list`, emit the honest split through `self._status`:

> `🔒 149/226 chương là chương trả phí trên QQ — chỉ tải được 77 chương miễn phí.`

`ScanWorker` wires `on_status` to its progress signal at `workers.py:108`, so this reaches the scan status label without any GUI change.

### 2.6 URL matching and normalisation

```python
url_patterns = [r"book\.qq\.com/book-(?:detail|read)/\d+"]
```

`matches` uses `re.search` (`base.py:116-118`), so no anchoring is needed, and this accepts both the detail URL and a chapter URL. Accepting the chapter form matters because `adapter_for_url` (`__init__.py:16-20`) is what decides whether the app says "Chưa hỗ trợ trang web này" (`workers.py:101-104`), and a user who lands on a chapter and copies the address bar is the normal case, not the exotic one.

Both entry points normalise first, via module-level helpers in the shape of `shuba69.py:59-80` and `tieuthuyetmang.py:70-79`:

```python
def book_id(url) -> str      # /book-detail/<bid> or /book-read/<bid>/<n>; raises ScrapeError
def detail_url(url) -> str   # https://book.qq.com/book-detail/<bid>
def chapter_url(bid, n) -> str
def chapter_number(url) -> int   # the <n> out of a /book-read/ URL; raises ScrapeError
```

`fetch_metadata` and `fetch_chapter_list` both fetch `detail_url(url)`, sharing one cached page between them the way `tieuthuyetmang.py:582-597` does — a scan is **one** request, not two.

**`NovelMeta.url` is canonicalised to the detail URL, not echoed.** This diverges from the nearest precedent (`tieuthuyetmang.py:256-257` echoes) and follows the other (`giatocvuongtai.py` canonicalises to `/stories/<slug>/`). The reason to diverge: `Library.find_by_url` is exact string equality (`library.py:53`), so echoing would let `/book-detail/58625737` and `/book-read/58625737/12` become **two projects for one novel**. `tieuthuyetmang`'s echo rule exists to avoid orphaning projects that already exist on disk; bookqq has none, so the better rule is available for free.

Canonicalising has one sharp edge, and it is pre-existing rather than introduced here: `ScanWorker` looks up `find_by_url(self.url)` — the **pasted** URL (`workers.py:113`) — not `meta.url`. So a user who re-scans by pasting a *chapter* URL misses the existing project, falls into `create_project` (`workers.py:119`), and `NovelProject.create` **overwrites meta.json wholesale** (`project.py:227-234`), discarding `translated_title`, `tags`, `thumbnail_prompt` and `video_settings` — everything `refresh_meta` (`project.py:839-848`) was written to protect. Chapter content survives (`replace_toc` preserves it, `project.py:283-298`) and the folder is reused (same `sha1(meta.url)` digest, `project.py:222-223`), so this is metadata loss, not data loss.

This bug exists **today** for `giatocvuongtai`. Step 7 proposes the one-line fix; it is optional to this feature and separable.

### 2.7 Politeness and headers — the defaults are already right

**Recommendation: no adapter-specific throttle, no UA work, no cookie plumbing.**

- **Delay.** `HttpClient` defaults to 1.5 s (`base.py:26`) and both workers pass `config.request_delay`, itself defaulting to 1.5 (`config.py:27`, `:159-160`, `tab_scrape.py:334-350`). Do **not** add a `max(delay, X)` clamp. The one precedent for clamping (`workers.py:1134`) exists because `tieuthuyetmang.py:22-24` is a small paid site pulling 200 MB files and its docstring demands it. Tencent is not that, and G1's pre-emptive skip already cuts the batch from 226 requests to ~77. Adding a floor would be cargo-culting a rule whose justification does not transfer.
- **User-Agent.** Already a desktop Chrome UA, set on the session at construction (`base.py:15-18`, `:35`). The reconnaissance needed one; the app already sends one. **Nothing to do.**
- **`logTrackKey` / `secToken`.** Set by the response and persisted automatically — `HttpClient` holds a single `requests.Session` for the adapter's whole life (`base.py:34`), and both workers construct one client per batch (`workers.py:99`, `:2099`). **Nothing to do.**
- **Cookies.** `book.qq.com` is not in `SITE_COOKIES`, so `cookies_for_url` returns `""` and `set_cookies` no-ops on a blank string (`base.py:45-47`, `config.py:254-257`). Leave it that way — logged-in sessions are explicitly out of scope. Adding it later is two lines (a `SITE_COOKIES` entry plus a Settings field) and nothing in this design blocks it.
  - ⚠️ **Flagged for whoever adds it, not for now:** `set_cookies` writes a raw `Cookie` *header* (`base.py:47`), while the site's own `logTrackKey`/`secToken` live in the session's cookie *jar*. How `requests` resolves that collision when the jar is non-empty is **not verified here** and should be measured — not assumed — before any bookqq cookie support ships.
- **Encoding.** `get_html` only consults `apparent_encoding` when the response declares nothing or ISO-8859-1 (`base.py:85-86`). QQ serves UTF-8 with a charset header (**inferring**); if it did not, chardet would run over 283 KB per page. Not a problem at this size, but worth knowing if page fetches ever look slow.
- **No parallelism.** `DownloadWorker` is sequential and nothing in this feature changes that.

## 4. What breaks if this is done naively

### 4.1 A teaser saved as content is permanent and silent — the whole reason for §2.3

`save_content` sets `status = downloaded`, clears `error`, and writes the text (`project.py:518-524`). `pending_download` selects on `content = ''` **only** (`project.py:371`). So a saved teaser is never re-queued: it flows into `pending_translation` (`project.py:401-408`), gets translated on the user's own API quota, gets voiced by TTS, gets rendered into video, and gets exported into the EPUB — and at no point does anything look wrong. The only cure is the user noticing 149 short chapters and forcing a re-download of exactly those rows.

This is the failure feature 059 hit, and this feature must not.

### 4.2 Returning `""` instead of raising is the *other* silent failure

The opposite mistake fails differently and just as badly: `save_content(idx, "")` leaves `content = ''`, so `pending_download` returns that chapter **forever**. Every "Tải các chương" re-fetches all 149 from Tencent, the progress bar restarts at 149 every run, and because `mark_error` was never called the row shows no error at all — the user has no way to learn why. Hence: `fetch_chapter` must **always** raise, never return empty. This is why the family-wide `if not lines: raise` (`ixdzs.py:106-107`, `xbanxia.py:86-87`, `shuba69.py:155-156`) is a convention and not a formality.

### 4.3 Picking `RateLimitedError` costs 20 hours per run

`_fetch_with_backoff` (`workers.py:2074-2093`) retries it `_RATE_LIMIT_MAX_RETRIES = 8` times at `_RATE_LIMIT_WAIT_SECONDS = 60` each (`workers.py:33-34`). 149 chapters × 8 minutes ≈ 20 hours, with a countdown ticking in the status bar the whole time. Pin it with a subclass assertion (`test_scrapers_tieuthuyetmang.py:270-276`).

### 4.4 Picking `DailyLimitError` loses the free chapters after chapter 65

`DailyLimitError` `break`s the batch (`workers.py:2140-2148`) and fires `daily_limit_hit`, which the scrape tab turns into an unlock flow that means nothing here. The brief measured occasional free chapters interleaved after the contiguous run, so aborting at the first paid chapter permanently loses them.

### 4.5 149 permanently-failing chapters do make the default reporting misleading

With `total = len(pending_download(...)) = 226` on a fresh project, the run ends at `_on_download_finished` (`tab_scrape.py:611-623`) with:

> `Tải xong: 77 chương thành công, 149 lỗi (bấm 'Tải các chương' để thử lại).`

That parenthetical is an invitation to re-run 149 hopeless fetches — and because `mark_error` leaves `content = ''` (`project.py:717-722`), `pending_download` really does return all 149 again next time. There is no "known-unavailable" state in the schema and adding one is out of scope.

**Recommendation: do not change the worker or the tab. Fix it entirely from inside the adapter**, three ways:

1. G1 skips the 149 **without requesting them** (§2.3), so the run costs 77 requests and finishes in about two minutes rather than seven.
2. `fetch_chapter_list`'s status line states the split at **scan** time, before the user ever presses download.
3. The per-chapter error string is self-explanatory (§2.3), so 149 identical rows read as one policy fact rather than 149 mysteries.

Flag as a possible follow-up, not part of this feature: a "retry only chapters that failed for a retryable reason" affordance. It would need an error *kind* persisted alongside the message, which is a schema change and belongs to its own feature.

### 4.6 `replace_toc` and `pending_download` do nothing surprising — but positional URLs do

- `replace_toc` (`project.py:283-298`) upserts by `idx`, preserves `content`, updates `title`/`url`, and respects `title_custom`. Re-scanning to pick up new chapters is safe, including for chapters that can never be fetched — they simply stay `content = ''`.
- `pending_download` (`project.py:362-378`) has no concept of "unavailable" and returns errored rows again. Confirmed, and §4.5 is the consequence.
- ⚠️ **The real hazard is `<n>` being positional.** If Tencent ever *inserts* a chapter, every later `<n>` points at different content. `replace_toc` updates the url and title but keeps the old content, so a previously-downloaded chapter would keep chapter *k*'s text under chapter *k+1*'s title. This affects any positional-URL site and is not introduced here, but it is the one argument for having kept `cid` (§2.5). Record it in the module docstring so it is discoverable rather than rediscovered; do not act on it now.

### 4.7 `content_is_translated` must stay `False`

If it were flipped, `DownloadWorker` (`workers.py:2122-2136`) would write the Chinese into `translated` and mark the chapter `STATUS_TRANSLATED`, so `pending_translation` (`project.py:401-408`) would skip it and the user's Vietnamese output would be Chinese. This is a Chinese-source adapter (`base.py:99-102`); the brief is explicit. A one-line test pins it, per `test_scrapers_tieuthuyetmang.py:361-364`.

### 4.8 A module-level TOC cache would cross-contaminate novels

`ScanWorker` and `DownloadWorker` each construct their own adapter (`workers.py:100`, `:2100`), but the process is long-lived and the user switches novels in the GUI. A module-global cache would serve novel A's `free` flags to novel B — which, via G1, would refuse the wrong chapters. Instance attributes only. `tieuthuyetmang.py:575-580` makes the same point in its comment.

## 5. Testing strategy

Saved fixtures only. **No test in the default suite makes a network request** — the discipline `test_scrapers_xbanxia.py`, `test_scrapers_ixdzs.py` and `test_scrapers_tieuthuyetmang.py` all keep, using `responses` for adapter wiring and `load_fixture` (`conftest.py:79-80`) for the parsing layer.

### Fixtures: what to save, how to trim, what each proves

Trimming rule, stated once and applied to all four: **keep the structure verbatim, replace the prose entirely.** Structure is what the parser reads and what a test can meaningfully pin; prose is what would make the file large and would put Tencent's copyrighted text in this repo for no test value. `test_scrapers_tieuthuyetmang.py:1-6` argues the same point from the other direction (a built fixture encodes the trap deliberately; a captured one contains it only by luck).

Procedure: save the page, then in an editor — keep `<head>`, the site header/nav, the content container and the subscribe block **exactly as served**; delete all but 2–4 `<p>` and replace their text with invented Chinese sentences; inside `window.__NUXT__`, keep the IIFE shape and the argument table intact but truncate the chapter array to ~8 entries with invented `chapterName` values. Target a few KB per file.

| Fixture | Shape | What it proves |
|---|---|---|
| `detail.html` | Nuxt IIFE with ~8 entries: a contiguous free run, then paid, then **one free entry after a paid one**; plus a rendered TOC and whatever head tags the real page carries | payload parsing incl. the argument table; `free`/`purchased` extraction; that the interleaved free chapter is not lost; metadata tiers |
| `chapter_free.html` | free chapter, 3–4 invented `<p>`, **site header with its 登录 link retained** | extraction works; and the header's 登录 does **not** trip G2 — the single most likely false positive |
| `chapter_paid.html` | teaser: 2 invented `<p>` + the subscribe block markup verbatim | G2 fires; and it fires **before** extraction |
| `detail_no_payload.html` | `detail.html` with the chapter-array key renamed | the HTML TOC fallback produces refs (without flags), instead of failing the scan |

## 7. Risks and genuinely open items

1. **The Nuxt payload parser (§2.1) — highest structural risk.** Handled by degrading to an HTML TOC rather than failing the scan, and by keeping `fetch_chapter` entirely independent of it. The residual is a TOC without `free` flags, which costs the pre-emptive skip and the status line but not correctness — because G2 still gates every chapter.
2. **G2's CTA selector and marker set (§2.3) — highest correctness risk.** Cannot be specified from here; **inferring** the shape of the subscribe block. Derived from `chapter_paid.html` at implementation time and pinned by the free/paid fixture pair in both directions. Both failure directions are visible: too broad refuses free chapters loudly, too narrow is caught by the paid-fixture test and, on the live site, by `TestLive`. Neither direction silently saves a teaser.
3. **`SEL_CONTENT` (§2.2) — inferring.** A candidate chain plus a structural last resort; missing it entirely raises `ScrapeError` rather than returning a partial body.
4. **Metadata field availability (§2.4) — inferring.** Only title is required; every other field degrades to `""`, which the GUI already handles.
5. **Positional `<n>` URLs (§4.6).** A chapter inserted upstream silently re-points every later row. Not introduced here, not fixed here, recorded in the module docstring. `cid` is the stable key if this ever bites; §2.5 explains why it is cheap to reintroduce.
6. **Progress/error reporting with 149 permanent failures (§4.5).** Mitigated from inside the adapter. The residual — the "bấm 'Tải các chương' để thử lại" invitation — is accepted deliberately rather than solved with a schema change, and named as a possible follow-up.
7. **Step 7's `ScanWorker` line touches shared code** and changes behaviour for `giatocvuongtai` too. Genuinely an improvement (it prevents metadata loss), but it is separable and should be its own commit so it can be reverted independently.
8. **Tencent's tolerance is untested at volume.** ~77 requests at 1.5 s is about two minutes; nothing observed suggests a problem, and §2.7 argues against pre-emptively slowing it down. If a live run shows throttling, the correct response is to map the throttle signal to `RateLimitedError` — which `_fetch_with_backoff` already handles (`workers.py:2077-2092`) — **not** to raise the global delay.
9. **Cookie support remains out of scope**, and the `set_cookies` raw-header/jar interaction (§2.7) is unverified. Anyone picking that up should measure it first. G1's `purchased` conjunction is the one piece of forward-compatibility built in deliberately, so that path does not require revisiting the gate.
