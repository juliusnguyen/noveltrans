# 039 — Pick a playlist from the channel, and push every part into it in order

## The ask

> Parse the `Danh sách phát` from the youtube account, then let the user choose the right
> `Danh sách phát`.
> Making a button to add all youtube video in order to the `Danh sách phát`.

## Settled scope

- **Picker is editable**: a dropdown seeded from the channel's real playlists, but a name
  that doesn't exist yet can still be typed and gets created on upload — today's
  behaviour, plus the list.
- **Add-all is clear-then-add**: the playlist is emptied first, then every part is added
  in order, so the order is exact every time.
  The user was shown the trade-off (destroys any manual arrangement, and briefly empties
  a playlist that may be public) and chose it deliberately.

## What exists today

`Danh sách phát` is a free-text `QLineEdit` (`tab_video.py`, `_build_upload_box`). Its
value goes into `UploadRequest.playlist`, and `_set_playlist` (`youtube_upload.py`) opens
Studio's picker during the upload, searches for the name, ticks it if found, and creates
it otherwise. Nothing ever reads the channel's actual playlists — so a typo silently
creates a second, near-identically-named playlist, and there is no way to add a part to a
playlist after it has been uploaded.

Machinery this builds on:

- `_launch_context()` / `profile_dir()` / `open_login()` — the persistent `.youtube-profile`.
- `_current_channel(page)` — returns the channel id, which the playlists page URL needs.
- The 034 pattern: navigate to a video's **edit page**, change one thing, confirm the save.
  Adding an already-uploaded video to a playlist is the same shape as replacing its
  thumbnail, and can reuse the same page and the existing `_PLAYLIST_*` selectors.
- `uploaded_video_id()` (034) — which parts have a video on the channel at all.
- `YouTubeThumbnailWorker` (034) — the worker/signal shape to copy.

## Open questions for `/plan`

- Where to read the playlists from: Studio's playlists page (`/channel/<id>/playlists`)
  vs. opening the upload dialog's own picker. The first is a plain list page; the second
  requires being mid-upload.
- Whether fetching needs its own button (it opens a browser, so it can't be automatic on
  tab load) and what the combo shows before the first fetch.
- **The clearing step is the risky part.** Studio has no "remove all"; it is a per-row
  menu action repeated N times. Decide what happens when clearing fails halfway — the
  playlist is already damaged at that point, so the run must not then add a scrambled
  mixture on top and report success.
- Whether to scrape the existing contents *before* clearing so a failure can tell the user
  exactly what was removed.
- Which parts the button covers: every part with a `video_id` in the current selection,
  presumably, in part order.

## Out of scope

- Reordering a playlist without clearing it (drag-and-drop is not reliably automatable).
- Creating playlists from the picker outside the upload flow.
- Playlist metadata (description, visibility, thumbnail).
