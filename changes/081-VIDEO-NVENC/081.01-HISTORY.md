# 081 — GPU (NVENC) cho video encode trên Windows — History

## [FEATURE] 081-VIDEO-NVENC — 2026-09-06
Created feature scaffolding, initially as `changes/080-GPU-AUDIO-VIDEO` (combined
audio+video GPU investigation). Renumbered to 081 after `git pull` on `main`
revealed 080 was already taken (PR #80, `080-VIENEU-3.4-UPGRADE`, had merged).

## [PLAN] 081.01-GPU-AUDIO-VIDEO-PLAN — 2026-09-06
Generated a combined plan covering both audio (VieNeu-TTS CUDA) and video
(ffmpeg NVENC) GPU acceleration. Ran a real capability check on this machine
(not simulated): confirmed via `nvidia-smi` an NVIDIA GeForce RTX 3060 Ti
(8 GB VRAM, driver 610.88), and confirmed the bundled
`packaging/ffmpeg/win/ffmpeg.exe` is a `8.1-full_build-www.gyan.dev` build
with NVENC/CUVID/NVDEC/AMF enabled — `h264_nvenc`/`hevc_nvenc` encodes
succeed at ~7x realtime. Recommendation: split into two sequenced features —
video/NVENC first (low risk, zero new deps), audio/CUDA second (source-install
only for v1, workers clamped to 1 on GPU).

## [SPLIT] 081-VIDEO-NVENC / 082-AUDIO-CUDA-TTS — 2026-09-06

## [IMPLEMENTATION] NVENC video encode — 2026-09-06
Implemented per the plan:
- `src/noveltrans/tts/video.py`: `nvenc_available()` (real sub-second probe
  encode via `ffmpeg -c:v h264_nvenc`, `lru_cache`d for the process lifetime
  — not just an `-encoders` listing check, since a universal ffmpeg build
  lists NVENC regardless of hardware); `VIDEO_ENCODERS`/`video_encoder_args()`
  (libx264 unchanged default, h264_nvenc with `-preset p4 -cq 23`); `render_video`
  gained an `encoder` param and retries once with libx264 if a non-default
  encoder fails mid-render (deletes the partial output first).
- `src/noveltrans/config.py`: `video_encoder` property (`libx264`/`h264_nvenc`,
  validated, defaults to `libx264`), mirroring `tts_precision`'s pattern.
- `src/noveltrans/video_settings.py`: added `video_encoder` to `WORKFLOW_KEYS`
  (a per-novel override that inherits the user's last-used habit, same as
  `video_quality`).
- `src/noveltrans/gui/tab_video.py`: new "Encode:" combo next to "Chất lượng:"
  (CPU/GPU), GPU item disabled with a tooltip when `nvenc_available()` is
  False; a stored `h264_nvenc` choice from a different machine falls back to
  `libx264` on load rather than landing on a disabled item.
- `src/noveltrans/gui/workers.py`: `VideoWorker` threads `encoder` through to
  `render_video`.

Verified for real, not just mocked: ran `render_video(..., encoder="h264_nvenc")`
end-to-end on this machine (the same RTX 3060 Ti / bundled ffmpeg from the
plan's capability check) — produced a valid playable MP4. Also launched the
actual app (`python -m noveltrans`), opened "5. Video", and screenshotted the
new combo: renders cleanly next to "Chất lượng:", both items shown enabled
(GPU correctly detected), no layout breakage.

Added tests: `tests/test_video.py` (`TestVideoEncoders`, `TestNvencAvailable`,
new `TestRenderArgv` cases for encoder selection + GPU-failure fallback),
`tests/test_video_settings.py` (`TestVideoEncoderConfig`), `tests/test_tab_video.py`
(`TestVideoEncoderCombo`). Full suite: 3222 passed, 4 skipped.

Not in scope here (see `changes/082-AUDIO-CUDA-TTS`): GPU for VieNeu-TTS audio.
