# 079 — bqg5.com scraper — history

## [PLAN] 079.01-INITIAL-PLAN — 2026-09-06

Generated plan: `079.01-INITIAL-PLAN.md`

Preceded by live reconnaissance of bqg5.com through `curl` and the repo's own
`HttpClient`. The headline finding overturns the premise in the prompt: the site is
**not** mobile-only. It runs a **User-Agent allowlist** — `base.USER_AGENT` gets HTTP
404 (548 bytes) on *both* `m.bqg5.com` and `www.bqg5.com`, and an iPhone Safari UA gets
200 on both. No Cloudflare, no JS challenge, no browser needed.

Consequence: with a mobile UA the `www` host serves the full desktop layout — the whole
chapter list in one request (`#list dl`) and each chapter complete in one page
(`#content`). The `m.` host paginates the TOC across 22 pages and splits every chapter
into `_N.html` sub-pages. So the adapter accepts the `m.` URL the user pastes but
normalises to `www` internally.

Traps the plan pins, all measured on novel `4_4217`:
- The TOC's first `<dt>` is a 最新章节 block whose `<dd>`s duplicate the newest chapters —
  **9** of them, not a fixed count, so the real 正文 block must be located structurally.
- 439 real `<dd>` against a last title of `第438章`, so a sto9/twkan-style `stated_total`
  guard would refuse every scan. Deliberately not written.
- `#info` contributes a 449th chapter-shaped anchor; `#listtj` recommendations are other
  books. Both leak into a loose `a[href]` scrape.
- gbk with no charset header — `HttpClient.get_html`'s `apparent_encoding` fixup already
  carries it; no adapter-side encoding code.
- `#intro` / `og:description` carry literal `\n` and `\"` escape sequences, and `\xa0`
  indent runs, rather than real markup.

## [IMPL] bqg5.com adapter — 2026-09-06

Implemented per `079.01-INITIAL-PLAN.md`. Offline suite 78 passed, live suite 5 passed,
full suite **3203 passed** (no regressions), `ruff check src tests` clean.

### One deviation from the plan

`_chapter_dds`' fallback was tightened while building the fixtures. The plan said
"prefer the `<dt>` containing 正文, else the LAST `<dt>`" — but that rule cannot tell a
novel whose only section is the real one (`index_one_dt.html`, must parse) from a page
whose only section is the 最新章节 decoy (`index_no_body_dt.html`, must refuse). Written
as planned it would hand back the newest 9 chapters as chapters 1-9, which is the exact
misfiling the whole no-fallback policy exists to prevent. The fallback now excludes any
`<dt>` whose text contains 最新章节, so both fixtures behave. `_LATEST_SECTION` is the
new constant; `test_a_toc_with_only_the_decoy_section_is_refused` pins it.

Fixtures also carry `&nbsp;` entities rather than raw U+00A0 — both more faithful to the
live markup (which is where the `\xa0` in the parsed DOM comes from) and necessary,
since a raw NBSP is not encodable in gbk and would have broken the round-trip that
`test_gbk_bytes_with_no_charset_header_decode_correctly` depends on.

### Plan §9 verification, against the live site

1. **Other novels' TOC shape** — checked `0_16` (295 ch), `0_35` (1020 ch), `0_37`
   (321 ch), `0_38` (60 ch). All four have the same two-`<dt>` structure, all four put the
   `#info` 最新章节 anchor at the END of the parsed list, all four have a real cover.
   *No live novel with a single `<dt>` was found* — `index_one_dt.html` models a shape the
   fallback handles but the site has not been observed to serve.
2. **Chapter pagination on `www`** — none. 12 chapters of `0_38` fetched whole,
   2 200-4 036 chars, zero `第(1/`, `点击下一页` or `加入书签` markers. `_2.html` 404s.
3. **`apparent_encoding` on a short page** — the shortest chapter page (14 691 bytes)
   still sniffs `gbk`, and no chapter produced a replacement character.
4. **A `nocover` novel** — still unverified: every novel sampled has a real cover. The
   blanking is pinned by fixture only, and the string is the one the live markup names in
   `data-evt`, so the risk is that `og:image` uses a different filename than `#fmimg`.
5. **Rate limiting over a long run** — not exercised. 12 sequential chapters at the
   default delay drew no 429.
6. **`m.` vs `www.` chapter ids** — identical on the reference novel; not re-checked
   elsewhere.

`0_38` numbers its chapters in Chinese numerals (`第十一章`), which is independent
confirmation of the plan's decision to take `index` from position and never from the
title — a `第\d+章` parse would return nothing at all for that novel.

### Files

- **`src/noveltrans/scrapers/bqg5.py`** (new) — `Bqg5Adapter` plus a pure parsing layer
  (`book_id`, `read_url`, `chapter_url`, `parse_metadata`, `latest_chapter_url`,
  `_chapter_dds`, `parse_chapter_list`, `parse_chapter`). `_get_html` is the single

  `base.py` is untouched and the shared session cannot leak the UA to another site.

- **`tests/fixtures/bqg5/`** (new) — 9 fixtures, hand-built to the measured structure
  with invented filler prose. All nine verified to round-trip through gb18030.
- **`README.md`** — one row after timotxt.

### Notes for later

`NovelMeta.url` is always `https://www.bqg5.com/<id>/`, never the pasted string, so a
project scanned from the `m.` link and one scanned from the `www` link are the same
project. `ScanWorker` already does `find_by_url(pasted) or find_by_url(meta.url)`, so
re-pasting the mobile link still finds it.

The desktop-UA 404 is pinned by a live canary (`test_the_desktop_user_agent_is_still_
refused`) against BOTH hosts. If the site ever drops the gate that test fails loudly,
rather than the UA override quietly becoming dead code nobody can explain.
