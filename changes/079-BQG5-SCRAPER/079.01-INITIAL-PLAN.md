# 079-BQG5-SCRAPER — Implementation Plan

## 0. Headline decisions (and why)

| Question | Decision |
|---|---|
| Is this a Cloudflare/browser site? | **No.** Plain `HttpClient`. No `cf_browser`, no Playwright. |
| Why is it "mobile only"? | It is a **User-Agent allowlist**, not a mobile site. Measured: `www.bqg5.com/4_4217/` and `m.bqg5.com/4_4217/` both return **HTTP 404, 548 bytes** with `base.USER_AGENT`, and both return **200** with an iPhone Safari UA. Nothing about the viewport matters. |
| Which host does the adapter actually read? | **`www.bqg5.com` only.** `m.` is accepted in `url_patterns` (it is what the user pastes) but normalised away immediately. |
| How is the mobile UA plumbed? | **Per-request `headers=` through `client.get_html(url, headers=...)`.** `base.py` is not touched. |
| Ad/junk stripping | **Nothing new.** Measured: `#content` on the www layout contains only `<br>` — 0 `<script>`, 0 `<div>`, 0 `<a>`. `translators/ads.py` is already generic and domain-anchored; no change there either. |
| Metadata source | **OpenGraph** (the page has a full `og:novel:*` block), with the `#info`/`#intro`/`#fmimg` DOM as fallback. |
| `stated_total` guard | **Deliberately absent.** See §3.6 — copying sto9/twkan's guard here would refuse every scan. |

## 1. Live facts measured (2026-09-06, novel `4_4217`)

Everything below was measured through the repo's own `HttpClient`.

### 1.1 The UA gate
```
GET https://www.bqg5.com/4_4217/   UA=base.USER_AGENT  -> 404, 548 bytes
GET https://m.bqg5.com/4_4217/     UA=base.USER_AGENT  -> 404, 548 bytes
GET https://www.bqg5.com/4_4217/   UA=iPhone Safari    -> 200, 64 077 bytes
```
The desktop UA 404s on **both** hosts — so the mobile UA is required on every request on
every path, not just the `m.` one.

### 1.2 Encoding — already handled, but pin it
```
content-type: text/html          (no charset — this is the whole point)
<meta http-equiv="Content-Type" content="text/html; charset=gbk" />
requests -> response.encoding == "ISO-8859-1"   (its text/* default)
        -> HttpClient.get_html fixup fires
        -> response.apparent_encoding == "gbk"
        -> decoded text is byte-identical to content.decode("gb18030")
```
0 x `U+FFFD` on the TOC page and on two chapter pages. **No adapter-side encoding code is
needed.** Do not hardcode `response.encoding`; that would require a new `HttpClient` hook
for one site.

### 1.3 The www TOC page (`https://www.bqg5.com/4_4217/`) — one request, whole list

`div#list > dl` has exactly **two `<dt>`** and **448 `<dd>`**:

| block | `<dt>` text | `<dd>` count |
|---|---|---|
| 0 | `《…》最新章节 （提示：已启用缓存技术…）` | **9** — duplicates of the newest chapters |
| 1 | `《…》正文` | **439** — the real, ordered list |

> The duplicated block is **9** entries today, not the 5 seen in an earlier probe.
> **A hardcoded "drop the first N" is wrong** — the block must be located structurally.

Other `/4_4217/<cid>.html` anchors on the page: **449** total = 9 + 439 + **1** in `#info`
(the 最新章节 link, which points at the same URL as the last real `<dd>`). `#listtj`
recommendations are other books (`/0_500/`, `/1_1781/` …) and do **not** match the chapter
shape — but they *would* match a loose `a[href*="/4_"]`.

Divs with ids on this page: `wrapper, banner, maininfo, info, intro, sidebar, fmimg,
listtj, list, footer`.

### 1.4 OpenGraph on the TOC page
```
og:novel:book_name  = <title>
og:novel:author     = <author>
og:novel:category   = 穿越小说
og:novel:status     = 连载中
og:novel:read_url   = https://www.bqg5.com/4_4217/     <- the site's own canonical form
og:novel:update_time= 2026-09-06 00:23:57
og:novel:latest_chapter_name = 第438章…
og:image            = https://www.bqg5.com/files/article/image/4/4217/4217s.jpg  (ABSOLUTE)
og:description      = …570 chars…
```
`og:novel:read_url` confirms `https://www.bqg5.com/<id>/` is the site's *own* canonical
URL — that is what `read_url()` should produce.

DOM fallback:
- `#info h1` -> title
- `#info p` -> `作\xa0\xa0者：…`, `状\xa0\xa0态：…`, `更新时间：…`, `最新章节： …`.
  **The label padding is `\xa0` (NBSP), not a normal space** — so `text.startswith("作者")`
  fails; split on the colon instead.
- `#fmimg img[src]` = `/files/article/image/4/4217/4217s.jpg` — **relative**, needs `urljoin`.
- `#fmimg img` also carries `data-evt="src='/images/nocover.jpg'"` — **the placeholder
  cover this CMS family uses is evidenced right there in the markup**, and it is the same
  string `sto9.py:62` already blanks.

### 1.5 The description trap
Both `og:description` (570 chars) and `#intro` (571) carry **literal two-character escape
sequences**, not real markup:
- `23 x` literal `\n` (backslash + n) and **0** real newlines in `og:description`
- literal `\"` for quotes
- `32 x` `\xa0` used as a mid-line indent run

`og:description` is the same text with a cosmetic trailing `...`. -> **prefer `#intro`,
fall back to `og:description`**, and run both through one `_clean_description`.

### 1.6 Chapter page (`https://www.bqg5.com/4_4217/2029247.html`)
- `<h1>` = `' 第1章 …'` — **leading space**, lives in `div.bookname`, **outside** `#content`.
- `div#content` children: **`br` only.** Shape:
  `\xa0\xa0\xa0\xa0<prose><br/>\n<br/>\n<br/>\n\xa0\xa0\xa0\xa0<prose>…`
- `get_text("\n")` + drop-blanks -> **114 paragraphs, 2 148 chars.** No junk lines, no promo
  line, no `第(N/M)页` marker, no bookmark link.
- Nav lives in sibling `div.bottem1` / `div.bottem2` (`上一章 /4_4217/`,
  `下一章 /4_4217/2029248.html`, `章节目录`, plus a `/newmessage.php?…` report-an-error link).
- **`https://www.bqg5.com/4_4217/2029247_2.html` -> 404.** The www layout does **not**
  paginate chapters; the mobile split is a mobile-template artefact.
- Last chapter (`2266895.html`) parses identically: 2 199 chars, whole.

Mobile equivalent, for the record: `#chaptercontent` on `2029247.html` (1 111 chars) +
`2029247_2.html` (1 148) = 2 259, of which ~111 chars are the `第1章 …第(1/2)页` header and
the `『加入书签，方便阅读』` footer that appear **on every sub-page**. Same prose, 2 requests,
plus stripping.

### 1.7 The numbering trap — why there is no `stated_total`
- The real block has **439 `<dd>`**, but the last one is titled **`第438章`**, and
  `og:novel:latest_chapter_name` says **`第438章…`**.
- Chapter titles use the site's own inconsistent spacing: `第1章 …`, `第 269章…`,
  `第270 章 …`, `第 273章 …` — 37 of 439 titles do not match `第\d+章`.
- No duplicate hrefs and no duplicate titles inside the real block.

**Conclusion: `len(refs)` and the title numbers disagree by design.** sto9's and twkan's
`stated_total` refusal guard, transplanted here, would reject a perfectly good 439-entry
list as "439/438". It must not be written.

### 3.3 `read_url` — the host-normalisation decision

```python
def read_url(url: str) -> str:
    """The canonical URL for a novel — the site's own `og:novel:read_url` shape.

    Always the `www` host, whichever the user pasted. Two reasons, and both are
    load-bearing:

    * `Library.find_by_url` is exact string equality, so echoing the pasted string would
      let `m.bqg5.com/4_4217/`, `www.bqg5.com/4_4217/` and a chapter URL become three
      projects for one novel, each with its own translation progress and video settings.
      `ScanWorker` looks a project up by BOTH the pasted URL and `meta.url`, so a re-scan
      pasted in the `m.` form still finds the project this creates.
    * `NovelMeta.source_host` strips only `www.`, so storing the `m.` host would print
      "m.bqg5.com" in the novel tab bar and the picker.
    """
    return f"{ORIGIN}/{book_id(url)}/"
```

**Why the mobile layout is not implemented at all** (document this in the module
docstring): its TOC is 22 requests instead of 1 (`index_N.html`, 20/page); its chapters are
split across `_N.html` sub-pages chained by `a#pt_next`, whose last link points at the
*next chapter's* id — a chain that silently runs off the end of a chapter is exactly the
misfiling hazard `replace_toc` makes permanent; and its bodies carry a `第N章…第(1/2)页`
header, a `第N章…,点击下一页继续阅读。` footer and a `『加入书签，方便阅读』` bookmark anchor
on every sub-page, plus a `p.synopsisAd` next to the container. The `www` layout serves
**the same prose at the same chapter ids** in 1 + 1 requests with none of that. An unused
mobile fallback would be untested code on a data-integrity path.

### 3.4 `_chapter_dds` — the load-bearing selector

```python
def _chapter_dds(dl) -> list:
    """The <dd>s of the 正文 section, in document order — never the 最新章节 block.

    `#list dl` is FLAT: two <dt> section headings and 448 <dd> as siblings, no nesting.
    The first section is 最新章节 and its <dd>s are duplicates of the NEWEST chapters
    (9 of them on the reference novel — the count varies, so it can never be hardcoded).

    Preferred rule: the <dt> whose text contains 正文. Fallback: the LAST <dt>, which is
    the same node whenever there is one, and is also correct for a novel whose 最新章节
    block is absent entirely (one <dt>, all the <dd>s real).

    There is deliberately NO "if that fails, take every <dd>" branch. That fallback
    returns the 9 newest chapters at indices 0-8 — `ChapterRef.index` is dense and
    positional, `replace_toc` preserves content across re-scans, so chapter 431's body
    would sit under index 0 forever behind a later-corrected title. Same trap as
    timotxt's reversed recent block (timotxt.py:31) and sto9's truncated page. Returning
    [] here makes the caller raise, which is the safe direction.
    """
    children = [t for t in dl.children if getattr(t, "name", None)]
    headings = [i for i, t in enumerate(children) if t.name == "dt"]
    if not headings:
        return []
    start = next(
        (i for i in headings if _BODY_SECTION in children[i].get_text()),
        headings[-1],
    )
    return [t for t in children[start + 1 :] if t.name == "dd"]
```

### 3.5 `parse_chapter_list`

```python
def parse_chapter_list(markup: str, url: str) -> list[ChapterRef]:
    soup = BeautifulSoup(markup, "lxml")
    dl = soup.select_one(SEL_LIST)
    anchors = []
    if dl is not None:
        anchors = [
            a
            for dd in _chapter_dds(dl)
            for a in dd.select("a[href]")
            if _CHAPTER_HREF_RE.search(a.get("href") or "")
        ]
    if not anchors:
        raise ScrapeError("Chapter list not found — page layout may have changed", url)

    # `index` from enumerate, never from a number parsed out of the title. Measured on
    # the reference novel: 439 entries whose highest title number is 第438章, and 37 of
    # those titles do not even match `第\d+章` because the site spaces them
    # inconsistently ("第 269章", "第270 章"). The <dd> order IS the reading order.
    #
    # Titles are the anchor's text, stored verbatim including that spacing: they are
    # persisted, exported and read aloud, so a tidy-up normaliser here would silently
    # rewrite them across a re-scan.
    return [
        ChapterRef(index=i, title=a.get_text(strip=True), url=urljoin(ORIGIN, a["href"]))
        for i, a in enumerate(anchors)
    ]
```

### 3.7 `parse_metadata`

- OG first: `og:novel:book_name` -> `og:title` -> `#info h1`. Missing title =>
  `ScrapeError("Novel title not found — page layout may have changed", url)`.
- Author: `og:novel:author`, else scan `#info p` and split on `[:：]` — **not**
  `startswith("作者")`, because the label is `作\xa0\xa0者`.
- Description: `_clean_description(#intro text or og:description)`.
- Cover: `og:image` else `urljoin(ORIGIN, #fmimg img[src])`; blank it if it ends with
  `_PLACEHOLDER_COVER`.
- `url=read_url(url)`, `source_lang="zh"` (written explicitly, per house style).

`_clean_description` must, in order: unescape literal `\"` -> `"`, literal `\n` -> newline,
collapse `_WS_RE` runs (this is what removes the `\xa0\xa0\xa0\xa0` indents *inside* a
line — `strip()` alone only handles the ends), collapse `\n{3,}` -> `\n\n`, `strip()`.

### 3.8 `parse_chapter`

Same shape as `twkan.parse_chapter`: select `SEL_CONTENT`, decompose `SEL_CHROME`,
`get_text("\n")`, drop blank lines, drop at most one leading line when
`_norm(line) == _norm(title)` (mandatory here — the `<h1>` has a **leading space** and the
TOC title does not), raise `"Chapter content is empty"` when nothing survives, join with
`\n\n`. `\xa0` is `str.isspace()` in Python 3, so plain `line.strip()` removes the indents
— do not add a blanket `replace("\xa0", "")`, which would also eat the NBSPs the site uses
mid-line.

### 3.9 The adapter

```python
@register
class Bqg5Adapter(SiteAdapter):
    name = "bqg5"
    display_name = "笔趣阁 (bqg5.com)"
    # One pattern covers www., m. and the bare host, and the `\d+_\d+` id shape keeps
    # the category pages (/xuanhuanxiaoshuo/) and /map/ out. Host-anchored so it cannot
    # steal a neighbour's URLs — ADAPTERS is first-match-wins by import order.
    url_patterns = [r"bqg5\.com/\d+_\d+"]
    content_is_translated = False

    def __init__(self, client):
        super().__init__(client)
        # Per-instance, never module-level: the app is long-lived and the user switches
        # novels, so a shared cache would answer one novel's questions with another's page.
        self._toc: tuple[str, str] | None = None   # (bid, markup)

    def _get_html(self, url: str) -> str:
        """The single seam between this adapter and the network.

        The mobile UA is a PER-REQUEST header, never a mutation of the shared session.
        Today one `HttpClient` is built per worker run and bound to exactly one adapter,
        so mutating it would happen to be safe — but `HttpClient.set_cookies` already
        documents the "scope one client to one site" assumption as an assumption, and
        requests merges a per-request `headers=` over the session's for the same key, so
        this costs nothing and cannot leak. It also leaves `base.py` untouched, which is
        the whole blast radius of this feature.
        """
        return self.client.get_html(url, headers=_HEADERS)

    def _toc_page(self, url: str) -> str:      # cached, mirrors timotxt._landing_page
        ...

    def fetch_metadata(self, url) -> NovelMeta:
        return parse_metadata(self._toc_page(url), url, self.name)

    def fetch_chapter_list(self, url) -> list[ChapterRef]:
        markup = self._toc_page(url)
        refs = parse_chapter_list(markup, read_url(url))
        # ...leak guard from §3.6...
        return refs

    def fetch_chapter(self, ref) -> str:
        return parse_chapter(self._get_html(ref.url), ref.title, ref.url)
```

**A scan costs exactly one request** — metadata and the chapter list come off the same
page, and `_toc_page` caches it. Worth pinning in a test; no other adapter in the repo has
this property (twkan and timotxt both cost two).

`close()` is inherited (nothing held). No `__init__.py` ordering hazard: `bqg5` sorts first
alphabetically and its pattern is host-anchored.

## 5. Ads / junk — what belongs where

**Nothing changes outside the adapter.** Reasoning to record in the module docstring:

- **Structural junk:** measured, the www `#content` has 0 `<script>`, 0 `<div>`, 0 `<a>`.
  `SEL_CHROME` is defensive insurance, named per element (never a blanket `div`
  decompose — `twkan.py:135` records why that eats prose).
- **`translators/ads.py` (feature 069):** already the right net if bqg5 ever water-marks a
  chapter with a promo line. Its predicate is *shape*-based and domain-anchored
  generically (`_fold` NFKC-normalises and closes up decorative glyphs), so a
  `bqg5(decorated).com` line is caught with no code change and no new blocklist entry.
  Adding a bqg5 string there would be a literal blocklist, which that module exists to
  avoid. The two nets are complementary: `ads.py` runs on fresh translator output; any
  stripping here is structural, on DOM nodes, before anything is stored.
- **`cleanup.py`** is the *file-deletion planner* (audio/video), unrelated to this feature
  despite the name. No change.
- The mobile layout's junk (`第N章…第(1/2)页`, `『加入书签，方便阅读』`, `p.synopsisAd`) is
  another reason the mobile path is not implemented — see §3.3.

## 9. Things the implementer must verify against the live site

1. **A second novel's TOC shape.** Everything above is measured on `4_4217` only. Confirm
   the two-`<dt>` structure (and that some novels genuinely have one `<dt>`, which is what
   `index_one_dt.html` models) on at least one other book — pick one from `#listtj`, e.g.
   `https://www.bqg5.com/0_500/`.
2. **Whether any chapter is paginated on `www`.** `2029247_2.html` 404s and chapters 1 and
   438 are both whole, but check the site's longest chapter. If a `第(1/2)页` marker ever
   appears in `#content`, the adapter needs a sub-page loop — and the `<h1>` would then need
   a suffix strip.
3. **`apparent_encoding` on a very short page.** `charset_normalizer` is content-length
   sensitive; it returned `gbk` on a 64 KB TOC and a 12 KB chapter. Fetch the shortest
   chapter and assert no replacement characters. Also note `apparent_encoding == "gbk"`
   (not `gb18030`) means a character outside GBK would be replaced via requests'
   `errors="replace"` — not observed, but it is the failure mode to watch, and the live
   test's mojibake check is the detector.
4. **A real `nocover` novel.** The placeholder string is evidenced in the markup
   (`data-evt="src='/images/nocover.jpg'"`) but no coverless novel was found; confirm that
   `og:image` (not just `#fmimg`) actually carries that filename when a novel has no cover,
   otherwise the blanking only fires on the fallback path.
5. **Rate-limiting over a full 439-chapter run** at the app's default delay. Not measured.
   If the site 429s or blocks, the adapter needs the `RateLimitedError` treatment the
   download worker already has backoff for — not the browser.
6. **Whether `m.` and `www.` ever disagree on chapter ids** for a novel other than the
   reference. They are identical here, and the whole host-normalisation decision rests on it.
